# T-464 — `LiveQAClip`

**Branch**: `task/T-464-live-qa-clip`

## Goal

Ship the **LiveQAClip** family. Mirrors the LivePoll-family template
(T-461..T-463), with per-kind shapes:

- Vote: `{ kind: 'live-qa', action: 'submit' | 'upvote', text?: string,
  questionId?: string }`. `text` present when action is `submit`
  (length ≤ 500); `questionId` present when action is `upvote`.
- Aggregation: `{ questions: readonly { id, text, upvotes, submittedAt,
  answered? }[], totalQuestions }`. The `questions` array is ordered
  server-side by `upvotes` desc (stable for ties; secondary
  `submittedAt` asc) and capped at `topN` (default 100).
- Rendering: a vertical list of question cards. Each card shows: text;
  upvote count badge; "answered" badge (if true); a relative-time
  "Asked X mins ago" label. The top-3 cards get a subtle highlight
  ring (most-popular indicator).
- Voter UI: a tabbed surface — `Submit` tab is a `<textarea
  maxLength={500}>` + submit button; `Browse` tab lists the live
  questions with an upvote button on each (disable after own upvote
  per `questionId`; one upvote per voter per question).

§13 verification is option-1 — `render-e2e.test.ts` drives the
static-fallback with a known questions snapshot + asserts on observable
DOM ordering, count badges, top-3 highlight, and pixel-bucket
non-blankness.

## Implementation notes

- **Schema**: `props: { topic: z.string().min(1), allowUpvoting:
  z.boolean().default(true), moderationMode: z.enum(['open',
  'moderated']).default('open'), maxLength: z.number().int().positive().
  max(2000).default(500), topN: z.number().int().positive().max(500).
  default(100), sessionId: z.string().optional() }`. `permissions`
  tuple as before.
- **Static-fallback rendering**: vertical list of question cards.
  Sort defensively by `upvotes` desc (stable for ties; secondary
  `submittedAt` asc). Top-3 cards get `data-highlight="popular"`.
  Each card renders: text, upvote count badge, "answered" badge if
  true, relative-time string from `submittedAt`. Total label reads
  `${totalQuestions} questions`.
  - **Determinism note**: relative-time computation MUST be a pure
    function of `submittedAt` + `ctx.frame * (1 / fps)` derived
    timestamp — NO `Date.now()`. The renderer accepts a `now: number`
    prop (epoch ms) which the host injects from the deterministic
    frame clock; tests pass a controlled value. This matches the T-454
    determinism perimeter.
- **Voter input UI** (`live-qa-voter-input.tsx`): tabbed surface with
  two tabs, `Submit` and `Browse`.
  - `Submit`: `<textarea maxLength={maxLength}>` + submit button. On
    submit, call `onSubmit({ kind: 'live-qa', action: 'submit', text
    })`; clear text + show "Question submitted".
  - `Browse`: subscribes to the live aggregation (via the parent
    voter-app-client's snapshot stream); renders the list of
    questions with an upvote button on each. On upvote, emit
    `{ kind: 'live-qa', action: 'upvote', questionId }` + memo the
    questionId in component state to disable that button.
- **Mirror T-461..T-463 exactly** for layout / tests / dispatcher
  registration.
- **Determinism perimeter**: same as prior — static-fallback pure
  (relative-time uses injected `now` prop); factory's
  `runAudienceClient` is the only non-deterministic surface.
- **Pre-empt skills-sync drift**.
