# T-322a — fix LyricsClip rendering bugs (karaoke-wipe width, multi-line layout, glow visibility)

**Branch**: `task/T-322a-lyrics-render-fixes`

## Goal

Unblock T-367 (`karaoke-progressive-wipe`). Visual review of T-367's parity
golden at frame 105 (mid-line2, 40% wipe progress, 3-line stack) found four
LyricsClip rendering bugs in
`packages/runtimes/frame-runtime-bridge/src/clips/lyrics.tsx`:

1. **Karaoke-wipe width as pixels, not percent.** Line 277:
   `width={karaokeProgress * 100}` — SVG reads `40` as 40 user-space px at
   progress 0.40, not 40% of the region. Wipe essentially invisible.
2. **Long lines overflow at default size 96.** `whiteSpace: 'nowrap'`
   (line 227) makes T-367's `"WE WERE STRONGER TOGETHER"` (25 chars × ~50 px
   ≈ 1250 px) clip the 1024 px position width.
3. **Line 3 missing in 3-line stack.** Only lines 1–2 visible at frame 105;
   line 3 absent.
4. **Glow halo invisible.** T-367 declared `glow: { color: '#FFFFFF',
   blur: 6 }`; no perceptible halo on the active line.

T-322's spec contract is correct; only the implementation diverges. T-322a
is a surgical ~10–30 LOC patch + 4–6 regression vitest cases. After T-322a
lands, T-367 retries unchanged. Same pattern as T-316 → T-316a → T-365-retry.

Existing tests didn't catch these because JSDOM doesn't rasterize SVG; test
inputs used minimal-length lines; 3-line + glow combinations weren't
exercised together.

## Architectural decisions

### D-T322a-1. Bug 1 — percentage-string `<rect>` width

Change `width={karaokeProgress * 100}` (line 277) to
`width={\`${karaokeProgress * 100}%\`}`. SVG reads unitless numbers as
user-space pixels; percentage computes against the enclosing `<svg>`
viewport spanning the line region. `height="100"` → `height="100%"` for
symmetry. Alternative (`clipPathUnits="objectBoundingBox"`) is equivalent
but more invasive — pick percentage.

### D-T322a-2. Bug 2 — investigate; smallest non-regressive change

- (a) **Drop `whiteSpace: 'nowrap'`** — natural wrap. Risk: regresses tests
  assuming single-line.
- (b) **Reduce `DEFAULT_FONT.size` from 96 to 64.** 25-char line at 64 px ≈
  800 px, fits 1024 px width. One-constant change.
- (c) **`textLength` / `lengthAdjust`** — incompatible with the
  `<foreignObject>` path. NOT.

**Recommendation**: prefer (b) if existing tests rely on nowrap; (a) if not.
Implementer picks; document in PR body.

### D-T322a-3. Bug 3 — bypass entrance fade for non-active roles

The visible-window math (lines 393–417) correctly emits slots
`{-1, 0, +1}` for `maxLinesVisible: 3` and `activeIndex = 1`. But
`computeLineEntrance` (lines 124–150) interpolates opacity from the line's
`startMs`-derived frame; for line 2 (`startMs = 5000`) at frame 105
(currentTimeMs 3500), `entranceStartFrame = 150` is **future** →
`interpolate` clamps left → opacity 0. The line renders with **opacity 0**,
hence "missing" visually.

**Fix**: pass `entranceState = { opacity: 1, translateY: 0 }` for
`entry.role !== 'active'`. The entrance animation is the active line's
"I am now active" beat; preview / past lines render at full opacity
(subject to `muteOpacity` role-gating which is independent).

### D-T322a-4. Bug 4 — compose glow via `<feComposite>` + `<feMerge>`

Current filter (lines 258–262 / 321–325) emits only `<feGaussianBlur>` +
`<feFlood>` — produces no output because blur and flood are not composed.
Apply standard SVG glow recipe to both filter bodies:

```svg
<filter id="...">
  <feGaussianBlur in="SourceAlpha" stdDeviation="..." result="blur"/>
  <feFlood flood-color="..." result="flood"/>
  <feComposite in="flood" in2="blur" operator="in" result="coloredBlur"/>
  <feMerge>
    <feMergeNode in="coloredBlur"/>
    <feMergeNode in="SourceGraphic"/>
  </feMerge>
</filter>
```

Stable IDs (line-index-derived) unchanged per T-322 D-T322-4.

### D-T322a-5. NO bundled T-367 retry

Surgical. T-367's resolver entry + preset markdown + parity golden +

### D-T322a-6. Tests assert rendered shape, not just attribute equality

+ non-zero opacity for all 3 lines; `<feMerge>` substring for glow;
long-line render at default font fits position width.
