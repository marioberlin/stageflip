# T-348b — Parity-golden non-blank CI gate

## Why this task exists

The Cluster D regression slipped through CI because both the expected golden and the actual render were equally blank — a blank-vs-blank PSNR / SSIM comparison scores as `∞` (identical), so the parity-fixture-scoring CI gate passed despite the rendered pixels being visually wrong. Phase 4 closes this silent-CI-bypass class by adding a positive-content invariant on signed parity goldens themselves: a signed golden must contain at least N distinct color buckets, OR no single bucket may dominate ≥ X% of sampled pixels. A near-uniform PNG fails the gate; the gate runs in the existing `pnpm check-preset-integrity` job with no new CI wiring.

This is **Phase 4** of the regression remediation per [`docs/handover-cluster-d-regression.md`](../handover-cluster-d-regression.md). Phase 2 (architectural fix) shipped in T-348a / PR #445. Phase 3 (re-generate + PO ratify) lands in a separate task once PO is available.

## Decisions

### D-T348b-1 — only check signed goldens

Pending-user-review goldens are by definition WIP and may legitimately be blank stubs. `na` goldens are explicitly opted-out. The new invariant matches `signOff.parityFixture` against `/^signed:\d{4}-\d{2}-\d{2}$/` and skips otherwise. This is the safety property: a green CI on a signed preset MUST imply the golden is positively content-bearing.

### D-T348b-2 — metric: two-stage detection (refined post-empirical-tuning)

Initial design proposed a "distinct buckets < 50 AND dominance > 97%" combined criterion. Empirical testing against the 35 currently-signed goldens revealed that several **legitimate** Cluster F + G presets — `coinbase-dvd-qr` (small QR rectangle on solid black), `tiktok-follow-pulse` (faded pulse circle on white), `youtube-subscribe-bounce`, `instagram-link-sticker`, `ali-abdaal-opacity-karaoke` — sit numerically inside that envelope (3-20 distinct buckets, 97-99.9% dominance) due to small foreground elements on flat canvases.

The shipped metric uses a two-stage formulation:

A bucket is **significant** when it holds at least `NON_BLANK_SIGNIFICANT_BUCKET_FRACTION = 0.05%` of total pixels (~1037 px on 1080p). The gate fires when BOTH:

1. `significantBuckets < NON_BLANK_MIN_SIGNIFICANT_BUCKETS = 2` — only one color band crosses the significance floor, AND
2. `maxBucketFraction > NON_BLANK_BLANK_DOMINANCE_THRESHOLD = 99.95%` — essentially every pixel matches the dominant bucket; anti-aliasing fringe accounts for less than 0.05% of the image.

The 0.05% gap between the significance fraction (0.05%) and the dominance gate (99.95%) is intentional: a golden with > 0.05% non-modal pixels EITHER concentrates them in one secondary bucket (clears stage 1) OR spreads them across many micro-fringe buckets (the dominance is < 99.95%, clearing stage 2).

**Empirical verification** against the on-disk corpus:

| Preset | Significant buckets | Dominance | Verdict |
|---|---|---|---|
| `coinbase-dvd-qr` (QR + black canvas) | 2 | 97.2% | PASS (stage 1) |
| `tiktok-follow-pulse` (faded pulse @ frame 30) | 1 | 99.94% | PASS (stage 2 — dominance below 99.95%) |
| `youtube-subscribe-bounce` | 2 | 99.3% | PASS (stage 1) |
| `instagram-link-sticker` | 2 | 98.9% | PASS (stage 1) |
| `ali-abdaal-opacity-karaoke` | 2 | 98.4% | PASS (stage 1) |
| Synthetic pure-white blank (regression mode) | 1 | 100.00% | FAIL |
| Synthetic pure-sepia blank (regression mode) | 1 | 100.00% | FAIL |
| Synthetic anti-aliased near-blank (0.03% noise) | 1 | 99.97% | FAIL |

The 5 affected Cluster D regression goldens hit BOTH criteria when they were incorrectly signed.

**Rejected alternatives**:
- **Luminance stddev only** — simple but false-positives on legitimate single-color-dominant presets.
- **PSNR-against-known-blank** — requires a reference blank for each canvas size; brittle to fade-mode tones.
- **Single-criterion (significant-buckets only)** — fails on `tiktok-follow-pulse` whose pulse is too small/faded to contribute a significant secondary bucket.
- **Single-criterion (dominance only)** — fails on legitimate small-element-on-flat-canvas presets (97-99% dominance is normal).

### D-T348b-3 — full-pixel scan, no stride

Original design proposed sampling every Nth pixel (~10k samples per image) for cost. Empirical testing showed stride sampling can miss small elements (a 50px-diameter pulse circle ~2000 px) because the stride may not land on it. Full-pixel scan at 1080p costs ~50 ms per image (~2 MP @ ~50 ns / pixel for the 5-bit quantize + Map increment); ~2 seconds total across 35 signed goldens. Acceptable for the CI gate.

### D-T348b-4 — failure mode: error (not warning)

The existing `parityFixture-signOff` invariant (#6) is a warning. The new `parityFixture-non-blank` invariant is a hard error: if a signed golden is blank, the sign-off was incorrect; CI must block the merge. Pass-through warnings would have allowed the regression to land in the first place.

### D-T348b-5 — sync decoding via `pngjs.PNG.sync.read`

`runIntegrityChecks` is fully synchronous. Adding async-await for PNG decode would require refactoring all 14 invariants' control flow. `PNG.sync.read(buffer)` is sufficient at fixture sizes (~2 MP per image; 10k-sample loops complete in well under 50 ms each). Adding `pngjs` to `scripts/package.json` deps is a 2-line change.
