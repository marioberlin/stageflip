# T-423 — `asset-generation` handler bundle + auto-gen `tools/asset-generation/SKILL.md`

**Branch**: `task/T-423-asset-generation-bundle`

## Goal

Ship the `asset-generation` engine handler bundle exposing **three** agent-callable tools that wrap the just-merged Phase 14 α infrastructure (T-418 `@stageflip/adapters-core`, T-419 `@stageflip/asset-gen-contract`, T-420 `@stageflip/asset-cache`, T-421 `MediaProvenance` schema). The bundle is **canonical bundle #25** (the implementation-plan row's "#18" count is stale; current count on `main` is 24 post-T-379).

Tools:

| Tool | Context | Summary |
|---|---|---|
| `generate_asset` | `MutationContext` (soft seams) | Dispatch `(modality, prompt, model?, voice?, params?, seed?, target)` through `AdapterRegistry` → `LicenseGate` → `FallbackChainExecutor`; on success, derive a content-addressed `cacheKey` via `@stageflip/asset-cache`, build `MediaProvenance`, and emit a JSON-Patch op that mounts an `audio` / `image` / `video` element with `provenance` populated. |
| `list_adapters` | `ToolContext` (soft seam) | Enumerate registered `AdapterDescriptor`s, optionally filtered by modality. |
| `get_adapter_capabilities` | `ToolContext` (soft seam) | Look up a single adapter by `(modality, adapterId)`. |

The bundle ships the **dispatch shell only**; it does NOT register concrete adapters. Reference adapters land via T-426..T-434. With zero adapters wired today, every `generate_asset` call returns `{ ok: false, reason: 'no_adapter_for_modality' }` (or `'asset_generation_unavailable'` when the executor has not wired the seam) — both are typed-error responses, not exceptions.

T-423 is an M-sized handler-bundle task. It mirrors the cluster-compose dispatches (T-340 / T-347 / T-379) for shape, with the addition of the soft-seam `AssetGenerationContext` pattern proven by `arrange-variants` (T-386).

## Architectural decisions

### D-T423-1. Bundle name + path

**Decision**: Bundle name is `asset-generation` (singular, kebab-case, mirrors `display-mode` / `video-mode` / `arrange-variants` / `semantic-layout` siblings). Handler files live at `packages/engine/src/handlers/asset-generation/`. Reviewer demand for a plural / cluster-keyed name (e.g., `asset-gen` / `cluster-asset-compose`) → escalate; the bundle is not cluster-shaped, it is an infra dispatcher.

### D-T423-2. Tools declare `MutationContext` for symmetry, with soft seams for adapter / license / cache wiring

**Decision**: All three handlers' `TContext` parameter is `MutationContext` (the canonical write-tier context). Two of the three are read-only with respect to the document — `list_adapters` + `get_adapter_capabilities` only consult the adapter registry — but declaring them on `MutationContext` keeps the bundle homogeneous. The wiring seams (`adapterRegistry`, `licenseGate`, `tenantContext`, `assetCacheStore`, `executeAdapterCall`) are exposed via an optional sub-interface `AssetGenerationContext extends MutationContext` (mirror T-386's `VariantPersistenceContext`).

When the seams are absent — which is the current state on `main` (no executor wiring) — every handler returns a typed `{ ok: false, reason: 'asset_generation_unavailable' }` response. Hosts wire the seams at orchestrator-construction time; T-423 ships the seam shape, not the wiring. The orchestrator wires the bundle against a plain `MutationContext` router today; downstream consumer tasks (T-425 capability-routing engine + T-426..T-434 reference adapters) wire the seams.

The determinism gate at `CLAUDE.md` §3 covers `packages/runtimes/**` / `packages/frame-runtime/**` / `packages/renderer-core/src/clips/**` only — handler-bundle paths are out of its globs. The handlers themselves are pure (no `Date.now()`, no `Math.random()`, no I/O at the bundle layer; the adapter calls themselves live OUTSIDE the determinism perimeter per ADR-007 §D10). The bundle does call `crypto.subtle.digest` indirectly via `deriveCacheKey` — this is permitted (cache-key derivation is deterministic; `crypto.subtle` is universally available).

### D-T423-4. Top-level type definitions

```ts
export const ASSET_GENERATION_BUNDLE_NAME = 'asset-generation';

/**
 * Soft-seam context the executor wires for asset-generation tools. When
 * any seam is absent, handlers return `{ ok: false, reason: 'asset_generation_unavailable' }`.
 *
 * - `adapterRegistry`     — read-side; lists / lookups adapters.
 * - `licenseGate`         — gates an adapter by tenant license posture.
 * - `tenantContext`       — passed to the licenseGate.
 * - `executeAdapterCall`  — host-supplied call function; receives the
 *                           gated adapter + the input + the cache key,
 *                           returns the produced asset URI. Decoupled
 *                           from per-modality call shapes (T-419 owns
 *                           those); the seam is opaque on purpose.
 * - `assetCacheStore`     — optional; T-423 only writes to it on success.
 */
export interface AssetGenerationContext extends MutationContext {
  readonly adapterRegistry?: AdapterRegistry;
  readonly licenseGate?: LicenseGate;
  readonly tenantContext?: TenantContext;
  readonly executeAdapterCall?: (input: ExecuteAdapterCallInput) => Promise<ExecuteAdapterCallResult>;
  readonly assetCacheStore?: AssetCacheStore<{ assetUri: string }>;
}
```

### D-T423-5. `generate_asset` input + dispatch flow

Input shape (root `.strict()`):

```ts
{
  modality: AdapterModalityKind;       // sealed enum from @stageflip/adapters-core
  prompt: string (1..16000);
  model?: string (1..200);
  voice?: string (1..200);             // TTS-only by convention; opaque to the bundle
  params?: Record<string, unknown>;    // forwarded into cache-key recipe verbatim
  seed?: number | string;              // forwarded into cache-key recipe verbatim
  researchSessionId?: string;          // when source-grounded; forwarded to provenance
  target: {
    slideId: string;
    elementType: 'audio' | 'image' | 'video';
    transform: { x; y; width; height; rotation?; opacity? };  // canvas placement
    src: AssetRef;                     // adapter call result — caller supplies; the bundle does not own asset upload
  };
}
```

Dispatch flow (in handler):

1. Derive `cacheKey` via `deriveCacheKey({ modality, model, voice, prompt, params, seed })` from `@stageflip/asset-cache`.
2. If `adapterRegistry` / `licenseGate` / `tenantContext` / `executeAdapterCall` seam is absent → `{ ok: false, reason: 'asset_generation_unavailable' }`.
3. Look up candidate adapters: `adapterRegistry.list(modality)`. If empty → `{ ok: false, reason: 'no_adapter_for_modality' }`.
4. Filter by `licenseGate.evaluate(adapter, tenantContext)` admitting `'allow'` only. If empty → `{ ok: false, reason: 'no_licensed_adapter' }`.
5. Run `FallbackChainExecutor.execute(adapters, async (adapter) => executeAdapterCall({ adapter, input, cacheKey }))`. On exhaustion → `{ ok: false, reason: 'all_adapters_failed', errors: [...] }`.
6. On success: build `MediaProvenance` (`{ kind: kindForModality(modality), provider: adapter.id, model, prompt: normalizePrompt(prompt), cacheKey: cacheKeyString(cacheKey), seed?, voiceId?, researchSessionId? }`).
7. Build the `MediaElement` (audio/image/video) per `target.elementType`, populate `provenance`, push a JSON-Patch `add` op via `ctx.patchSink`.
8. Optionally write to `assetCacheStore` if seam present (`{ assetUri: target.src }`).
9. Return `{ ok: true, elementId, slideId, provenance, cacheKey: cacheKeyString(...) }`.

### D-T423-6. `list_adapters` + `get_adapter_capabilities` flow

Both tools declare `MutationContext` (consistent with bundle posture per D-T423-2) but only consult `ctx.adapterRegistry`.

`list_adapters`:
- Input: `{ modality?: AdapterModalityKind }`.
- Output: `{ ok: true, adapters: AdapterDescriptor[] }` or `{ ok: false, reason: 'asset_generation_unavailable' }` when seam is absent.
- When seam is present + no matching adapters → returns `{ ok: true, adapters: [] }` (the empty list IS the answer; not an error).

`get_adapter_capabilities`:
- Input: `{ modality: AdapterModalityKind, adapterId: string (kebab-case 1..200) }`.
- Output: `{ ok: true, descriptor: AdapterDescriptor }` or `{ ok: false, reason: 'not_found' | 'asset_generation_unavailable' }`.

### D-T423-7. Modality → MediaProvenance.kind mapping

Per ADR-008 §D2, `MediaProvenance.kind` ∈ `{ tts | video-gen | music-gen | sfx | three-d | image-gen | imported }`. The 15 modality kinds map to provenance kinds as follows:

```ts
const MEDIA_PROVENANCE_KIND_FOR_MODALITY: Record<AdapterModalityKind, MediaProvenanceKind> = {
  'tts':              'tts',
  'video-gen':        'video-gen',
  'music-gen':        'music-gen',
  'sfx':              'sfx',
  'three-d':          'three-d',
  'infographic-gen':  'image-gen',
  // Source-grounded modalities all funnel into `'image-gen'` in v1 (their
  // visual output IS an image). T-431..T-434 may refine.
  'slide-deck-gen':   'image-gen',
  'mind-map-gen':     'image-gen',
  'table-gen':        'image-gen',
  'quiz-gen':         'image-gen',
  'flashcard-gen':    'image-gen',
  'report-gen':       'image-gen',
  // Session/marketplace modalities — not asset-producing in v1; rejected
  // by an enum filter in the input schema.
  'research-session': 'imported',  // unreachable (filtered by ASSET_PRODUCING_MODALITIES)
  'audience-backend': 'imported',
  'bundle':           'imported',
};
```

The input schema constrains `modality` to `ASSET_PRODUCING_MODALITIES = AdapterModalityKind \ { 'research-session', 'audience-backend', 'bundle' }` so the unreachable `'imported'` rows never fire.

### D-T423-8. Tool-count budget (I-9)

3 tools in the bundle; well under the 30-tool cap per `concepts/tool-bundles` §"Enforcement". Future asset-related tools (e.g., `get_asset_cache_stats`) extend the bundle, not the catalog.

### D-T423-9. Determinism / read-only invariants

The bundle's tools dispatch through ASYNC seams (`executeAdapterCall`); successive calls with the same input + the same wired adapter + a deterministic adapter implementation produce identical `cacheKey`s (proven by `@stageflip/asset-cache`'s tests). The handler itself does not call `Date.now()` / `Math.random()` / `setTimeout`. `crypto.subtle.digest` is a deterministic pure function.

### D-T423-10. §13 statement (NOT a structural extension)

T-423 adds a NEW handler bundle — it does not add a new field to `ClipKindBinding` / `RIRElement` / `RIRDocument`, does not add a new element type, does not introduce a new compositing mode, does not add a new top-level prop on a primitive that materially changes render output, and does not add a new runtime kind. The §13 obligation does not apply.

End-to-end render verification is unnecessary because:
- The provenance slot the bundle populates was already exercised by T-421's roundtrip tests + T-421's audio/image/video element-with-provenance tests.
- The bundle emits standard `add`-op patches against existing element schemas; the element schemas were exercised by T-421.
- No new pixel paths.

The bundle's correctness is demonstrated via unit tests covering: cache-key derivation matches `@stageflip/asset-cache`'s output; provenance shape passes `mediaProvenanceSchema.parse`; patchSink emits the expected JSON-Patch op; seam-absent + no-adapter + no-licensed + all-failed paths return the typed error responses; the determinism property holds across same-input pairs.
