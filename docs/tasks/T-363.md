# T-363 — Preset: `mrbeast-komika-axis` (caption, Cluster F)

**Branch**: `task/T-363-mrbeast-komika-axis`

## Goal

Promote `mrbeast-komika-axis` from `status: stub` to `status: substantive` and ship it as the **second Cluster F (creator captions) preset** AND the **first Cluster F preset to use the per-presetId resolver-override mechanism** (T-360 D-T360-2 → `PRESET_ID_BINDINGS[<presetId>]`). T-362 took the clipKind-default `caption → caption` slot in `DEFAULT_CLIP_KIND_RESOLVER`; T-363 must add a per-presetId override (different `style` + different `WordTiming[]` snapshot than T-362). T-363 is **M-sized** — same envelope as T-362. CaptionClip primitive already shipped (T-316); `mrbeast` STYLE_BUNDLE cycling-color + bounce contracts verified during spec drafting (D-T363-13 / D-T363-14); override mechanism on `main` from T-360. Three new surfaces validated together: cycling-color highlight + bounce entrance + per-presetId override pattern in cluster F.

  text: string; startMs: number; endMs: number;
  emphasis?: 'normal' | 'highlight' | 'mute';

  { text: 'I',        startMs:    0, endMs:  350 },
  { text: 'gave',     startMs:  350, endMs:  700, emphasis: 'highlight' },
  { text: 'away',     startMs:  700, endMs: 1050 },

  runtimeId: 'frame-runtime',

### D-T363-5. Canonical caption text — `"I gave away one million dollars"`

Six words, plausible MrBeast register (high-stakes, contest-flavored). Words 2 / 4 / 6 (`'gave'` / `'one'` / `'dollars'`) carry `emphasis: 'highlight'`; cycling colors fire (red → yellow → green, each used exactly once). Odd-indexed connector words (`'I'` / `'away'` / `'million'`) render in `#FFFFFF` foreground white. Six-word length lets the parity frame catch a clear active-word state with siblings + exercises all three cycling slots. Alternative considered: `"Last to leave wins ten thousand"` (similar register; same shape would work). Cluster owners rebrand at compose time; preset contract is **shape** (high-stakes declaration + cycling-color emphasis + bounce + stroke), not literal text.

### D-T363-6. WordTiming[] shape — 350ms per word; canonical mid-hold at frame 60 (= 2000ms)

Six words × **350 ms** = **2100 ms** total (T-362 used 300 ms; MrBeast emphasis-heavy register stays slightly longer per word). Mid-hold = **`frame: 60`** (= `2000 ms` @ 30 fps).

At frame 60:
- All six words past their `startMs` → all visible.
- Word 6 `'dollars'` active (`1750 <= 2000 < 2100`); past `emphasis: 'highlight'` words 2 / 4 keep their cycling color (`resolveColor` branches on emphasis regardless of `isActive`).
- Cycling: word 2 `highlightedIndex 0` → red `#FF3B30`; word 4 `highlightedIndex 1` → yellow `#FFD60A`; word 6 `highlightedIndex 2` → green `#34C759`.
- Connector words 1 / 3 / 5 render `#FFFFFF` white.
- Bounce settled for all six (last-word settle frame ≈ 52.5; frame 60 is 7.5 past settle).

Net visual: three cycling-color words + three white connectors + 5px black stroke + bounce settled — crisp evidence of cycling logic + stroke + post-settle in one frame.

If floating-point drift makes word 5 active instead of word 6, acceptable — the parity contract is "three cycling colors visible + bounce settled + thick stroke." Document whichever word lands active. Do NOT shift the frame; do NOT introduce a second variant.

### D-T363-7. Font posture — Komika Axis is BYO commercial; Bangers OFL fallback

Stub already declares `preferredFont.license: commercial-byo` — **keep**. OFL fallback `Bangers` (Google Fonts SIL OFL 1.1, weight 400) is also already in the stub — keep. In headless puppeteer, Komika Axis is unlikely loaded → the system-stack fallback renders (NOT Bangers, because Bangers isn't in the bundle's stack). ### D-T363-13. **Multi-color cycling — VERIFIED in T-316**

**Verified during spec drafting** by reading `caption.tsx`:
- `STYLE_BUNDLES.mrbeast.highlightColor` is a **3-entry** array `['#FF3B30', '#FFD60A', '#34C759']` (red / yellow / green; NOT 4 — the task brief said 4 but the impl ships 3).
- `highlightedIndex` (lines 524–537): rolling count of `emphasis === 'highlight'` words; increments only on highlight words.
- `pickHighlightColor` (lines 241–249): `highlightedIndex % len`. Three highlight words → `[0, 1, 2] % 3` → red, yellow, green (each color exactly once).
- `resolveColor` (lines 326–346): routes `word.emphasis === 'highlight' || isActive` through `pickHighlightColor`. So active non-highlight words also pick a cycling color. T-363's snapshot lands the active word ON a highlight word (word 6) — single-source cycling color, no double-routing ambiguity.

**No escalation needed**: cycling logic is implemented + tested (`caption.test.tsx` cases 15–16). T-363 adopts the 3-color cycle. If Implementer's reading contradicts (single fixed color, different routing), escalate per CLAUDE.md §6 and drop to a single highlight word (cycling color = `#FF3B30` red, the first array entry).

### D-T363-14. **Bounce entrance — VERIFIED in T-316**

**Verified during spec drafting** by reading `caption.tsx` lines 297–311: `entrance: 'bounce'` two-phase ramp `[0, 0.6, 1]` → scale `[0, 1.15, 1.0]`; opacity `0 → 1` linear over 12 frames; per-word stagger `staggerMs * i` ms BEFORE word `startMs`.

For T-363's snapshot (staggerMs 80, last word `startMs: 1750`), last-word entrance start = `(1750 - 5 * 80) / 1000 * 30 = 40.5` frame; settles by frame 52.5. Frame 60 (parity reference) is 7.5 frames past last-word settle → all six words at scale 1.0, opacity 1. Bounce overshoot is invisible at frame 60 by design — the parity golden documents the **settled** state. The bounce contract is documented in body §Animation prose + tested in `caption.test.tsx` case 14. If Implementer's reading contradicts (entrance never settles), escalate and shift canonical frame later (e.g., `frame: 90`).
