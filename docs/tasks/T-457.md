# T-457 — `audience-engagement` bundle

**Branch**: `task/T-457-audience-engagement-bundle`

## Goal

Ship the **`audience-engagement` semantic-tools bundle** — the agent
surface for authoring Live Audience clips into slides. Mirrors the
`cluster-X-compose` bundle pattern (T-340..T-379 closer): each tool
takes a semantic brief and returns `(presetId | undefined, clipKind,
props)`; the caller mounts via the existing `add_clip` tool from
`create-mutate`.

The bundle ships:

1. **11 `compose_audience_*` tools** — one per `AudienceClipKind`
   discriminant from `@stageflip/audience-contract` (T-452):
   - `compose_live_poll_multiple_choice`
   - `compose_live_poll_open_text`
   - `compose_live_poll_rating`
   - `compose_live_qa`
   - `compose_live_quiz`
   - `compose_leaderboard`
   - `compose_word_cloud`
   - `compose_survey`
   - `compose_heatmap`
   - `compose_reaction_stream`
   - `compose_audience_ai_prompt`
2. **`audience-engagement` bundle entry** in
   `packages/engine/src/bundles/catalog.ts` — appended as the 26th
   canonical bundle (the bundle inventory grows from 25 → 26).
3. **`packages/engine/src/handlers/audience-engagement/`**:
   - `handlers.ts` — 11 handlers, one per tool. Each is pure (no I/O,
     no `Date.now`, no `Math.random`). Per T-379 pattern: declare
     `ToolContext` (NOT `MutationContext`); composer paths neither
     read nor mutate the document.
   - `register.ts` — wires handlers into the registry + router.
   - `handlers.test.ts` — vitest cases per tool covering happy path +
     schema rejection.
   - `register.test.ts` — verifies registration + the bundle exposes
     all 11 tools.
4. **`skills/stageflip/tools/audience-engagement/SKILL.md`** —
   auto-generated by `pnpm gen:tool-skills` from the handler bundle's
   metadata. Carries the per-tool JSON-schema, capability summary, and
   usage notes.
5. **Orchestrator wiring** in
   `packages/app-agent/src/orchestrator.ts`:
   - Import `registerAudienceEngagementBundle` from `@stageflip/engine`.
   - Call `registerAudienceEngagementBundle(registry, router)`
     alongside the other 25 bundle registrations. **Per the recurring
     lesson** (the orchestrator wiring is a SECOND register site — the
     first is `gen-tool-skills.ts` — and is easy to miss).
6. **Count assertion bump** in
   `packages/engine/src/bundles/registry.test.ts` — `expect(r.size).toBe(25)`
   becomes `expect(r.size).toBe(26)`.

**Strict scope** — agent-side composer tools only. NO concrete clip
implementations (T-461..T-471 ship the per-kind clips). NO new server
endpoints (T-453 already ships the server API). NO new schema (T-460
ships the `AudienceProvenance` type). NO Cluster I preset cluster
(T-486 — the compose tools currently emit `presetId: undefined` until
Cluster I presets ratify; calling `add_clip` with the returned
`(undefined, clipKind, props)` triple still works because the `kind`
disambiguates the runtime dispatch).

## Implementation notes

- **Tool input briefs**: each `compose_X` accepts a semantic brief
  describing the audience interaction (question, options, threshold,
  etc.). The brief is per-kind:
  - `compose_live_poll_multiple_choice` → `{ question, options[2..10] }`
  - `compose_live_poll_open_text` → `{ question, maxLength? }`
  - `compose_live_poll_rating` → `{ question, scaleMin, scaleMax }`
  - `compose_live_qa` → `{ topic, allowUpvoting?, moderationMode? }`
  - `compose_live_quiz` → `{ question, options, correctIndex,
    timerSeconds? }`
  - `compose_leaderboard` → `{ dataSourceClipId, topN? }`
  - `compose_word_cloud` → `{ prompt, maxWords? }`
  - `compose_survey` → `{ questions[1..20] }`
  - `compose_heatmap` → `{ prompt, imageRef }`
  - `compose_reaction_stream` → `{ prompt, reactionSet? }`
  - `compose_audience_ai_prompt` → `{ basePrompt, voterPromptTemplate }`
- **Tool output**: every handler returns
  `{ presetId: string | undefined, clipKind: AudienceClipKind, props:
  Record<string, unknown> }`. The `presetId` is `undefined` until
  Cluster I (T-486) ratifies presets; downstream `add_clip` accepts
  the triple and runtime dispatches by `clipKind`.
- **Determinism**: each handler is a pure function of its input. NO
  `Date.now`, NO `Math.random`, NO I/O. Document this at the top of
  `handlers.ts` per the T-379 / cluster-h-compose template.
- **Tool-skills regen**: AFTER editing the bundle, run
  `pnpm gen:tool-skills` to regenerate
  `skills/stageflip/tools/audience-engagement/SKILL.md` +
  `skills/stageflip/tools/SKILL.md` index. Commit the regenerated
  skill pages. **Per the recurring lesson** (`gen:tool-skills:check`
  enforces drift-zero in CI; missing the regen makes the gate red).
- **Orchestrator wiring**: per the recurring lesson, the
  `packages/app-agent/src/orchestrator.ts` register sites must be
  updated alongside `packages/engine/src/index.ts`'s re-export. Both
  spots register the bundle; both must list it.
- **Skills-sync**: AFTER tool-skills regen, run `pnpm skills-sync` to
  sync the bundle's manifest contributions across the skill index.
  Commit any sync changes.
