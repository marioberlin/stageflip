# T-466 — `LeaderboardClip`

**Branch**: `task/T-466-leaderboard-clip`

## Goal

Ship the **LeaderboardClip** family — the paired derived clip that
ranks voters by their LiveQuiz score. Per ADR-010 §D2,
`LeaderboardVote = never` — voters do NOT submit directly; the
aggregation is derived server-side from the upstream
`LiveQuizAggregation` referenced by `quizId`.

This is the **first non-voter-input clip family** — the voter-input
dispatcher resolves `'leaderboard'` to a "no-op / view-only"
component (since `LeaderboardVote = never`).

Per-kind shapes (already in `@stageflip/audience-contract`):

- Vote: **none** — `LeaderboardVote = never` per ADR-010 §D2. Vote
  schema rejects `kind: 'leaderboard'` payloads.
- Aggregation: `{ kind: 'leaderboard', quizId: string, ranking: [{
  voterToken (hashed), displayName?, score, rank }, ...] (length ≤
  topN), totalParticipants }`.
- Rendering: a vertical ranked list. Each row: `#${rank}` badge,
  `displayName` (or "Anonymous voter" if absent), `score`. Top-3 rows
  carry medal-style highlights (gold / silver / bronze). Total label
  reads "${totalParticipants} participants".
- Voter UI: NONE — the dispatcher routes this kind to a `<LeaderboardViewOnly>`
  notice (e.g., "This is a results display; no vote required").

§13 verification is option-1 — `render-e2e.test.ts` drives the
static-fallback with a known ranking snapshot + asserts on observable
DOM ordering, medal-highlight logic, and pixel-bucket non-blankness.

## Implementation notes

- **Schema**: `props: { quizId: z.string().min(1), topN:
  z.number().int().positive().max(100).default(10), title:
  z.string().min(1).optional(), sessionId: z.string().optional() }`.
  - `quizId` is the foreign-key to the `LiveQuizClip` instance; the
    server-side derivation joins on the quiz's session to compute
    rankings. The schema-level constraint is just that `quizId` is a
    non-empty string; cross-clip-reference validation is downstream
    (the renderer-core dispatcher or a future cluster-i CI rule).
  - `permissions: z.tuple([z.literal('audience-network')])`.
  - `provenance: audienceProvenanceSchema.optional()`.
- **Static-fallback rendering**: vertical ranked list.
  - For each `ranking[i]`: render a row with `#${rank}` badge,
    display-name (`ranking[i].displayName ?? 'Anonymous voter'`),
    score badge.
  - Top-3 rows: `data-medal="gold" | "silver" | "bronze"` + accent
    colors (e.g., yellow / gray / amber via CSS classes).
  - Ranks 4+: no medal class.
  - Title (if `clip.props.title`) shown above the list.
  - Total label: `${totalParticipants} participants`.
  - Pure function. No `Date.now()`, no `Math.random()`.
- **Live-mount rendering**: identical to static-fallback in v1 — the
  ranking updates via WebSocket snapshot events at the snapshot
  cadence; rendering is the same vertical list.
- **Voter UI** (`leaderboard-view-only.tsx`):
  - `props: { title? }`.
  - Renders a friendly notice: "This is a results display. Sit back and
    watch the leaderboard!" — NO interaction.
  - This is the FIRST view-only voter component; reserves the
    pattern T-466's leaderboard + future "results-only display" clips
    can plug into.
- **Dispatcher entry**: register `'leaderboard'` → `<LeaderboardViewOnly>`.
  The dispatcher's `voterInputRegistry` accepts components of two
  shapes: vote-emitting (`{ onSubmit }`) AND view-only (no `onSubmit`).
  If the dispatcher's type contract requires `onSubmit`, the view-only
  component accepts `onSubmit: (() => void)` and ignores it (no-op).
  Document the convention at the dispatcher's TSDoc.
- **Mirror T-461..T-465 exactly** for layout / tests / dispatcher
  registration.
- **Determinism perimeter**: same as prior — static-fallback pure;
  factory's `runAudienceClient` is the only non-deterministic surface.
- **Pre-empt skills-sync drift**.
- **Biome format** every touched file.
