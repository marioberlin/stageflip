# T-374 — Cluster G (CTAs / social) composer tools

**Branch**: `task/T-374-cluster-g-compose-tools`

## Goal

Ship the `cluster-g-compose` engine handler bundle exposing four agent-callable composer tools that take semantic intent (CTA action, platform / channel, brand, handles, QR payload) and emit a Cluster G preset binding — preset id + complete props payload validated against the chosen preset's resolver-snapshot Zod schema. The tools are **read-only** (no `MutationContext` patches; they return a preset id + payload that the caller — typically a higher-tier orchestrator or the agent's own plan step — feeds to a separate write-tier handler that mounts the corresponding clip).

T-374 is the **fifth and final cluster-compose task** of the Phase 13 cluster-compose-tools series, after T-340 (Cluster B Sports), T-368 (Cluster F Captions), T-331 (Cluster A News), and T-361 (Cluster E Data) — all of which shipped earlier this session as PRs #401 / #402 / #403 / #404. T-374 brings Cluster G's agent surface up to parity with the four originally-ratified clusters and closes the cluster-compose-tools sweep. Cluster G is **5/5 substantive + signed + RATIFIED** as of 2026-05-07; all five preset bindings are stable on `main` and ready for an agent-callable composer surface.

The four tools dispatch into the five ratified Cluster G presets:

- `compose_cta` → broadest tool; sealed `intent` discriminator routes across all 5 presets — `intent: 'subscribe'` (with platform discriminator) → `youtube-subscribe-bounce` | `tiktok-follow-pulse`; `intent: 'follow'` → same as `subscribe` semantically (alias accepted); `intent: 'link'` → `instagram-link-sticker`; `intent: 'qr'` → `coinbase-dvd-qr`; `intent: 'social-handle'` → `social-handle-lower-third`.
- `compose_subscribe_prompt` → 2 of 5 (the platform-CTA consumers): `youtube-subscribe-bounce` (platform='youtube'; binds to `SubscribeButton` / T-317) and `tiktok-follow-pulse` (platform='tiktok'; binds to `FollowPrompt` / T-318). **Instagram is intentionally NOT in this tool's dispatch** — Instagram's "follow" UX is a different surface (link-sticker overlay rather than a subscribe-button mimicry); the `compose_cta(intent: 'link')` path is the canonical route to `instagram-link-sticker`. Documented at D-T374-5.
- `compose_social_handle` → 1 of 5 (`lowerThird` consumer): `social-handle-lower-third` (only consumer; the `handles` array is the lower-third's per-platform text payload).
- `compose_qr_bounce` → 1 of 5 (`QRCodeBounce` consumer / T-319): `coinbase-dvd-qr` (only consumer; opaque `qrMatrix` + optional `brand` overrides).

All 5 Cluster G presets are fully covered (no `not_yet_implemented` reserved surfaces — different from T-340 which reserved `compose_var_call` + `compose_player_intro`). The handlers do not touch any clip code, parity-cli, preset markdown, or signed parity goldens. Pure agent-layer wrapping over the existing preset surface.

## Architectural decisions

### D-T374-1. Handler-bundle name + path

**Decision**: Bundle name is `cluster-g-compose`. Handler files live at `packages/engine/src/handlers/cluster-g-compose/`. Mirrors the `cluster-{letter}-compose` convention established by T-340 / T-368 / T-331 / T-361. The `cluster-g-` prefix signals "cluster-scoped composer" and closes the 5-cluster-compose sweep (`cluster-a-compose` + `cluster-b-compose` + `cluster-e-compose` + `cluster-f-compose` + `cluster-g-compose`).

Reviewer demand for `cta-compose` / `social-compose` / any non-cluster-keyed name → escalate. The cluster discipline is sealed across all five compose bundles.

### D-T374-2. Tools are read-only — declare `ToolContext`, NOT `MutationContext`

**Decision**: Each handler's `TContext` parameter is `ToolContext` (the narrowest router context — only the optional `AbortSignal`). Mirrors T-340 / T-368 / T-331 / T-361 verbatim. The handler signature is:

```ts
const composeCta: ToolHandler<ComposeCtaInput, ComposeCtaOutput, ToolContext> = {
  name: 'compose_cta',
  bundle: CLUSTER_G_COMPOSE_BUNDLE_NAME,
  description: '...',
  inputSchema: composeCtaInputSchema,
  outputSchema: composeCtaOutputSchema,
  handle: (input, _ctx) => {
    // pure dispatch — no patchSink.push, no document reads
  },
};
```

Rationale (mirrors T-340-D2):

1. **No mutation.** The composer's job is to emit a `(presetId, props)` tuple. The downstream caller mounts the clip via a separate write-tier tool (e.g., `add_clip` from `create-mutate`).
2. **No document reads.** Composer dispatch is a pure function of its input; it doesn't read existing document state.
3. **Determinism rules at `CLAUDE.md` §3 don't apply.** Those rules govern `packages/runtimes/**` / `packages/frame-runtime/**` / `packages/renderer-core/src/clips/**`. The composer lives at `packages/engine/src/handlers/**` — NOT a clip / runtime / renderer-core path. T-374's handlers are still pure (no `Date.now()`, no `Math.random()`, no I/O) by code-review discipline, but the lint rule does not enforce it. Documented in the file header comment so reviewers don't trip over the absence of determinism comments.

Reviewer demand for declaring `MutationContext` → escalate; the read-only posture is the architectural seal across all five cluster-compose bundles.

### D-T374-5. `compose_cta` schema (input)

The umbrella tool. Sealed `intent: CtaIntent` enum + optional `platform: CtaPlatform` discriminator + per-intent payload fields.

```ts
const composeCtaInput = z.object({
  intent: z.enum(CTA_INTENTS),
  platform: z.enum(CTA_PLATFORMS).optional(),
  // Per-intent payload fields (all optional at root; the dispatch validates per-intent inside handle())
  channelName: z.string().min(1).max(80).optional(),               // subscribe / follow
  subscriberCount: z.string().min(1).max(20).optional(),            // subscribe / follow — pre-formatted ('1.2M')
  handles: z.array(z.object({
    platform: z.enum(['youtube', 'tiktok', 'instagram', 'twitter', 'linkedin', 'github']),
    handle: z.string().min(1).max(40),
  }).strict()).min(1).max(6).optional(),                            // social-handle
  url: z.string().url().optional(),                                 // link / qr
  qrMatrix: z.string().min(1).optional(),                           // qr — opaque base64 / asset id
  brand: z.object({
    primary: z.string().regex(/^#[0-9a-fA-F]{6}$/),
    accent: z.string().regex(/^#[0-9a-fA-F]{6}$/).optional(),
    font: z.string().min(1).max(80).optional(),
  }).strict().optional(),
  theme: z.enum(['platform-native', 'branded', 'unbranded']).optional(),  // qr — Coinbase canon: unbranded
  repetition: z.number().int().min(1).max(8).optional(),            // social-handle — per cluster SKILL line 49
}).strict();
```

The handler routes by `intent`:

- `intent: 'subscribe' | 'follow'` → requires `platform: 'youtube' | 'tiktok'` (the only two platforms that have a subscribe-button mimicry preset). Dispatches to `youtube-subscribe-bounce` / `tiktok-follow-pulse`.
- `intent: 'link'` → requires `platform: 'instagram'` AND `url`. Dispatches to `instagram-link-sticker`.
- `intent: 'qr'` → requires `qrMatrix`; routes to `coinbase-dvd-qr` (only QR consumer).
- `intent: 'social-handle'` → requires `handles[]` (length ≥ 1). Dispatches to `social-handle-lower-third`.

**Why Instagram is excluded from `compose_subscribe_prompt` but accepted by `compose_cta(intent: 'link')`**: the cluster SKILL distinguishes `subscribe` / `follow` (subscribe-button mimicry register; YouTube + TikTok) from `link-sticker` (Instagram's pill-overlay register; semantically different — it's an outbound URL, not a follow-action). Per Cluster G SKILL line 44 ("Mimicry wins") — the YouTube + TikTok subscribe-button presets mimic native UI; Instagram's link-sticker is a different native UI. Documented at D-T374-7.

### D-T374-6. `compose_cta` schema (output)

```ts
const composeCtaOutput = z.discriminatedUnion('ok', [
  z.object({
    ok: z.literal(true),
    presetId: z.enum(CLUSTER_G_PRESET_IDS),
    clipKind: z.enum(['subscribeButton', 'followPrompt', 'linkSticker', 'qrBounce', 'lowerThird']),
    props: z.record(z.unknown()),     // opaque payload — caller validates against the primitive's schema
  }).strict(),
  z.object({
    ok: z.literal(false),
    reason: z.enum([
      'platform_required',                   // intent='subscribe'/'follow' without platform
      'invalid_platform_for_intent',          // platform doesn't match intent (e.g., subscribe + instagram)
      'url_required',                         // intent='link' without url
      'qr_matrix_required',                   // intent='qr' without qrMatrix
      'handles_required',                     // intent='social-handle' without handles
      'no_preset_for_platform',               // platform outside the sealed enum
    ]),
    detail: z.string().optional(),
    candidatePresets: z.array(z.enum(CLUSTER_G_PRESET_IDS)).optional(),
  }).strict(),
]);
```

The `props` field is opaque (`z.record(z.unknown())`) at the composer-tool layer — the **primitive's** Zod schema (e.g., `subscribeButtonPropsSchema` from `subscribe-button.tsx`) is the authoritative validator at clip-mount time. Validating it twice (once at compose, once at mount) duplicates work and couples this bundle to clip-package internals; we let mount-time validation catch shape errors. Mirrors T-340-D6 / T-368-D10 / T-331-D9 / T-361-D5 verbatim. Reviewer demand for tighter typing → escalate; the architectural posture is preset-id + opaque props.

### D-T374-7. `compose_cta` dispatch table

```ts
const CTA_DISPATCH: Readonly<Record<`${CtaIntent}:${CtaPlatform | 'any'}`, { presetId: ClusterGPresetId, clipKind: ClipKind } | undefined>> = {
  // Subscribe / follow — YouTube + TikTok only
  'subscribe:youtube':       { presetId: 'youtube-subscribe-bounce',   clipKind: 'subscribeButton' },
  'follow:youtube':          { presetId: 'youtube-subscribe-bounce',   clipKind: 'subscribeButton' },
  'subscribe:tiktok':        { presetId: 'tiktok-follow-pulse',        clipKind: 'followPrompt' },
  'follow:tiktok':           { presetId: 'tiktok-follow-pulse',        clipKind: 'followPrompt' },
  // Instagram link sticker
  'link:instagram':          { presetId: 'instagram-link-sticker',     clipKind: 'linkSticker' },
  // QR bounce — Coinbase-register only
  'qr:coinbase':             { presetId: 'coinbase-dvd-qr',            clipKind: 'qrBounce' },
  'qr:any':                  { presetId: 'coinbase-dvd-qr',            clipKind: 'qrBounce' },  // platform optional for QR
  // Social-handle lower-third — platform-agnostic (handles array carries per-platform identity)
  'social-handle:any':       { presetId: 'social-handle-lower-third',  clipKind: 'lowerThird' },
};
```

The dispatch table is a `Readonly<Record<...>>` so TypeScript surfaces typos at compile time. Reviewer demand for a runtime-only Map → escalate; the const-record posture is the architectural seal.

`subscribe:instagram` / `follow:instagram` is **not** in the table; the handler returns `{ ok: false, reason: 'invalid_platform_for_intent', detail: 'Instagram has no subscribe-button mimicry preset; use compose_cta with intent: "link" for the link-sticker register' }`. Per D-T374-5 rationale.

### D-T374-8. `compose_subscribe_prompt` schema + dispatch

```ts
const composeSubscribePromptInput = z.object({
  platform: z.enum(['youtube', 'tiktok']),     // sealed at the 2 subscribe-button platforms
  channelName: z.string().min(1).max(80),
  subscriberCount: z.string().min(1).max(20).optional(),    // pre-formatted ('1.2M' / '847K')

  brand: z.object({
    primary: z.string().regex(/^#[0-9a-fA-F]{6}$/),
    accent: z.string().regex(/^#[0-9a-fA-F]{6}$/).optional(),
  }).strict().optional(),

```

Dispatch:

- `platform: 'youtube'` → `youtube-subscribe-bounce` (clipKind: `subscribeButton`).
- `platform: 'tiktok'` → `tiktok-follow-pulse` (clipKind: `followPrompt`).

Output mirrors `composeCtaOutput`. The `ok: false` arm is unreachable from Zod-validated input (the platform enum is sealed at 2 values; a pre-validated input always has a dispatch entry) but typed for consistency.

Rationale string format: `"platform=<youtube|tiktok> + channel=<channelName> → <preset-id>"`.

```ts
    accent: z.string().regex(/^#[0-9a-fA-F]{6}$/).optional(),
  }).strict().optional(),
  theme: z.enum(['unbranded', 'branded']).optional(),         // Coinbase canon: 'unbranded' default
  bounceSpeed: z.enum(['slow', 'normal', 'fast']).optional(),
}).strict();
```

Dispatch (single-target):

- Always → `coinbase-dvd-qr` (clipKind: `qrBounce`). Only consumer in cluster.

Per Cluster G SKILL line 46 ("Curiosity gaps beat branding (sometimes). Coinbase's unbranded bouncing QR got 20M hits in 60 seconds. When the brief demands attention-max … consider zero-branding presets. Otherwise default to branded.") — the `theme` field exposes the canonical choice. Default: handler treats absent `theme` as `'unbranded'` (Coinbase canon).

The handler does NOT generate the QR bit-grid; the `qrMatrix` is opaque host-supplied input (typically the output of an upstream QR encoder running outside the executor loop). Per "Out of scope" table.

Output: `{ ok: true, presetId: 'coinbase-dvd-qr', clipKind: 'qrBounce', props: { qrMatrix, url, brand, theme, bounceSpeed } }`. The `ok: false` arm is unreachable from Zod-validated input.

Rationale: `"qr-matrix → coinbase-dvd-qr (qrBounce; <theme> register)"`.
