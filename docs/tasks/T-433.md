# T-433 — `@stageflip/music-yue` (YuE music adapter; stub-mode v1)

**Branch**: `task/T-433-music-yue`

## Goal

Ship the **eighth reference adapter** in the Phase 14 β sequence
(T-426..T-434): `@stageflip/music-yue`. Wraps the YuE music-generation
model (Apache 2.0; full-song generation; attribution-required;
monetizable) behind the `MusicGenerationProvider` interface from T-419,
declares an `AdapterDescriptor` per T-418, and exposes a stable shape
that the asset-generation handler bundle (T-423) + capability router
(T-425) consume.

T-433 is the **second `music-gen` modality adapter** (after T-432
ACE-Step) and the **first Apache-2.0-licensed music adapter**. It also
exercises the **`attribution-required` branch** of
`MusicGenCapabilityDescriptor.outputLicense` — the FIRST adapter to
declare this disposition. The provider's `generate()` body emits an
`attribution` string in its `MusicGenResult` that downstream
consumers (T-423 handler bundle; T-436 captions/music sync; the
exporter chain) propagate into `MediaProvenance.attribution` so the
user-facing UI surfaces a "Generated with YuE (Apache 2.0)"-style
notice in the credits / exporter output. This satisfies Apache 2.0's
attribution clause without touching the schema layer (T-421's
`MediaProvenance.attribution` is the dedicated lane).

The clearance through `pnpm check-asset-licenses` is the **eighth
real exercise** of the per-modality whitelist (ADR-008 §D13 line 655:
`music-gen` admits `apache-2.0`, `mit`, `cc-by`, `proprietary-byo`,
`proprietary-vendored`). `apache-2.0` is already in the whitelist on
`main` — no whitelist extension is required.

T-433 follows the **same structural template** as T-432 (ACE-Step):
in-process + permissive-license-family + edge-deployable + stub-mode
posture. Both declare `sandbox.kind: 'in-process'` (YuE community
ports are emerging as ONNX-runnable on supported hardware; production
wire-up audit deferred to T-433a).

T-433 ships in **stub mode**: the `generate()` body emits a
deterministic silent-WAV byte payload at the declared sample rate +
returns a shaped `MusicGenResult` carrying the canonical attribution
string. Production wire-up (YuE checkpoint → ONNX runtime → real
audio) is gated on a follow-up task (T-433a) to keep this PR's blast
radius tight + let downstream consumers develop against the
deterministic stub.

T-433 is M-sized: one new package, ~250–400 LOC across 3 src modules
(descriptor / provider / stub-audio) + matched tests, ~250–400 lines
of spec, no schema / parity / clip / preset changes.

   - `YUE_GENRES`, `YUE_MAX_DURATION_S`, `YUE_SAMPLE_RATE_HZ`,
   - `YUE_ATTRIBUTION` (the canonical attribution string the provider
     emits in `MusicGenResult.attribution`).
3. **Descriptor shape**:
   ```ts
   {
     id: 'yue',
     modality: { kind: 'music-gen' },
     capability: {
       genres: ['electronic', 'pop', 'rock', 'classical', 'hip-hop', 'jazz', 'ambient', 'folk'],
       maxDurationS: 300,
       outputFormats: ['wav', 'mp3'],
       outputLicense: 'attribution-required',  // Apache 2.0 attribution clause
       maxDurationSec: 300,
       sampleRateHz: 44100,
       supportsStructure: true,
       qualityHint: 'high',
     },
     license: { kind: 'apache-2.0' },          // Apache 2.0 (NOT mit; whitelisted)
     sandbox: { kind: 'in-process' },
     costPerCall: { usd: 0 },
     latencyMs: { p50: 8_500, p95: 9_800 },    // 'fast' tier (< 10s p95)
   }
   ```
   `maxDurationSec` + `sampleRateHz` are extra capability fields the
   T-424 catalog generator reads; the strict T-419
   `musicGenCapabilityDescriptorSchema` is `.strict()` and would
   reject them — so the descriptor uses a capability shape that
   passes the T-418 envelope's `z.record(z.unknown())` but tests
   pass the validator a SUBSET stripped of the extras.
4. **`YUE_ATTRIBUTION`** constant: `"Generated with YuE (Apache 2.0)"`.
   This is the canonical string the provider emits in
   `MusicGenResult.attribution`. Downstream consumers (T-423 handler
   bundle) propagate it to `MediaProvenance.attribution` for the
   exporter / UI to surface.

   **Attribution-metadata posture**:
   - The descriptor declares `capability.outputLicense:
     'attribution-required'` (the routing-layer / consumer-side flag).
   - The descriptor declares `license.kind: 'apache-2.0'` (the
     CI-gate-facing flag — `check-asset-licenses` consults this).
   - The provider emits `attribution: YUE_ATTRIBUTION` in every
     `MusicGenResult` (the runtime-side propagation lane).
   - There is NO separate `license.attribution` boolean / sub-field
     on `AdapterDescriptor.license` — the `AdapterLicensePosture`
     discriminated union from `packages/adapters-core/src/adapter-descriptor.ts`
     does not carry that surface. The attribution requirement is
     encoded TWO places: (a) on the modality-specific capability
     envelope as `outputLicense: 'attribution-required'`, which the
     routing engine reads; (b) on the runtime `MusicGenResult` as
     the string itself, which the handler bundle propagates.

   This split is intentional: `license.kind` is a closed enum for
   distribution-license bookkeeping (CI-gate facing); `outputLicense`
   is a runtime-output disposition flag (routing-layer / exporter
   facing). They answer different questions and have different
   audiences.
5. **`YueMusicProvider` class** implements `MusicGenerationProvider`:
   - Constructor takes `{ mode: YueProviderMode }` (defaults to
     `'stub'`).
   - `id` / `modality` / `capability` / `license` / `sandbox` /
     `costPerCall` / `latencyMs` are passed through from
     `yueDescriptor` (so the class instance is itself a valid
     `MusicGenerationProvider`).
   - `generate(call: MusicGenCall): Promise<MusicGenResult>`:
     - Validates `call.prompt` is non-empty (after trim); throws
       `Error('YueMusicProvider.generate: prompt must be non-empty')`.
     - Validates `call.outputFormat === 'wav'`; throws on mismatch.
     - Validates `call.durationS > 0` AND `call.durationS <= 300`;
       throws on out-of-range.
     - Validates `call.genre`, when present, is in
       `yueDescriptor.capability.genres`; throws on unknown genre.
     - In `'stub'` mode: synthesizes a deterministic silent-WAV byte
       payload, derives a canonical `cacheKey` via `deriveCacheKey`,
       returns `{ cacheKey, url, durationS, attribution:
       YUE_ATTRIBUTION }`. The `attribution` field is **present** for
       every call (mandatory for the `attribution-required`
       disposition). `url` = `data:audio/wav;base64,<base64-of-silent-wav>`.
     - In `'production'` mode: throws `NotYetImplementedError(
       'YueMusicProvider.generate: production wire-up deferred to
       T-433a (YuE ONNX runtime audit pending)')`.
6. **`generateSilentWavDataUri(durationS, sampleRate)`** in

## Monetization posture

YuE ships under Apache 2.0. Apache 2.0 permits commercial use of the
model and its outputs provided the attribution clause is honored.
T-433's contract closes the loop:

1. **Distribution license** (CI-gate facing): `license.kind:
   'apache-2.0'` clears `check-asset-licenses` (apache-2.0 ∈
   music-gen whitelist).
2. **Output license** (routing-layer facing):
   `capability.outputLicense: 'attribution-required'` signals to T-425
   capability-router (and to T-422's tenant-policy filter, if a
   tenant opts out of attribution-required output) that the generated
   track requires attribution at the exporter.
3. **Per-call attribution** (runtime-side): every `MusicGenResult`
   carries `attribution: YUE_ATTRIBUTION`. T-423 handler bundle
   propagates this into `MediaProvenance.attribution`; the exporter
   (CDP / static-export renderer) surfaces it in the credits / UI.

This three-layer encoding means commercial monetization is permitted
without code-level branching — the system just has to thread the
attribution string from `MusicGenResult` → `MediaProvenance` → UI.
The data is in the right places for downstream consumers to honor
the clause.

## Stub-mode vs production-mode contract

The `YueProviderMode` discriminator gates the `generate()` body
behavior **only**. Every other surface (descriptor, capability,
genre list, validation, error throwing, cache-key derivation,
attribution emission) is identical between modes. The production
wire-up (T-433a) MUST:

1. Keep `yueDescriptor` byte-identical (no new genres added to v1).
2. Replace the `generate()` `mode === 'production'` branch with a
   real YuE library call.
3. Keep the input validation paths byte-identical.
4. Keep the cache-key derivation byte-identical.
5. NOT widen the `MusicGenResult` shape. `attribution` remains
   present and equal to `YUE_ATTRIBUTION` for every call.

Anything in the production wire-up that conflicts with this contract
is a spec change — file an ADR.
