# T-426 — `@stageflip/tts-kokoro` (Kokoro TTS adapter; stub-mode v1)

**Branch**: `task/T-426-tts-kokoro`

## Goal

Ship the **first reference adapter** in the Phase 14 β sequence
(T-426..T-434): `@stageflip/tts-kokoro`. Wraps the Kokoro TTS model
(community Apache 2.0; ~82M params; sub-0.3s latency; edge-deployable)
behind the `TTSProvider` interface from T-419, declares an
`AdapterDescriptor` per T-418, and exposes a stable shape that the
asset-generation handler bundle (T-423) + capability router (T-425)
consume.

T-426 sets the **structural template** every other reference adapter
(T-427..T-434) follows:

1. New package `@stageflip/<modality>-<vendor>` at `packages/<prefix>`.
2. `src/descriptor.ts` declares the static `AdapterDescriptor` const.
3. `src/provider.ts` implements the per-modality provider interface.
4. `src/index.ts` is the public barrel — exports `descriptor` + the
   provider class. The `descriptor` named export is what the T-422
   `check-asset-licenses` discovery walker dynamic-imports + parses.
5. The `descriptor` is registered into the host `AdapterRegistry` at
   `scripts/sync-skills.ts`'s `buildAssetProvidersPkg()` site so the
   T-424 catalog auto-gen picks it up.

T-426 ships in **stub mode**: the `synthesize()` body emits a
deterministic silent-WAV byte payload at the declared sample rate +
returns a shaped `TtsResult`. Production wire-up (Kokoro npm package
→ ONNX runtime → real audio) is gated on a follow-up task (T-426a) to
keep this PR's blast radius tight + let downstream T-436 (TTS↔captions
integration) develop against the stub.

T-426 is M-sized: one new package, ~250–400 LOC across 3 src modules
(descriptor / provider / stub-audio) + matched tests, ~250–400 lines of
spec, no schema / parity / clip / preset changes.

## Out of scope

| Item | Why deferred |
|---|---|
| **Production wire-up to a real Kokoro library** (npm `kokoro-js`, ONNX runtime, or Python sidecar) | The Kokoro npm ecosystem in May 2026 is unsettled — `kokoro-js` exists but its license, version stability, and edge-runtime compatibility (Cloudflare Workers / Vercel Edge) need a separate audit. Deferring to **T-426a** keeps T-426's blast radius tight + lets T-436 (captions/TTS integration) develop against the deterministic stub. The `descriptor` shape declared here is the contract the production wire-up MUST match; T-426a only swaps the body, never the shape. |
| **Voice cloning** | Kokoro v1 ships ~10 library voices (no cloning). `descriptor.capability.supportsVoiceClone = false`; the §D4 `TenantVoiceConsentStore` consent path is not exercised. T-427 (`@stageflip/tts-fish-speech`) is the first cloning adapter. |
| **Multi-language synthesis** | Stub-mode declares English voices only (matches Kokoro v1's primary language). The descriptor structure supports arbitrary `voice.languages` arrays; production wire-up populates per-voice ISO-639-1 lists. |
| **Word-timestamp emission** | `descriptor.capability.emitsWordTimestamps = false` for v1. Whisper-bypass path (T-436) consumes this flag; setting it to `true` would obligate the stub to synthesize plausible timestamp triples (out of scope; would constrain the production body). |
| **Adapter-side caching** | `synthesize()` derives the canonical `cacheKey` per ADR-008 §D1 + returns it in `TtsResult.cacheKey`, but the adapter does NOT consult `AssetCacheStore` itself. The orchestrator (handler bundle T-423) is the cache owner. |
| **Telemetry / cost-metering** | Descriptor declares `costPerCall.usd = 0` + `latencyMs.{p50,p95}` hints; no per-call telemetry emission. Telemetry lives at the orchestrator boundary. |
| **AssetStorage upload** | `synthesize()` returns `url` as an inline `data:` URI for the silent-WAV stub. Production wire-up uploads to an `AssetStorage` adapter + returns the storage URL; the shape stays identical. |
| **Capability-validator hook into `CapabilityDescriptorParser`** | T-419 ships `validateTtsCapability`; T-426 declares a capability that satisfies it but does NOT register the validator into a host-shell parser (host-shell wiring is out of scope). Tests assert the descriptor passes `validateTtsCapability` directly. |
| **Schema / parity / clip / preset / parity-golden changes** | All untouched. |

## Acceptance criteria

1. New package `@stageflip/tts-kokoro` at `packages/tts-kokoro/` with
   `package.json`, `tsconfig.json` (matches the
   `@stageflip/asset-cache` + `@stageflip/capability-router` shape: no
   per-package `tsup.config.ts` / `vitest.config.ts` — defaults via
   package.json scripts suffice).
2. Public barrel `src/index.ts` exports:
   - `kokoroDescriptor` (the canonical `AdapterDescriptor`),
   - `descriptor` (alias of `kokoroDescriptor`; named export the T-422
     discovery walker reads),
   - `KokoroTtsProvider` (the class implementing `TTSProvider`),
   - `KokoroProviderMode` (`'stub' | 'production'`),
   - `NotYetImplementedError` (thrown by `production` mode).
3. **Descriptor shape** (verbatim from ADR-007 §D1 + ADR-008 §D5):
   ```ts
   {
     id: 'kokoro',
     modality: { kind: 'tts' },
     capability: {
       voices: [
         { id: 'af_bella', label: 'Bella (en, US, female)', origin: 'library', languages: ['en'] },
         { id: 'af_nicole', label: 'Nicole (en, US, female)', origin: 'library', languages: ['en'] },
         { id: 'af_sarah', label: 'Sarah (en, US, female)', origin: 'library', languages: ['en'] },
         { id: 'am_adam', label: 'Adam (en, US, male)', origin: 'library', languages: ['en'] },
         { id: 'am_michael', label: 'Michael (en, US, male)', origin: 'library', languages: ['en'] },
         { id: 'bf_emma', label: 'Emma (en, GB, female)', origin: 'library', languages: ['en'] },
         { id: 'bf_isabella', label: 'Isabella (en, GB, female)', origin: 'library', languages: ['en'] },
         { id: 'bm_george', label: 'George (en, GB, male)', origin: 'library', languages: ['en'] },
         { id: 'bm_lewis', label: 'Lewis (en, GB, male)', origin: 'library', languages: ['en'] },
         { id: 'af_default', label: 'Default voice (en, US, female)', origin: 'library', languages: ['en'] },
       ],
       outputFormats: ['wav'],
       sampleRates: [24000],
       maxDurationS: 60,
       emitsWordTimestamps: false,
       supportsVoiceClone: false,
       // T-424 catalog-summary fields (read by skills-sync's
       // capabilitySummary helper):
       voiceCount: 10,
       sampleRateHz: 24000,
     },
     license: { kind: 'apache-2.0' },
     sandbox: { kind: 'in-process' },
     costPerCall: { usd: 0 },
     latencyMs: { p50: 200, p95: 300 },
   }
   ```
   `voiceCount` + `sampleRateHz` are extra capability fields the
   T-424 catalog generator reads; the strict T-419
   `ttsCapabilityDescriptorSchema` is `.strict()` and would reject them
   — so the descriptor uses a capability shape that is `.passthrough()`
   compatible at the T-418 envelope level (which uses
   `z.record(z.unknown())`). Tests assert: (a) the descriptor passes
   `parseAdapterDescriptor()`; (b) the relevant subset
   `{voices,outputFormats,sampleRates,maxDurationS,emitsWordTimestamps,supportsVoiceClone}`
   passes `validateTtsCapability` after stripping the catalog-summary
   keys.
4. **`KokoroTtsProvider` class** implements `TTSProvider`:
   - Constructor takes `{ mode: KokoroProviderMode }` (defaults to
     `'stub'`).
   - `id` / `modality` / `capability` / `license` / `sandbox` /
     `costPerCall` / `latencyMs` are passed through from
     `kokoroDescriptor` (so the class instance is itself a valid
     `TTSProvider`).
   - `synthesize(call: TtsCall): Promise<TtsResult>`:
     - Validates `call.voiceId` is in `descriptor.capability.voices`;
       throws `Error('KokoroTtsProvider.synthesize: unknown voiceId
       "${voiceId}"')` if not.
     - Validates `call.outputFormat === 'wav'` (only declared format);
       throws on mismatch.
     - Validates `call.sampleRate === 24000` (only declared sample
       rate); throws on mismatch.
     - In `'stub'` mode: synthesizes a deterministic silent-WAV byte
       payload (`generateSilentWavDataUri(durationS, sampleRate)`),
       derives a canonical `cacheKey` via
       `deriveCacheKey({ modality: 'tts', model: 'kokoro:<voiceId>',
       voice: voiceId, prompt: text, params: {sampleRate,
       outputFormat}, seed })`, emits
       `cacheKeyString(key)`, returns `{ cacheKey, url, durationS }`.
       `durationS` = `text.length / 15` clamped to `[0.5, 60]` (rough
       proxy: ~15 chars per second of synthesized speech; deterministic).
       `url` = `data:audio/wav;base64,<base64-of-silent-wav>`.
     - In `'production'` mode: throws `NotYetImplementedError(
       'KokoroTtsProvider.synthesize: production wire-up deferred to
       T-426a (kokoro-js / ONNX runtime audit pending)')`.
5. **`generateSilentWavDataUri(durationS, sampleRate)`** in
   `src/stub-audio.ts`:
   - Pure function. No `Date`, no `Math.random`, no `fetch`, no timers.
   - Returns a `data:audio/wav;base64,...` URI for a mono 16-bit PCM
     WAV file with the specified duration + sample rate, where every
     PCM sample is `0` (silent).
   - WAV header is built per the standard `RIFF/WAVE/fmt /data` chunk
     layout (44 bytes; 16-bit mono PCM). Tests assert:
     (a) the URI starts with `data:audio/wav;base64,`;
     (b) the decoded bytes start with `RIFF` (offset 0..3) +
     `WAVE` (offset 8..11) + `fmt ` (offset 12..15);
     (c) the sample-rate field at offset 24..27 (little-endian
     uint32) equals `sampleRate`;
     (d) the data-chunk size at offset 40..43 equals
     `Math.floor(durationS * sampleRate) * 2` (16-bit mono);
     (e) all PCM samples (offset 44..end) are zero;
     (f) two calls with identical inputs return byte-identical URIs
     (determinism).
6. **`NotYetImplementedError`** is a regular `class extends Error`
   with `name = 'NotYetImplementedError'`. Exported from the barrel.
7. Tests cover (≥85% coverage on changed files):
   - **Descriptor**: passes `parseAdapterDescriptor()`; `id === 'kokoro'`;
     `modality.kind === 'tts'`; `license.kind === 'apache-2.0'`;
     `sandbox.kind === 'in-process'`; capability subset passes
     `validateTtsCapability()`; voice count = 10; every voice has
     `origin: 'library'`; `supportsVoiceClone === false`.
   - **Stub-audio**: see AC #5 (a)..(f).
   - **Provider**:
     - `mode: 'stub'` constructor returns a working provider; `id`,
       `modality`, `capability`, `license`, `sandbox` all match
       `kokoroDescriptor`.
     - `synthesize()` returns a `TtsResult` whose `url` starts with
       `data:audio/wav;base64,`, `cacheKey` matches
       `<modality>/<64-hex>` shape, `durationS` is in `[0.5, 60]`.
     - Two `synthesize()` calls with identical input → identical
       `cacheKey` (determinism).
     - `synthesize()` with unknown `voiceId` throws.
     - `synthesize()` with non-`'wav'` `outputFormat` throws.
     - `synthesize()` with non-`24000` `sampleRate` throws.
     - `mode: 'production'` constructor builds; `synthesize()` throws
       `NotYetImplementedError`.

## Stub-mode vs production-mode contract

The `KokoroProviderMode` discriminator gates the `synthesize()` body
behavior **only**. Every other surface (descriptor, capability,
voice list, validation, error throwing, cache-key derivation) is
identical between modes. The production wire-up (T-426a) MUST:

1. Keep `kokoroDescriptor` byte-identical (no new voices added to
   v1; voice expansion lands in T-426b at earliest).
2. Replace the `synthesize()` `mode === 'production'` branch with a
   real Kokoro library call (`kokoro-js` — pending license + edge-
   runtime audit — or ONNX runtime over a pinned model checkpoint).
3. Keep the input validation paths (unknown voice / wrong format /
   wrong sample rate → throw) byte-identical.
4. Keep the cache-key derivation byte-identical (so cached results
   from the stub-mode era + production-mode era share the same
   keyspace; the orchestrator's `AssetCacheStore` does not need a
   per-mode bucket).
5. NOT widen the `TtsResult` shape (no new fields; no
   `wordTimestamps`).

Anything in the production wire-up that conflicts with this contract
is a spec change — file an ADR.
