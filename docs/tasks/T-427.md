# T-427 — `@stageflip/tts-fish-speech` (Fish Speech TTS adapter; voice cloning + tenant consent; stub-mode v1)

**Branch**: `task/T-427-tts-fish-speech`

## Goal

Ship the **second reference adapter** in the Phase 14 β sequence
(T-426..T-434): `@stageflip/tts-fish-speech`. Wraps the Fish Speech
TTS model (community Apache 2.0; voice cloning; 8 languages; MOS 4.1)
behind the `TTSProvider` interface from T-419, declares an
`AdapterDescriptor` per T-418, and **exercises the §D4
`TenantVoiceConsentStore` consent path for the first time** — Fish
Speech is the v1 voice-clone adapter named in ADR-008 §D4 / T-419.

T-427 follows the **structural template** T-426 (`@stageflip/tts-kokoro`)
established. The deltas vs Kokoro:

| Field | Kokoro | Fish Speech |
|---|---|---|
| `id` | `kokoro` | `fish-speech` |
| `latencyMs.{p50,p95}` | `200 / 300` (interactive) | `1200 / 3000` (fast) |
| `sandbox.kind` | `in-process` | `sidecar` (runtime: `python`) |
| Voice languages | English (US/GB) only | en / zh / ja / ko / fr / de / es / ru |
| `supportsVoiceClone` | `false` | **`true`** |
| Voice list | 10 library voices | 8 library voices (one per language) + cloned-voice support |
| Sample rate | 24000Hz | 22050Hz |
| Voice-consent (§D4) | not exercised | **enforced on every cloned-voice call** |

T-427 ships in **stub mode**: the `synthesize()` body emits a
deterministic silent-WAV byte payload at 22050Hz + returns a shaped
`TtsResult`. Production wire-up (Fish Speech Python sidecar / pinned
model checkpoint) is gated on a follow-up task (T-427a) — same
v1-stub-mode-with-production-deferral pattern as T-426.

T-427 is M-sized: one new package, ~350–500 LOC across 4 src modules
(descriptor / provider / voice-consent / stub-audio) + matched tests,
~250–400 lines of spec, no schema / parity / clip / preset / ADR
changes.

## Out of scope

| Item | Why deferred |
|---|---|
| **Production wire-up to a real Fish Speech runtime** (Python sidecar holding the model checkpoint, ONNX export, or cloud-hosted endpoint) | The Fish Speech ecosystem in May 2026 ships a Python reference implementation; the JS / edge-runtime story is unsettled. Deferring to **T-427a** keeps T-427's blast radius tight + lets downstream T-436 (captions/TTS integration) develop against the deterministic stub. The `descriptor` shape declared here is the contract the production wire-up MUST match; T-427a only swaps the body, never the shape. |
| **Concrete `TenantVoiceConsentStore` adapter implementations** (in-memory, Firebase, Postgres) | T-419 ships only the interface; adapter implementations are downstream of T-427's first consumer. The provider takes a `TenantVoiceConsentStore` instance via construction options — tests pass a tiny inline fake (≤10 LOC; `assertActive` resolves or throws based on a Set of granted triples). The first real impl (in-memory) lands in T-427b once a host-shell consumer needs it; storage-adapter shapes (Firebase / Postgres) follow the existing storage-adapter pattern. |
| **Voice-clone enrollment / consent-admin UX** | Out of scope. The provider only **reads** the consent store via `assertActive`; the write path (admin-declared grants) is a sibling task (T-411e per ADR-008 §D4). |
| **Word-timestamp emission** | `descriptor.capability.emitsWordTimestamps = false` for v1 — same posture as Kokoro. T-436 (Whisper-bypass) consumes the flag; setting it to `true` here would obligate the stub to synthesize plausible timestamp triples. |
| **Adapter-side caching** | `synthesize()` derives the canonical `cacheKey` per ADR-008 §D1 + returns it in `TtsResult.cacheKey`, but the adapter does NOT consult `AssetCacheStore` itself. The orchestrator (handler bundle T-423) is the cache owner. |
| **Telemetry / cost-metering** | Descriptor declares `costPerCall.usd = 0` (Apache 2.0 model — the deployment cost is the tenant's, not licensing cost) + `latencyMs.{p50,p95}` hints; no per-call telemetry emission. Telemetry lives at the orchestrator boundary. |
| **AssetStorage upload** | `synthesize()` returns `url` as an inline `data:` URI for the silent-WAV stub. Production wire-up uploads to an `AssetStorage` adapter + returns the storage URL; the shape stays identical. |
| **Capability-validator hook into `CapabilityDescriptorParser`** | T-419 ships `validateTtsCapability`; T-427 declares a capability that satisfies it but does NOT register the validator into a host-shell parser. Tests assert the descriptor passes `validateTtsCapability` directly. |

   passes `validateTtsCapability` after stripping the catalog-summary
   keys.
4. **`FishSpeechTtsProvider` class** implements `TTSProvider`:
   - Constructor takes
     `{ mode?: FishSpeechProviderMode, voiceConsentStore?: TenantVoiceConsentStore }`.
     Defaults: `mode = 'stub'`, `voiceConsentStore = undefined`.
   - `id` / `modality` / `capability` / `license` / `sandbox` /
     `costPerCall` / `latencyMs` are passed through from
     `fishSpeechDescriptor`.
   - `synthesize(call: TtsCall): Promise<TtsResult>`:
     - Resolves the requested voice from
       `descriptor.capability.voices` OR treats it as a cloned voice
       when the id is unknown to the library (cloned voices are
       per-tenant; the provider does not maintain a registry).
     - For a **library voice** (origin `'library'`): no consent
       check needed.
     - For a **cloned voice** (id absent from the library list): the
       provider MUST call `assertVoiceConsentIfNeeded({ store,
       tenantId, voiceId })`. When `store` is `undefined`, throws
       `VoiceConsentRequiredError` synchronously (the orchestrator
       must wire a store before invoking cloned voices). When the
       store throws (no active row), the provider re-throws as
       `VoiceConsentRequiredError`.
     - Validates `call.outputFormat === 'wav'` and `call.sampleRate
       === 22050` after the consent check (so consent is never
       leaked to a malformed call); throws on mismatch.
     - In `'stub'` mode: synthesizes a deterministic silent-WAV
       payload (`generateSilentWavDataUri(durationS, 22050)`),
       derives a canonical `cacheKey` via
       `deriveCacheKey({ modality: 'tts', model:
       'fish-speech:<voiceId>', voice: voiceId, prompt: text,
       params: { sampleRate, outputFormat,
       voiceCloneFingerprint? }, seed })`. The
       `voiceCloneFingerprint` field is included (deterministic
       `clone:${voiceId}`) ONLY when the voice is a cloned one — so
       library-voice cache keys remain backwards-compatible should
       Fish Speech ever expose the same `voiceId` under both
       library and clone modes. Returns `{ cacheKey, url, durationS }`.
       `durationS = clamp(text.length / 15, 0.5, 60)` (same proxy
       as Kokoro).
     - In `'production'` mode: throws `NotYetImplementedError(
       'FishSpeechTtsProvider.synthesize: production wire-up
       deferred to T-427a (Fish Speech Python sidecar / model
       checkpoint audit pending)')`. Validation + consent paths
       fire BEFORE this branch.
5. **`assertVoiceConsentIfNeeded`** in `src/voice-consent.ts`:
   - Pure async helper. Signature:
     ```ts
     async function assertVoiceConsentIfNeeded(input: {
       store: TenantVoiceConsentStore | undefined;
       tenantId: string;
       voiceProvider: 'fish-speech';
       voiceId: string;
       isClonedVoice: boolean;
     }): Promise<void>;
     ```
   - When `isClonedVoice === false`: returns immediately. Library
     voices bypass consent (per ADR-008 §D4).
   - When `isClonedVoice === true` and `store === undefined`: throws
     `VoiceConsentRequiredError` with a message that names the
     missing prerequisite (the orchestrator must wire a
     `TenantVoiceConsentStore` instance before invoking cloned
     voices).
   - When `isClonedVoice === true` and the store throws: re-wraps as
     `VoiceConsentRequiredError` with the original error's message
     attached (the throw is the `LF-VOICE-CONSENT-MISSING`
     propagation per ADR-008 §D11).
   - When the store resolves: returns `void`.
6. **`generateSilentWavDataUri(durationS, sampleRate)`** in
   `src/stub-audio.ts`:
   - Pure function. No `Date`, no `Math.random`, no `fetch`, no
     timers. Same byte-shape contract as Kokoro's: standard
     RIFF/WAVE/fmt /data 44-byte header (mono, 16-bit PCM) + zero
     PCM samples.
   - Stub-audio tests cover 22050Hz at the offset-24 sample-rate
     field, plus the same RIFF/WAVE/fmt /data magics + determinism +
     bounds-check error paths Kokoro covers.
7. **Errors**:
   - `NotYetImplementedError` — class extends `Error`, name
     `'NotYetImplementedError'`, used in `'production'` mode.
   - `VoiceConsentRequiredError` — class extends `Error`, name
     `'VoiceConsentRequiredError'`, exported from the barrel. The
     adapter's pre-call hook propagates the §D4 refusal as this
     error type so the orchestrator can map to
     `LF-VOICE-CONSENT-MISSING` per ADR-008 §D11 (the orchestrator

## Voice-consent integration (the differentiator vs T-426)

Fish Speech is the **first adapter to exercise the §D4 voice-consent
contract.** Per ADR-008 §D4:

- Library voices (everything in `FISH_SPEECH_LIBRARY_VOICES`) bypass
  consent. The provider's `assertVoiceConsentIfNeeded` short-circuits
  when `isClonedVoice === false`.
- Cloned voices (any `voiceId` not in the library list) require an
  active `TenantVoiceConsentStore` row for the
  `(tenantId, 'fish-speech', voiceId)` triple. The store's
  `assertActive` is the throw-on-missing API; the provider wraps the
  throw as `VoiceConsentRequiredError`.
- The check fires on **every** cloned-voice synthesize() call — no
  per-session caching (per ADR-008 §D4 D-VOICE-CONSENT-3). A
  revocation must take effect immediately.
- When the orchestrator has not wired a `TenantVoiceConsentStore`
  instance, cloned-voice calls throw `VoiceConsentRequiredError`
  with a message that names the missing prerequisite. This is a
  fail-closed default — the adapter never silently bypasses consent.

T-427 ships only the consumer side. The first concrete
`TenantVoiceConsentStore` impl (in-memory) lands in T-427b once a
host-shell consumer needs it; the inline test fakes in
`provider.test.ts` + `voice-consent.test.ts` are sufficient unit
coverage for T-427's body.

## Stub-mode vs production-mode contract

The `FishSpeechProviderMode` discriminator gates the `synthesize()`
body behavior **only**. Every other surface (descriptor, capability,
voice list, validation, consent enforcement, error throwing,
cache-key derivation) is identical between modes. The production
wire-up (T-427a) MUST:

1. Keep `fishSpeechDescriptor` byte-identical (no new voices added
   to v1; voice expansion lands in T-427c at earliest).
2. Replace the `synthesize()` `mode === 'production'` branch with a
   real Fish Speech library call (Python sidecar over the runtime
   field declared in the descriptor's sandbox; pinned model
   checkpoint).
3. Keep the input validation paths (wrong format / wrong sample
   rate → throw) byte-identical.
4. Keep the consent-enforcement path byte-identical (cloned voice
   without active store row → `VoiceConsentRequiredError`).
5. Keep the cache-key derivation byte-identical (so cached results
   from the stub-mode era + production-mode era share the same
   keyspace).
6. NOT widen the `TtsResult` shape (no new fields; no
   `wordTimestamps`).

Anything in the production wire-up that conflicts with this contract
is a spec change — file an ADR.
