# T-429 — `@stageflip/3d-meshy` (Meshy 3D adapter; props + environment; triangle topology; proprietary-byo; stub-mode v1)

**Branch**: `task/T-429-3d-meshy`

## Goal

Ship the **fourth reference adapter** in the Phase 14 β sequence
(T-426..T-434) and the **second 3D adapter**:
`@stageflip/3d-meshy`. Wraps the Meshy commercial AI 3D model
generator (props + environment + vehicles + hard-surface objects;
triangle-soup topology; **no** auto-rigging; GLB output; ~1 min
per asset; tenant-supplied API credentials) behind the
`ThreeDAssetProvider` interface from T-419, declares an
`AdapterDescriptor` per T-418, and exercises the
**`proprietary-byo`** license posture for the **second** time
(T-428's Tripo3D was the first).

T-429 is the structural sibling of T-428: same modality (`three-d`),
same `proprietary-byo` license posture, same `remote-service`
sandbox shape, same v1-stub-mode-with-production-deferral pattern,
same surrounding shape (descriptor / provider / stub-glb / index
barrel). The deltas are functional, not structural.

| Field | Tripo3D (T-428) | Meshy (T-429) |
|---|---|---|
| Subject scope | characters | **props, environment, vehicles, hard-surface** |
| `id` | `tripo` | `meshy` |
| `topology` | `quad-clean` (rigging-eligible quads) | **`triangle-soup`** (faster pipeline; rigging refused) |
| `supportsAutoRigging` | `true` | **`false`** (props / environment do not need bones) |
| `maxVertices` | `50_000` | **`30_000`** (Meshy's lower per-asset cap; declarative budget) |
| `latencyMs.{p50,p95}` | `60_000 / 120_000` | **`60_000 / 90_000`** (~1 min typical; still **batch tier**) |
| `costPerCall.usd` | `0.5` | **`0.2`** (per-asset; tenant pays Meshy; representative-call hint) |
| `sandbox.baseUrlEnvVar` | `TRIPO_API_BASE_URL` | **`MESHY_API_BASE_URL`** |
| Stub payload | unit cube + optional rigged variant | **regular icosahedron** (12 vertices; 20 triangles via 60 indices); no rig variant |
| `model` cache-key field | `tripo:character` | **`meshy:prop-environment`** |

T-429 ships in **stub mode**: the `generate()` body emits a
deterministic placeholder GLB byte payload (a regular icosahedron —
visually distinct from Tripo's unit cube for diff readability) and
returns a shaped `ThreeDResult`. Production wire-up (real Meshy
HTTPS API call + GLB download) is gated on a follow-up task
(T-429a) — same v1-stub-mode-with-production-deferral pattern as
T-426 / T-427 / T-428.

T-429 is M-sized: one new package, ~350–500 LOC across 3 src modules
(descriptor / provider / stub-glb) + matched tests, ~250–400 lines
of spec, no schema / parity / clip / preset / ADR changes.

## Out of scope

| Item | Why deferred |
|---|---|
| **Production wire-up to the real Meshy HTTPS API** (job submit, polling, GLB download to `AssetStorage`) | Same reasoning as T-428a: the Meshy public API surface in May 2026 is iterating; locking the production path now would couple the adapter shape to the current vendor surface. Deferring to **T-429a** keeps T-429's blast radius tight + lets downstream T-437 (3D scene clip integration) develop against the deterministic stub. The `descriptor` shape declared here is the contract the production wire-up MUST match; T-429a only swaps the body, never the shape. |
| **Tenant-credential injection mechanism** | The descriptor declares `sandbox: { kind: 'remote-service', baseUrlEnvVar: 'MESHY_API_BASE_URL' }` — that env var is the production credentials anchor. A typed credentials struct lands with the production wire-up (T-429a); the stub-mode body never reads the env var. |
| **Topology / vertex-count enforcement** (refusing requests over `capability.maxVertices`) | Adapter declares; orchestrator enforces (per ADR-008 §D6). |
| **Character / animator-grade variants** | Out of scope. Meshy's product line includes character generation, but T-429 covers the props + environment surface only — the descriptor declares `topology: 'triangle-soup'` and `supportsAutoRigging: false`. A character-grade Meshy adapter would ship as a separate package with its own descriptor (just as Tripo characters and Tripo props would be separate). |

     `validateThreeDCapability`),

3. **Descriptor shape** (verbatim from ADR-007 §D1 + ADR-008 §D6):
   ```ts
   {
     id: 'meshy',
     modality: { kind: 'three-d' },
     capability: {
       outputFormats: ['glb'],
       topology: 'triangle-soup',
       supportsAutoRigging: false,
       maxVertices: 30_000,
       // T-424 catalog-summary fields (read by skills-sync's
       // capabilitySummary helper for `three-d`):
       formats: ['glb'],
       maxPolyCount: 30_000,
     },
     license: { kind: 'proprietary-byo' },
     sandbox: { kind: 'remote-service', baseUrlEnvVar: 'MESHY_API_BASE_URL' },
     costPerCall: { usd: 0.2 },
     latencyMs: { p50: 60_000, p95: 90_000 },
   }
   ```
   `formats` + `maxPolyCount` are catalog-summary fields the T-424
   generator reads via `readStringArray('formats')` /
   `readNumber('maxPolyCount')` — the strict T-419
   `threeDCapabilityDescriptorSchema` is `.strict()` and would
   reject them. Tests assert: (a) the descriptor passes
   `parseAdapterDescriptor()`; (b) the relevant subset
   `{outputFormats,topology,supportsAutoRigging,maxVertices}`
   passes `validateThreeDCapability` after stripping the
   catalog-summary keys.
4. **`MeshyThreeDProvider` class** implements `ThreeDAssetProvider`:
   - Constructor takes `{ mode?: MeshyProviderMode }`.
     Default: `mode = 'stub'`.
   - `id` / `modality` / `capability` / `license` / `sandbox` /
     `costPerCall` / `latencyMs` are passed through from
     `meshyDescriptor`.
   - `generate(call: ThreeDCall): Promise<ThreeDResult>`:
     - Validates `call.prompt` is a non-empty string after trim;
       throws `Error` on empty.
     - In `'stub'` mode: synthesizes a deterministic placeholder
       GLB payload via `generateStubGlbDataUri(call.prompt,
       call.seed)`; derives a canonical `cacheKey` via
       `deriveCacheKey({ modality: 'three-d', model:
       'meshy:prop-environment', prompt: call.prompt, params: {
       outputFormat: 'glb', topology: 'triangle-soup', rig: false
       }, seed })`. Returns `{ cacheKey, url, vertices: 12,
       rigged: false }`. The icosahedron stub has 12 vertices
       regardless of input; `rigged` is **always** `false` because
       `capability.supportsAutoRigging === false` (per ADR-008 §D6:
       T-437 refuses rigging on `triangle-soup`).
     - In `'production'` mode: throws `NotYetImplementedError(
       'MeshyThreeDProvider.generate: production wire-up deferred
       to T-429a (Meshy HTTPS API audit pending)')`. Validation
       fires BEFORE this branch (defensive ordering).
5. **`generateStubGlbDataUri(prompt, seed?)`** in
   `src/stub-glb.ts`:
   - Pure function. No `Date`, no `Math.random`, no `fetch`, no
     timers. Deterministic — same inputs → byte-identical output.
   - Builds a minimal valid GLB binary in TypeScript using
     `Uint8Array` + `DataView` (no external GLB library — write
     the JSON chunk + binary chunk directly). The GLB conforms to
     the [glTF 2.0 binary container spec](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#binary-gltf-layout):
     - 12-byte header: `magic = 0x46546C67` ("glTF"), `version = 2`,
       `length`.
     - JSON chunk: `chunkType = 0x4E4F534A` ("JSON"), padded to a
       4-byte boundary with `0x20` (space). JSON describes 1 mesh
       (a regular icosahedron: 12 vertices, 20 triangular faces via
       60 indices), 1 node, 1 scene. **No skin / joints / weights**
       — Meshy props/environment never rig (`supportsAutoRigging:
       false`).
     - BIN chunk: `chunkType = 0x004E4942` ("BIN\0"), padded to a
       4-byte boundary with `0x00`. Holds the icosahedron's
       positions and indices.
   - The JSON chunk does NOT embed `prompt` or `seed` — those
     differentiate the cache key only. The on-the-wire stub bytes
     are byte-identical for ANY input (since there is no `rig`
     branching, the GLB has a single canonical form).
   - Returns `data:model/gltf-binary;base64,<base64-of-GLB-bytes>`.
   - **Visually distinct from Tripo's stub** (regular icosahedron
     vs. Tripo's unit cube) — diff readers can tell adapter outputs
     apart at a glance.
6. **Errors**:
   - `NotYetImplementedError` — class extends `Error`, name
     `'NotYetImplementedError'`, used in `'production'` mode.
7. Tests cover (≥85% coverage on changed files):
   - **Descriptor**: passes `parseAdapterDescriptor()`; `id ===
     'meshy'`; `modality.kind === 'three-d'`; `license.kind ===

   - **Stub GLB**: returns a `data:model/gltf-binary;base64,` URI;

## BYO credentials posture

Meshy is the **second adapter to declare the `proprietary-byo`
license posture** (Tripo3D was the first via T-428). Per ADR-008
§D13 (line 657), the `three-d` modality whitelist admits
`apache-2.0`, `mit`, `proprietary-byo`, and `proprietary-vendored`.
`proprietary-byo` means:

- The adapter wraps a commercial vendor model (Meshy); the vendor's
  licensing terms govern model use.
- The tenant brings their own API credentials (a Meshy API key and
  potentially a base URL override). The descriptor declares the
  credentials anchor via `sandbox.{kind: 'remote-service',
  baseUrlEnvVar: 'MESHY_API_BASE_URL'}` — that env var is the
  production wire-up's secrets entry point.
- StageFlip ships **no vendored model checkpoint**.
- The `pnpm check-asset-licenses` gate accepts the descriptor
  because `proprietary-byo` is in the `three-d` whitelist; tenant
  credential validation is a runtime concern at the orchestrator
  boundary.

T-429 ships only the descriptor declaration of this posture. The
production wire-up (T-429a) reads the env var, builds an HTTPS
client, and surfaces the `LF-ADAPTER-CREDENTIAL-MISSING` failure
class (per ADR-008 §D11) when credentials are absent. The stub
mode never reads the env var.

## Stub-mode vs production-mode contract

The `MeshyProviderMode` discriminator gates the `generate()` body
behavior **only**. Every other surface (descriptor, capability,
validation, error throwing, cache-key derivation) is identical
between modes. The production wire-up (T-429a) MUST:

1. Keep `meshyDescriptor` byte-identical (no new capability fields
   in v1; capability expansion lands in a follow-up at earliest).
2. Replace the `generate()` `mode === 'production'` branch with a
   real Meshy API call (HTTPS POST to the job-submit endpoint at
   `process.env[MESHY_BASE_URL_ENV_VAR]`, polling the job-status
   endpoint, downloading the produced GLB).
3. Keep the input validation paths (empty prompt → throw)
   byte-identical.
4. Keep the cache-key derivation byte-identical (so cached
   results from the stub-mode era + production-mode era share the
   same keyspace — production-mode results MUST hash identically
   to stub-mode results when the same `(prompt, seed)` is used;
   the canonical params dict declared here is the contract).
5. NOT widen the `ThreeDResult` shape (no new fields).
6. Honor the `capability.maxVertices` budget — refuse calls whose
   declared expected vertex count exceeds the budget (per
   ADR-008 §D6).
7. NEVER emit `rigged: true` (Meshy capability declares
   `supportsAutoRigging: false`; T-437 refuses rigging on
   `triangle-soup` topology regardless).

Anything in the production wire-up that conflicts with this
contract is a spec change — file an ADR.
