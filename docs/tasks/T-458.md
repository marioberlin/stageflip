# T-458 — Rate-limit / spam protection

**Branch**: `task/T-458-rate-limit-spam-protection`

## Goal

Harden the audience-backend rate-limit posture per ADR-009 §D3 + §D8.
T-453 already shipped the base layer (per-tenant + per-voter token
buckets, per-IP join-rate limiter, per-session voter cap). T-458 adds
the remaining two pieces ADR-009 specifies:

1. **`AbuseTrackingStore` facet** in `@stageflip/storage`:
   - Tracks per-IP + per-voter-token abuse counters (rate-limit hits
     accumulated over a sliding window).
   - When a threshold is crossed, the source is **flagged** — subsequent
     requests from the flagged source get an escalating back-off:
     - First flag: 30s cooldown.
     - Second flag (within 1h): 5min cooldown.
     - Third flag (within 1h): 1h cooldown + `LF-AUDIENCE-VOTER-RATE-LIMITED`
       severity-elevation.
   - The store is the audience analog of `TenantCostTrackerStore`
     (T-443) — small facet, sibling to `TenantSettingsStore`. 5 methods:
     `recordHit(source) / getCounter(source) / flag(source, level) /
     getFlag(source) / cleanup(beforeTimestamp)`. Time-window arithmetic
     uses an injected `now: () => number` (T-453 pattern) so tests are
     deterministic.
2. **Per-clip-kind voter-rate overrides** per ADR-009 §D3 line 231:
   - Default `1 vote / 500ms` per voter (2 Hz) — already T-453's
     hardcoded per-voter limit.
   - Override for `reaction-stream`: `10 reactions / second` per voter
     (10 Hz) — matches ADR-009's explicit override.
   - The override map lives on `VoterRateLimiter`:
     `voterRateLimiter.setClipKindOverride('reaction-stream', 10)`.
   - The audience-WS handler picks the limiter rate per-message based on
     the message's `clipKind` (read from the active session's stored
     `clipKind`).
3. **Escalating back-off wired into `audience-rate-limit.ts`**:
   - `TenantRateLimiter.tryConsume` + `VoterRateLimiter.tryConsume` +
     the join's per-IP limiter all consult `AbuseTrackingStore` BEFORE
     the bucket check. If the source is flagged + still in cooldown,
     refuse immediately with `accepted: false, rejectReason: 'abuse-cooldown'`.
   - On rate-limit refusal (bucket exhausted, not abuse-flagged yet),
     call `abuseStore.recordHit(source)`; if hits-in-window crosses the
     threshold (default 10 hits in 60s), call `abuseStore.flag(source,
     nextLevel)`.
4. **Loss-flag emission** uses existing codes per ADR-009 §D11 (the
   eight `LF-AUDIENCE-*` codes are FROZEN by T-452):
   - `LF-AUDIENCE-VOTER-RATE-LIMITED` (info) — emitted on every bucket
     refusal + on every abuse-cooldown refusal.
   - Severity escalation is a property of the emitted EVENT's
     `metadata.abuseLevel` field (0 = first hit, 1 = first flag,
     2 = second, 3 = third) — the code stays the same; the metadata
     informs presenter-side analytics.

**Strict scope** — server-side rate-limit hardening only. NO presenter
UX surfacing of abuse flags (T-459 result-export covers post-session
analytics). NO Firestore-backed `AbuseTrackingStore` (T-458 ships only
the in-memory impl + interface; production wiring follows the T-411a
pattern). NO new `LF-AUDIENCE-*` codes (the inventory is frozen). NO
captcha / proof-of-work UX (out of v1 per ADR-009 §D8 — punted to
future). NO IP-geolocation-based blocking (privacy posture — out of
v1).

## Implementation notes

- **Window**: sliding 60-second window for hit accumulation. The
  in-memory impl uses a simple `Map<source, number[]>` of timestamps;
  on each `recordHit`, prune entries older than the window head, then
  push the current timestamp. `getCounter` returns the length after
  pruning.
- **Threshold**: default 10 hits in 60s triggers escalation. The
  `flagLevel` argument to `flag()` is the level the caller wants to set
  (0 = clear, 1/2/3 = escalation steps). Caller logic in the limiter
  reads current `getFlag(source)` to determine the next level.
- **`AbuseSource` shape**: `{ kind: 'voter-token' | 'ip', value: string }`
  — discriminated union so the same store handles both axes. Voter-token
  abuse and IP abuse are tracked independently.
- **Cooldown enforcement**: `getFlag(source)` returns
  `{ level, expiresAt: number }`; if `expiresAt > now()`, the source is
  still in cooldown. Tests use the injected clock.
- **Clock injection**: `AbuseTrackingStore` accepts a `now: () => number`
  param matching T-443's pattern + T-453's `TenantRateLimiter`. Default
  `() => Date.now()` in production wiring; tests pass a controlled
  clock.
