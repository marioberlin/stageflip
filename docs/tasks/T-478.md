# T-478 — `@stageflip/audience-native`

**Branch**: `task/T-478-audience-native`

## Goal

Ship `@stageflip/audience-native` — the **first concrete
`AudienceBackendProvider` implementation**, wrapping the existing
T-453 audience backend service + T-474 Firestore-backed store. This
is the audience-modality analog of the 9 P14 reference adapters
(T-426..T-434). v1 ships **stub-mode** (no production wire-up;
matches the P14 reference-adapter convention).

Carries four concerns:

1. **`packages/audience-native/src/descriptor.ts`** — static
   `AdapterDescriptor` per ADR-009 §D2:
   - `id: 'audience-native'`.
   - `modality: { kind: 'audience-backend' }`.
   - `capability`: `AudienceCapabilityDescriptor` per T-452 (with
     `persistenceTier: 'durable'`, `maxConcurrentVoters: 1000`,
     `supportedClipKinds: AUDIENCE_CLIP_KINDS` — all 11, including
     motion-native), `supportsMotionNative: true`, `voterIdentity:
     'anonymous'`, `supportsStaticFallback: true`, `maxIngestRateHz: 100`,
     `snapshotCadenceHz: 30`.
   - `license.kind: 'mit'` (it's our own code).
   - `sandbox.kind: 'in-process'` (lives in `apps/api`).
2. **`packages/audience-native/src/provider.ts`** — concrete
   `AudienceBackendProvider`:
   - 4 methods per ADR-009 §D2 (`openSession` / `submitVote` /
     `subscribe` / `closeSession`).
   - Delegates to the existing T-453 REST endpoints +
     WebSocket multiplexer via internal calls (the `apps/api` server is
     the implementation; this provider is the typed CLIENT facade).
   - For tests + non-deployed contexts: a stub mode that delegates to
     the `InMemoryAudienceResultsStore` directly.
3. **Registration**: re-export from `packages/runtimes/audience` so
   the runtime can `findProvider('audience-native')` via the standard
   adapter registry (per ADR-007's pattern).
4. **`packages/audience-native/security.json`** sidecar manifest
   per T-446 (data-flow security CI gate): declares the perimeter
   (`in-process` — no remote network in stub mode), no PII fields,
   T-446 SecurityManifest shape.

**Strict scope** — stub-mode descriptor + provider + security manifest.
NO production wire-up to a deployed `apps/api` (that's downstream
wiring at the host). NO vendor-adapter implementations (T-479..T-483).
NO new schema. NO new audience clip kinds.

## Implementation notes

- **Descriptor** mirrors the P14 reference-adapter descriptor pattern
  (see `packages/tts-kokoro/src/descriptor.ts`):
  ```ts
  export const descriptor: AdapterDescriptor = {
    id: 'audience-native',
    name: 'StageFlip Audience (Native)',
    modality: { kind: 'audience-backend' },
    capability: { /* AudienceCapabilityDescriptor */ },
    license: { kind: 'mit' },
    sandbox: { kind: 'in-process' },
    cost: { type: 'free' },
    latency: { p50Ms: 50, p95Ms: 200 },
  };
  ```
- **Provider** holds a reference to the store (passed via constructor):
  ```ts
  export interface AudienceNativeProviderConfig {
    store: AudienceResultsStore;
    voterTokenPepper: string;
    now?: () => number;
  }
  export function createAudienceNativeProvider(config: AudienceNativeProviderConfig): AudienceBackendProvider {
    return {
      descriptor,
      async openSession(opts) { /* delegate to store */ },
      async submitVote(opts) { /* validate + appendEvent + ack */ },
      subscribe(opts) { /* AsyncIterable from store.readSnapshot polled at snapshotCadenceHz */ },
      async closeSession(opts) { /* store.closeSession + final snapshot */ },
    };
  }
  ```
- **Stub vs production**: the provider doesn't know about `apps/api`
  routes — it just uses the store directly. The `apps/api` REST/WS
  endpoints are an ALTERNATIVE access pattern (presenter UI hits them
  via HTTP); the provider is the agent-tool-tier access (programmatic).
- **Security manifest** per T-446's `SecurityManifest` schema:
  - `dataPerimeter: 'in-process'`.
  - `piiClassification: 'no-pii'` (voter tokens are hashed; no PII).
  - `networkEgress: []` (none in stub mode).
