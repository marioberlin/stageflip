# T-408 — Export matrix routing layer

**Branch**: `task/T-408-export-router`

## Goal

Ship `packages/export-router` — a pure-function routing layer that consumes the
existing `EXPORT_MATRIX` (per ADR-003 §D3, defined at
`packages/schema/src/clips/export-targets.ts`) and produces a typed
**routing decision** describing which per-format exporter package to invoke
and which render mode (`'static' | 'live'`) it must run in for a given
`(ExportTarget, Document)` pair.

The router is the **dispatcher** that sits in front of the seven existing
exporter packages (`@stageflip/export-pptx`, `@stageflip/export-video`,
`@stageflip/export-html5-zip`, `@stageflip/export-pdf`,
`@stageflip/export-loss-flags`, `@stageflip/export-google-slides`,
`@stageflip/export-marp`). It does NOT itself invoke the exporters — that
remains the caller's responsibility — so the routing layer is BROWSER-SAFE
and side-effect-free.

This unblocks the `// T-408` TODO at `packages/variant-gen/src/generate.ts:6`
(variant-gen produces per-coordinate Documents that downstream callers must
route to the correct exporter).

## §13 (structural extension) statement

**NOT a structural extension.** Adds a new package that consumes an existing
schema (`EXPORT_MATRIX` + `Document` + `InteractiveClip` from
`@stageflip/schema`). No new `clipKind` / `Element` variant / compositing
mode / runtime kind / new field on `ClipKindBinding`/`RIRElement`/`RIRDocument`.
Render verification N/A — the routing layer is a pure function over typed
inputs, fully covered by unit tests.

## Architectural seals

- **Pure function**. `routeExport(target, document)` has no I/O, no async
  surface, no side effects. The chosen exporter is responsible for the actual
  export.
- **No matrix duplication**. The router imports `EXPORT_MATRIX` from
  `@stageflip/schema`. The mapping `ExportTarget → exporterPackage` is the
  ONLY new lookup table the router defines — and that mapping is per-target
  (not per-mode), so it does not duplicate the static/live discriminator.
- **Determinism**. Routing decision is pure function of `(target, document)`.
  No `Date.now()`, no `Math.random()`. (Determinism gate doesn't cover
  `export-*` packages, but discipline still applies — code-review check.)
- **Static-only fallback for static-mode targets**. When `EXPORT_MATRIX[target]`
  is `'static'` AND the document contains live clips, the routing decision is
  `{ kind: 'fallback', mode: 'static', exporterPackage, reason:
  'target_is_static_only', liveClipsOmitted: [...] }` — naming each live
  clip's id + family so the caller can surface a loss flag. The exporter
  receives the same Document and is expected to render the `staticFallback`
  array of every interactive clip (existing exporter behavior — no exporter
  signature change).
- **Live-mode targets carry both clip kinds**. When
  `EXPORT_MATRIX[target]` is `'live'`, the routing decision is
  `{ kind: 'route', mode: 'live', exporterPackage, reason: 'target_is_live_capable' }`
  regardless of whether the document contains live clips. Documents without
  live clips render identically across modes.
- **Browser-safe**. No `fs` / `path` / `child_process` / Node-only imports.
  Router is consumed by browser-side variant pipelines (per
  `feedback_t304_lessons.md`).
- **Test coverage** ≥ 85% on the new `router.ts` module.

## API shape (decided up-front)

```typescript
import type { Document, ExportTarget, InteractiveClipFamily } from '@stageflip/schema';

export type ExporterPackage =
  | '@stageflip/export-video'        // mp4, image-sequence
  | '@stageflip/export-pptx'         // pptx-flat
  | '@stageflip/export-html5-zip'    // html-slides, display-interactive
  | '@stageflip/export-google-slides' // live-presentation
  | '@stageflip/export-pdf'          // (reserved — currently a stub; not in matrix today)
  | '@stageflip/export-marp'         // (reserved — currently a stub; not in matrix today)
  | '@stageflip/export-loss-flags';  // display-pre-rendered (loss-flag-emitting raster)

export interface OmittedLiveClip {
  readonly id: string;
  readonly family: InteractiveClipFamily;
}

export type RoutingDecision =
  | {
      readonly kind: 'route';
      readonly target: ExportTarget;
      readonly mode: 'live';
      readonly exporterPackage: ExporterPackage;
      readonly reason: 'target_is_live_capable';
    }
  | {
      readonly kind: 'route';
      readonly target: ExportTarget;
      readonly mode: 'static';
      readonly exporterPackage: ExporterPackage;
      readonly reason: 'no_live_clips' | 'target_is_static_only_no_live_clips';
    }
  | {
      readonly kind: 'fallback';
      readonly target: ExportTarget;
      readonly mode: 'static';
      readonly exporterPackage: ExporterPackage;
      readonly reason: 'target_is_static_only';
      readonly liveClipsOmitted: ReadonlyArray<OmittedLiveClip>;
    };

export function routeExport(target: ExportTarget, document: Document): RoutingDecision;

/** Pure helper: walks Document content + groups looking for `interactive-clip` elements. */
export function detectLiveClips(document: Document): ReadonlyArray<OmittedLiveClip>;
```

The router emits exactly one of three `kind`s:

- `'route'` with `mode: 'live'` — target supports live clips; exporter mounts
  liveMount components.
- `'route'` with `mode: 'static'` — target is static OR no live clips present;
  exporter renders staticFallback (or unchanged document if no live clips).
- `'fallback'` with `mode: 'static'` and a non-empty `liveClipsOmitted` — the
  CALLER's signal that this export drops live behavior. Useful for surfacing a
  pre-export warning ("3 interactive clips will be rendered as static
  posters").

## Per-target exporter mapping

| ExportTarget            | EXPORT_MATRIX | Exporter package                  |
|-------------------------|---------------|-----------------------------------|
| `mp4`                   | `static`      | `@stageflip/export-video`         |
| `image-sequence`        | `static`      | `@stageflip/export-video`         |
| `pptx-flat`             | `static`      | `@stageflip/export-pptx`          |
| `html-slides`           | `live`        | `@stageflip/export-html5-zip`     |
| `live-presentation`     | `live`        | `@stageflip/export-google-slides` |
| `display-pre-rendered`  | `static`      | `@stageflip/export-html5-zip`     |
| `display-interactive`   | `live`        | `@stageflip/export-html5-zip`     |
| `on-device-player`      | `live`        | `@stageflip/export-html5-zip`     |

Notes on the mapping:

- `display-pre-rendered` routes to `@stageflip/export-html5-zip` (the existing
  HTML5 banner exporter handles the IAB/GDN raster fallback path internally
  via its `FallbackProvider`).
- `display-interactive` and `on-device-player` route to
  `@stageflip/export-html5-zip` because that package already orchestrates
  bundling for in-browser interactive bundles. The exact runtime host
  (`renderer-cdp` interactive lane vs. on-device player) is the exporter's
  internal concern, not the router's.
- `live-presentation` routes to `@stageflip/export-google-slides` (the
  existing Google Slides exporter that produces live in-browser slide decks).
- `@stageflip/export-pdf`, `@stageflip/export-marp`, and
  `@stageflip/export-loss-flags` are currently stub packages with no exporter
  function. Their inclusion in `ExporterPackage` is reserved — adding a PDF or
  Marp `ExportTarget` to the matrix later will wire them in via this router
  with no signature change.

## Live-clip detection algorithm

1. Switch on `document.content.mode`:
   - `'slide'`: for each slide, walk `slide.elements`.
   - `'video'`: for each track, walk `track.elements`.
   - `'display'`: walk `content.elements`.
2. For each `Element`, check `element.type`:
   - `'interactive-clip'` → record `{ id, family }`.
   - `'group'` → recurse into `group.children`.
3. Other element types are ignored. Bridge clips (`bridge-clip`,
   `blender-clip`) are NOT live — they render via frame-runtime regardless of
   target.

Implementation walks the document in a single pass, deterministic order
(content order; slide order then in-element order). No allocation when no
live clips present.
