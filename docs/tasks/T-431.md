# T-431 — `@stageflip/video-runway` (Runway Gen-4 video adapter; production-tier 10s 4K silent video; proprietary-byo; stub-mode v1)

**Branch**: `task/T-431-video-runway`

## Goal

Ship the **sixth reference adapter** in the Phase 14 β sequence
(T-426..T-434) and the **second `video-gen` modality adapter**:
`@stageflip/video-runway`. Wraps the Runway Gen-4 commercial
production-tier text-to-video model accessed via the Runway HTTPS API
(up to 10s output at 1080p / 4K; **no native audio** — silent video
only; broad aspect-ratio support; batch latency ~1–3 min per video;
tenant-supplied API credentials) behind the `VideoGenerationProvider`
interface from T-419, declares an `AdapterDescriptor` per T-418, and
exercises the **`proprietary-byo`** license posture for the
**fourth** time (T-428 → Tripo3D; T-429 → Meshy; T-430 → Seedance).

T-431 is the structural sibling of T-430 (same proprietary-byo +
remote-service + `video-gen` posture) with **functional, not
structural** deltas:

| Field | Seedance (T-430) | Runway Gen-4 (T-431) |
|---|---|---|
| Modality | `video-gen` | `video-gen` |
| `id` | `seedance` | **`runway`** |
| Stub payload | minimal valid MP4 (1920×1080 / 30fps / 15s) | **minimal valid MP4 (3840×2160 / 24fps / 10s)** — declarative; byte-distinct |
| Distinguishing capability | 15s @ 1080p + **native audio + lip-sync** | **10s @ up to 4K, broad aspect-ratio set, NO native audio, NO lip-sync, cinematic 24fps default** |
| `frameRates` | `[30]` | **`[24]`** (film-style) |
| `aspectRatios` | `['16:9', '9:16', '1:1']` | **`['16:9', '9:16', '1:1', '4:3', '3:4']`** (broader set) |
| `maxDurationS` | `15` | **`10`** (Runway Gen-4 conservative cap; longer durations gated on tier) |
| `supportsNativeAudio` | `true` | **`false`** (THE differentiator — Runway is silent; audio paired separately) |
| `supportsLipSync` | `true` | **`false`** (no audio path) |
| `supportedResolutions` | `['1080p']` | **`['1080p', '4k']`** (Runway Gen-4 supports 4K) |
| `emitsAudio` | `true` | **`false`** (silent stub; production stays silent) |
| `qualityHint` (catalog-summary only) | n/a | **`'highest'`** (production-tier) |
| `sandbox.baseUrlEnvVar` | `FAL_API_BASE_URL` | **`RUNWAY_API_BASE_URL`** |
| `costPerCall.usd` | `1.5` | **`2.0`** (per-video; enterprise tier; production-grade pricing per Runway commercial rates) |
| `latencyMs.{p50,p95}` | `90_000 / 180_000` | **`90_000 / 180_000`** (~1–3 min typical; batch tier; same as Seedance) |
| `model` cache-key field | `seedance:2.0` | **`runway:gen-4`** |

T-431 ships in **stub mode**: the `generate()` body emits a
deterministic placeholder MP4 byte payload (a minimal valid MP4
declaring 3840×2160 @ 24fps / 10s; byte-distinct from the Seedance
stub) and returns a shaped `VideoGenResult`. Production wire-up
(real Runway HTTPS API call + MP4 download) is gated on a follow-up
task (T-431a) — same v1-stub-mode-with-production-deferral pattern
as T-426 / T-427 / T-428 / T-429 / T-430.

T-431 is M-sized: one new package, ~350–500 LOC across 3 src
modules (descriptor / provider / stub-video) + matched tests,
~250–400 lines of spec, no schema / parity / clip / preset / ADR
changes.

## Stub MP4 fixture rationale

T-431 inherits the **Option A** decision documented in T-430's
spec at `docs/tasks/T-430.md` §"Stub MP4 fixture rationale": ship
a hard-coded base64-encoded minimal valid MP4 fixture (~200–600
bytes) and decode it inside `generateStubMp4DataUri` on each call.
The trade-offs (50 LOC vs 500 LOC; no box-format writer surface to
maintain; opaque fixture mitigated by an `ftyp` magic-bytes test
at offset 4) apply verbatim.

**Byte-distinctness from the Seedance stub** is the only T-431
material delta. The Runway fixture declares **3840×2160 width ×
height** in the tkhd (vs Seedance's 1920×1080), **24 timescale**
in the mdhd (vs Seedance's 30), and **240 sample duration**
(vs Seedance's 450). The resulting fixture is a different byte
sequence and the base64 string literal is different — a `data:`
URI consumer comparing the two stubs at the byte level can tell
them apart. This is a visible-in-catalog differentiator the agent
UI surfaces alongside the `supportsNativeAudio: false` /
`supportedResolutions: ['1080p', '4k']` capability flags.

The fixture used is a 188-byte minimum-viable MP4 with an `ftyp`
brand of `isom` (ISO base media) and a tiny `moov` declaring a
3840×2160 single-frame track at 24fps with an empty `mdat`.
Decoders recognize the container; there's no codec-recognized
frame data. Production wire-up (T-431a) replaces the entire body
and the surrounding `url: string` shape stays identical.

## BYO credentials posture

Runway is the **fourth adapter to declare the `proprietary-byo`
license posture** (Tripo3D was the first via T-428; Meshy was the
second via T-429; Seedance was the third via T-430) and the
**second `video-gen` modality** to do so. Per ADR-008 §D13 (line
654), the `video-gen` modality whitelist admits `apache-2.0`,
`mit`, `proprietary-byo`, and `proprietary-vendored`.
`proprietary-byo` means:

- The adapter wraps a commercial vendor model (Runway Gen-4 via
  Runway's HTTPS API); Runway's licensing terms govern model use.
- The tenant brings their own API credentials (a Runway API key
  and potentially a base URL override). The descriptor declares
  the credentials anchor via `sandbox.{kind: 'remote-service',
  baseUrlEnvVar: 'RUNWAY_API_BASE_URL'}` — that env var is the
  production wire-up's secrets entry point.
- StageFlip ships **no vendored model checkpoint**.
- The `pnpm check-asset-licenses` gate accepts the descriptor
  because `proprietary-byo` is in the `video-gen` whitelist;
  tenant credential validation is a runtime concern at the
  orchestrator boundary.

T-431 ships only the descriptor declaration of this posture. The
production wire-up (T-431a) reads the env var, builds an HTTPS
client, polls Runway's async job endpoint, downloads the produced
MP4, and surfaces the `LF-ADAPTER-CREDENTIAL-MISSING` failure
class (per ADR-008 §D11) when credentials are absent. The stub
mode never reads the env var.

## Stub-mode vs production-mode contract

The `RunwayProviderMode` discriminator gates the `generate()`
body behavior **only**. Every other surface (descriptor,
capability, validation, error throwing, cache-key derivation) is
identical between modes. The production wire-up (T-431a) MUST:

1. Keep `runwayDescriptor` byte-identical (no new capability
   fields in v1; capability expansion lands in a follow-up at
   earliest).
2. Replace the `generate()` `mode === 'production'` branch with a
   real Runway API call (HTTPS POST to the job-submit endpoint at
   `process.env[RUNWAY_BASE_URL_ENV_VAR]`, polling the
   job-status endpoint, downloading the produced MP4).
3. Keep the input validation paths (empty prompt → throw)
   byte-identical.
4. Keep the cache-key derivation byte-identical (so cached results
   from the stub-mode era + production-mode era share the same
   keyspace — production-mode results MUST hash identically to
   stub-mode results when the same `(prompt, aspectRatio,
   frameRate, durationS, outputFormat, seed)` is used; the
   canonical params dict declared here is the contract).
5. NOT widen the `VideoGenResult` shape (no new fields).
6. Honor the `capability.maxDurationS` budget — refuse calls whose
   `durationS` exceeds 10s (per ADR-008 §D6).
7. Honor the `capability.aspectRatios` allow-list — refuse calls
   whose `aspectRatio` is not in the allow-list.
8. Honor the `capability.frameRates` allow-list — refuse calls
   whose `frameRate` is not 24.

Anything in the production wire-up that conflicts with this
contract is a spec change — file an ADR.

   `docs/tasks/T-431.md`. Commit.
2. Scaffold package: `package.json`, `tsconfig.json`, empty
   `src/index.ts`. Commit.
3. Test-first: write `descriptor.test.ts`, `stub-video.test.ts`,
   `provider.test.ts` with cases from AC #7. Tests fail (no
   implementation). Commit.
4. Implement `stub-video.ts` → `descriptor.ts` → `provider.ts`.
   Wire barrel in `src/index.ts`. Commit `feat(video-runway):
   T-431 — Runway Gen-4 video adapter (production-tier;
   proprietary-byo; stub mode v1)`.
5. `pnpm install` (workspace picks up the new package) → `pnpm
   --filter @stageflip/video-runway build && pnpm --filter
   @stageflip/video-runway test`.
6. Wire `runwayDescriptor` into `scripts/sync-skills.ts
   buildAssetProvidersPkg()` alongside the existing five reference
   adapters. Commit.
7. Run **all** local gates BEFORE pushing — see "Local gates"
   below. Commit any incidental skills-sync regens as a single
   dedicated commit (pre-empts the skills-sync drift lesson).
8. Add lowercase changeset.
9. Push → open PR.
