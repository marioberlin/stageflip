# T-410 — GA readiness checklist pass (Phase δ Lock-in)

**Branch**: `task/T-410-ga-readiness`

## Goal

Ship a programmatic GA-readiness audit (`pnpm check-ga-readiness`) that walks
the system, verifies a defined checklist of criteria spanning cluster
ratification, CI gates, documentation, frontier runtime, enterprise
admin, and Phase 13 closeout, and emits a markdown report enumerating
PASS / FAIL / WARN / N/A for every criterion.

The output is a **gap list** the orchestrator uses as the GA punch list.
T-410 is **NOT a CI gate** (architectural seal — it would block PRs on
out-of-band concerns like PO ratification, T-411 enterprise admin
delivery, and T-412 documentation pass).

The inaugural report (committed as `docs/ga-readiness-report.md`) is
expected to show multiple FAILs given outstanding Phase 13 work
(Cluster C + H awaiting PO ratification, Track A finale T-397+ not
merged, T-411 / T-412 not done). That is the point — T-410's value is
the checklist definition + the audit script + the inaugural report
showing current state.

## Architectural seals

- **Pure script.** `scripts/check-ga-readiness.ts` is a Node CLI; output
  = stdout markdown report + exit code (0 = all PASS / WARN / N/A;
  non-zero = at least one FAIL). WARN does NOT affect exit code (a
  qualified pass is still a pass). The script also writes the rendered
  markdown to `docs/ga-readiness-report.md` so the on-disk report stays
  in sync with the latest run.
- **Markdown report.** Includes a generated-at ISO8601 timestamp, a
  summary table at the top (counts of PASS / FAIL / WARN / N/A per
  category), a per-criterion table with status + note, and a "Top
  punch-list items" section enumerating FAIL criteria for orchestrator
  consumption.
- **NOT a CI gate.** T-410 deliberately does NOT add a step to
  `.github/workflows/ci.yml`. PR template + handover docs reference
  the report; orchestrator runs `pnpm check-ga-readiness` manually
  during phase boundaries.
- **No new package.** Just a script + the report file. Mirrors T-409's
  posture — touches no `packages/` files, so the changeset CI gate
  auto-passes.
- **Determinism.** Report content is deterministic for a given main
  HEAD — except the generated-at timestamp + the script's check-execution
  timing. The timestamp is intentional (it's a report, not a gate);
  documented as the only non-deterministic surface.
- **Stays in-process.** The script does NOT spawn child processes for
  CI gates (no `pnpm typecheck` / `pnpm test` shell-out). Spawning would
  be expensive and unreliable in repeated runs. Instead, category 2
  (CI gates) is verified by checking that each `package.json` script
  entry exists + each `scripts/check-*.ts` file is on disk + each
  workflow step is in `.github/workflows/ci.yml`. The audit verifies
  GATE PRESENCE / WIRING; the CI itself verifies GATE BEHAVIOR every
  push.

## CLI ergonomics

```
$ pnpm check-ga-readiness
check-ga-readiness: scanning repo at <root>...
check-ga-readiness: 7 categories, 23 criteria
check-ga-readiness [Cat 1: Cluster ratification]: 3 PASS / 2 FAIL / 0 WARN / 0 N/A
check-ga-readiness [Cat 2: CI gates]: 3 PASS / 0 FAIL / 1 WARN / 0 N/A
... (per category) ...
check-ga-readiness: report written to docs/ga-readiness-report.md
check-ga-readiness: FAIL (5 criteria — see report for the punch list)
```

On PASS, exit code 0 + summary tail. On FAIL, exit code 1 + the
top-N FAIL items echoed to stderr.

Flags:
- `--repo-root=<path>` — override default (auto-discovered as the dir containing `package.json` with `"name": "stageflip"`).
- `--report-out=<path>` — override default `docs/ga-readiness-report.md`.
- `--no-write` — skip writing the report (for unit tests / CI dry-runs).
- `--help` / `-h`.

## Acceptance criteria

1. **Script exists.** `scripts/check-ga-readiness.ts` with a file
   header, TSDoc on every public function, no `any`, no `console.log`
   outside the CLI entry block.
2. **CLI exit code.** `pnpm check-ga-readiness` runs to completion.
   Exit code reflects FAIL count — 0 if zero FAIL criteria; 1 if any
   FAIL. WARN does NOT affect exit code.
3. **Report written.** `docs/ga-readiness-report.md` is updated each
   run with summary table + per-criterion table + punch-list section.
4. **Inaugural report committed.** The committed
   `docs/ga-readiness-report.md` reflects the state at T-410 PR-creation
   time (expected: multiple FAILs in categories 5, 6 and possibly 1).
5. **Unit tests** in `scripts/check-ga-readiness.test.ts` covering
   each pure-function helper (criterion definitions, status
   classification, report formatter, summary aggregator). Coverage
   ≥85% on changed files.
6. **Pure script.** No `Date.now()` in clip/runtime code (the
   determinism gate's enforcement zone). The script itself MAY use
   `new Date()` for the report timestamp — `scripts/**` is exempt
   from the determinism rule per CLAUDE.md §3.
7. **NOT in CI.** No new step in `.github/workflows/ci.yml`.
8. **Local gates green.** `pnpm typecheck && pnpm lint && pnpm test &&
   pnpm check-licenses && pnpm check-remotion-imports &&
   pnpm check-determinism && pnpm check-skill-drift &&
   pnpm gen:tool-skills:check` all pass.
