# T-421 — `MediaElement.provenance` + `Document.research?` schema additions

**Branch**: `task/T-421-media-provenance-schema`

## Goal

Add the two optional schema additions ADR-008 §D2 / §D3 specify, on the
canonical `@stageflip/schema` package:

1. **`MediaProvenance`** — per ADR-008 §D2. Strict, optional `provenance?`
   slot on every media-element shape (`audio`, `image`, `video`).
   Records how a generated asset was produced: `kind` discriminator,
   `provider`, `model`, `prompt`, `cacheKey` (matching T-420 output),
   `seed`, TTS-specific fields (`voiceProvider`, `voiceId`,
   `clonedFromConsent`), source-grounded fields (`researchSessionId`,
   `sourceIds`).
2. **`Document.research?: ResearchSessionRef`** — per ADR-008 §D3.
   Optional top-level slot binding the document to a research session;
   asset-gen calls fired against the document inherit the session id
   (per ADR-008 §D7 routing). Bundles `provider` + `sessionId` +
   `sources[]` + `createdAt`.

Both additions are **non-breaking** — existing persisted documents and
fixtures parse unchanged, no migration required (ADR-008 §D2 / §D3 +
§D14 explicitly: "SchemaVersion bump … NOT REQUIRED — both fields are
optional additions").

**Strict scope** — Zod schemas + element merges + barrel re-exports +
roundtrip tests ONLY. NO consumer migration (T-419 placeholder swap is
a separate downstream task; the placeholder remains in place). NO
`LF-RESEARCH-*` / `LF-VOICE-CONSENT-*` loss-flag wiring (separate task
per ADR-008 §D11 / `@stageflip/loss-flags`). NO render-code changes
(provenance is metadata; does not affect any rendered output). NO
`BlenderClip` / `three-d` GLB-wrapper extension (T-437 scope per
ADR-008 §D2 wiring note).

## §13 (structural extension) statement — DEFERRAL per option 3

This task IS a structural extension per CLAUDE.md §13: it adds new
optional fields to the document model (`Document.research?`) and to
three element types (`audio.provenance?`, `image.provenance?`,
`video.provenance?`). The §13 obligation applies.

Per CLAUDE.md §13 acceptable-evidence options:

- **Option 1** (real-render integration test on observable output):
  **N/A**. `provenance` is metadata; it does not affect any rendered
  pixel. No clip-code path reads it; no compositor branches on it. A
  PNG-pixel-bucket assertion would be identity-against-itself
  regardless of whether the field is present.
- **Option 2** (reference preset signed off via parity-fixture +
  PO visual inspection): **N/A**. There is no visual artifact to
  inspect — the field is metadata.
- **Option 3** (explicit deferral note acknowledging pixel-level
  verification is gated on a downstream consumer task): **THIS
  TASK USES OPTION 3.**

## Risk

- **Tension between ADR-008's `interface MediaProvenance` and Zod
  `.strict()` semantics** — ADR-008 specifies the conceptual shape as
  a TS `interface` with `readonly` modifiers. Zod parsing produces
  plain objects; `readonly` is a TS-only annotation (Zod doesn't
  enforce it at runtime). The Zod schema is `.strict()` so unknown
  fields throw; the inferred type carries no `readonly` modifier on
  inferred fields. Acceptable: callers who want immutability annotate
  the inferred type themselves (or the asset-gen-contract package
  exposes a `Readonly<MediaProvenance>` alias if needed). Documented
  in TSDoc on the schema.
- **`exactOptionalPropertyTypes`** is on per CLAUDE.md §3 — every
  optional field MUST tolerate the explicit-`undefined` and absence
  cases identically. Zod's `.optional()` covers absence; explicit-
  `undefined` is also accepted. Verified in tests.
- **Cross-package consumer drift** — T-419's placeholder is a
  verbatim copy. After T-421 merges, the placeholder drifts from the
  canonical schema if either side changes independently. The
  placeholder file already carries a `// TODO(T-421)` comment for
  swap; the placeholder swap is the recommended follow-up and SHOULD
  land soon after T-421 to eliminate the drift surface. Until the
  swap, the placeholder remains the authoritative shape for
  `@stageflip/asset-gen-contract` consumers and the Zod schema is
  authoritative for `@stageflip/schema` consumers; the two MUST be
  kept identical via PR review.
