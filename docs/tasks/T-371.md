# T-371 — Preset: `instagram-link-sticker` (socialMedia, Cluster G)

**Branch**: `task/T-371-instagram-link-sticker`

## Goal

Promote the existing `instagram-link-sticker` preset stub from `status: stub` to `status: substantive` and ship it as the **fifth and final Cluster G (CTAs / social) preset to land** AND the **first consumer of the `link-sticker` runtime-clip primitive** (T-371a; just landed at main HEAD `8f7dbd4b`) AND the **first production binding for the `socialMedia` clipKind** in the parity-CLI resolver. The preset captures the Instagram Stories link-sticker canon: a rounded-pill sticker (~200 × 44 px native) free-form-positioned on a Story frame with a continuous closed-form linear shimmer / highlight sweep across the label glyphs (3 s cycle), one of four sealed `variant` values (`'white-on-dark'` / `'dark-on-white'` / `'frosted-glass'` / `'brand-color'`; default white-on-dark per stub line 43), customizable text (default: destination domain), Inter Medium fallback typography (Instagram's proprietary system font is `platform-byo`). Common uses: any Story-style CTA where the platform-recognizable pill shape lowers cognitive friction more than a custom button could.

T-371 is the **first** preset to bind the `socialMedia` clipKind. The `'socialMedia'` clipKind is in `VALID_CLIP_KINDS` (verified: `scripts/check-preset-integrity.ts` line 73) but has no entry in the parity-CLI resolver as of main `8f7dbd4b`. T-371 must therefore wire its binding via the **`PRESET_ID_BINDINGS` override map** keyed on `'instagram-link-sticker'` — Pattern C from `docs/handover-phase13-cluster-b.md` §"Pattern C", consistent with the entire Cluster B cohort AND the four Cluster G presets already merged (T-369 youtube-subscribe-bounce + T-373 social-handle-lower-third + T-370 tiktok-follow-pulse + T-372 coinbase-dvd-qr). The `DEFAULT_CLIP_KIND_RESOLVER` is **NOT** modified — there is no clipKind-default arm for `'socialMedia'` in v1, and T-371 does NOT introduce one (the override-only pattern matches the entire Cluster G posture; clipKind-defaults are reserved for the all-presets-of-the-clipKind-share-a-binding case, which does not apply since v1 has exactly one `socialMedia`-bound preset — T-371).

T-371 is **M-sized** — same envelope as T-369 / T-370 / T-372 / T-373. ~30–45 LOC binding + snapshot constant + single mid-shimmer parity golden + sign-off in-PR. No primitive-side changes (T-371a's `link-sticker.tsx` is already on main; not modified). No schema change. Inherits the Cluster G `PRESET_ID_BINDINGS` shape end-to-end from T-372 / T-369 / T-370 / T-373.

T-371 ships **cluster-norm parity thresholds**: PSNR ≥ 42 dB / SSIM ≥ 0.98 (NOT the lowered 38 / 0.94 used by T-372 — `instagram-link-sticker` has no motion blur; the shimmer is a smooth linear-gradient sweep over a static pill with high steady-state contrast, which is the steady-state-icon range that 42 / 0.98 assumes). The preset stub explicitly pre-declares these thresholds at line 47 ("PSNR ≥ 42 dB, SSIM ≥ 0.98"); T-371 must respect them at the F-4 generator-flag invocation.

Cluster G is currently **4/5 signed** as of main `8f7dbd4b` (T-369 youtube-subscribe-bounce + T-373 social-handle-lower-third + T-370 tiktok-follow-pulse + T-372 coinbase-dvd-qr). **T-371 brings it to 5/5 — closing Cluster G to ELIGIBLE.** This is the **first cluster expansion (beyond the four originally-ratified A/B/E/F clusters) to fully close**; the cluster-composer batch step then flips every typography-carrying preset's `signOff.typeDesign` from `pending-cluster-batch` to `signed:<date>` (T-369 + T-370 + T-373 + T-371; T-372 stays `na` per the text-free short-circuit).

## Architectural decisions

### D-T371-1. Compass register match — rounded-pill `'white-on-dark'` link sticker + center-canvas-safe position + mid-shimmer at frame 60

The stub (lines 22–47) defines the canonical Instagram link-sticker register:

- **Pill geometry**: rounded-pill ~200 × 44 px native (stub line 23). T-371 inherits the primitive defaults `width = 200`, `height = 44` (`borderRadius = height / 2 = 22 px`). Does NOT pass `width` / `height`.
- **Color variant**: 4 sealed values per stub line 24; default `'white-on-dark'` per stub line 43 ("Color variant should be chosen for legibility against the underlying media; default white-on-dark"). T-371 ships **`variant: 'white-on-dark'`** (D-T371-2). Background `#000000`, text `#FFFFFF`, shadow `#000000`, shimmer-highlight `#FFFFFF` per the primitive's `VARIANT_TOKENS['white-on-dark']` table.
- **Label text**: customizable (default: destination domain) per stub line 25. T-371 ships `label: 'instagram.com/yourhandle'` (D-T371-2) — domain-canon per stub guidance; does NOT encode any real handle.
- **Typography**: Instagram proprietary (platform-byo) with Inter Medium fallback (stub lines 30–32). T-371's parity render uses Inter Medium (OFL; registered via T-307). Font-size default 14 px (lower bound of stub's 14–16 px range; line 32). T-371 inherits the primitive default `fontSize = 14`.
- **Shimmer animation**: subtle 3 s cycle, light sweep across glyphs (stub line 36). T-371 inherits the primitive default `cycleFrames = ceil(fps * 3) = 90` at fps 30 AND default `bandWidth = 40`. **D-T371-3 evaluates whether to override `cycleFrames` to land the shimmer band visibly on-pill at frame 60** (with the default cycle, frame 60 is at phase progress ≈ 0.667 → `shimmerX ≈ 120` — the band has just exited the right edge; potentially-invisible). The decision below resolves that.
- **Phase**: `'shimmering'` (primitive default; D-T371-1).
- **Position**: free-form draggable on Story frame (stub line 26). T-371 ships canvas-safe `position: { x, y }` for parity-CLI 1280 × 720 landscape (D-T371-4) — **`{ x: 540, y: 338 }`** centers the 200 × 44 pill on the canvas: `x = (1280 - 200) / 2 = 540`; `y = (720 - 44) / 2 = 338`.
- **Reference frame**: 60 (cluster-norm; D-T371-5; mid-shimmer per stub line 46).

T-371 binds these to the existing `link-sticker` primitive (T-371a). The mapping:
