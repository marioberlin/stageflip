# T-416 — ADR-008: Asset Generation contract

**Branch**: `task/T-416-adr-008-asset-generation`

## Goal

Ship the second Phase 14 α ADR — the asset-generation contract that builds on ADR-007's `AdapterDescriptor` envelope. ADR-008 defines:

1. The content-addressed cache key scheme (§D1).
2. The `MediaElement.provenance` schema (§D2) — strict, optional, with the `researchSessionId` + `sourceIds` slots the source-grounded proposal §2.3 specified plus the `clonedFromConsent` slot the voice-consent policy demands.
3. The `Document.research?: ResearchSessionRef` schema slot (§D3).
4. The voice-consent policy (§D4) — per-call, tenant-admin-declared, dedicated `TenantVoiceConsentStore` storage facet matching the `TenantSettingsStore` pattern from T-411a.
5. The five β modality contracts (§D5 / §D6) — TTS, video-gen, music-gen, SFX, 3D — each extending `AdapterDescriptor`.
6. The `ResearchSessionProvider` asset-gen wiring (§D7) — how a per-modality call against a grounded document picks up the session id.
7. The seven source-grounded provider class bodies (§D9) — `SlideDeckGenerationProvider`, `MindMapGenerationProvider`, `TableGenerationProvider`, `QuizGenerationProvider`, `FlashcardGenerationProvider`, `ReportGenerationProvider`, `InfographicGenerationProvider` — preserved scope from ADR-007 §D6.
8. The four `LF-RESEARCH-*` LossFlagCodes plus two `LF-VOICE-CONSENT-*` codes (§D11).
9. Plugin manifest per-modality extensions (§D12).
10. Per-modality license-posture preview for T-422 (§D13).

This is **the** Phase 14 hard gate, second of two. After ADR-007 (T-415, merged 2026-05-11) and ADR-008 (this PR) merge, all of T-417+ can dispatch.

**Spec / ADR only — no code, no packages, no scripts, no CI.**
