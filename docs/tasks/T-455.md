# T-455 — `check-audience-permissions` CI rule

**Branch**: `task/T-455-check-audience-permissions`

## Goal

Ship the **`check-audience-permissions`** CI gate that enforces ADR-005
§D2 / ADR-009 §D13 / ADR-010 §D6: every Live Audience clip module under
`packages/runtimes/audience/src/clips/**` declares
`permissions: ['audience-network']` in its co-located manifest. The
rule:

1. **Adds a typed `AudienceClipManifest` to
   `@stageflip/runtimes-audience`** — a small co-located manifest object
   exported alongside every clip's `ClipDefinition`:
   ```ts
   export interface AudienceClipManifest {
     readonly kind: AudienceClipKind;
     readonly permissions: readonly ['audience-network'];
     // (forward-compat slots for ADR-005 §D2 manifest convention)
   }
   ```
2. **Adds an inaugural empty `clips/` directory convention** —
   `packages/runtimes/audience/src/clips/<kind>/` is the convention
   T-461..T-471 plug into. Each clip module exports `MANIFEST`
   (typed as `AudienceClipManifest`) alongside its `ClipDefinition`.
   The empty-directory state passes the gate.
3. **Adds `scripts/check-audience-permissions.ts`** — pure script that:
   - Discovers every directory under
     `packages/runtimes/audience/src/clips/`.
   - For each, parses the directory's `manifest.ts` (or `index.ts` if
     `manifest.ts` is absent) via the TypeScript compiler API (already
     a dep on the workspace for `check-determinism` / scripts).
   - Locates the `MANIFEST` export, statically extracts its
     `permissions` array literal.
   - Fails if `MANIFEST` is absent or `permissions` is not
     `['audience-network']`.
4. **Adds `pnpm check-audience-permissions` script** to the root
   `package.json` running `tsx scripts/check-audience-permissions.ts`.
5. **Wires the gate into CI** (`.github/workflows/ci.yml`) — appends to
   the existing `typecheck · lint · test · gates` job.
6. **Adds `scripts/check-audience-permissions.test.ts`** — vitest
   suite covering: (a) empty `clips/` passes (inaugural); (b) clip with
   correct manifest passes; (c) clip missing manifest fails; (d) clip
   with manifest missing `audience-network` fails; (e) clip with extra
   permissions besides `audience-network` fails (the rule is strict-equal
   to `['audience-network']` per ADR-009 §D13 — `audience-network` is
   scoped specifically; mixing with broader permissions defeats the
   scope).

**Strict scope** — script + manifest type + tests + CI wire only. NO
concrete clip implementations (T-461..T-471). NO schema-side wiring
(T-460 ships `AudienceClip.permissions: Permission[]` at the schema
layer). NO runtime-level enforcement of the permission at mount time
(T-454's `MountContext.permissions` already carries through ADR-003's
runtime-tier `PermissionShim`; this PR is a STATIC gate, not a runtime
check).

## Implementation notes

- **Manifest discovery**: walk `packages/runtimes/audience/src/clips/`
  directly (not via TypeScript compiler — that's overkill for an S-sized
  static check). For each immediate subdirectory, read `manifest.ts`
  (preferred) or `index.ts` (fallback). Use a regex / simple AST walk
  (`@typescript-eslint/typescript-estree` or `acorn` are already
  workspace deps via other CI scripts) to find the `MANIFEST` export +
  its `permissions` array-literal. Reject if extraction is ambiguous
  (e.g., `MANIFEST` is computed from a non-literal expression — the
  static check needs literal `permissions` to be sound).
- **Why static-literal not import + introspect**: avoids running clip
  code at CI time (no module side effects, no determinism perimeter
  concerns, no transpile-on-the-fly). Mirrors `check-asset-licenses` in
  spirit (pure source scan).
- **Test fixtures**: use `node:os` `tmpdir()` + `node:fs/promises` to
  scaffold a fake `clips/` tree per test case; export a `runCheck(opts:
  { clipsDir: string }): CheckResult` function so tests inject the path.
  The CLI entry calls `runCheck({ clipsDir:
  packages/runtimes/audience/src/clips })` with workspace-relative
  resolution.
- **Strict equality on permissions**: per ADR-009 §D13 the
  `audience-network` permission is scoped to the audience-backend
  origin allowlist. Adding `network` (broader) defeats the scope; the
  gate rejects any deviation from `['audience-network']` exactly. If a
  future clip genuinely needs a second permission (e.g.,
  `microphone` for live-audio AudienceAiPrompt), the rule will need a
  per-kind exception table; punt that to a future task and document it.
- **File headers**: per CLAUDE.md §3.
- **TSDoc**: on every exported function / interface / type.
- **No `console.log` outside `scripts/**`**: the gate script lives at
  `scripts/`, so logging is fine.

  `skills/stageflip/tools/` or audience-runtime SKILL page — run
  `pnpm skills-sync` and commit any sync changes.
- **Biome format** every touched file before commit (memory).
- **NEVER `git add -A`** — stage specific paths (memory).
