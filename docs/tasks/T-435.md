# T-435 — Adapter regression test suite

**Branch**: `task/T-435-adapter-regression`

## Goal

Ship a CI gate (`pnpm check-adapter-regression`) and supporting
package (`@stageflip/adapter-regression`) that guard the 9 reference
adapters merged via T-426..T-434 against silent behavioral drift.

For each adapter:

1. A canonical sample input (per modality) is fed through the
   adapter's stub-mode `synthesize()` / `generate()` method.
2. The resulting `cacheKey` and an SHA-256 over the canonicalized
   adapter output are recorded into a per-adapter JSON snapshot
   committed at `packages/adapter-regression/snapshots/<adapter-id>.json`.
3. CI replays each snapshot and asserts byte-equality against the
   live adapter output. Any drift (descriptor reshape, capability
   change, stub-output change, cache-key-derivation change) breaks
   the gate.

Mirrors the existing `scripts/check-preset-integrity.ts` "fixture
sign-off" pattern from the parity-fixture flow: a committed snapshot
is the source of truth; the gate verifies live output matches.

## Architectural seals

### Package

`packages/adapter-regression/` — new private workspace package.
Mirrors the shape of `@stageflip/export-router` (T-408): a small
verification-focused package with a CLI runner + reusable pure-function
primitives + a vitest test suite.

### Per-adapter snapshot shape

Committed JSON at `packages/adapter-regression/snapshots/<adapter-id>.json`.
The file is byte-equal across replays:

```json
{
  "id": "<adapter-id>",
  "modality": "<modality.kind>",
  "descriptorSha256": "<64-hex sha256 of canonicalized descriptor>",
  "sampleInputs": [
    {
      "name": "minimal",
      "input": { ... },
      "outputSha256": "<64-hex sha256 of canonicalized synthesize/generate result>",
      "cacheKey": "<the cache key the adapter emitted>"
    }
  ]
}
```

Canonicalization re-uses `canonicalize()` from `@stageflip/asset-cache`
(recursive key-sort + stable JSON) so descriptor hash + output hash
are stable independent of object-key insertion order.

### Per-modality canonical input fixtures

Defined in `packages/adapter-regression/src/canonical-input.ts`.
One fixture per modality (5 modalities, one input each — 9 adapters
re-use the same per-modality fixture). The fixtures are deliberately
minimal — the goal is to exercise the stub-mode body's
output-shaping, NOT to fuzz the validation surface (which is the
adapter's own test suite's job).

| Modality | Canonical input |
|---|---|
| `tts` | `{ tenantId: 't-regression', voiceId: <adapter-specific default>, text: 'Hello world.', outputFormat: 'wav', sampleRate: <adapter-specific>, seed: 1 }` |
| `video-gen` | `{ prompt: 'A cat on a mat.', aspectRatio: '16:9', frameRate: 24, durationS: 5, outputFormat: 'mp4', seed: 1 }` |
| `music-gen` | `{ prompt: 'Ambient pad.', durationS: 30, outputFormat: 'wav', seed: 1 }` |
| `sfx` | `{ prompt: 'A door creak.', durationS: 2, outputFormat: 'wav', sampleRate: <adapter-specific>, seed: 1 }` |
| `three-d` | `{ prompt: 'A simple character.', rig: false, seed: 1 }` |

Per-adapter overrides (e.g. `voiceId`, `sampleRate`) live in a small
table in `canonical-input.ts` keyed by adapter id, because the strict
validation in each adapter rejects calls that don't match its
declared capability.

### CLI runner

`scripts/check-adapter-regression.ts` — pure Node CLI. Dynamic-imports
each of the 9 adapter packages (using the same convention as
`scripts/check-asset-licenses.ts`: walk `packages/*/package.json` for
the adapter naming convention). For each:

1. Reads the committed snapshot from
   `packages/adapter-regression/snapshots/<id>.json`. If missing,
   FAIL with `MISSING-SNAPSHOT`.
2. Recomputes `descriptorSha256` from the live descriptor;
   compares against the snapshot.
3. For each `sampleInputs[].input`, instantiates the adapter's
   provider class in stub mode, calls `synthesize()` / `generate()`,
   canonicalizes the result, SHA-256s it, compares against
   `outputSha256` + `cacheKey`.
4. Exit 0 = all match; non-zero = at least one mismatch (the gate
   names the adapter + sample + which field drifted).

### Regenerator

`scripts/regenerate-adapter-regression-snapshots.ts` — writes the
9 snapshot files based on live adapter output. Idempotent: re-running
it produces byte-identical files. Invoked once at task creation, then
each time an adapter intentionally changes its descriptor / capability
/ stub output / cache-key derivation. The PR template for any adapter
change must include either (a) "no regen needed" or (b) the regenerated
snapshot diff.

### Determinism

Per CLAUDE.md §3, the determinism gate scopes to clip/runtime code
(`packages/frame-runtime/**`, `packages/runtimes/**/src/clips/**`,
`packages/renderer-core/src/clips/**`). `scripts/` and
`packages/adapter-regression/` are explicitly out of scope — same
posture as `check-asset-licenses` and `check-export-parity`. Even so,
the runner is pure (no `Date.now()`, no `Math.random()`, no
`fetch()`); SHA-256 via Web Crypto SubtleCrypto.

### Inaugural state

T-435 commits both:

1. The script + package + tests, AND
2. The 9 snapshot files generated by the regen script.

The inaugural local-gate run produces a PASS because the snapshots
are written from the same live adapter output the gate then verifies.

## Acceptance criteria

1. **Package exists.** `packages/adapter-regression/` has a working
   `package.json` (`@stageflip/adapter-regression`), `tsconfig.json`,
   `src/index.ts` barrel, and passes
   `pnpm --filter @stageflip/adapter-regression typecheck lint test`.

2. **Per-modality canonical-input fixtures.** `canonical-input.ts`
   exports a pure `canonicalInputFor(adapterId, modalityKind)`
   helper that returns the canonical input for that adapter. Tested
   over all 9 adapter ids.

3. **Snapshot format helpers.** `snapshot-format.ts` exports
   `descriptorSha256(descriptor)`, `outputSha256(result)`, and a Zod
   schema for the snapshot JSON shape. Both hashes use the
   `canonicalize()` + SHA-256 pipeline from `@stageflip/asset-cache`'s
   cache-key.ts.

4. **Pure runner.** `snapshot-runner.ts` exports
   `runAdapterAgainstSnapshot(adapter, snapshot, sampleInputResolver)`
   returning a verdict `{ ok: true } | { ok: false, drift: [...] }`.
   No I/O. Tested with synthetic adapter doubles.

5. **9 snapshot files committed.** One JSON file per adapter in
   `packages/adapter-regression/snapshots/`. Each has the shape from
   "Per-adapter snapshot shape" above; `sampleInputs.length >= 1`.

6. **CI gate CLI runs.** `pnpm check-adapter-regression` exits 0
   against the in-tree snapshots. With a hand-mutated snapshot it
   exits non-zero with a human-legible drift report naming the
   adapter + sample + field.

7. **Regen CLI runs.** `pnpm regenerate-adapter-snapshots` re-writes
   all 9 snapshot files. Re-running produces byte-identical output.

8. **CI step wired.** `.github/workflows/ci.yml` runs the new gate
   under the existing `typecheck · lint · test · gates` job as
   `Gate - check-adapter-regression`, ordered after
   `Gate - check-asset-licenses`.

9. **Inaugural state PASS.** All local gates pass on this PR:
   - `pnpm typecheck` / `pnpm lint` / `pnpm test`.
   - `pnpm check-licenses` / `pnpm check-asset-licenses`.
   - `pnpm check-remotion-imports` / `pnpm check-determinism`.
   - `pnpm check-skill-drift` / `pnpm gen:tool-skills:check`.
   - `pnpm check-adapter-regression` (new — green on inaugural).
