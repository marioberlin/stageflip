# T-446 — Per-provider data-flow security audit

**Branch**: `task/T-446-data-flow-security`

## Goal

Document and codify "what leaves the StageFlip perimeter; PII handling"
for each of the 9 reference adapters (T-426..T-434). Produces:

1. A **machine-readable security manifest** (`security.json`) per
   adapter — strict-typed declaration of perimeter, data-leaving-the-
   perimeter flags, PII posture, network endpoint, data retention,
   and audit-signal coverage.
2. A **`SecurityManifest` Zod schema** in `@stageflip/adapters-core`
   that enforces the manifest shape and is consistent with each
   adapter's `AdapterDescriptor.sandbox.kind`.
3. A **CI gate** (`pnpm check-data-flow-security`) that asserts every
   adapter ships a complete + descriptor-consistent manifest.
4. A **human-readable audit report**
   (`docs/security/data-flow-audit-2026-05-11.md`) — per-adapter
   findings with the inaugural 2026-05-11 review date.

T-446 is the **second** Phase 14 δ task (Lock-in phase). It is gated by
T-444 (sandbox + audit emitter — supplies the `AdapterAuditEvent` shape
the manifest's `auditSignal` references) and T-445 (usage telemetry —
supplies the `AdapterUsageEvent` fields the manifest references). T-446
itself is one of T-447's GA-readiness gate criteria ("data-flow
audited and codified for all 9 reference adapters").

  - `fish-speech` (tts) — `sidecar` (python)

  with `networkEndpoint` populated.

## Architecture overview

### SecurityManifest schema

```ts
// packages/adapters-core/src/security-manifest.ts
export interface SecurityManifest {
  readonly adapterId: string;
  readonly perimeter: 'in-process' | 'sidecar-local' | 'remote-network';
  readonly dataLeavingPerimeter: {
    readonly prompt: boolean;
    readonly inputBytes: boolean;
    readonly tenantId: boolean;
    readonly cacheKey: boolean;
  };
  readonly pii: {
    readonly voiceClone: boolean;
    readonly userContent: boolean;
  };
  readonly networkEndpoint?: {
    readonly hostname: string;
    readonly protocol: 'https';
    readonly authMethod: 'bearer-token' | 'api-key-header';
  };
  readonly dataRetention: {
    readonly providerRetainsInput: boolean;
    readonly providerRetainsOutput: boolean;
    readonly retentionDurationDays?: number;
    readonly retentionPolicy:
      | 'tenant-controlled'
      | 'provider-default'
      | 'unknown';
  };
  readonly auditSignal: {
    readonly relevantAuditEvents: ReadonlyArray<
      'start' | 'complete' | 'failed' | 'killed-for-resource-limit'
    >;
    readonly relevantUsageFields: ReadonlyArray<
      | 'tenantId'
      | 'adapterId'
      | 'modality'
      | 'latencyMs'
      | 'costAmount'
      | 'outcome'
      | 'timestamp'
    >;
  };
  readonly lastReviewedAt: string; // ISO date (YYYY-MM-DD)
}
```

Strict Zod schema: unknown keys rejected at every level;
`adapterId` kebab-case; `networkEndpoint` PRESENT iff
`perimeter === 'remote-network'`; `lastReviewedAt` matches
`^\d{4}-\d{2}-\d{2}$`.

### Manifest file convention

One file per adapter, located at
`packages/<adapter-pkg>/security.json`. Discovered by the CI gate
via the same adapter-package discovery used by
`scripts/check-asset-licenses.ts` (prefix-match on
`@stageflip/{tts-,video-,music-,sfx-,3d-,...}`).

### CI gate (`scripts/check-data-flow-security.ts`)

Pure Node CLI (no I/O beyond `readFileSync` + `readdirSync`). Per
adapter:

1. Locate `packages/<adapter>/security.json`. Missing → `MISSING`.
2. Parse JSON. Invalid → `PARSE-ERROR`.
3. Validate against `securityManifestSchema`. Reject → `INVALID`.
4. Load adapter descriptor via dynamic import. Check
   manifest-vs-descriptor consistency:
   - `manifest.adapterId === descriptor.id`.
   - `descriptor.sandbox.kind === 'in-process'` →
     `manifest.perimeter === 'in-process'` AND
     `manifest.networkEndpoint` absent AND
     `dataLeavingPerimeter.{prompt,inputBytes,tenantId,cacheKey}`
     all `false`.
   - `descriptor.sandbox.kind === 'sidecar'` →
     `manifest.perimeter === 'sidecar-local'` AND
     `manifest.networkEndpoint` absent.
   - `descriptor.sandbox.kind === 'remote-service'` →
     `manifest.perimeter === 'remote-network'` AND
     `manifest.networkEndpoint` present.
5. Emit per-adapter `PASS` / `FAIL`. Exit 1 on any failure.

Inaugural state on this PR: all 9 manifests present + consistent →
exit 0.

## Failure modes the gate catches

- **MISSING** — adapter package exists but no `security.json` ships.
- **PARSE-ERROR** — file present but not valid JSON.
- **INVALID** — JSON valid but rejected by Zod (missing field, wrong
  type, unknown key).
- **INCONSISTENT** — manifest disagrees with descriptor (e.g.,
  declares `in-process` perimeter but descriptor says
  `remote-service`; or declares `remote-network` but no
  `networkEndpoint`).
- **ORPHAN** — `security.json` present but no descriptor (would
  indicate a stale manifest after adapter removal).

## Per-adapter declarations (preview; full text in audit report)

| Adapter | Perimeter | Prompt leaves | PII (voice clone) | PII (user content) | Provider retains input | Network endpoint |
|---|---|---|---|---|---|---|
| kokoro | in-process | no | no | no | no | — |
| fish-speech | sidecar-local | no | yes (voice-clone refs) | yes (reference audio) | no | — |
| acestep | in-process | no | no | no | no | — |
| yue | in-process | no | no | no | no | — |
| stable-audio-open | in-process | no | no | no | no | — |
| tripo | remote-network | yes | no | yes (image input) | unknown (provider default) | api.tripo3d.ai |
| meshy | remote-network | yes | no | yes (image input) | unknown (provider default) | api.meshy.ai |
| seedance | remote-network | yes | no | yes (image-to-video reference) | unknown (provider default) | fal.run |
| runway | remote-network | yes | no | yes (image-to-video reference) | unknown (provider default) | api.runwayml.com |

Notable findings:

- Four `remote-network` adapters send the user's prompt + (where
  applicable) reference image bytes to the provider. Tenant must
  understand that prompts/images leave the perimeter when these
  adapters are selected. Per ADR-007 §D3, tenant license posture +
  per-modality license gate already filter these; T-446 adds the
  human-legible posture.
- Fish Speech's `sidecar-local` perimeter posture intentionally
  recognizes that the adapter's PII surface (voice-clone reference
  samples) is held LOCAL to the host — the Python subprocess runs
  in the same trust boundary as the host process.
- None of the four `remote-network` providers publish a
  machine-readable retention policy at the API level. The manifest
  uses `retentionPolicy: 'provider-default'` and the audit report
  cites the public ToS URLs known as of 2026-05-11. Tenants who
  need stricter handling should refuse these adapters at the
  per-tenant license policy layer.
