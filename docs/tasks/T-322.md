# T-322 — `LyricsClip` (music-synced, line-level + per-line karaoke wipe)

**Branch**: `task/T-322-lyrics-clip-primitive`

## Goal

Ship a frame-runtime-bridge clip — `lyrics` — that renders **line-level** music-video lyric panels with optional per-line **karaoke wipe** (left-to-right color front sweeping across the active line as it plays), three-line stack registers (previous dimmed at top / active highlighted in middle / upcoming preview at bottom), and an explicit "highlight-current" mono-line variant. The primitive is the missing piece that blocks T-367 (`karaoke-progressive-wipe`) — the **last** Cluster F preset (5/6 of Cluster F is signed: T-362, T-363, T-364, T-365, T-366; only T-367 remains, and per `skills/stageflip/presets/captions/karaoke-progressive-wipe.md` line 44 the rule is explicit: *"Use `LyricsClip` (T-322), not `CaptionClip` — they're distinct gap clips because the timing model is musical, not transcription-based"*).

T-322 is **distinct from T-316 CaptionClip** even though both surface karaoke-style word-level wipe. CaptionClip (T-316) is **single-line, word-level** transcription captions for spoken video (Hormozi / MrBeast / TikTok / Ali / Netflix / per-word karaoke-wipe). LyricsClip (T-322) targets **music-video lyric panels**:

- **Line-level timing first**, with per-line word-level wipe driven by `(currentTimeMs − line.startMs) / (line.endMs − line.startMs)` — the timing model is rhythmic, not transcription.
- **Multi-line stacked layout** (previous dimmed at top, current highlighted in middle, next preview at bottom — the `'three-line-stack'` register is the canonical music-video lyric card shape).
- **Three style bundles** — `'karaoke-wipe'` (left-to-right color sweep within the active line), `'three-line-stack'` (3-row stacked register), `'highlight-current'` (only active line visible, full-screen).
- **Display sans register** — large bold heading-grade type (Bebas Neue / Anton / Montserrat Bold) with optional `glow?` text-shadow halo for music-video aesthetic.
- **Reusable beyond T-367** — music-video lyric overlays, sing-along / karaoke cards, music-show graphics, lyric-video YouTube short-form (Cluster F + future Cluster A music-show / Cluster G social-music presets).

T-322 is **M-sized**: ~300–400 LOC component + ~150–200 LOC tests + barrel + ~6 LOC catalog/manifest entries + changeset. Slightly bigger than T-358a (S, ~250 LOC) due to multi-line layout dispatch (3-line stack vs single-line vs current-only), per-line karaoke clip-path math (mirroring T-316 D-T316-12), and three style bundles. Sized comparable to caption.tsx's body (~700 LOC) trimmed by the lyrics-only style scope. It does NOT touch T-367's preset markdown, parity resolver, or parity goldens — those land in the T-367-retry PR after this primitive merges.

## Architectural decisions

### D-T322-1. Distinct primitive vs. extending CaptionClip

T-322 ships a **distinct** primitive (`lyrics`), NOT an extension of `CaptionClip` (T-316). Rationale:

- **Timing granularity diverges.** CaptionClip is **word-only** (`words: { text, startMs, endMs }[]`). LyricsClip is **line-first** (`lines: { text, startMs, endMs }[]`); per-line karaoke wipe derives word-level progress from line ms-progress, not from individual word timing. Modeling lyrics as words flattens the multi-line structural register and forces the host to fabricate per-word timings from line-level beat-aligned data.
- **Layout register diverges.** CaptionClip is **single-line** at the bottom-third of the screen (typical caption posture). LyricsClip's canonical register is **three-line stacked** (previous dimmed / active highlighted / next preview) at the screen center, filling 60–80% of width. Bolting three-line layout onto CaptionClip pollutes its style-bundle dispatch and breaks its existing tests.
- **Style bundles diverge.** CaptionClip ships six caption styles (`hormozi`, `mrbeast`, `tiktok`, `ali-abdaal`, `netflix`, `karaoke-wipe`). LyricsClip ships three lyrics styles (`karaoke-wipe`, `three-line-stack`, `highlight-current`) — none overlap semantically (caption's `karaoke-wipe` is per-word in a single line; lyrics' `karaoke-wipe` is per-line wipe within a stack).
- **`skills/stageflip/presets/captions/karaoke-progressive-wipe.md` line 44** explicitly pins T-322 as the exclusive primitive: *"Use `LyricsClip` (T-322), not `CaptionClip`"*. This is a documented architectural rule, not a stylistic preference.
- Per-line karaoke wipe **reuses** caption's clip-path technique (D-T316-12 stable IDs, `clip-path: polygon(...)` driven by ms-progress) — the implementation pattern is shared, but the primitives are separate.

Reviewer demand for merging into CaptionClip → escalate per CLAUDE.md §6.

### D-T322-2. Maximum line count — 40

`lines` array bounded `1..40`. Covers a song's verse + chorus blocks comfortably:

- A typical verse is 4–8 lines; a chorus is 4–8 lines. A two-verse + two-chorus structure caps at ~32 lines.
- A full song's lyrics rarely exceed 40 lines on screen at one time without splitting into multiple lyrics-clip instances (composed in sequence). Songs with >40 lines decompose naturally per-section (verse-1 / chorus / verse-2 / bridge / outro).
- 40 covers >95% of music-video lyric-card use cases without forcing the renderer to compute scroll geometry.

Higher counts split into multiple clip instances at compose time. A future preset needing >40 is a one-line bump after layout review. Mirrors the conservative-cap pattern from T-355a (56) / T-357a / T-358a.

### D-T322-3. Three style bundles — `'karaoke-wipe'`, `'three-line-stack'`, `'highlight-current'`

Three orthogonal visual registers cover the canonical music-video posture:

- **`'karaoke-wipe'`** — within the active line, a left-to-right color front sweeps across each character as it should be sung. Past characters render in `highlightColor`; upcoming characters render in `foreground` (or `muteColor` when set). Driven by `(currentTimeMs − line.startMs) / (line.endMs − line.startMs)`. Mirrors T-316 D-T316-12 (stable clipPath IDs; `clip-path: polygon(...)`); no `crypto.randomUUID()`. This is the canonical karaoke-bouncing-ball-descendant register. Past lines (above the active) render dimmed; upcoming lines (below) render at preview opacity. Uses the three-line stack layout.
- **`'three-line-stack'`** — same multi-line layout as `'karaoke-wipe'` but **without** the per-line wipe. Active line renders fully in `highlightColor` once the line-window enters; past lines render dimmed at top; next preview line renders at upcoming opacity at bottom. Suitable for ballad / acoustic posture where a full-line color flip is preferable to a within-line sweep.
- **`'highlight-current'`** — only the active line is visible (no past dimmed line above; no next preview below). Renders the active line full-screen, centered, in `highlightColor`. Past and future lines do not render. Suitable for high-impact mono-line lyric cards (chorus drop, hook landing).

The three styles dispatch in a single `switch (style)` block in the component; each style maps to a distinct render path. No "hybrid" / configurable per-feature toggle in v1 — the three bundles are sealed. Future styles add via an additive enum extension (no breakage).

### D-T322-4. Karaoke-wipe implementation — clip-path polygon driven by ms-progress; stable clipPath IDs

Mirrors `caption.tsx`'s per-word karaoke-wipe pattern (T-316 D-T316-12) verbatim, swapping per-word ms-progress for **per-line** ms-progress:

```ts
// Within active line whose [startMs, endMs) bracket the current frame:
const lineProgress = clamp01((currentTimeMs - line.startMs) / (line.endMs - line.startMs));
// SVG <text> rendered twice:
//   1. base layer → foreground (or muteColor) color, full width
//   2. highlight layer → highlightColor, clipped via clip-path: polygon(0 0, X% 0, X% 100%, 0 100%) where X = lineProgress * 100
// Stable clipPath ID: `lyrics-line-${stableLineId}-clip` — derived from line index, not crypto.randomUUID().
```

`stableLineId` is the line's index in the `lines` array. No `crypto.randomUUID()`; no `Math.random()`; no per-render UUID generation. Verifies via the determinism test (render the same props twice at the same frame; HTML byte-identical).

The clip-path technique is SVG-native (uses `<defs><clipPath>` + `clipPath` CSS / attribute on a duplicate `<text>` element). DOM `<div>` rendering with `background-clip: text` is an alternative for non-SVG mode, but SVG is the v1 default per caption.tsx's posture; T-322 follows.

### D-T322-5. Beat alignment — out of scope; lines are data input

Beat detection / audio-track parsing / rhythmic timestamp inference is **out of scope**. The primitive accepts pre-computed `lines: { text, startMs, endMs }[]` as data; the host (or a sister primitive / authoring tool) handles beat alignment.

Rationale:

- Beat detection requires audio-track access (`<audio>` / `Web Audio API` / FFT analysis), which is fundamentally non-deterministic at the runtime layer (audio decode timing varies; `AudioContext.currentTime` drift). The primitive must remain frame-deterministic per CLAUDE.md §3.
- Authoring-time tools (a future T-XXX) can derive `lines[]` from audio + lyrics text + a bpm. The primitive renders pre-aligned data.
- The preset stub explicitly says *"Without a `musicCue`, the preset is unusable; escalate"* — meaning T-367 expects pre-computed timing as a hard input. T-322 honors that contract.

If a Reviewer demands inline beat detection → escalate per CLAUDE.md §6.

### D-T322-6. Optional `glow?` — text-shadow halo via SVG `<filter>`

Optional `glow?: { color: string; blur: number }` prop renders a halo around the active line (and only the active line) — the canonical music-video lyric aesthetic per the preset stub line 39 (*"glow on active word (10 px outer glow building 100 ms)"*).

Implementation: SVG `<filter id="lyrics-glow-${stableLineId}"><feGaussianBlur stdDeviation="..."/><feFlood flood-color="..."/></filter>` applied to the active line's `<text>` element. Stable filter IDs (line-index-derived); no `crypto.randomUUID()`. When `glow` absent, no `<filter>` block emits.

`glow.blur` is in canvas-pixel units (interpreted as SVG `stdDeviation`); `glow.color` is a hex string. v1 ships static glow (no animated build-up over 100 ms — that's an inline animation concern for v2). Past / future lines do NOT glow even when the active does.

### D-T322-7. `maxLinesVisible` — `1 | 3 | 5`, default `3`

`maxLinesVisible?: 1 | 3 | 5` (default `3`) controls how many neighbor lines render alongside the active:

- `1` — only the active line. Equivalent to `'highlight-current'` style behavior, but layout-orthogonal (a `'karaoke-wipe'` style with `maxLinesVisible: 1` shows the within-line wipe on a single visible line, no dimmed neighbors).
- `3` (default) — active + 1 line above (past, dimmed) + 1 line below (next, preview).
- `5` — active + 2 lines above (past, dimmed) + 2 lines below (next, preview).

Rendered window centers on the active line. When the active is line 0, lines above are absent (rendered window is `[active, +1, +2]`); when the active is the last line, lines below are absent. Edge clipping is silent (no error / placeholder). Mirrors common music-video lyric-card layout discipline.

When `style` is `'highlight-current'`, `maxLinesVisible` is forced to `1` regardless of the prop value (style dominates).

### D-T322-8. Theme slots vs explicit prop colors — explicit with theme-slot fallback

Mirrors T-316 caption.tsx, T-358a, T-356a, T-357a, T-355a verbatim: every color prop is **optional**; theme slot fills in when absent. Cluster owners pass explicit hex (lyric-yellow `#F3CE32`, cyan `#00FFFF`, bright white) or rely on the theme.

```ts
themeSlots: {
  background: { kind: 'palette', role: 'background' },
  foreground: { kind: 'palette', role: 'foreground' },
}
```

Top-level optional color props: `background?`, `foreground?` (inactive line color), `highlightColor?` (active / wiped color), `muteColor?` (past / upcoming dim color override; defaults to `foreground` at reduced opacity per `muteOpacity`), `wipeColor?` (alias for `highlightColor` to match the preset stub vocabulary; if both set, `highlightColor` wins). `muteOpacity?: number ∈ [0, 1]` (default `0.5`).

Per-line `region.color`-style overrides are NOT supported in v1 (lyrics lines don't carry per-line color semantics; the line-level enum register is enough). If a Reviewer pushes for per-line color → push back; that's the v2 path. If `palette/foreground` or `palette/background` are not defined on the active theme, the bridge's slot resolution falls back per T-131a rules (Implementer verifies; if rules differ from spec, document + adjust).

### D-T322-12. Casing transforms — `'as-is' | 'uppercase' | 'lowercase' | 'title-case'`

Per the preset stub (line 33: *"ALL CAPS for impact"* + line 45 noting Mixed Case acceptable for ballad/acoustic): top-level optional `casing?: 'as-is' | 'uppercase' | 'lowercase' | 'title-case'` (default `'as-is'`). Applied to every rendered line's text via JS string transform at render time (no CSS `text-transform` — keeps the rendered text byte-stable for parity goldens).

Mirrors caption.tsx's `casing` prop verbatim. Title case is naive ASCII (capitalize first letter of each whitespace-separated token); locale-aware title casing is v2.

### D-T322-13. Entrance animation — `'none' | 'fade' | 'rise'`, default `'fade'`

Per-line entrance is computed purely from frame, mirrored from T-355a D-T355a-7 (swap per-region for per-line):

- **`'none'`** — every visible line renders at full opacity at `frame=0`; entrance baked off.
- **`'fade'`** (default) — a 12-frame fade-in window starts when each line enters its visibility window. Opacity interpolates `0 → 1` over `[lineStartFrame, lineStartFrame + 12]`.
- **`'rise'`** — fade + 12 px translate-up over the same window. `translateY` interpolates `12 → 0`.

No per-line stagger across the whole song (lines are time-gated, not stagger-gated). The entrance window opens when the line enters its `[startMs, endMs)` bracket — purely frame-derived.

No `setTimeout` / `Date.now()` / `Math.random()`; pure frame-derived. Mirrors caption.tsx's per-word entrance pattern.

## Acceptance criteria

### Primitive shape (AC #1–#13)

1. `packages/runtimes/frame-runtime-bridge/src/clips/lyrics.tsx` exists with file header naming the file + purpose.
2. `lyricsPropsSchema` (Zod) accepts:
   - `lines: { text: string; startMs: number; endMs: number }[]` of length 1..40 (per D-T322-2)
   - `style: 'karaoke-wipe' | 'three-line-stack' | 'highlight-current'` (per D-T322-3)
   - `font?: { family: string; weight: number; size: number; letterSpacing?: number }`
   - `casing?: 'as-is' | 'uppercase' | 'lowercase' | 'title-case'` (per D-T322-12)
   - Optional explicit colors: `background?`, `foreground?`, `highlightColor?`, `muteColor?`, `wipeColor?` — hex strings (`/^#[0-9a-fA-F]{6}$/`)
   - `muteOpacity?: number ∈ [0, 1]` (default `0.5`)
   - `position: { x: number; y: number; width: number; alignment: 'left' | 'center' | 'right' }`
   - `lineGap?: number` (default `80`; non-negative — vertical space between lines in the stack)
   - `entrance?: 'none' | 'fade' | 'rise'` (default `'fade'`; per D-T322-13)
   - `glow?: { color: string; blur: number }` (per D-T322-6)
   - `maxLinesVisible?: 1 | 3 | 5` (default `3`; per D-T322-7)
   All optional except `lines`, `style`, `position`. Strict mode (no extras).
3. `lyricsClip` is `defineFrameClip<LyricsProps>({ kind: 'lyrics', component: Lyrics, propsSchema: lyricsPropsSchema, themeSlots: { background: { kind: 'palette', role: 'background' }, foreground: { kind: 'palette', role: 'foreground' } } })`.
4. `Lyrics` component visibility-gates each line by `(currentTimeMs ∈ [line.startMs, line.endMs))`; line `i` is "active" when its window contains the current frame's ms-time (computed from `frame / fps × 1000`).
5. `style: 'karaoke-wipe'` produces a left-to-right color front within the active line: past characters in `highlightColor` (or `wipeColor` if `highlightColor` absent), upcoming in `foreground`. Wipe progress = `(currentTimeMs − line.startMs) / (line.endMs − line.startMs)`. Implementation uses SVG `<defs><clipPath>` with stable line-index-derived IDs (per D-T322-4).
6. `style: 'three-line-stack'` shows previous line (dimmed at `muteOpacity`) above + active line (in `highlightColor`) in middle + next line (preview at `muteOpacity`) below. No within-line wipe.
7. `style: 'highlight-current'` shows only the active line, full-screen, in `highlightColor`. Past and future lines do not render. `maxLinesVisible` is forced to `1` regardless of prop (per D-T322-7).
8. `casing` transform applied: `'uppercase'` renders `'wake me up'` as `'WAKE ME UP'`; `'title-case'` as `'Wake Me Up'` (naive ASCII). `'as-is'` is the no-op default. Applied via JS string transform at render time (no CSS `text-transform`).
9. `glow` prop, when present on the active line render path, emits an SVG `<filter>` element with stable `filter` ID (line-index-derived) applying a Gaussian blur halo of `glow.blur` stdDeviation in `glow.color`. When absent, no `<filter>` element emits.

12. Theme slots `palette/background` + `palette/foreground` provide defaults when their corresponding optional props are absent; explicit prop colors win when set (per D-T322-8).
13. Frame-deterministic — same `frame` + same props → byte-identical SVG / DOM output. No `Date.now()`, no `Math.random()`, no `crypto.randomUUID()`, no `setTimeout`, no `setInterval`, no `fetch`. Stable clipPath + filter IDs (line-index-derived).
