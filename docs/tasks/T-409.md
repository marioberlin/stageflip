# T-409 — CI: preset × export parity job (cross-product matrix)

**Branch**: `task/T-409-export-parity-ci`

## Goal

Add a CI gate (`pnpm check-export-parity`) that, on every push, exercises the
cross-product of **every ratified preset × every `ExportTarget`** through the
`@stageflip/export-router` (T-408) and verifies that:

1. Every `(preset, target)` pair receives a well-formed `RoutingDecision`
   (the discriminated union shape from `packages/export-router/src/types.ts`).
2. Every `RoutingDecision`'s `exporterPackage` field names a real exporter
   package on disk under `packages/`.
3. The matrix-vs-decision coupling is consistent: targets the matrix marks
   `'live'` produce `mode: 'live'`; targets the matrix marks `'static'`
   produce `mode: 'static'` (with the appropriate discriminator branch).
4. The router's `'fallback'` discriminator is reachable: a synthetic Document
   carrying a live (`type: 'interactive-clip'`) child paired with a
   static-only target produces a `kind: 'fallback'` decision with a non-empty
   `liveClipsOmitted` array.

The new gate is a structural check, not an execution check. Running every
exporter on every preset would inflate CI time substantially and is already
covered by the existing `parity (fixture scoring)` job for pixel-level
verification.

## §13 (structural extension) statement

**NOT a structural extension.** Adds a CI gate over existing contracts
(`EXPORT_MATRIX` from `@stageflip/schema`, `routeExport` from
`@stageflip/export-router`, the on-disk preset markdown corpus). No new
`clipKind` / `Element` variant / compositing mode / runtime kind / new field
on `ClipKindBinding` / `RIRElement` / `RIRDocument`. Render verification N/A
— the script is a pure-function CLI over typed inputs and filesystem
metadata, fully covered by unit tests + the gate's exit code on the live
corpus.

## Architectural seals

- **Verification, not execution.** The gate verifies routing DECISIONS for
  every `(preset, target)` pair are well-formed and point at real exporter
  packages. Actual exporter execution is OUT OF SCOPE — pixel-level
  comparison happens in the existing `parity (fixture scoring)` CI job.
- **Pure script.** `scripts/check-export-parity.ts` is a pure Node CLI:
  input = filesystem (preset markdown files + the exporter-package directory
  layout), output = stdout report + exit code (0 = pass, non-zero = fail).
  No `Date.now()`, no `Math.random()`, no network. Mirrors the existing
  `check-*` scripts' posture verbatim.
- **Cross-product matrix.** 50 presets × 8 export targets = 400 pairs. Each
  pair lands on a typed `RoutingDecision`; the gate asserts:
  - `kind` ∈ {`'route'`, `'fallback'`}.
  - `exporterPackage` resolves to a real `packages/export-*/package.json`
    on disk.
  - `mode` matches `EXPORT_MATRIX[target]` (`'live'` ↔ `'live'`,
    `'static'` ↔ `'static'`).
  - For `'route'` + `'static'`, `reason: 'target_is_static_only_no_live_clips'`.
  - For `'route'` + `'live'`, `reason: 'target_is_live_capable'`.
  - For `'fallback'`, `reason: 'target_is_static_only'` AND
    `liveClipsOmitted.length > 0`.
- **Live-clip branch coverage.** Today's preset corpus is entirely
  static-clipKind (no `family:` declarations). To exercise the `'fallback'`
  discriminator, the gate also runs a synthetic Document with one
  `type: 'interactive-clip'` element through every static target and
  asserts the `'fallback'` branch fires.
- **No new packages.** T-409 ships infrastructure (a script + a CI job +
  this spec); no consumer-visible package surface changes.
- **Synthetic Document construction.** The gate constructs a minimal
  `Document` per preset. Today every ratified preset has a static
  clipKind, so the synthetic doc is a slide-mode doc with one text element
  per preset and no live clips. The Document is NOT round-tripped through
  the schema's Zod validator at gate time (the loader already validates
  preset frontmatter; constructing a schema-strict Document per preset is
  out of scope and would conflate this gate with `check-preset-integrity`).
  The script casts the synthetic shape via `as unknown as Document`,
  matching the established pattern in
  `packages/export-router/src/test-fixtures.ts`.

## CLI ergonomics

```
$ pnpm check-export-parity
check-export-parity: scanning skills/stageflip/presets...
check-export-parity: 50 presets × 8 targets = 400 pairs to verify
check-export-parity [route-shape]: PASS
check-export-parity [exporter-package-exists]: PASS
check-export-parity [matrix-mode-consistency]: PASS
check-export-parity [fallback-branch-coverage]: PASS
check-export-parity: PASS
```

On failure, FAIL lines are emitted to stderr with the offending
`(preset, target)` pair and the violated invariant.

Flags:
- `--presets-root=<path>` — override default `skills/stageflip/presets`.
- `--packages-root=<path>` — override default `packages` (lookup root for
  exporter package existence).
- `--help` / `-h`.

## Acceptance criteria

1. **Script exists.** `scripts/check-export-parity.ts` with a file header,
   TSDoc on every public function, no `any`, no `console.log`.
2. **CLI exit code.** `pnpm check-export-parity` exits 0 on `main` (today's
   corpus). Exits 1 when a routing-decision invariant fails.
3. **Cross-product coverage.** Iterates every preset × every `ExportTarget`
   member, plus one synthetic-live-clip Document × every static target.
4. **Route-shape invariant.** Asserts `kind ∈ {'route', 'fallback'}`,
   `exporterPackage` is a string, `mode ∈ {'live', 'static'}`, `target`
   round-trips.
5. **Exporter-package-exists invariant.** Each `exporterPackage` resolves
   to a real `packages/export-*/package.json` (looked up in
   `--packages-root`).
6. **Matrix-mode-consistency invariant.** `EXPORT_MATRIX[target]` matches
   the decision's `mode` for both `'route'` and `'fallback'` branches.
7. **Fallback-branch-coverage invariant.** A synthetic Document with a
   `type: 'interactive-clip'` element produces `kind: 'fallback'` for
   every static target, with `liveClipsOmitted.length > 0`.
8. **Unit tests** in `scripts/check-export-parity.test.ts` covering each
   pure-function helper (route iteration, decision verification, package
   existence). Coverage ≥85% on changed files.
9. **CI integration.** `.github/workflows/ci.yml` includes a new step
   `Gate - preset × export parity` under the `verify` job, running
   `pnpm check-export-parity`.
10. **Local gates green.** `pnpm typecheck && pnpm lint && pnpm test &&
    pnpm check-licenses && pnpm check-remotion-imports &&
    pnpm check-determinism && pnpm check-skill-drift &&
    pnpm gen:tool-skills:check` all pass.
