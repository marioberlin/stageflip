# T-445 — Per-modality usage telemetry

**Branch**: `task/T-445-usage-telemetry`

## Goal

Track adapter selection / latency / cost per tenant. Every adapter
invocation now emits an `AdapterUsageEvent` (distinct from T-444's
`AdapterAuditEvent` — usage telemetry is the metrics-class event, audit
is the security-class event) carrying:

- `tenantId`, `adapterId`, `modality`
- `selectedReason` — `'capability-router'` (ranked & chosen by
  `routeCapability`) vs `'explicit'` (caller supplied an `adapterId`)
- `latencyMs` — wall-clock from `SandboxRunner.run` invocation to
  result
- `costAmount`, `costCurrency` — sourced from
  `AdapterDescriptor.costPerCall.usd` (T-443's source-of-truth)
- `outcome` — `'success'` | `'failed'` | `'killed'` (mirrors T-444's
  audit-event terminal kinds)
- `timestamp` — ISO-8601 (host-supplied clock seam; deterministic in
  tests)

T-445 is **Phase 14 δ first task; Lock-in phase**. It gates T-446
(security audit consumes both event classes) and is one of T-447's
GA-readiness criteria ("telemetry on for all 9 adapters").

## §13 statement — NOT a structural extension

T-445 adds:

1. A NEW event class — `AdapterUsageEvent` — emitted alongside (not
   inside) `AdapterAuditEvent`. Lives in a new package; carries no
   field on `AdapterDescriptor`, `RIRElement`, `RIRDocument`,
   `ClipKindBinding`, or any document-tree node.
2. A NEW tool in an EXISTING bundle — `query_usage_telemetry` in
   `asset-generation` (bundle #25; current tool count 4 → 5).

Neither change adds a degree of freedom to the document model, the
binding model, or a renderer pipeline. The §13 backstop
(`parityFixture-non-blank`) is N/A. **Render verification N/A.**

## Schema audit

Performed 2026-05-11 against `origin/main` HEAD `933eb0b0`:

- **`AdapterAuditEvent`** (T-444) — discriminated union with four
  kinds (`start` / `complete` / `failed` /
  `killed-for-resource-limit`). Already wired into all three
  `SandboxRunner` impls. T-445 layers `AdapterUsageEvent` on top:
  every adapter call emits BOTH the audit event AND the usage event.
- **`AdapterDescriptor.costPerCall.usd`** (T-418 / T-443) — already
  present on every reference adapter. T-445 reads this verbatim into
  `AdapterUsageEvent.costAmount` (free adapters → `0`).
- **`RoutingDecision`** (T-425) — already carries the ranked
  candidates. T-445's `selectedReason` is supplied by the caller
  (the `asset-generation` handler or `FallbackChainExecutor`); we do
  not modify `RoutingDecision`.
- **`TenantCostTrackerStore`** (T-443) — usage telemetry is
  ORTHOGONAL to the cost tracker (one is metrics; the other is a
  per-tenant budget ledger). T-445 does NOT consume / modify it.
  Both can coexist.
- **Asset-generation bundle** — currently exports 4 tools
  (`generate_asset`, `list_adapters`, `get_adapter_capabilities`,
  `query_cost_budget`). T-445 adds a fifth: `query_usage_telemetry`.

## Architecture overview

### Event class

```ts
// packages/usage-telemetry/src/types.ts
export interface AdapterUsageEvent {
  readonly tenantId: string;
  readonly adapterId: string;
  readonly modality: string;
  readonly selectedReason: 'capability-router' | 'explicit';
  readonly latencyMs: number;
  readonly costAmount: number;
  readonly costCurrency: string;
  readonly outcome: 'success' | 'failed' | 'killed';
  readonly timestamp: string; // ISO-8601
}
```

Zod schema enforces the same shape strictly (unknown keys rejected;
`latencyMs` / `costAmount` nonnegative finite; `costCurrency`
ISO-4217 alpha-3 (`/^[A-Z]{3}$/`); `timestamp` `.datetime()`).

### Pluggable emitter

```
                    ┌──────────────────────────┐
                    │   SandboxRunner.run      │
                    │                          │
                    │   ① emit AuditEvent      │
                    │   (start)                │
                    │                          │
                    │   ② invoke adapter       │
                    │                          │
                    │   ③ emit AuditEvent      │
                    │   (complete/failed/      │
                    │    killed)               │
                    │                          │
                    │   ④ emit UsageEvent ←──── new in T-445
                    │   (success/failed/killed)│
                    └──────────────────────────┘
```

`UsageTelemetryEmitter` is the interface; `InMemoryUsageTelemetryEmitter`
is the bounded ring-buffer default (mirrors `InMemoryAuditEmitter`).
Production emitters (Cloud Logging / Prometheus) land downstream — the
seam is documented but no impl ships in v1.

### Per-tenant aggregation

```ts
// packages/usage-telemetry/src/aggregate.ts
export interface UsageRollup {
  readonly tenantId: string;
  readonly adapterId: string;
  readonly modality: string;
  readonly count: number;
  readonly successCount: number;
  readonly failedCount: number;
  readonly killedCount: number;
  readonly p50LatencyMs: number;
  readonly p95LatencyMs: number;
  readonly totalCostAmount: number;
  readonly costCurrency: string;
}

export function aggregateUsage(
  events: readonly AdapterUsageEvent[],
  filter: {
    readonly tenantId: string;
    readonly adapterId?: string;
    readonly sinceTimestamp?: string; // ISO-8601, inclusive
    readonly untilTimestamp?: string; // ISO-8601, exclusive
  },
): readonly UsageRollup[];
```

The aggregator is a pure function over the event array. Production
emitters will replace `events` with a Cloud Logging query result; the
shape stays the same.

### Wiring into `SandboxRunner`

Each of the three runners (`InProcessSandboxRunner`,
`SidecarSandboxRunner`, `RemoteServiceSandboxRunner`) gains an
OPTIONAL `usageEmitter` + `clock` + `selectedReason` field on
`SandboxInvocation`. When absent, usage emission is a no-op
(back-compat — existing wiring without usage telemetry continues to
emit only audit events). When present:

1. `start` audit emit (unchanged).
2. Capture `clock()` as `startMs`.
3. Invoke adapter (unchanged).
4. Capture `clock()` as `endMs`.
5. Emit terminal audit event (unchanged).
6. Emit usage event with `latencyMs = endMs - startMs`,
   `outcome = success | failed | killed`, `costAmount = descriptor.
   costPerCall.usd ?? 0`, `costCurrency = 'USD'`, `timestamp = new
   Date(endMs).toISOString()`.

The clock seam lives on the invocation (not on the runner) so a single
runner instance can serve multiple tenants without sharing state. Tests
inject a deterministic counter; production wires `Date.now`.

### New tool — `query_usage_telemetry`

Bundle #25 (`asset-generation`) gains a fifth tool. Input:

```ts
{
  adapterId?: string;          // optional adapter filter
  modality?: AdapterModalityKind; // optional modality filter
  sinceTimestamp?: string;     // ISO-8601 (default: 7 days back)
  untilTimestamp?: string;     // ISO-8601 (default: now)
}
```

Output:

```ts
{
  ok: true,
  rollups: UsageRollup[]
}
| { ok: false, reason: 'usage_telemetry_unavailable' }
```

Read soft-seam: requires `usageTelemetryReader` + `tenantId` on
`AssetGenerationContext`. When unwired, returns
`{ ok: false, reason: 'usage_telemetry_unavailable' }` (back-compat;
dev hosts running without telemetry continue to function).

`usageTelemetryReader` is the dual of `UsageTelemetryEmitter` — an
interface returning `readonly AdapterUsageEvent[]` for a given
tenantId. The default `InMemoryUsageTelemetryEmitter` implements BOTH
interfaces (it stores events in a ring buffer and exposes them via
`events()`).

## Acceptance criteria

### AC #1 — `AdapterUsageEvent` Zod schema

- Strict interface + Zod schema in
  `packages/usage-telemetry/src/types.ts`.
- All fields strict; `selectedReason` / `outcome` are sealed enums;
  `costCurrency` matches `/^[A-Z]{3}$/`; `latencyMs` /
  `costAmount` nonnegative finite; `timestamp` `.datetime()`.
- Unit tests round-trip happy + every rejection path.

### AC #2 — `UsageTelemetryEmitter` interface

- `emit(event: AdapterUsageEvent): void` — pure sync.
- Default `InMemoryUsageTelemetryEmitter` with bounded ring buffer
  (default capacity 1000, drops oldest on overflow). Mirrors
  `InMemoryAuditEmitter`.
- Implements a sibling `UsageTelemetryReader` interface —
  `eventsForTenant(tenantId): readonly AdapterUsageEvent[]`. The
  in-memory impl filters its ring buffer; production readers query
  the backing store.

### AC #3 — `aggregateUsage` helper

- Pure function. Deterministic. Sorts events by timestamp before
  bucketing.
- Per-tenant + per-adapter rollups with count / success / failed /
  killed / p50 / p95 latency / total cost.
- Currency mixing rejected: if a bucket has multiple currencies, the
  aggregator throws `UsageAggregationError`. (Tenants currently have
  a single currency per T-443's `aiBudget`; this guards future
  drift.)
- p50 / p95 use nearest-rank percentile on the sorted latency array.
- Tests: empty input → empty output; single-event → single rollup;
  multi-tenant → only filtered tenant returned; window filter
  inclusive-start exclusive-end.

### AC #4 — `SandboxInvocation` extension

- New optional fields on `SandboxInvocation` (declared in
  `@stageflip/adapter-sandbox`):
  - `usageEmitter?: UsageTelemetryEmitter`
  - `clock?: () => number`
  - `selectedReason?: 'capability-router' | 'explicit'`
- When all three are wired, every adapter invocation in all three
  runners emits a `AdapterUsageEvent` post-invocation.
- When any is unwired, usage emission is a no-op.

### AC #5 — `InProcessSandboxRunner` usage emit

- After the terminal audit event, emits
  `AdapterUsageEvent` with `outcome: 'success'` on resolution,
  `outcome: 'failed'` on rejection.
- Test: happy path emits both audit `complete` AND usage `success`.
- Test: failure path emits both audit `failed` AND usage `failed`.
- Test: with `usageEmitter` absent, no usage event is emitted.

### AC #6 — `SidecarSandboxRunner` usage emit

- Same shape as in-process, plus:
  - `outcome: 'killed'` when the resource-limit timer fires
    (matches T-444's `killed-for-resource-limit` audit event).
- Tests inject the same fake spawn + stdio fixtures as T-444; assert
  both audit AND usage events emitted.

### AC #7 — `RemoteServiceSandboxRunner` usage emit

- Same shape as in-process.
- Tests inject the same fake `httpsCallable` as T-444.

### AC #8 — `query_usage_telemetry` tool

- New tool in the `asset-generation` bundle (count 4 → 5).
- Input schema strict; defaults `sinceTimestamp` to 7 days back from
  `untilTimestamp` (which defaults to "now"). Test seam: clock
  injectable via `AssetGenerationContext.nowMs`.
- Output: discriminated `{ ok: true, rollups }` /
  `{ ok: false, reason }`.
- Soft-seam: requires `usageTelemetryReader` + `tenantId`. When
  unwired: `{ ok: false, reason: 'usage_telemetry_unavailable' }`.
- Tests: happy-path with seam wired; unwired returns the typed
  error; aggregation matches `aggregateUsage` direct call.

## Out of scope

- **Production transport** — `CloudLoggingUsageTelemetryEmitter` /
  Prometheus exporter / OTLP exporter all deferred. The seam is
  documented; v1 ships only the in-memory default.
- **Cross-currency aggregation** — `aggregateUsage` rejects mixed
  currencies. Multi-currency tenants land post-Phase 14.
- **Real-time streaming surface** — usage events are stored in the
  ring buffer; the query tool reads on demand. SSE / push lands when
  T-442's transport stack is generalized post-GA.
- **Historical backfill** — events emitted from this point forward
  only; no retroactive reconstruction.
