# T-420 — `@stageflip/asset-cache`

**Branch**: `task/T-420-asset-cache`

## Goal

Ship `@stageflip/asset-cache` — the content-addressed cache primitive
that ADR-008 §D1 specifies. Every asset-gen modality (TTS, video-gen,
music-gen, sfx, three-d, image-gen) keys its generated assets under a
deterministic SHA-256 over `{ modality, model, voice, prompt, params,
seed }` so two callers issuing identical inputs short-circuit at the
cache layer with no provider call.

The package ships three concerns:

1. **`canonicalize`** — JSON canonical-form serializer. Sorts object
   keys recursively, normalizes numbers, produces a stable byte-string
   suitable for hashing. Pure, deterministic, runtime-agnostic.
2. **`deriveCacheKey` + `cacheKeyString`** — async SHA-256 derivation
   per ADR-008 §D1's exact recipe (prompt normalization, model:voice
   concatenation, seed rendering as base-10 integer or `"none"`, params
   canonicalization). Async because Web Crypto's `SubtleCrypto.digest`
   is async on every runtime; matches the captions package pattern.
3. **`AssetCacheStore<T>` + `InMemoryAssetCacheStore<T>`** — pluggable
   cache contract (`get` / `set` / `has`) plus a `Map`-backed default
   implementation. Mirrors the captions `TranscriptCache` shape but
   generalized to any payload type.

The captions package has the same shape today (`packages/captions/src/{cache,hash,types}.ts`)
specialized to `{ sha256, language }` keys + `Transcript` payloads.
T-420 generalizes that pattern. **Captions migration is deferred** —
see "Migration tradeoff" below.

**Strict scope** — cache-key derivation + canonical serializer +
in-memory store ONLY. NO AssetStorage backing (downstream task). NO
captions package edits (deferred). NO eviction policy (downstream).
NO LRU / TTL semantics (downstream). NO disk / Redis / CDN backing
(downstream).

## Out of scope

- **Captions migration** — captions cache stays self-contained. See
  "Migration tradeoff" below.
- **AssetStorage-backed store** — a downstream task (likely T-420b or
  bundled into T-435 / T-436 / T-437) wraps `@stageflip/storage`'s
  `AssetStorage` contract behind an `AssetCacheStore<T>` impl. T-420
  ships only the in-memory implementation.
- **Eviction policy** — no LRU, no TTL, no max-size enforcement. The
  in-memory store is unbounded; production callers wrap it.
- **Cross-tenant cache sharing** — no tenant scoping at the cache key
  level (T-420 is content-addressed; ADR-008 §D1 explicitly notes that
  modality-bucket prefixing happens at the storage layer, not the
  cache-key layer).
- **`computeAssetCacheKey` exact API surface** — ADR-008 §D1 sketches
  `computeAssetCacheKey(input): AssetCacheKey` returning `{ modality,
  hash }`. T-420 ships the same primitive under the name
  `deriveCacheKey` for symmetry with the captions package's
  `deriveCacheKey` + `cacheKeyString` pair. The two names are the same
  function; an alias export is included for ADR continuity.
- **Modality bucket prefixing** at write time — that's a storage-layer
  concern (per ADR-008 §D1 last paragraph). T-420's keys are pure
  hashes; storage layer prepends `{bucket-root}/{modality}/{hash[:2]}/`
  on write.
- **Loss-flag emission** for cache misses or hits — the cache layer is
  silent; loss flags are an adapter-call concern, not a cache concern.

## Migration tradeoff (captions self-containment, deferred)

The captions package's existing in-memory cache is structurally
identical to T-420's `InMemoryAssetCacheStore<Transcript>`. A trivial
migration would:

1. Have `packages/captions` add `@stageflip/asset-cache` as a workspace
   dep.
2. Replace `createMemoryCache()` with `new InMemoryAssetCacheStore<Transcript>()`.
3. Replace `deriveCacheKey(source, language)` calls with
   `deriveCacheKey({ modality: 'tts', model: 'whisper', prompt:
   sourceHash, params: {}, voice: language })` (or a similar shaping).

**T-420 does NOT migrate captions.** Reasoning:

- **Scope discipline.** T-420 is the contract package; captions
  migration is a behaviour change with its own test surface (the
  existing `cache.test.ts` + `hash.test.ts` would need to be rewritten
  against the generalized API).
- **Bundling concerns.** Captions is consumed by browser apps; adding
  a new workspace dep needs a bundle audit per the lessons in
  `feedback_t304_lessons.md`.
- **Shape mismatch.** Captions hashes audio bytes (or URL strings),
  not prompts; the generalization to `(modality, model, voice, prompt,
  params, seed)` requires a deliberate mapping decision (e.g., is
  "language" a `voice` field? a `params` entry? a separate modality?).
  That decision belongs in the migration task, not the contract task.

A future task (provisionally **T-436a** or similar) will:

1. Decide the captions → generalized-cache mapping.
2. Migrate `packages/captions/src/{cache,hash}.ts` to consume
   `@stageflip/asset-cache`.
3. Update `concepts/captions/SKILL.md`.
4. Verify bundle size + any browser-build implications.

Until then, captions stays self-contained and `@stageflip/asset-cache`
serves only the new asset-gen modalities (downstream consumers
T-435 / T-436 / T-437).

## Architectural seals

- **Package**: `packages/asset-cache/` — standard layout (mirrors
  `packages/asset-gen-contract/` shape). ESM + CJS via tsup. Pure
  TypeScript with `zod` available but unused in T-420 (no schema
  validation needed; the cache-key primitive is type-checked at compile
  time).
- **Generic cache key derivation** per ADR-008 §D1, exact recipe:

  ```ts
  type CanonicalCacheKeyInput = {
    modality: string;        // 'tts' | 'video-gen' | 'music-gen' | 'three-d' | 'sfx' | 'image-gen' | …
    model: string;           // adapter-id + model-id (e.g., 'kokoro-82m')
    voice?: string;          // TTS-specific; opaque string for non-TTS
    prompt: string;          // user-supplied prompt (will be normalized)
    params: Record<string, unknown>;  // canonicalized JSON before hashing
    seed?: number | string;  // optional determinism seed
  };

  // Normalization (matches ADR-008 §D1 verbatim):
  //   1. params → canonicalize (recursive key-sort)
  //   2. prompt → trim + collapse whitespace runs to single space + Unicode NFC
  //   3. model:voice concatenation with literal ":" separator
  //      ("model:voice" or "model:" when voice absent)
  //   4. seed → base-10 integer or literal "none"
  //
  // Hash input = utf-8(JSON.stringify({ modality, model, voice, prompt, params, seed }))
  // Hash       = SHA-256 via Web Crypto SubtleCrypto.digest
  // Output     = { modality, hash: <64-hex> }
  ```

- **`AssetCacheStore<T>` interface** — minimal surface:

  ```ts
  interface AssetCacheStore<T> {
    get(key: string): Promise<T | undefined>;
    set(key: string, value: T): Promise<void>;
    has(key: string): Promise<boolean>;
  }
  ```

  The string key is the flattened `cacheKeyString(cacheKey)` — typically
  `${modality}/${hash}` — so callers can use the store with any string
  key and the cache-key primitive is just one valid producer.

- **`InMemoryAssetCacheStore<T>`** — `Map<string, T>` backed; no
  eviction, no concurrency, no transport. Each instance is isolated
  (mirrors captions' `createMemoryCache()` semantics).

- **Determinism**:
  - `canonicalize(value)` is pure (deterministic for same input).
  - `deriveCacheKey(input)` is pure (same input → same hash).
  - `cacheKeyString(key)` is pure (same key → same string).
  - `InMemoryAssetCacheStore<T>` is deterministic w.r.t. operation
    order: `set` then `get` returns the set value; `has` reflects
    presence. No clocks, no random.

- **SHA-256 via Web Crypto SubtleCrypto** — matches the captions
  pattern (`crypto.subtle.digest('SHA-256', data)`). Available in
  Node 20+ and every modern browser. No `node:crypto` import — keeps
  the package runtime-agnostic for browser bundles.

- **§13 statement**: NOT a structural extension — adds a new package
  implementing existing ADR-008 §D1 contract. No new degree of freedom
  in document model, binding model, or renderer pipeline. Render
  verification N/A.
