# T-422 — `check-asset-licenses` CI gate

**Branch**: `task/T-422-check-asset-licenses`

## Goal

Ship the `check-asset-licenses` CI gate — a pure Node CLI under
`scripts/check-asset-licenses.ts` that enforces ADR-008 §D13's per-modality
adapter-license whitelist against every adapter discoverable in the
workspace. Mirrors the structure of `scripts/check-licenses.ts` (the
existing dep-license gate from ADR-001 §D4) and slots into the same
`typecheck · lint · test · gates` job in `.github/workflows/ci.yml` as a
sibling step.

This is the **CI precondition for the reference-adapter sequence
T-426..T-434**. Per `docs/implementation-plan.md` line 883:

> **T-422** (`check-asset-licenses`) → adapter PRs

T-426..T-434 cannot land until this gate is on `main`. Each adapter PR's
descriptor will be checked against the per-modality whitelist before merge.

T-418 + T-419. It does not add a new degree of freedom to the document
model, the binding model, or any renderer pipeline. Render verification

## Failure modes the gate catches

1. **Non-whitelisted license per modality** — an adapter declares
   `license.kind: 'cc-by'` for a `tts` modality (cc-by not in the tts
   whitelist). FAIL with the adapter id, modality, declared license, and
   permitted set surfaced.
2. **Proprietary-without-ADR** — an adapter declares
   `license.kind: 'proprietary-vendored'` without an accompanying
   license-clearance ADR reference. Mirrors the `check-licenses.ts`
   LGPL-without-ADR pattern. The gate surfaces a `NEEDS-ADR` warning
   listing the adapter; FAIL until an ADR is filed and the adapter id
   added to a `PROPRIETARY_OK` allowlist (mirrors the `REVIEWED_OK` map
   in `check-licenses.ts`). On inaugural ship the allowlist is empty.
3. **Unknown modality** — an adapter declares a `modality.kind` that is
   not in `ADAPTER_MODALITY_KINDS`. This is caught by
   `parseAdapterDescriptor` at registration time (Zod schema rejects
   the parse); the gate surfaces the parse error verbatim.
4. **`gpl-incompatible` license declaration** — always denied, regardless
   of modality. Surfaced as a FORBIDDEN entry.

## Inaugural-empty-state behavior

When the gate runs on `main` after T-422 lands but before any of
T-426..T-434 has merged, **no `packages/<adapter>/` dir exists**. The
gate's discovery step yields an empty candidate list; the
`AdapterRegistry` it populates is empty; `registry.list().length === 0`;
the gate prints:

```
check-asset-licenses: 0 adapters registered; whitelist not yet exercised
check-asset-licenses: PASS
```

and exits 0. Documented at the top of `scripts/check-asset-licenses.ts`
as the expected initial state.

This is the "0 candidates → exit 0" pattern from `check-export-parity.ts`
when no presets exist (analogous structural posture).

## Adapter discovery convention

The gate scans `packages/*/package.json` for any package whose
unscoped name (the part after `@stageflip/`) matches one of the
canonical adapter prefixes:

- `tts-*` (e.g., `tts-kokoro`, `tts-fish-speech`)
- `video-*` (e.g., `video-seedance`, `video-runway`)
- `music-*` (e.g., `music-acestep`, `music-yue`)
- `sfx-*` (e.g., `sfx-stable-audio`)
- `3d-*` (e.g., `3d-tripo`, `3d-meshy`)
- `slide-deck-*`, `mind-map-*`, `table-gen-*`, `quiz-*`, `flashcard-*`,
  `report-gen-*`, `infographic-*`, `research-session-*` — for the
  source-grounded modalities (T-419 contract).
- `audience-*` (Phase 15), `bundle-*` (Phase 16).

For each candidate package, the gate dynamic-imports the package's
`src/index.ts` (via tsx, same loader the script itself runs under) and
looks for one of:

- a named export `descriptor` of type `AdapterDescriptor`, OR
- a named export `descriptors` of type `AdapterDescriptor[]` (for
  packages shipping multiple modalities under one bundle).

Any matching exports are passed through `parseAdapterDescriptor` (which
throws on malformed input) and registered into a fresh `AdapterRegistry`.
A package matching the prefix convention but exporting neither
`descriptor` nor `descriptors` is a FAIL (`MISSING-DESCRIPTOR` bucket)
to catch adapter packages that ship without a registered descriptor.

This convention is **not** prescribed by ADR-007 / ADR-008; it is an
implementation choice for this gate and is documented at the top of
`scripts/check-asset-licenses.ts`. T-426 (the first reference adapter)
ratifies the convention by its first PR — a cross-cutting rev to this
discovery layer is acceptable if T-426 lands a different export shape;
the gate code is small.

## Architecture detail

### Validation core is pure

The pure-function validation core lives in
`scripts/check-asset-licenses.ts` and exports a `validateRegistry`
function (and the `PER_MODALITY_LICENSE_WHITELIST` const + the
`PROPRIETARY_OK` allowlist) so the test file can drive validation
against a synthetic in-memory registry without spawning the script as
a subprocess. The `main()` function wires filesystem discovery →
dynamic-import → `validateRegistry` → stdout report → exit code.

The test file imports `validateRegistry` directly and constructs
synthetic `AdapterDescriptor` objects via `parseAdapterDescriptor` (so
test inputs are also schema-valid). This keeps the gate's pure logic
testable without requiring on-disk fixture packages.

### Failure-mode surface

Mirrors `check-licenses.ts`'s `forbidden` / `needsAdr` / `unknown`
buckets:

- `forbidden` — `license.kind === 'gpl-incompatible'` OR not in the
  per-modality whitelist. Always FAIL.
- `needs-adr` — `license.kind === 'proprietary-vendored'` (vendored
  third-party code requires an ADR per CLAUDE.md §3 / THIRD_PARTY.md;
  this gate echoes that posture for adapter-shipped vendored bundles).
  Adapter id may be added to the `PROPRIETARY_OK` allowlist (with an
  ADR reference comment) once cleared.
- `missing-descriptor` — a package matching the adapter naming
  convention exports neither `descriptor` nor `descriptors`. FAIL.
- `parse-error` — `parseAdapterDescriptor` rejected the descriptor
  (Zod error). FAIL with the Zod issue list verbatim.

### Determinism posture

The script is **gate-side**, not runtime — the determinism rules in
CLAUDE.md §3 ("Determinism (in clip + runtime code only)") explicitly
scope to `packages/frame-runtime/**`, `packages/runtimes/**/src/clips/**`,
and `packages/renderer-core/src/clips/**`. The script lives at
`scripts/` and may use `fs`, `path`, dynamic `import()`, etc. — same
posture as `check-licenses.ts` and `check-export-parity.ts`.

The script does not call `Date.now()`, `Math.random()`, or `fetch()` in
its body — output is a deterministic function of the workspace state.

### CI step placement

Inserted in `.github/workflows/ci.yml` between `Gate - skill drift`
(line 68) and `Gate - skills-sync` (line 71), so the asset-license
gate runs alongside the other adapter-contract-aware gates and before
the heavier export-parity / determinism / size-limit gates.
