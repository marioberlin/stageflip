# T-442 — Streaming agent events

**Branch**: `task/T-442-streaming-agent-events`

## Goal

Add a Server-Sent Events (SSE) streaming transport for the agent's
`ExecutorEvent` stream so the editor UI receives **progress events**
(`step-start`, `tool-call`, `tool-result`, `patch-applied`, `step-end`,
`plan-end`) as they happen — instead of waiting for the full Planner →
Executor → Validator pipeline to complete before the route returns its
JSON blob.

This resolves the **P7 carry-forward** from
`docs/handover-phase7-complete.md` §6:

> *Carries forward to Phase 8: streaming events from
> `/api/agent/execute`, copilot `document` plumbing, …*

It is also the **delivery channel for T-438's placeholder→real swaps**:
T-438 wired the optimistic-placeholder emit / swap protocol through
the executor (the asset-gen handler dispatches a placeholder
immediately and later patches the document with the resolved asset),
but until T-442 the editor only sees the swap when it triggers the
NEXT agent run, because the existing JSON route blocks until the full
plan completes. Streaming makes the swap visible in real time.

## §13 statement — NOT a structural extension

T-442 adds a **transport** over the existing `ExecutorEvent` discriminated
union. It does NOT:

- introduce a new `RIRElement` variant,
- introduce a new clip kind, runtime kind, or compositing mode,
- add an optional field to `ClipKindBinding` / `RIRElement` / `RIRDocument`,
- change the document schema,
- change parity goldens or rendering pipeline.

`ExecutorEvent` already exists and is already an `AsyncIterable<ExecutorEvent>`
on the executor; T-442 only adds an SSE encoder + a ReadableStream wrapper
+ a client consumer + a streaming branch on the existing POST handler.
**Render verification N/A** per CLAUDE.md §13.

## Function

The new transport surfaces in three places:

### 1. `packages/agent/src/streaming.ts` — SSE encoder + ReadableStream

Exports:

- `encodeExecutorEventAsSse(event: ExecutorEvent, id: number): string`
  — converts a single event to the SSE wire format:
  `id: <n>\nevent: <kind>\ndata: <JSON>\n\n`.
  The `event:` field carries the discriminator (`step-start`,
  `tool-call`, etc.) so a future `EventSource` consumer can attach
  per-event listeners; the `data:` field is the full JSON-serialized
  event body. Each frame ends with the spec-mandated blank line.
- `decodeExecutorEventFromSse(frame: string): ExecutorEvent` — inverse
  for round-trip tests + the editor-shell consumer.
- `toReadableStream(iterable: AsyncIterable<ExecutorEvent>, opts?): ReadableStream<Uint8Array>`
  — wraps the executor's async iterable in a `ReadableStream` whose
  chunks are UTF-8 encoded SSE frames. Accepts an optional `AbortSignal`
  that, when triggered (e.g. client disconnect), propagates cancellation
  to the underlying iterator via its `return()` method.
- `STREAM_SENTINEL_PLAN_CANCELLED` — terminal event emitted by the
  encoder when the upstream signal aborts mid-stream:
  `{ kind: 'plan-cancelled', reason: 'aborted' }`. This is NOT a member
  of `ExecutorEvent` proper; it is a transport-only sentinel so the
  client knows the stream was truncated by abort vs. completed normally.

### 2. `apps/stageflip-slide/src/app/api/agent/execute/route.ts`

The existing POST handler is extended with a streaming branch driven
by the `?stream=true` query param:

```
POST /api/agent/execute?stream=true
Content-Type: application/json
Accept: text/event-stream
```

Behavior:

- Body validation: same Zod schema as the non-streaming branch.
- Response: `text/event-stream`, `cache-control: no-store`,
  `connection: keep-alive`, `x-accel-buffering: no` (disables
  reverse-proxy buffering on nginx / vercel-proxy).
- Response body: the `ReadableStream<Uint8Array>` produced by
  `toReadableStream(orchestrator.streamEvents(...))`.
- Cancellation: `request.signal` is forwarded into the executor as
  its `AbortSignal`; when the client closes the connection, the
  executor unwinds, drains pending patches, and the stream emits the
  `plan-cancelled` sentinel before closing.

The non-streaming JSON path is **untouched** — callers who don't pass
`?stream=true` get exactly the response shape they got at d68b4e3a.

### 3. `packages/editor-shell/src/streaming-consumer.ts`

Client-side SSE consumer. Surfaces:

- `consumeAgentStream(response: Response, handlers: AgentStreamHandlers): Promise<void>`
  — reads the body's `ReadableStreamDefaultReader<Uint8Array>`, splits
  on the SSE record delimiter (`\n\n`), decodes each record via
  `decodeExecutorEventFromSse`, and dispatches into the provided
  `AgentStreamHandlers` map (one optional callback per event kind plus
  an `onCancelled` for the transport sentinel).
- `AgentStreamHandlers` interface — discriminated by event kind so
  type-narrowed payloads land at the right handler without manual
  switching.

The consumer handles:

- Partial frames at chunk boundaries (a `\n\n` may split across two
  network chunks).
- Trailing whitespace.
- Empty keepalive frames (server-emitted `: keepalive\n\n` comments —
  silently dropped, never dispatched).

## Orchestrator surface (`@stageflip/app-agent`)

A new `streamAgent(request: RunAgentRequest, options?: { signal?: AbortSignal })`
exports an `AsyncIterable<ExecutorEvent>`. Internally it runs the
Planner synchronously (planner emits one Plan, not events), then forwards
the executor's iterable. The validator runs **after** the executor
iterable completes; its result is published as a synthesized
`{ kind: 'plan-end', finalDocument, validation }` augmentation — but
since `plan-end` already carries `finalDocument`, we instead emit one
additional event after `plan-end`:

```ts
| { kind: 'validation-complete'; validation: ValidationResult }
```

— a transport-layer-only event NOT added to the canonical
`ExecutorEvent` union. The streaming layer's wire format carries both
shapes; the typed consumer surfaces it via `handlers.onValidationComplete`.

## Cancellation contract

| Client action | Server response |
|---|---|
| `fetch(..., { signal })` aborted | `request.signal.aborted` flips → forwarded to executor → executor returns `step-end` with status `'aborted'` → stream emits `plan-cancelled` → stream closes |
| TCP close mid-stream | Same — Next.js surfaces this on `request.signal` |
| Stream completes normally | `plan-end` → `validation-complete` → close |

Server-side cleanup:

- Pending patches in the executor's `patchSink` are drained and dropped.
- LLM in-flight `provider.complete` calls receive the abort signal via
  the existing `LLMProvider` contract.
- No partial mutation persists — the document mutation lives inside the
  executor's async generator; on abort, the iterator's `return()` triggers
  a clean unwind without partial writes leaking out.

## SSE wire format

```
id: 0
event: step-start
data: {"kind":"step-start","stepId":"s1"}

id: 1
event: tool-call
data: {"kind":"tool-call","stepId":"s1","name":"create_slide","args":{...}}

id: 2
event: tool-result
data: {"kind":"tool-result","stepId":"s1","name":"create_slide","result":{...},"isError":false}

id: 3
event: patch-applied
data: {"kind":"patch-applied","stepId":"s1","patch":[{"op":"add","path":"/...","value":...}]}

id: 4
event: step-end
data: {"kind":"step-end","stepId":"s1","status":"ok"}

id: 5
event: plan-end
data: {"kind":"plan-end","finalDocument":{...}}

id: 6
event: validation-complete
data: {"kind":"validation-complete","validation":{"tier":"pass","programmatic":[...],"qualitative":[...]}}
```

The `id:` field is a monotonically-increasing integer for each event in
this stream (NOT a stable cross-request id). It exists for spec
compliance (`EventSource.lastEventId`) but resumability is **out of
scope** for T-442; reconnect = new stream.

  the SSE encoder + decoder (`encode → decode === input`).

  frames with monotonic `id:` values; abort propagation triggers the
  `plan-cancelled` sentinel.
- `route.test.ts` — `?stream=true` returns 200 with

  the request signal closes the stream and emits `plan-cancelled`.

  split-frame boundaries + comment lines) through `consumeAgentStream`
  and verifies handler dispatch.

  appends `validation-complete`.
