# T-456 — Audience-join UX

**Branch**: `task/T-456-audience-join-ux`

## Goal

Ship the **audience-join UX**: the public voter landing page that QR /
code links resolve to, plus the in-editor QR + code modal presenters
display to invite voters. Carries three concerns:

1. **`apps/audience-join` — Next.js public voter landing page**:
   - New app at port `3500` (free port; aligns with the
     `stageflip-{slide,video,display}` 31xx-32xx-33xx convention with a
     35xx slot for the audience surface).
   - Public route `/[sessionId]` — anonymous-OK; mints a voter-token
     via `POST /v1/audience/sessions/:sessionId/join` (T-453 endpoint),
     opens a WebSocket via `@stageflip/runtimes-audience`'s
     `runAudienceClient` (T-454), and renders the per-clip-kind voter
     input UI.
   - Per-clip-kind voter UI — minimal v1 scaffolds dispatched by
     `clipKind`: each renders a placeholder pending T-461..T-471
     (e.g., `<LivePollMultipleChoiceVoterInput />`). T-456 ships the
     dispatcher + a generic "submit vote" form scaffold; the per-kind
     polished UIs land with their clip families.
   - Connection-status surface — shows WebSocket connection state +
     surfaces `LF-AUDIENCE-CONNECTION-LOST` from the client at budget
     exhaustion.
   - Determinism: this app sits OUTSIDE the determinism perimeter (it
     is `apps/**`, not `packages/runtimes/**`); standard browser
     primitives are fine.
2. **`packages/editor-shell/src/audience-join/` — `<AudienceJoinModal>`**:
   - Modal component the editor mounts when the presenter opens an
     audience-clip's "Invite voters" affordance.
   - Renders QR code (via `qrcode` MIT lib + a small React wrapper) for
     the voter URL `https://<audience-join-app>/<sessionId>` + a 6-char
     room code (a deterministic mapping from `sessionId` for human
     entry).
   - Surfaces the active session's voter count + a "close session"
     button (calls `POST /v1/audience/sessions/:sessionId/close`).
   - Tenant-feature-gated: hidden when
     `TenantSettings.features.audience.enabled !== true`.
3. **Voter-URL config + room-code helper**:
   - `packages/audience-join-shared/` — small workspace package that
     ships the `roomCodeFor(sessionId): string` helper (deterministic
     6-char alphanumeric encoding of the sessionId — collision-resilient
     by design; not a security boundary, just a human-friendly entry
     code) + the public voter-URL builder.
   - Both the editor-shell modal AND the audience-join app import from
     here so the URL/code generation is one source of truth.

**Strict scope** — voter UX surfaces only. NO new audience-clip
implementations (T-461..T-471 ship the per-kind voter inputs the
landing page dispatches into). NO server-side auth/session changes
(T-453 already ships the join endpoint + voter-token mint). NO QR
scanning in the editor (the editor displays the QR — voters scan it
with their phones outside the app boundary). NO push notifications. NO
WebSocket fallback / long-polling (out-of-scope per ADR-009). NO
editor-side analytics dashboards (T-459 result-export covers
post-session export).

## Implementation notes

- **Port assignment**: `3500` for `apps/audience-join` (slot:
  31xx-32xx-33xx are slide/video/display; 34xx free; 35xx audience).
  Document in the new app's package.json scripts.
- **`qrcode` lib choice**: `qrcode@^1.5.4` (MIT). Alternative
  `qrcode.react` adds React-specific bindings but `qrcode` returns a
  data-URL string + the modal can render `<img src={dataUrl} />`. The
  smaller surface keeps the dep minimal.
- **Room-code algorithm**: take SHA-256 of `sessionId`, base32-encode
  the first 30 bits → 6 chars from alphabet `[A-Z2-9]` (excluding
  ambiguous `I`, `O`, `0`, `1`). Deterministic; collision rate at 30 bits
  / Crockford-style alphabet is ≈1B unique codes — well within v1
  needs. Document the algorithm in TSDoc.
- **Voter-URL builder**: validates `baseUrl` is a non-empty https URL
  (or http for local dev); returns `${baseUrl}/${sessionId}`.
- **Per-clip-kind dispatcher**: a `Map<AudienceClipKind, React.ComponentType<...>>`
  populated by per-kind imports later. T-456 ships an empty registry +
  a `<UnregisteredKindFallback />` component that displays "Voting
  for this clip kind is not yet available". The runtime contract is
  identical to T-454's `audienceClipRegistry` pattern.
- **Connection-status surface**: a small banner component reading
  `runAudienceClient`'s status events (idle / connecting / connected /
  reconnecting / disconnected). The loss-flag surface is via the
  injected `emitLossFlag` callback the voter app provides.
- **Tenant-feature gating in the modal**: the modal accepts a
  `tenantAudienceEnabled: boolean` prop the editor injects from
  `TenantSettings.features.audience.enabled`. When false, the modal
  renders a "Audience features are disabled for your tenant" notice
  instead of the QR.
- **No `console.log`** outside `scripts/**`.
- **No default exports** except Next.js pages (CLAUDE.md §3 — Next.js
  pages MUST default-export per the framework convention).
- **File headers** on every new file.
- **TSDoc** on exports.
- **Pre-empt skills-sync drift**: run `pnpm skills-sync`; the
  audience-engagement skill (T-457) lives downstream so this is likely
  a no-op.
- **Biome format** every touched file.
- **NEVER `git add -A`**.
