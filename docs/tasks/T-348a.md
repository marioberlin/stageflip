# T-348a — Cluster D multi-clip composition rendering fix

## Why this task exists

PO ratification 2026-05-08 caught a multi-clip composition regression in Cluster D — 5 of 6 signed presets rendered blank or near-blank despite passing parity-fixture-scoring CI gates. Root cause documented in [`docs/handover-cluster-d-regression.md`](../handover-cluster-d-regression.md): each `RIRDocument.elements` entry composites in the host's z-stack, and the topmost overlay (`photographic-overlay`) renders an OPAQUE rect that masks everything below. Reverted in PR #444; the 5 presets are back to `pending-user-review`.

This task is **Phase 2** of the regression remediation per the handover doc. It implements the architectural fix; **Phase 3** (re-generate goldens + PO ratification) is a separate task; **Phase 4** (CI gate against blank parity goldens) is a separate task; **F-30 process lesson** documentation is a separate task.

## Decisions

### D-T348a-1 — diagnosis: photographic-overlay was the only broken primitive

The handover doc's Option A prescribed transparent-by-default across all 5 affected primitives. Closer reading of the host composition flow ([`composition.tsx:49`](../../packages/cdp-host-bundle/src/composition.tsx)) and the regression visuals (succession + got-trajan rendered pale-yellow = sepia tint of opaque white) shows:

- **`grain`**: already renders a `<canvas>` with no opaque background → already transparent.
- **`light-leak`**: outer `<div>` has `mixBlendMode: 'screen'`, no opaque background → already composites correctly.
- **`particles`**: container declares `backgroundColor: 'transparent'` by default → already transparent.
- **`photographic-overlay`**: SVG renders `<rect fill="rgba(255,255,255,1)">` filtered to a tinted output — OPAQUE post-filter; this is the visible-mask primitive in 4 of 5 affected presets.
- **`title-sequence`**: at zIndex 0, its `background: '#000000'` IS the canvas backdrop in the multi-clip case — correct. But the primitive defaulted `props.background` to `#000000` even when caller omits the prop, which would mask future overlay-context use.

### D-T348a-2 — fix: `mixBlendMode: 'multiply'` on photographic-overlay's SVG

Multiply preserves solo-use behaviour against the host's white canvas backdrop (`white × tinted-white = tinted-white`, byte-identical to pre-T-348a output) AND tints content rendered below in multi-clip composition (`titleSequence-content × tinted-white = tinted-content`). All 4 modes (sepia / cross-process / cinematic-lut / fade) use the same blend mode; the `intensity` alpha-blend chain remains unchanged.

**Rejected alternatives**:

- `mixBlendMode: 'screen'` (per fade mode only) — adds per-mode logic; inconsistent compositing semantics.
- `backdrop-filter` — non-deterministic across CDP versions; fails the determinism contract.
- Renderer-side compositing (Option B from regression doc) — broader scope; touches host bundle + parity-CLI; out of scope for Phase 2.

### D-T348a-3 — defensive default: `title-sequence.tsx` no longer hard-codes `#000000`

When `props.background` is omitted, the root container renders without an opaque `backgroundColor` so layers below in the z-stack composite through. Caller-provided `background` still respected. The 5 affected presets continue to pass `background: '#000000'` (zIndex 0 = canvas backdrop = correct opaque). `palette-jump-cut` style continues to drive container `backgroundColor` from active `colorPanel.color`.

This is a no-op for current consumers (squid-game-geometric passes `'#0E0E12'`; the 5 multi-clip presets pass `'#000000'`) but is defensive against future overlay-context consumers of titleSequence.

### D-T348a-4 — preset bindings unchanged

The 5 multi-clip presets (`STRANGER_TITLE_SEQUENCE_PROPS`, `TRUE_DETECTIVE_TITLE_SEQUENCE_PROPS`, `SUCCESSION_TITLE_SEQUENCE_PROPS`, `SEVERANCE_TITLE_SEQUENCE_PROPS`, `GOT_TRAJAN_TITLE_SEQUENCE_PROPS`) keep their explicit `background: '#000000'`. The deep-canvas backdrop is correct semantic for zIndex 0 in these presets — the regression is at the TOP of the z-stack (photographic-overlay), not the bottom.
