# T-418 — `@stageflip/adapters-core`

**Branch**: `task/T-418-adapters-core`

## Goal

Ship the first substantive Phase 14 α code package — `@stageflip/adapters-core`
— implementing the runtime substrate for ADR-007 (T-415, PR #478, merged
2026-05-11; Provider Seam Pattern). This is the package every reference
adapter (T-426..T-434) registers itself into; the capability-routing engine
(T-425) consumes from; and Phase 16 marketplace contributions (T-490+)
ratify against.

The package ships five concerns:

1. **`AdapterDescriptor`** — type + Zod schema verbatim from ADR-007 §D1
   (id / modality / capability / license / sandbox / costPerCall? /
   latencyMs? / sourceGrounded? / requiresResearchProvider?).
2. **`AdapterRegistry`** — in-memory map keyed by `(modality.kind, id)`;
   `register` / `unregister` / `lookup` / `list` / `byCapability`.
3. **`CapabilityDescriptorParser`** — pluggable per-modality validator
   dispatch. The parser itself ships only the dispatch shell; per-modality
   validators (TTS sample-rate, video-gen aspect-ratio, etc.) land via
   T-419 in `@stageflip/asset-gen-contract`.
4. **`LicenseGate`** — pluggable predicate
   `(adapter, tenantContext) => 'allow' | 'deny' | 'requires-consent'`.
   Default impl matches the `THIRD_PARTY.md` whitelist (per ADR-007 §D3 +
   CLAUDE.md §3): `gpl-incompatible` is refused unconditionally;
   `proprietary-byo` requires tenant credential present;
   `proprietary-vendored` admissible only under `permit-vendored` /
   `permit-all` postures; etc.
5. **`FallbackChainExecutor`** — `execute<T>(adapters, call)` iterates the
   chain on failure; emits one telemetry event per failure; returns either
   `{ ok: true, result, adapter, attempts }` or
   `{ ok: false, errors: AdapterError[] }`.

**Strict scope** — registry + dispatch + license-gate + fallback-executor
ONLY. Modality-specific contracts (per-call shapes for TTS / video-gen /
etc.) are T-419's freedom. Concrete adapters (Kokoro TTS, Suno music,
Mubert SFX, etc.) are T-426..T-434.

## Architecture detail

### `AdapterDescriptor` shape

Verbatim from ADR-007 §D1. The `capability` field is typed as the opaque
`CapabilityDescriptor = Readonly<Record<string, unknown>>` envelope so the
registry / license-gate / fallback-executor can be modality-agnostic.

`modality` is the discriminated union of all 14 kinds enumerated in
ADR-007 §D1:

- Phase 14 β asset-gen: `tts` / `video-gen` / `music-gen` / `sfx` /
  `three-d`
- Phase 14 source-grounded: `slide-deck-gen` / `mind-map-gen` /
  `table-gen` / `quiz-gen` / `flashcard-gen` / `report-gen` /
  `infographic-gen`
- Source-grounded session: `research-session`
- Phase 15: `audience-backend`
- Phase 16: `bundle`

`license` is the discriminated union of six postures from ADR-007 §D1:
`apache-2.0` / `mit` / `proprietary-byo` / `proprietary-vendored` /
`cc-by` / `gpl-incompatible`.

`sandbox` is the discriminated union of four kinds from ADR-007 §D4:
`in-process` / `{ kind: 'sidecar', runtime: 'node' \| 'python' }` /
`{ kind: 'remote-service', baseUrlEnvVar }` / `wasm-sandbox`.

`costPerCall` is `{ usd?: number; tokensIn?: number; tokensOut?: number }`
(rough vendor-quoted estimate); `latencyMs` is
`{ p50?: number; p95?: number }`. Both optional. The capability-routing
engine (T-425) will use these for ranking when multiple adapters satisfy
the capability filter.

### `AdapterRegistry` keying

The key is `${modality.kind}::${id}`. The same `id` MAY repeat across
modalities (e.g., a hypothetical adapter shipping both TTS and SFX would
register twice with the same id; this is allowed). Duplicate
`(modality.kind, id)` pairs throw on `register()`.

### `CapabilityDescriptorParser` plug-in shape

The parser is a dispatch shell. Per ADR-007 §D1's "Why `capability` is
opaque" rationale, T-418 cannot validate per-modality shapes — that is
T-419's responsibility. T-418 ships the constructor that accepts a
`Map<AdapterModality['kind'], (capability: unknown) => CapabilityValidationResult>`
and a `parse(descriptor)` method that:

1. Dispatches by `descriptor.modality.kind`.
2. If no validator registered: returns `{ ok: 'unvalidated', capability: descriptor.capability }`.
3. If validator returns `{ ok: true }`: passes capability through.
4. If validator returns `{ ok: false, error }`: returns the error verbatim.

This lets T-419 land its first validator (e.g., for TTS) without touching
T-418's source.

### `LicenseGate` decision matrix

Per ADR-007 §D3 + THIRD_PARTY.md (Permitted vs. Forbidden Licenses):

| License posture (adapter) | `apache-2.0-only` | `permissive-only` | `permit-byo` | `permit-vendored` | `permit-all` |
|---|---|---|---|---|---|
| `apache-2.0` | allow | allow | allow | allow | allow |
| `mit` | deny | allow | allow | allow | allow |
| `cc-by` | deny | allow | allow | allow | allow |
| `proprietary-byo` (cred present) | deny | deny | allow | allow | allow |
| `proprietary-byo` (cred missing) | deny | deny | requires-consent | requires-consent | requires-consent |
| `proprietary-vendored` | deny | deny | deny | allow | allow |
| `gpl-incompatible` | **deny (unconditional)** | deny | deny | deny | deny |

`gpl-incompatible` is refused unconditionally — preserves the
CLAUDE.md §3 / `pnpm check-licenses` whitelist invariant. The
`requires-consent` outcome surfaces as `LF-ADAPTER-CREDENTIAL-MISSING`
in the routing engine (per ADR-007 §D11); T-418 only emits the verdict
— the loss-flag wiring is T-425.

`TenantContext.credentials` is a `ReadonlySet<string>` keyed by
`adapter.id` — caller decides what counts as "credential present"; the
gate just checks `credentials.has(adapter.id)` on `proprietary-byo`.

### `FallbackChainExecutor` determinism

The executor body is deterministic for given input:

- `adapters` array iterated in order — order is the caller's contract
  (the routing engine will produce a ranked list per ADR-007 §D3 step 5).
- `call(adapter)` is awaited sequentially — no `Promise.all` /
  `Promise.race`; ranked-fallback semantics are sequential by design.
- On rejection: an `AdapterError` is captured with deterministic fields
  (`adapterId`, `modality`, `cause: unknown`); telemetry emit with
  `event: 'adapter.fallback.failure'` and `attributes: { adapterId,
  modality, errorMessage }` (no timestamps unless caller injected a
  `clock`).
- On success: returns `{ ok: true, result, adapter, attempts }` with
  `attempts: number` recording how many adapters were tried (1-indexed).
- On all-failed: returns `{ ok: false, errors: AdapterError[] }` in
  iteration order.
- Empty `adapters[]` returns `{ ok: false, errors: [] }` immediately
  (telemetry NOT emitted — there was no failure to report).

The executor itself does not call `Date.now()` / `performance.now()`. If
the caller wants timestamped telemetry, they pass a `clock?: () => number`
option; the value is included in telemetry attributes verbatim.

### Telemetry shape

Mirrors `packages/runtimes/interactive/src/contract.ts:57`:
`type EmitTelemetry = (event: string, attributes: Record<string, unknown>) => void`.
Default `noopEmitTelemetry` swallows the event. Production wiring (when
T-264 OpenTelemetry hooks are connected to adapters-core in a later
task) supplies a forwarding implementation.

## Acceptance criteria

- **AC-1**: `AdapterDescriptor` type + Zod schema parse all 14 modality
  kinds + 6 license postures + 4 sandbox kinds round-trip without loss.
- **AC-2**: `AdapterRegistry.register()` throws on duplicate
  `(modality.kind, id)`; `unregister()` is idempotent; `list()` returns
  insertion order; `lookup(modality, id)` returns `undefined` on miss;
  `byCapability(modality, predicate)` filters correctly.
- **AC-3**: `CapabilityDescriptorParser` dispatches by `modality.kind`;
  returns `unvalidated` when no validator registered; passes-through
  validator-returned errors verbatim.
- **AC-4**: `LicenseGate` default impl matches the matrix above for every
  cell. `gpl-incompatible` denies under every posture.
- **AC-5**: `FallbackChainExecutor.execute()` short-circuits on first
  success, aggregates all errors on full failure, emits exactly one
  telemetry event per failure, and produces deterministic telemetry
  payloads for given input.
- **AC-6**: `pnpm --filter @stageflip/adapters-core build` succeeds.
- **AC-7**: `pnpm --filter @stageflip/adapters-core test` ≥85% coverage
  on every module.
- **AC-8**: All repo-wide gates green: `pnpm typecheck && pnpm lint &&
  pnpm test && pnpm check-licenses && pnpm check-remotion-imports &&
  pnpm check-determinism && pnpm check-skill-drift &&
