# T-452 — `@stageflip/audience-contract`

**Branch**: `task/T-452-audience-contract`

## Goal

Ship `@stageflip/audience-contract` — the audience-modality contract
package that ADR-009 (T-450 / PR #512) + ADR-010 (T-451 / PR #513)
specify. T-418 (`@stageflip/adapters-core`) ships the substrate
(`AdapterDescriptor`, `AdapterRegistry`, `CapabilityDescriptorParser`);
T-419 (`@stageflip/asset-gen-contract`) ships the Phase 14 per-modality
plug-ins. T-452 is the **Phase 15 α first post-hard-gate task** — it
ships the audience analog of T-419: pure interfaces + Zod schemas + a
capability validator that plugs into `CapabilityDescriptorParser`.

The package ships five concerns:

1. **`AudienceBackendProvider` interface** per ADR-009 §D2:
   - Extends `AdapterDescriptor` from `@stageflip/adapters-core`
   - Four methods: `openSession` / `submitVote` / `subscribe` /
     `closeSession`
   - `AudienceCapabilityDescriptor` shape + capability validator that
     plugs into `CapabilityDescriptorParser` (T-418).
2. **Per-clip-kind `VotePayload` discriminated union** per ADR-010 §D2:
   - One variant per `AudienceClipKind` (eleven discriminants; the
     `leaderboard` variant types as `never` per the §D2 derived-clip
     invariant).
   - Strict Zod schemas.
3. **Per-clip-kind `AggregationSnapshot` discriminated union** per
   ADR-010 §D3:
   - One variant per `AudienceClipKind` (eleven).
   - Strict Zod schemas.
4. **`AudienceProvenance` schema preview** per ADR-010 §D5:
   - Shared slots: `provider`, `sessionId`, `snapshotFrame`,
     `voterCountAtCapture`, `capturedAt`, `snapshotPolicy`, `clipKind`,
     `aggregation`.
   - Full schema lands in T-460 (schema additions); this is the
     preview the consumer service (T-453) imports as the typed
     `FinalSnapshot` companion.
5. **Loss-flag codes** per ADR-009 §D11:
   - Eight `LF-AUDIENCE-*` codes documented in TSDoc; values exported
     as a sealed `const` array.

Every consumer of this package (T-453 backend service, T-454 audience
runtime, T-461..T-471 audience clips, T-475/T-478 native +
T-479..T-483 vendor adapters) imports from here; no other package
re-declares these shapes.

**Strict scope** — interfaces + Zod schemas + capability validator
ONLY. NO concrete provider implementations (T-453 backend service +
T-475/T-478/T-479..T-483 native + vendor adapters). NO clip
implementations (T-461..T-471). NO schema-side wiring for
`AudienceProvenance` (T-460 lands the strict element-base merge). NO
modifications to `@stageflip/loss-flags` — the eight `LF-AUDIENCE-*`
codes are string-typed (per the package contract) and emit at use site;
T-453/T-454 consume the sealed `const` array this package exports.

## Implementation notes

- `audience-backend-provider.ts` mirrors `tts-provider.ts` structure: type declarations, then the provider interface that `Omit`s `modality` + `capability` from `AdapterDescriptor` and narrows them to the audience-specific shape.
- `capability.ts` is split out (vs. asset-gen-contract's per-modality file which bundles capability + call/result) because the audience modality has only ONE provider interface (not five); the capability schema is reused across the open/submit/subscribe/close lifecycle and gets its own file for clarity. The pattern is still T-419 — just with a different fan-out.
- `subscribe()` returns `AsyncIterable<AggregationSnapshot>` (per ADR-009 §D2). The contract package types this; the consumer (T-453) implements the WebSocket bridge that materializes the iterator.
- `closeSession()` returns `FinalSnapshot extends AggregationSnapshot` — per ADR-009 §D2 the final snapshot is the authoritative export bytes; T-460 wires this into `AudienceProvenance.aggregation`.
- The `kind: 'leaderboard'` variant of `VotePayload` types as `never` per ADR-010 §D2 ("Leaderboard is derived from LiveQuiz; voters do not submit directly"). The Zod schema for the discriminated union has no `leaderboard` member; consumers branch on `payload.kind !== 'leaderboard'` before calling `submitVote`.
- `AudienceProvenance.aggregation` typed as the full `AggregationValue` discriminated union (not just `unknown`) per ADR-010 §D5 — the bytes are inlined in the provenance for export-time durability (the rationale is in the ADR; T-452 just types it).
- Loss flags are exported as `LF_AUDIENCE_CODES = [...] as const` with a derived `LossFlagAudienceCode` type. T-453 + T-454 import the union type when emitting; the values match the ADR-009 §D11 inventory verbatim.
