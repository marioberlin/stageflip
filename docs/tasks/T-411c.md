# T-411c — Permission-shim wiring for tenant frontier flag

**Third downstream PR of T-411** (parent spec merged in #472, commit
`f25405d8`; storage layer merged in #473, commit `ebffa62f`; API + CLI
merged in #474, commit `ebfaf6bc`). Implements the **permission-shim
integration only** per T-411 §D-T411-4 + §D-T411-5: adds a
**tenant-flag cache** to the interactive runtime host and wires the
D-T411-4 `(features.interactive, target)` matrix into the existing
`PermissionShim`'s mount-time check.

Strict scope: NO admin UI (T-411e); NO docs cross-link or skill file
(T-411d); NO changes to storage / API / CLI (T-411a / T-411b own).

## Architectural decisions

All design intent is inherited from the parent T-411 spec. This sub-
spec resolves the implementation-level choices the parent left to the
implementer.

### D-T411c-1 — Two-surface split: `host/tenant-flag-cache.ts` (new) + `permission-shim.ts` (modified)

The cache lives in a new file `packages/runtimes/interactive/src/host/tenant-flag-cache.ts`.
Rationale:

- The cache has an independent lifecycle from the shim (populated at
  session start, drained on session end / reset; the shim is
  per-session-but-stateful around the grant cache).
- Co-locating the cache with the shim would force the shim to import
  storage types or a populator function it never invokes from the
  hot path.
- A separate file keeps the **populator surface** (the only async /
  network entry-point) clearly out of `permission-shim.ts` so future
  reviewers cannot accidentally introduce an `await` on the
  mount-time hot path.

The `host/` subdirectory is **new** — created by this PR. Future
host-shell-only surfaces (session-init plumbing, telemetry sinks
outside the shim) accrete here without polluting the public clip
contract surface.

### D-T411c-2 — Sync mount-time read, async populator at session start (T-411 D-T411-4 verbatim)

Two surface modes on `TenantFlagCache`:

```ts
interface TenantFlagCache {
  /**
   * Sync mount-time read. Returns the cached `features.interactive`
   * value for `(tenantId, target)`, or `undefined` when no entry was
   * populated. Callers MUST treat `undefined` as default-deny per
   * T-411 D-T411-5 (see `evaluateTenantFlagGating` in permission-shim.ts).
   *
   * Pure function over the cache state; no I/O, no `await`, no
   * `Date.now()`. Safe to call from clip-mount paths inside
   * `packages/runtimes/**/src/clips/**` (those paths are
   * determinism-gated; see CLAUDE.md §3).
   */
  readSync(tenantId: string, target: TenantFlagTarget): TenantFlagValue | undefined;
}
```

```ts
type TenantFlagPopulator = (
  tenantId: string,
) => Promise<TenantFlagValue | null>;

interface MutableTenantFlagCache extends TenantFlagCache {
  /**
   * Async populator. Called from the host shell at session start (NOT
   * from clip code). Resolves the tenant's `features.interactive`
   * value via the supplied populator (which calls
   * `TenantSettingsStore.getTenantSettings` or the equivalent HTTP
   * route from T-411b) and seeds entries for every target.
   *
   * Default-deny on populator returning `null` (absent tenant): the
   * cache stores `'disabled'` for every target. Default-deny on
   * populator throwing: the cache leaves the entries unset, which the
   * sync-read default-deny path treats identically to `'disabled'`.
   */
  populate(tenantId: string): Promise<void>;
  /**
   * Drain the cache for a single tenant (e.g., on tenant logout) or
   * for all tenants (no argument; e.g., on session end / test
   * teardown).
   */
  evict(tenantId?: string): void;
}
```

The factory `createTenantFlagCache({ populator })` returns a
`MutableTenantFlagCache`. Consumers narrow to the read-only
`TenantFlagCache` surface when handing it to the shim — the shim only
needs `readSync`.

### D-T411c-3 — Populator is injected, not imported

The cache does NOT import `@stageflip/storage`. Rationale:

- `@stageflip/runtimes-interactive` should not couple to the storage
  package — the runtime tier is browser-bundle-safe and storage adapters
  are server-side.
- The host shell (which lives outside this package — likely
  `apps/stageflip-{slide,video,display}` editor shells) decides how to
  resolve a tenant's settings: directly via
  `TenantSettingsStore.getTenantSettings` server-side, or via a fetch
  against T-411b's `GET /v1/tenant-settings/:tenantId` from the
  browser. Both shapes satisfy the `TenantFlagPopulator` signature.
- Tests inject an in-memory populator (a `vi.fn()` returning a fixed
  value) without touching real storage or network.

The populator returning `null` semantically means "tenant absent /
not yet provisioned" and the cache materialises the D-T411-5
default-deny posture (`'disabled'`).

### D-T411c-4 — D-T411-4 matrix as a sealed const

The `(setting, target)` matrix from T-411 D-T411-4 is encoded as a
typed const so TypeScript's exhaustiveness checking enforces every
cell is handled. Decision values: `'live-mount'` (the shim continues
through the existing tenant-policy + permission-prompt steps) or
`'static-fallback-only'` (the shim short-circuits to staticFallback,
mirroring the existing `tenant-denied` reason path):

```ts
type TenantFlagDecision = 'live-mount' | 'static-fallback-only';
type TenantFlagValue = 'disabled' | 'preview' | 'ga';
type TenantFlagTarget = 'html' | 'browser-live-preview' | 'on-device-display';

const TENANT_FLAG_GATING_MATRIX: Readonly<
  Record<TenantFlagValue, Readonly<Record<TenantFlagTarget, TenantFlagDecision>>>
> = {
  disabled: {
    html: 'static-fallback-only',
    'browser-live-preview': 'static-fallback-only',
    'on-device-display': 'static-fallback-only',
  },
  preview: {
    html: 'live-mount',
    'browser-live-preview': 'live-mount',
    'on-device-display': 'static-fallback-only',
  },
  ga: {
    html: 'live-mount',
    'browser-live-preview': 'live-mount',
    'on-device-display': 'live-mount',
  },
};
```

The matrix is restated **verbatim** from T-411 D-T411-4 (which itself
restates ADR-005 §D3). Both files MUST stay in sync; T-411d will
land the cross-link.

### D-T411c-5 — Permission-shim integration: optional new step 0 BEFORE tenant-policy

The existing shim's mount sequence (per its file header):
1. tenant-policy `canMount(family)` → short-circuit on deny
2. iterate permissions → short-circuit on deny

T-411c inserts a **new step 0** that is opt-in via constructor option
(`tenantFlagGate?`):

0. tenant-flag matrix check via `TenantFlagCache.readSync` → short-
   circuit to `staticFallback` on insufficient posture.

When the option is omitted (back-compat with all T-306 / T-385
consumers), the shim behaves exactly as before — no tenant-flag
check, no cache lookup. When the option is supplied, the shim
performs the matrix check FIRST, before the family-policy gate. This
ordering matches ADR-005 §D5 step 1 (tenant-flag check is the
outermost gate).

The new `PermissionResult` discriminator gains a third `reason`
value: `'tenant-flag-denied'`. Existing consumers that switch on
`reason` without exhaustiveness will continue to compile (the type
is widened, not narrowed); consumers using `assertNever`-style
exhaustiveness MUST add a case (a deliberate, narrow surface
change).

### D-T411c-6 — Default-deny on cache miss (T-411 D-T411-5 verbatim)

If `readSync(tenantId, target)` returns `undefined` (cache was not
populated for this tenant, or this target was never seeded), the
shim treats the value as `'disabled'` and returns
`'static-fallback-only'`. The `permission-denied-tenant-flag`
telemetry event (D-T411c-7) carries the cache-miss case explicitly
so operators can distinguish "actively disabled" from "tenant flag
not loaded" at observability time.

### D-T411c-7 — Telemetry event per T-411 AC #20

The shim emits `'permission-denied-tenant-flag'` with attributes:

```ts
{
  family: InteractiveClip['family'],
  tenantId: string,
  target: TenantFlagTarget,
  flagValue: TenantFlagValue | 'cache-miss',  // 'cache-miss' = default-deny path
}
```

Naming follows the existing `'tenant-denied'` / `'permission-denied'`
event family in `permission-shim.ts`. The telemetry sink is the
existing `EmitTelemetry` parameter — no new wiring.

### D-T411c-8 — Determinism posture: hot path stays sync + pure

The mount-time call chain is:

```
PermissionShim.mount(clip, options)
  → evaluateTenantFlagGating(cache, tenantId, target)
    → cache.readSync(tenantId, target)             // pure Map lookup
  → (existing) tenant-policy + permission iteration
```

No `Date.now()`, no `Math.random()`, no `fetch()`, no `setTimeout`,
no `await` on the hot path. The cache populator (`populate(tenantId)`)
DOES `await` the injected populator — but that runs at session start
in the host shell, never from clip code.

`packages/runtimes/interactive/src/host/**` is **not** subject to
the `packages/runtimes/**/src/clips/**` determinism rule (CLAUDE.md
§3 scope), but the cache is written defensively as if it were:
`readSync` is a pure function over the in-process Map; the
populator is the only async surface.

### D-T411c-9 — Cache eviction policy

`evict(tenantId)` clears a single tenant's entries (e.g., when a
tenant logs out or is impersonated). `evict()` (no argument) clears
the entire cache (test teardown; session end). There is no automatic
TTL eviction in v1 — operators flipping a tenant's flag run
`evict(tenantId)` explicitly, then `populate(tenantId)` to re-seed.
This matches T-411 D-T411-8: rollback is mount-time-only; in-flight
mounts are not torn down.

A future enhancement may add a `revalidate(tenantId)` convenience
that combines `evict + populate`; v1 leaves callers to compose them
explicitly so the eviction surface stays minimal and explicit.

### D-T411c-10 — Tests cover every (setting × target) cell + cache-miss + populator failure

Per T-411 AC #19, every cell of the D-T411-4 matrix is covered by an
explicit shim test. That's 9 cells (3 settings × 3 targets) plus:

- Cache-miss → `'static-fallback-only'` + telemetry with
  `flagValue: 'cache-miss'`.
- Populator returning `null` → cache stores `'disabled'` for every
  target (default-materialisation per D-T411c-3).
- Populator throwing → cache leaves entries unset; subsequent
  `readSync` returns `undefined`; shim treats as cache-miss.
- `evict(tenantId)` → subsequent `readSync` returns `undefined`.
- Backward compat: shim with no `tenantFlagGate` option behaves
  identically to T-306 / T-385 baseline.

## Determinism posture

- **Mount-time path** (`PermissionShim.mount` → `cache.readSync`) is
  sync + pure: a `Map` lookup against the in-process cache. No
  `Date.now()`, no `Math.random()`, no `fetch()`, no `setTimeout`,
  no `requestAnimationFrame`, no `await` between the flag check and
  the deny return.
- **Cache populator** (`cache.populate`) is the ONLY async / network
  surface. It is called from the host shell at session start, never
  from clip code. The populator function itself is injected by the
  consumer; the cache makes no assumption about whether it calls a
  storage adapter, an HTTP route, or returns a static value.
- `packages/runtimes/interactive/src/host/**` is NOT in the
  `packages/runtimes/**/src/clips/**` scope of the determinism gate
  (CLAUDE.md §3), so `await` in the populator is permitted. The
  cache file is still written defensively to keep the sync surface
  obvious and the async surface localised.
