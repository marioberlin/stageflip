## Goal

generator on `f1-sector-purple-green` end-to-end, producing the three real

## Architectural decisions

### D-T359b-1. Renderer execution environment — local-first, then CI verifies

The prod-bound renderer requires Chrome (via puppeteer) + ffmpeg + a Node
toolchain. Two viable execution sites:

- **Local dev machine** (operator's laptop) — fast iteration; quick visual
  inspection; matches `docs/ops/parity-fixture-signoff.md` step-2 ("the
  product owner opens the golden-frame PNG"). Operator owns the sign-off
  per ADR-004 §D5.
- **CI runner** — reproducible environment; canonical font + Chrome version
  pinned via the workflow image.

T-359b runs **local-first, then verifies CI reproduces** the artifacts
within the parity thresholds. Rationale:

- Sign-off is operator-driven; the operator inspects the golden PNG
  visually before stamping. That step is local.
- CI then validates the committed artifacts against the operator's render
  via the parity harness — same goldens, same thresholds. If CI's render
  drifts beyond `PSNR ≥ 42 dB / SSIM ≥ 0.98` (T-359's pinned thresholds),
  the PR fails and the operator investigates.
- This matches the T-313 contract: goldens are committed reference
  artifacts, not byte-exact across machines. The parity harness is what
  guarantees correctness across environments.

The Implementer documents the local environment in the PR body (OS, Chrome
version, Node version, puppeteer version pinned in `package.json`) so a
future re-render is reproducible.

### D-T359b-2. Font availability — fallback to OFL `Barlow Condensed`

`Formula1 Display` is `proprietary-byo`. Three options:

- **(a) Manual font install** for any operator running the generator. Brittle, undocumented, and asymmetric across the team.
- **(b) Add to a `.gitignore`d fonts dir** for CI use. Still requires the operator to have the font; license posture (BYO) means we cannot vendor it.
- **(c) Fall back to OFL `Barlow Condensed`** (already declared as `fallbackFont` in T-359's frontmatter). The renderer transparently substitutes when the BYO font is not registered. Goldens are then OFL-rendered.

T-359b picks **(c)**. Rationale:

- The font-license registry (T-307) and T-359 D-T359-7 already pin OFL
  `Barlow Condensed` as the fallback. The render posture is "good enough,
  not broadcast-exact" by design.
- Goldens are tested against themselves — the parity harness's PSNR/SSIM
  contract is "future renders match the committed reference", not "future
  renders match the broadcaster's literal F1 Display output".
- BYO `Formula1 Display` becomes an operator-side enhancement: any operator
  who has the BYO font installed locally can re-render and re-sign with
  `--force`; the goldens then reflect the BYO face. This is documented in
  the PR body but does NOT happen in this PR.

If the operator's local environment happens to have `Formula1 Display`
installed system-wide, the renderer may pick it up — that's acceptable
provided the CI verification render (which won't have it) still meets the
parity threshold against the committed reference. If parity fails, the
operator must explicitly disable the BYO face for the canonical render
(unset the system font, or ensure the renderer's font preload list omits
it). The Implementer pins the canonical render posture in the PR body.

### D-T359b-3. PNG byte-determinism — trust existing PSNR/SSIM thresholds

Real PNGs differ across Chrome versions, GPUs, font subpixel-renderers,
and headless flags. T-313 + T-359 accept this: PSNR/SSIM thresholds (T-359
pins ≥ 42 dB / ≥ 0.98) tolerate small drift; the goldens are reference
artifacts, not exact copies.

T-359b does NOT attempt byte-determinism across machines. The contract is:

- Local render produces the goldens; operator visually inspects + signs.
- CI re-render against the committed goldens passes the PSNR/SSIM
  thresholds.
- Future re-renders (different operator, different CI build) similarly
  match within thresholds.

If CI consistently fails the parity threshold after T-359b lands, escalate
per CLAUDE.md §6 (renderer-environment drift is a blocker for every
downstream cluster sign-off, not just T-359).

### D-T359b-4. Variant → props mapping — owned by `clipKindResolver`, NOT preset frontmatter

T-359's preset documents three states semantically (`sessionBest` /
`personalBest` / `neutral`) in its `## Rules` body. The renderer needs
concrete prop values per variant (color hex, sample driver code, sample
sector label, sample sector time). Two options:

- **(a) Variant-prop builders inside `clipKindResolver`** — the resolver
  returns a `(variantName: string) => ChartProps` factory per clipKind.
  Keeps preset frontmatter clean. Variant-prop logic is a runtime concern.
- **(b) Variant-prop overrides in preset frontmatter** — adds a
  `variantProps` map to the schema. Schema change. Cross-cuts every
  cluster.

T-359b picks **(a)**. Rationale:

- Preset frontmatter stays minimal (matches T-359 D-T359-2 — "frontmatter
  delta is minimal").
- Variant-prop logic is isomorphic to clip rendering — the `bigNumber`
  clipKind already binds to `AnimatedValue`; the variant-prop builder is
  the missing piece between "preset declares the state palette" and
  "renderer consumes concrete props".
- `DEFAULT_CLIP_KIND_RESOLVER` in `packages/parity-cli/src/generate-fixture.ts`
  is the natural home. T-359a wired the resolver entry; T-359b extends it
  with the variant-prop builder for `bigNumber` (or — if T-359a already
  ships a variant-prop hook — uses it).

**Implementer's first action**: read `packages/parity-cli/src/generate-fixture.ts`
end-to-end. If T-359a already shipped a variant-prop hook (per-variant
props builder accepted by `createGenerateFixtureRenderer`), USE IT — no
infra change. If not, T-359b adds the minimal hook (a small contract
extension on `DEFAULT_CLIP_KIND_RESOLVER` keyed by `(clipKind, variant)`).

If the hook addition is non-trivial (>~30 LOC + new tests), escalate per
CLAUDE.md §6 — the contract change is infrastructural and belongs in a
fresh follow-up task, not bundled with the operational sign-off.

### D-T359b-5. Re-run idempotency — pinned by T-359a, re-asserted on real artifact

T-359a tested idempotency on stub renderers. T-359b re-asserts on the

### D-T359b-6. Atomic sign-off — document the troubleshooting path

T-359a D-T359a-2 mandates "all variants must succeed for `--mark-signed`
to flip the frontmatter". If one of the three variants fails to render
(e.g., the puppeteer session crashes mid-render-loop), the frontmatter is
NOT mutated.

T-359b documents the troubleshooting path in the PR body:

1. Re-run the generator without `--mark-signed` to isolate the failing
   variant; inspect renderer logs.
2. Re-run with `--mark-signed` once all three variants render cleanly.
3. If a variant consistently fails, escalate per CLAUDE.md §6.

## Escalation triggers (CLAUDE.md §6)

- The renderer produces visibly broken output (text rendering issues,
  missing fonts, color drift, layout collapse). The operator cannot sign
  off on a frame that doesn't match the compass intent. Escalate; this is
  a renderer bug, not a sign-off question (per the workflow doc's
  "Authority + escalation" section).
- The local-render and CI-render goldens diverge beyond the PSNR/SSIM
  thresholds (`PSNR < 42 dB` or `SSIM < 0.98`). Escalate per D-T359b-3 —
  this is a renderer-environment drift bug that affects every downstream
  cluster sign-off, not just T-359.
- The `clipKindResolver` does not have a clean variant-prop hook (per
  D-T359b-4) and adding one requires more than ~30 LOC + new tests.
  Escalate; the infra change belongs in a fresh follow-up task, not
  bundled with the operational sign-off.
- Atomic sign-off semantics fail in practice — one variant succeeds, two
  fail; the rollback behavior leaves a half-rendered fixture dir. Escalate;
  the contract per T-359a D-T359a-2 is "no half-signed states" and a
  failure here is a T-359a infrastructure bug.
- The PR-time CI run cannot reproduce goldens (different Chrome version,
  GPU, headless flags). Escalate; pin the canonical render environment in
  the workflow image and re-render canonical goldens from CI.
- The `Barlow Condensed` OFL face is not in the renderer's preload list,
  and the parity goldens fall back to a system stack — the rendered text
  doesn't match the typography pinned in T-359 D-T359-3. Escalate; this is
  the same gap T-359 already flagged in its own escalation row, and it
  affects every cluster-E preset.
