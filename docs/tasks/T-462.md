# T-462 — `LivePollOpenTextClip`

**Branch**: `task/T-462-live-poll-open-text-clip`

## Goal

Ship the **open-text variant** of LivePoll. Mirrors the T-461
template established by the multi-choice variant, swapping the
discriminator + per-kind shapes:

- Vote: `{ kind: 'live-poll-open-text', text: string }` (length ≤
  `clip.maxLength`, default 280).
- Aggregation: top-N list of canonicalized-text entries with counts;
  default `topN = 50`.
- Rendering: a vertical list of "text — N votes" rows, ordered by
  count desc; live updates from the WebSocket subscription.
- Voter UI: a single text input + submit button.

T-461 established the template; T-462 follows it verbatim with the
open-text-specific shape changes. The §13 verification is option-1
(real-render integration test) again, asserting on observable DOM
+ pixel-bucket non-blankness.

## Implementation notes

- **Schema**: `props: { question: z.string().min(1), maxLength: z.number().int().positive().max(2000).default(280), sessionId: z.string().optional() }`. `permissions: z.tuple([z.literal('audience-network')])`.
- **Static-fallback rendering**: vertical list, one row per entry; row
  shows `text` + count badge. Sort by count desc (stable for ties);
  this is a property of the rendering — the snapshot's `entries` are
  ALREADY ordered server-side, but the renderer asserts the order
  defensively. Pure function.
- **Voter input UI**: single `<textarea>` (or `<input>` for short text)
  with maxLength matching the clip's `maxLength`; submit button calls
  `onSubmit({ kind: 'live-poll-open-text', text })`; disable after
  submit; show "Vote submitted".
- **Mirror T-461 exactly**: file layout, test layout, registration
  pattern, dispatcher entry. Reading T-461's PR #524 diff is the
  fastest onboarding.
- **Determinism perimeter**: same as T-461 — static-fallback pure;
  factory's `runAudienceClient` is the only non-deterministic surface.
- **Pre-empt skills-sync drift**: run `pnpm skills-sync`.
- **Biome format** every touched file.
- **NEVER `git add -A`**.
