# T-434 — `@stageflip/sfx-stable-audio` (Stable Audio Open SFX adapter; stub-mode v1)

**Branch**: `task/T-434-sfx-stable-audio`

## Goal

Ship the **ninth and FINAL reference adapter** in the Phase 14 β
sequence (T-426..T-434): `@stageflip/sfx-stable-audio`. Wraps
**Stable Audio Open** (Stability AI's open-release short-form SFX +
audio-clip model; Apache 2.0) behind the `SFXProvider` interface from
T-419, declares an `AdapterDescriptor` per T-418, and exposes a stable
shape that the asset-generation handler bundle (T-423) + capability
router (T-425) consume.

T-434 is the **FIRST and ONLY `sfx` modality adapter** in the Phase 14
β reference set. Closes all four audio-adjacent modality coverage
slots: tts × 2, three-d × 2, video-gen × 2, music-gen × 2, **sfx × 1**.
Closing T-434 finishes the Phase 14 β reference-adapter sequence (9 of
9); T-435 — Phase 14 β regression test suite — is the β closer.

Stable Audio Open emits short-form audio clips (one-shot sound effects;
ambient loops; foley) up to 30s at 44100Hz, mono PCM. License is
Apache 2.0 (Stability AI's open release). `apache-2.0` is already in
the per-modality whitelist for `sfx` (ADR-008 §D13 line 656:
`sfx` admits `apache-2.0`, `mit`, `cc-by`, `proprietary-byo`,
`proprietary-vendored`) — no whitelist extension required.

T-434 follows the **same structural template** as T-432 (ACE-Step) +
T-433 (YuE): in-process + permissive-license-family + edge-deployable +
stub-mode posture. Both prior music adapters declare
`sandbox.kind: 'in-process'` and Stable Audio Open follows the same
posture (small models, short clips, fast on consumer GPU; production
wire-up audit deferred to T-434a).

T-434 ships in **stub mode**: the `generate()` body emits a
deterministic silent-WAV byte payload at the declared sample rate
(44100Hz) + returns a shaped `SfxResult`. Production wire-up
(Stable Audio Open checkpoint → diffusion model → real audio) is gated
on a follow-up task (T-434a).

T-434 is M-sized: one new package, ~250–400 LOC across 3 src modules
(descriptor / provider / stub-audio) + matched tests, ~250–400 lines
of spec, no schema / parity / clip / preset changes.

## Out of scope

| Item | Why deferred |
|---|---|
| **Production wire-up to a real Stable Audio Open model** (diffusion model checkpoint; ONNX or PyTorch runtime; sidecar isolation) | Stable Audio Open's checkpoint redistribution, runtime selection (in-process ONNX vs PyTorch sidecar), and license-clean inference path need a separate audit. Deferring to **T-434a** keeps T-434's blast radius tight. The `descriptor` shape declared here is the contract the production wire-up MUST match; T-434a only swaps the body, never the shape. |
| **MP3 output** | Stub-mode declares `outputFormats: ['wav', 'mp3']` matching the spec but the synthesizer ONLY emits WAV (calling with `outputFormat: 'mp3'` throws). MP3 emission is gated on production wire-up + an encoder dependency audit. |
| **Seamlessly-loopable clip generation** | `descriptor.capability.supportsLoop: true` advertises the capability; the v1 stub-mode body does NOT loop-condition the (silent) sample output. The provider DOES honor the `call.loop` flag in `SfxResult.isLoopable` so downstream consumers receive the right shape. Production wire-up implements actual loop-conditioning. |
| **Long-form audio (> 30s)** | Stable Audio Open is short-form by design. The descriptor declares `maxDurationS: 30`; calls beyond this range throw. Long-form is the music-gen modality's lane (T-432 / T-433). |
| **Schema-layer attribution wiring** | The `SfxResult` shape (T-419) does NOT carry an `attribution` field. Apache 2.0 attribution for SFX is a downstream UI/exporter concern at the application layer, surfaced from the adapter id + license posture metadata. No schema / engine changes. |
| **Adapter-side caching** | `generate()` derives the canonical `cacheKey` per ADR-008 §D1 + returns it; the adapter does NOT consult `AssetCacheStore`. |
| **Telemetry / cost-metering** | Descriptor declares `costPerCall.usd = 0` + `latencyMs.{p50,p95}` hints; no per-call telemetry emission. |
| **AssetStorage upload** | `generate()` returns `url` as an inline `data:` URI for the silent-WAV stub. Production wire-up uploads to an `AssetStorage` adapter + returns the storage URL; the shape stays identical. |
| **Capability-validator hook into `CapabilityDescriptorParser`** | T-419 ships `validateSfxCapability`; T-434 declares a capability that satisfies it but does NOT register the validator into a host-shell parser. Tests assert the strict descriptor subset passes `validateSfxCapability` directly. |
| **Schema / parity / clip / preset / parity-golden changes** | All untouched. |

## Acceptance criteria

1. New package `@stageflip/sfx-stable-audio` at
   `packages/sfx-stable-audio/` with `package.json`, `tsconfig.json`
   (matches the `@stageflip/music-yue` shape: no per-package
   `tsup.config.ts` / `vitest.config.ts` — defaults via package.json
   scripts suffice).
2. Public barrel `src/index.ts` exports:
   - `stableAudioDescriptor` (the canonical `AdapterDescriptor`),
   - `descriptor` (alias of `stableAudioDescriptor`; named export the
     T-422 discovery walker reads),
   - `stableAudioSfxCapability` (strict `SfxCapabilityDescriptor`
     subset that passes `validateSfxCapability`),
   - `StableAudioSfxProvider` (the class implementing `SFXProvider`),
   - `StableAudioProviderMode` (`'stub' | 'production'`),
   - `StableAudioSfxProviderOptions`,
   - `NotYetImplementedError` (thrown by `production` mode),
   - `generateSilentWavDataUri` (re-exported from `./stub-audio.js`),
   - `STABLE_AUDIO_MAX_DURATION_S`, `STABLE_AUDIO_SAMPLE_RATE_HZ`.
3. **Descriptor shape**:
   ```ts
   {
     id: 'stable-audio-open',
     modality: { kind: 'sfx' },
     capability: {
       outputFormats: ['wav', 'mp3'],
       sampleRates: [44100],
       maxDurationS: 30,
       supportsLoop: true,
       // Catalog-summary fields read by skills-sync's `capabilitySummary`
       // helper (T-424 / packages/skills-sync/src/asset-providers-gen.ts):
       // `sfx` row reads `maxDurationSec` + `sampleRateHz`.
       maxDurationSec: 30,
       sampleRateHz: 44100,
       // Differentiator-surface fields (descriptive; the agent UI / catalog
       // can surface; the routing layer does NOT filter on them in v1):
       supportsOneShot: true,
       qualityHint: 'high',
     },
     license: { kind: 'apache-2.0' },           // Apache 2.0 (whitelisted)
     sandbox: { kind: 'in-process' },
     costPerCall: { usd: 0 },
     latencyMs: { p50: 5_000, p95: 8_000 },     // 'fast' tier (< 10s p95)
   }
   ```
   `maxDurationSec` + `sampleRateHz` are extra capability fields the
   T-424 catalog generator reads; the strict T-419
   `sfxCapabilityDescriptorSchema` is `.strict()` and would reject
   them — so the descriptor uses a capability shape that passes the
   T-418 envelope's `z.record(z.unknown())` but tests pass the
   validator a SUBSET stripped of the extras.
4. **`StableAudioSfxProvider` class** implements `SFXProvider`:
   - Constructor takes `{ mode: StableAudioProviderMode }` (defaults
     to `'stub'`).
   - `id` / `modality` / `capability` / `license` / `sandbox` /
     `costPerCall` / `latencyMs` are passed through from
     `stableAudioDescriptor` (so the class instance is itself a valid
     `SFXProvider`).
   - `generate(call: SfxCall): Promise<SfxResult>`:
     - Validates `call.prompt` is non-empty (after trim); throws
       `Error('StableAudioSfxProvider.generate: prompt must be non-empty')`.
     - Validates `call.outputFormat === 'wav'`; throws on mismatch.
     - Validates `call.durationS > 0` AND `call.durationS <= 30`;
       throws on out-of-range.
     - Validates `call.sampleRate` is in
       `stableAudioDescriptor.capability.sampleRates`; throws on
       unknown sample rate.
     - In `'stub'` mode: synthesizes a deterministic silent-WAV byte
       payload, derives a canonical `cacheKey` via `deriveCacheKey`,
       returns `{ cacheKey, url, durationS, isLoopable }` where
       `isLoopable = call.loop === true`. `url` =
       `data:audio/wav;base64,<base64-of-silent-wav>`.
     - In `'production'` mode: throws `NotYetImplementedError(
       'StableAudioSfxProvider.generate: production wire-up deferred
       to T-434a (Stable Audio Open ONNX runtime audit pending)')`.
5. **`generateSilentWavDataUri(durationS, sampleRate)`** in
   `src/stub-audio.ts`:
   - Same shape as `packages/music-yue/src/stub-audio.ts` (mirrored
     verbatim — duplication is intentional per T-432 / T-433 spec;
     keeps the adapter-discovery walker self-contained).
   - Pure; deterministic; tests cover RIFF/WAVE magics, sample-rate
     field, data-chunk size, all-zero samples, determinism.
6. **`NotYetImplementedError`** is a regular `class extends Error`
   with `name = 'NotYetImplementedError'`. Exported from the barrel.
7. Tests cover (≥85% coverage on changed files):
   - **Descriptor**: passes `parseAdapterDescriptor()`;
     `id === 'stable-audio-open'`; `modality.kind === 'sfx'`;
     `license.kind === 'apache-2.0'`; `sandbox.kind === 'in-process'`;
     capability subset passes `validateSfxCapability()`;
     `maxDurationS === 30`; `supportsLoop === true`;
     `outputFormats` includes `'wav'` and `'mp3'`; `sampleRates`
     declares `[44100]`.
   - **Stub-audio**: header magics; sample-rate at offset 24..27;
     data-chunk size at offset 40..43; all-zero samples; determinism;
     validation errors on bad inputs.
   - **Provider**:
     - `mode: 'stub'` constructor returns a working provider; `id`,
       `modality`, `capability`, `license`, `sandbox` all match
       `stableAudioDescriptor`.
     - `generate()` returns an `SfxResult` whose `url` starts with
       `data:audio/wav;base64,`, `cacheKey` matches `sfx/<64-hex>`
       shape, `durationS` matches the input.
     - **`isLoopable`** mirrors `call.loop === true` (PRESENT in
       every result; the routing-layer reads it to decide whether to
       wire the clip into a looping primitive).
     - Two `generate()` calls with identical input → identical
       `cacheKey` (determinism).
     - `generate()` with empty / whitespace-only prompt throws.
     - `generate()` with non-`'wav'` `outputFormat` throws.
     - `generate()` with `durationS > 30` throws.
     - `generate()` with `durationS <= 0` throws.
     - `generate()` with unknown `sampleRate` throws.

## Monetization posture

Stable Audio Open ships under Apache 2.0. Apache 2.0 permits
commercial use of the model and its outputs. The `SfxResult` shape
(T-419) does not carry an `attribution` field — Apache 2.0 attribution
for SFX is a downstream UI/exporter concern at the application layer,
surfaced from the adapter `id` + `license.kind` metadata captured on
the descriptor.

The two-layer encoding:

1. **Distribution license** (CI-gate facing): `license.kind:
   'apache-2.0'` clears `check-asset-licenses` (apache-2.0 ∈ sfx
   whitelist).
2. **Output disposition** (capability-router facing): the SFX
   capability does NOT carry an `outputLicense` enum (unlike
   `MusicGenCapabilityDescriptor`); routing relies on the descriptor's
   `license.kind` for per-tenant attribution UX decisions.

Commercial monetization is permitted without code-level branching.

## Stub-mode vs production-mode contract

The `StableAudioProviderMode` discriminator gates the `generate()`
body behavior **only**. Every other surface (descriptor, capability,
sample-rate list, validation, error throwing, cache-key derivation,
`isLoopable` propagation) is identical between modes. The production
wire-up (T-434a) MUST:

1. Keep `stableAudioDescriptor` byte-identical (no new capability
   fields added to v1).
2. Replace the `generate()` `mode === 'production'` branch with a
   real Stable Audio Open library call.
3. Keep the input validation paths byte-identical.
4. Keep the cache-key derivation byte-identical.
5. NOT widen the `SfxResult` shape.

Anything in the production wire-up that conflicts with this contract
is a spec change — file an ADR.
