# T-437 — 3D→ThreeSceneClip GLB consumer

**Branch**: `task/T-437-3d-three-scene-consumer`

## Goal

Wire the Phase 14 β 3D adapters (T-428 Tripo + T-429 Meshy) to
`ThreeSceneClip` (T-384) so generated GLB assets can be **mounted at
render time** via a deterministic `cacheKey` lookup against
`@stageflip/asset-cache` (T-420). Mirrors T-436's TTS→captions bypass
pattern — pure addition, host-side provider whitelist, fail-soft
fallback — but for the 3D modality.

The integration is **opt-in**: existing `ThreeSceneClip` mounts remain
byte-for-byte unchanged. Callers that want to mount a generated GLB
build a `seedSrc: { kind: 'asset-gen', cacheKey, provider }` reference,
hand it to the consumer entry point along with an `AssetCacheStore`
lookup, and either receive the cached GLB bytes or a placeholder when
the cache misses.

## Function

1. Phase 14 β 3D adapters (Tripo, Meshy) emit `ThreeDResult` carrying
   `cacheKey: string` derived from `deriveCacheKey({ modality: 'three-d',
   model, prompt, params, seed })` per ADR-008 §D1 (T-420).
2. A new entry point `resolveAssetGenGlb()` accepts a `seedSrc`
   descriptor `{ kind: 'asset-gen', cacheKey, provider }` plus an
   `AssetCacheStore<Uint8Array>` accessor. When the provider is on the
   3D bypass whitelist AND the cache returns a non-empty `Uint8Array`,
   the consumer returns `{ ok: true, bytes, provider }`. Otherwise the
   consumer returns `{ ok: false, reason }` and the caller falls back to
   a placeholder GLB.
3. `ThreeSceneClipFactoryOptions` gains an optional `assetGenResolver`
   hook — when set, the factory wires the resolver into the host's
   `setupProps` so the author's `ThreeClipSetup<P>` callback can call
   `props.resolveAssetGenGlb?.()` to mount the cached bytes inside the
   Three.js scene at setup time.
4. Fallback is silent: a missing provider, a non-whitelisted provider,
   or a cache miss returns `{ ok: false, reason }` rather than throwing,
   and the caller is expected to mount a placeholder GLB (a unit-cube
   data-URI is generated by the 3D adapters' own `stub-glb.ts` helpers
   and is suitable as a placeholder; this task does NOT bundle a
   placeholder of its own — provider-stub bytes flow through the same
   path the next time `generate()` is called).
5. The existing `threeSceneClipFactory` mount path is **untouched** when
   `assetGenResolver` is absent. The consumer is a leaf addition;
   existing tests pass without modification.

## Schema audit

`packages/schema/src/clips/interactive/three-scene-props.ts` defines
`ThreeSceneClipProps` with:

```
setupRef: componentRefSchema,
width, height: positive int,
setupProps: Record<string, unknown> (default {}),
posterFrame: int (default 0),
prngSeed: int (default 0),
```

There is **no `seedSrc` field**. Rather than extend the strict-shaped
schema (which would be a §13 structural extension requiring deferral
posture), T-437 ships the consumer as a **schema-agnostic wrapper** that
sits OUTSIDE `ThreeSceneClipProps`:

- Hosts build the `{ kind: 'asset-gen', cacheKey, provider }` descriptor
  at the call site (typically: editor → 3D-adapter call → store result
  on a `MediaElement` with a `MediaProvenance.kind === 'asset-gen'`).
- Hosts call `resolveAssetGenGlb()` independently and pass the resolved
  GLB bytes through `setupProps` (an opaque `Record<string, unknown>`
  per existing schema) into the author's `setup` callback.
- The factory option `assetGenResolver` is an OPTIONAL injection
  seam — when set, the resolver runs once per mount and the resolved
  result is merged into `setupProps` under a reserved key (`__assetGen`)
  before being forwarded to `ThreeClipHost`.

The reserved-key approach reuses the schema's existing
`setupProps: Record<string, unknown>` slot without adding a typed field.
The author's setup callback discovers the GLB bytes by reading the
reserved key. This is consistent with how T-436 mirrors the
`MediaProvenance` shape locally in `captions/tts-bypass.ts` rather than
adding `@stageflip/schema` as a runtime dep.

## §13 statement

**NOT a structural extension.** T-437 adds a new optional code path
gated by an optional factory option. No new schema fields, no new RIR
elements, no new runtime kinds, no new compositing modes. The existing
`ThreeSceneClipProps` shape is byte-identical. Render verification N/A
for this PR; pixel-level GLB rendering verification is gated on Track A
T-397+ (renderer-cdp + parity goldens for 3D modality), which mounts
live GLBs end-to-end. Unit-test coverage of the consumer (whitelist,
cache-miss fallback, fail-soft contract) and the factory's resolver hook
is sufficient per CLAUDE.md §13.

## Whitelist

Initial whitelist of 3D adapter ids whose GLB output the host trusts
for the asset-gen mount path:

```
['tripo', 'meshy']
```

These match the two reference adapter descriptors merged in T-428 +
T-429. Adding a third whitelist entry is a one-line code change inside
`asset-gen-consumer.ts` paired with the three-runtime SKILL update.

The whitelist is intentionally narrower than "every adapter whose
`ThreeDCapabilityDescriptor.outputFormats` includes `glb`": the host
must vouch for each adapter's GLB structural correctness before
ThreeSceneClip trusts them blindly. A future task (call site: ADR-008
§D5 follow-up) may promote the whitelist into a runtime registry
consulted via the adapter registry.

## Architectural seals

- **Pure addition**: the existing `threeSceneClipFactory` mount path is
  byte-for-byte identical when `assetGenResolver` is absent. The
  consumer is a leaf module; no existing tests change.
- **Provider-aware**: the whitelist check rejects unknown providers
  even when a cacheKey + bytes are present — the host's trust signal is
  the provider id, not the cache hit.
- **Fail-soft fallback**: cache misses, missing whitelist membership,
  and absent bytes all return `{ ok: false, reason }`. The consumer
  never throws; callers fall back to a placeholder (the 3D adapter's
  own stub-GLB output is the natural choice).
- **No new runtime dep on adapters**: `@stageflip/runtimes-interactive`
  does NOT import from `@stageflip/3d-tripo`, `@stageflip/3d-meshy`, or
  `@stageflip/asset-gen-contract`. The consumer mirrors the structural
  shape of `{ kind, cacheKey, provider }` locally so the runtime stays a
  leaf consumer of the 3D surface.
- **No new runtime dep on asset-cache**: the consumer accepts a pluggable
  `AssetCacheLookup` callback `(cacheKey: string) => Promise<Uint8Array |
  undefined>` rather than importing `@stageflip/asset-cache` directly.
  Hosts wire their own `AssetCacheStore` instance to the callback at the
  call site. This is the same dep-isolation pattern T-436 uses for
  `MediaProvenance` (mirrored structurally rather than imported).
- **Schema immutability**: the `ThreeSceneClipProps` schema is
  byte-identical. Reserved-key (`__assetGen`) under `setupProps` is the
  only contact surface with the host; authors that don't consume it see
  no change.

## Test scenarios

`asset-gen-consumer.test.ts`:

1. `THREE_D_BYPASS_WHITELIST` contains `tripo` and `meshy`, length 2.
2. `resolveAssetGenGlb` returns `{ ok: true, bytes, provider: 'tripo' }`
   when seed kind is `'asset-gen'`, provider is whitelisted, and cache
   returns bytes.
3. Returns `{ ok: true, bytes, provider: 'meshy' }` for Meshy.
4. Returns `{ ok: false, reason: 'kind-mismatch' }` when `seedSrc.kind`
   is not `'asset-gen'`.
5. Returns `{ ok: false, reason: 'provider-not-whitelisted' }` when
   provider is unknown.
6. Returns `{ ok: false, reason: 'provider-missing' }` when provider
   field is absent.
7. Returns `{ ok: false, reason: 'cache-miss' }` when cache returns
   `undefined`.
8. Returns `{ ok: false, reason: 'cache-empty' }` when cache returns a
   zero-length `Uint8Array`.
9. Returns `{ ok: false, reason: 'cacheKey-missing' }` when `cacheKey`
   is absent/empty.
10. Cache lookup is invoked with the exact `cacheKey` string —
    verified via a recording lookup.
11. Whitelist additions require explicit code edit (length=2 sentinel).

`factory.test.ts` (added):

12. Factory with `assetGenResolver` calls the resolver before mount and
    merges `{ __assetGen: { ok: true, bytes, provider } }` into
    `setupProps` visible inside the author's setup callback.
13. Factory with `assetGenResolver` that returns `{ ok: false }`
    merges the failure result under `__assetGen` so authors can
    fall back to a placeholder inside setup.
14. Factory without `assetGenResolver` (T-437 default) does NOT add the
    `__assetGen` key — existing setup-props are byte-identical to T-384
    behavior.

## Whitelist provider matrix

| Provider id | Source task | Modality | License | Output formats |
|-------------|-------------|----------|---------|----------------|
| `tripo`     | T-428       | three-d  | proprietary-byo | glb |
| `meshy`     | T-429       | three-d  | proprietary-byo | glb |

Both provider stub-mode outputs are `data:model/gltf-binary;base64,…`
strings encoding a unit-cube GLB; production-mode wire-up is gated on
T-428a / T-429a (vendor HTTPS API audits). The consumer treats both
modes identically — the cache stores bytes; whether those bytes came
from a stub or a real API call is irrelevant to ThreeSceneClip.
