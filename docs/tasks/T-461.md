# T-461 — `LivePollMultipleChoiceClip`

**Branch**: `task/T-461-live-poll-multiple-choice-clip`

## Goal

Ship the **first audience clip family** — the multi-choice variant of
LivePoll. Establishes the per-clip-kind authoring template the eight
sibling clip families (T-462..T-469) follow, and validates the
end-to-end render pipeline T-454 ships per CLAUDE.md §13.

The clip is a horizontal bar chart: one bar per option, height
proportional to `optionCounts[i] / totalVotes`, percentage label
overlaid. The live-mount path subscribes to `AggregationSnapshot`
updates; the static-fallback path renders deterministically from the
inlined `AudienceProvenance.aggregation`.

Carries five concerns:

1. **`packages/schema/src/elements/live-poll-multiple-choice.ts`** —
   Zod schema for the new RIRElement variant `LivePollMultipleChoiceClipElement`:
   - `kind: 'live-poll-multiple-choice'` discriminant.
   - `props: { question: string, options: readonly string[] (length 2..10), sessionId?: string }`.
   - `provenance?: AudienceProvenance` — schema-side per T-460.
   - `permissions: readonly ['audience-network']` — frozen tuple matching T-455's `AudienceClipManifest`.
2. **`packages/runtimes/audience/src/clips/live-poll-multiple-choice/`** —
   the `ClipDefinition` + factory + static-fallback dispatch:
   - `clip-definition.ts` — implements `ClipDefinition` from
     `@stageflip/runtimes-contract`. `kind: 'live-poll-multiple-choice'`,
     `propsSchema` derived from the schema package, `render(ctx)` returns
     a React tree of bars from the (live OR static) aggregation.
   - `factory.ts` — `AudienceClipFactory` that opens an `AudienceClient`
     subscription on mount; per ADR-009 §D2, the provider streams
     `AggregationSnapshot` events; the React tree updates on each. On
     `staticFallback`, the dispatcher reads `provenance.aggregation`
     (typed as `LivePollMultipleChoiceAggregation`) and renders
     deterministically.
   - `manifest.ts` — `MANIFEST: AudienceClipManifest = { kind:
     'live-poll-multiple-choice', permissions: ['audience-network'] }`
     per T-455.
   - `index.ts` — barrel + auto-registration: `audienceClipRegistry.register(
     'live-poll-multiple-choice', factory)` + `staticFallbackRenderer.register(
     'live-poll-multiple-choice', renderStaticFallback)` + `registerAudienceClipDefinition(
     'live-poll-multiple-choice', clipDefinition)` at module-load time.
3. **`apps/audience-join/src/components/live-poll-multiple-choice-voter-input.tsx`** —
   voter UI: N option buttons; tap submits `{ kind:
   'live-poll-multiple-choice', optionIndex: i }` via the
   `voterAppClient`'s `submitVote` callback. Disables after submission.
   Registered with the dispatcher in T-456 (`voter-input-dispatcher.tsx`)
   so the dynamic kind dispatch resolves to this component.
4. **End-to-end render verification per CLAUDE.md §13 option 1** — a
   Playwright integration test at
   `packages/runtimes/audience/src/clips/live-poll-multiple-choice/
   render-e2e.test.ts` that:
   - Mounts the clip definition with a known snapshot
     (`optionCounts: [10, 5, 3], totalVotes: 18`).
   - Renders to a real DOM (jsdom or playwright).
   - Captures the rendered output as a screenshot OR asserts on
     observable DOM (e.g., bar 0 width is the largest; total-vote
     label reads "18 votes"; each bar's text reads its option label).
   - PNG pixel-bucket assertion (per the T-348b non-blank gate
     pattern): the rendered output is NOT blank — at least one
     non-background-color pixel cluster exists.
5. **`AudienceClipKind` voter-input-dispatcher registration** in
   `apps/audience-join/src/components/voter-input-dispatcher.tsx`:
   - The empty registry T-456 ships gets its first entry: `live-poll-multiple-choice`
     → `<LivePollMultipleChoiceVoterInput>`.

**Strict scope** — the multi-choice variant only. The two sibling
LivePoll variants (`open-text` T-462, `rating` T-463) ship in their own
PRs. NO modifications to existing audience-contract / runtime-substrate
/ schema base / app-api / editor-shell.

## §13 (structural extension) statement

**THIS IS A STRUCTURAL EXTENSION.** This task adds a new RIRElement
variant + a new clip-kind to the audience runtime registry — both
existing degrees of freedom (the discriminated unions are designed for
extension), but new entries on the runtime-dispatch surface.

**Verification mechanism: Option 1 (real-render integration test).**
The PR ships `render-e2e.test.ts` that drives the clip through the
T-454 `StaticFallbackRenderer` with a known snapshot and asserts on
observable DOM AND PNG pixel-bucket non-blankness. Concretely:

- Snapshot fed: `{ kind: 'live-poll-multiple-choice', optionCounts:
  [10, 5, 3], totalVotes: 18 }`.
- DOM assertions: three bar elements present; bar 0's width >=
  bar 1's width >= bar 2's width (proportional ordering); total label
  reads "18 votes".
- Pixel assertion: at least one non-background pixel cluster present
  (per T-348b non-blank gate pattern).

This is the §13 obligation T-460 deferred (option 3) explicitly to
this task. Reviewers verify the render-e2e test runs in CI + asserts
on observable output, not just on the wired-up shape.

The §13 obligation does NOT extend to PO ratification of a Cluster I
preset — that's T-476's role + T-486's preset cluster. T-461's
verification is the integration-test layer; T-476 is the
cross-cluster fixture sign-off.

## Implementation notes

- **Schema-side `RIRElement` union extension**: this is the first new
  audience-clip variant on the union. The pattern matches T-421's
  `MediaElement` extension — additive, non-breaking. Document the
  `RIRElement.elements` discriminated union if it doesn't already
  list every variant; T-461 sets the precedent for T-462..T-471.
- **Static-fallback rendering**: pure layout pass per ADR-010 §D4.
  Given `optionCounts` + `totalVotes`, render N bars with widths
  `count / totalVotes * containerWidth`. Percentages overlaid. NO
  network, NO time, NO RNG (deterministic-by-construction).
- **Live-mount path**: `factory.ts` uses `runAudienceClient` from T-454.
  On each `AggregationSnapshot` event, update React state with the new
  `optionCounts`. Dispose on `signal.abort()`. The per-message rate
  observed is ≤30 Hz (the snapshot cadence per ADR-009 §D5).
- **Voter input UX**: N buttons; selecting one calls
  `voterAppClient.submitVote({ kind: 'live-poll-multiple-choice',
  optionIndex: i })`; disable all buttons after submission; show "Vote
  submitted" feedback. Connection-status banner from T-456 already
  surfaces error states.
- **Pixel-bucket assertion**: read the rendered DOM's bounding-box +
  computed-style colors; OR if Playwright is available, take a real
  screenshot with `page.screenshot({ type: 'png' })` + use a small
  helper to bucket pixel colors and assert at least one non-background
  bucket has > 100 pixels (per the T-348b pattern). Prefer Playwright
  if the existing test runner supports it; otherwise jsdom + DOM
  assertions are acceptable as long as the test is documented as
  satisfying §13 option 1.
- **Test-first**: write `render-e2e.test.ts` first; watch it fail
  (no clip exists); then implement bottom-up (schema → factory →
  static-fallback → voter UI).
- **No `console.log`**.
- **File headers** + **TSDoc**.
- **Pre-empt skills-sync drift**: run `pnpm skills-sync` before commit.
  T-455's audience-clip skill page may regenerate to reflect the first
  registered clip.
- **Biome format** every touched file.
