# T-331 — Cluster-A composer-tools handler bundle

**Branch**: `task/T-331-cluster-a-compose-tools`

## Goal

Ship the Cluster A (News & Broadcast) composer-tools handler bundle — four read-only LLM tools (`compose_breaking_news`, `compose_ongoing_update`, `compose_guest_intro`, `compose_documentary_title_card`) that resolve a brief plus a brand register hint into a preset-id pick across the 8 substantive Cluster A presets. The bundle name is `cluster-a-compose`. This is the third of four cluster-compose tasks in Phase 13 (sequence: T-331 (Cluster A) → T-340 (Cluster B) → T-368 (Cluster F) per `docs/implementation-plan.md:628 / :643 / :691`); the cluster's preset-tier work is already complete, the cluster SKILL `skills/stageflip/presets/news/SKILL.md` is `substantive` and ratified 2026-05-06, and all 8 Cluster A presets are ELIGIBLE.

T-331 wires the four tools as a fresh handler bundle in `packages/engine/src/handlers/cluster-a-compose/` mirroring `element-cm1` / `slide-cm1` / `table-cm1` etc. Each tool is a deterministic dispatch function: input is a small Zod object (headline / mainline / person / title + a small enum hint), output is a discriminated union with `{ ok: true, presetId, clipKind, rationale }` on success and `{ ok: false, reason }` on a brand-register miss. The handlers are **read-only** — no patches push to `ctx.patchSink`, no document mutations, no I/O. Dispatch is a sealed `switch` over the discriminator (severity / network / theme) → preset-id table. The eight Cluster A presets are: `cnn-breaking`, `cnn-classic`, `bbc-reith-dark`, `al-jazeera-orange`, `fox-news-alert`, `msnbc-big-board`, `netflix-doc-lt`, `apple-tv-lt`.

## Architectural decisions

### D-T331-1. Bundle naming — `cluster-a-compose`

The bundle is named `cluster-a-compose` (kebab-case, mirroring `element-cm1` / `slide-cm1` / `table-cm1` / `create-mutate` / `arrange-variants` / `clip-animation` / `data-source-bindings` / `display-mode` / `domain-finance-sales-okr` / `fact-check` / `layout` / `qc-export-bulk` / `read` / `semantic-layout` / `timing` / `validate` / `video-mode`). The naming pattern is `<scope>-<role>` where scope is `cluster-a` (sealed reference to the news cluster per `skills/stageflip/presets/news/SKILL.md`) and role is `compose` (the four tools share the `compose_*` prefix).

Rejected alternatives:

- `news-compose` — ambiguous with `news-ticker-bar` clip / `cnn-classic` preset etc. Cluster identifier is canonical.
- `compose-news` — breaks the `<scope>-<role>` ordering established by sibling bundles.
- `cluster-a` — too generic; the bundle is specifically the *compose-tier* tools for that cluster, not a catch-all for all cluster-A operations.

T-340 / T-368 follow the same pattern: `cluster-b-compose`, `cluster-f-compose`. Reviewer demand for a different naming → escalate per CLAUDE.md §6.

### D-T331-3. Read-only handlers — declare `MutationContext` but never push patches

T-331 handlers are **read-only**. They consume a structured input (brief fields + register hint) and return a preset-id pick. They never read the document and never push to `ctx.patchSink`.

For consistency with sibling write-tier bundles (which all declare `MutationContext`), T-331 declares `MutationContext` as the context type — but never invokes `ctx.patchSink.push` / `ctx.patchSink.pushAll`. This forward-compatible shape is friendly to a future `compose_*` enhancement that **would** push patches (e.g., a v2 `compose_breaking_news` that not only picks the preset but also drafts a patch attaching the preset to the active slide). Mirrors `read` bundle posture (read-only handlers in a write-tier shaped registry).

Rejected alternative: declare `DocumentContext` (no patchSink). Loses forward-compat with v2 patch-pushing variants, and bifurcates the bundle's typing surface. Rejected.

### D-T331-4. Tool 1 — `compose_breaking_news`

**Input** (Zod, strict):

```ts
const composeBreakingNewsInput = z
  .object({
    headline: z.string().min(1).max(200),
    severity: z.enum(['urgent', 'developing', 'standard']),
    network: z.enum(['cnn', 'fox', 'msnbc', 'bbc', 'ajazeera', 'aplus']),
    timestamp: z.string().optional(),  // ISO8601 hint; opaque passthrough
  })
  .strict();
```

**Output** (Zod, discriminated union on `ok`):

```ts
const composeOutput = z.discriminatedUnion('ok', [
  z
    .object({
      ok: z.literal(true),
      presetId: z.string(),
      clipKind: z.enum(['lowerThird', 'breakingBanner', 'fullScreen']),
      rationale: z.string(),
    })
    .strict(),
  z
    .object({
      ok: z.literal(false),
      reason: z.enum(['unsupported_network', 'unsupported_severity', 'register_unavailable']),
      detail: z.string().optional(),
    })
    .strict(),
]);
```

**Dispatch table** (severity × network → preset-id):

| severity | network | preset-id | clipKind |
|---|---|---|---|
| `urgent` | `cnn` | `cnn-breaking` | `breakingBanner` |
| `urgent` | `fox` | `fox-news-alert` | `breakingBanner` |
| `urgent` | `msnbc` | `msnbc-big-board` | `fullScreen` |
| `urgent` | `bbc` | `bbc-reith-dark` | `lowerThird` |
| `urgent` | `ajazeera` | `al-jazeera-orange` | `lowerThird` |
| `urgent` | `aplus` | `apple-tv-lt` | `lowerThird` |
| `developing` | (any) | route via `compose_ongoing_update` semantics — return `ok: false, reason: 'unsupported_severity', detail: 'use compose_ongoing_update for developing/non-urgent register'` |
| `standard` | (any) | same as `developing` |

The `developing` / `standard` rejection is intentional — Cluster A canon (compass §"Red = urgent. Never use red accent for a neutral update or ongoing coverage") forbids using a breaking-register preset for non-urgent material. The tool returns `ok: false` to force the agent to call `compose_ongoing_update` instead. Rationale string format: `"severity=urgent + network=<network> → <preset-id>"`.

Rejected alternative: silently downgrade `developing` to `cnn-classic`. Hides the register decision; the agent must learn to pick the correct compose-tool. Rejected per the cluster SKILL's "Register is load-bearing" rule.

### D-T331-8. Read-only — no patch emission, no document reads

Per D-T331-3, every handler is pure: input → output. No `ctx.document` reads, no `ctx.patchSink.push`, no `ctx.signal` cancellation handling beyond Zod parse (which is synchronous).

This means each handler's `handle` body is a sealed `switch` over the input discriminator returning the matching preset-id record. No async, no I/O, no side effects.

### D-T331-9. Output discriminated union — `ok: true` happy path + `ok: false` register-miss path

All four tools share a single `composeOutput` Zod schema (see D-T331-4). The `ok: false` reasons enum is sealed at exactly:

- `'unsupported_network'` — network is not in the tool's accepted enum (caught by Zod parse before reaching the handler; reachable only via a non-Zod-validated codepath; defensive).
- `'unsupported_severity'` — used by `compose_breaking_news` to reject `developing` / `standard` (per D-T331-4).
- `'register_unavailable'` — used by `compose_ongoing_update` / `compose_guest_intro` to reject networks without a matching register.

Every `ok: false` response includes a `detail: string` explaining the rejection and pointing the agent at the correct sister tool (e.g., `'use compose_ongoing_update for developing/non-urgent register'`).

### D-T331-10. LLM tool definitions (JSONSchema) — co-located with handlers

Mirrors `element-cm1`'s `*_TOOL_DEFINITIONS` array. Each tool definition has:

- `name`: matches the handler `name` (`compose_breaking_news` etc.).
- `description`: matches the handler `description` (one-paragraph guidance for the LLM, citing register canon and the brand-network mapping).
- `input_schema`: handwritten JSONSchema mirror of the Zod input schema with `additionalProperties: false`, `required: [...]`, full enum lists. The Zod schema is the validation truth; the JSONSchema mirror is what the LLM sees.

Output is **not** declared in the LLMToolDefinition (the LLM-abstraction layer doesn't surface output schemas to models — it's an internal validation concern).

export function registerClusterAComposeBundle<TContext extends MutationContext>(
