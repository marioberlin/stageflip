# T-468 — `SurveyClip`

**Branch**: `task/T-468-survey-clip`

## Goal

Ship the **SurveyClip** family. Multi-question survey — three question
types (`multiple-choice` / `open-text` / `rating`); the aggregation
reuses the LivePoll per-kind aggregation shapes per ADR-010 §D3.
Renders as a multi-question dashboard (one mini-result-card per
question); voter UI is a vertical scrolling form with all questions
on one page.

Per-kind shapes (already in `@stageflip/audience-contract`):

- Vote: `{ kind: 'survey', responses: [{ questionId, value }, ...] }`
  where `value: string | number | readonly string[]` (typed per the
  question's `type`).
- Aggregation: `{ questionAggregations: [{ questionId, type:
  'multiple-choice' | 'open-text' | 'rating', aggregation:
  LivePollMultipleChoiceAggregation | LivePollOpenTextAggregation |
  LivePollRatingAggregation }, ...], totalResponses }`.
- Rendering: vertical scroll of question-result cards. Each card
  renders a mini version of the corresponding LivePoll variant
  static-fallback. Total label reads "${totalResponses} responses".
- Voter UI: a vertical form with all questions on one page; one input
  per question (multiple-choice → radio buttons; open-text →
  textarea; rating → 1..scaleMax buttons); single submit button at
  bottom emits `{ kind: 'survey', responses: [...] }`.

§13 verification is option-1 — `render-e2e.test.ts` drives the
static-fallback with a known 3-question mixed-type aggregation +
asserts on observable DOM ordering, per-question-type renderings, and
pixel-bucket non-blankness.

## Implementation notes

- **Schema**: `props: { questions: z.array(surveyQuestionSchema).min(1).max(20), sessionId: z.string().optional() }`
  where `surveyQuestionSchema = z.discriminatedUnion('type', [
  z.object({ id: z.string().min(1), type: z.literal('multiple-choice'),
    text: z.string().min(1), options: z.array(z.string().min(1)).min(2).max(10) }).strict(),
  z.object({ id: z.string().min(1), type: z.literal('open-text'),
    text: z.string().min(1), maxLength: z.number().int().positive().max(2000).default(280) }).strict(),
  z.object({ id: z.string().min(1), type: z.literal('rating'),
    text: z.string().min(1), scaleMin: z.literal(1),
    scaleMax: z.number().int().min(2).max(10), labels: z.array(z.string()).optional() }).strict()
  ])`.
  - `permissions: z.tuple([z.literal('audience-network')])`.
  - `provenance: audienceProvenanceSchema.optional()`.
- **Static-fallback rendering**: vertical scroll of question-result
  cards. For each `questionAggregations[i]`:
  - Render a card with question text (looked up from `clip.props.questions`).
  - Dispatch by `type`:
    - `multiple-choice` → mini horizontal bar chart (one bar per
      option; width proportional to `optionCounts[i] / max(optionCounts)`).
    - `open-text` → top-5 entries as list rows (truncate ≥5 to avoid
      crowding); each row shows `text` + count.
    - `rating` → mini histogram (one bar per score 1..scaleMax); mean
      label "Mean: X.X" (or "—" if `totalVotes === 0`).
  - Total label at the bottom: `${totalResponses} responses`.
  - Pure function. No `Date.now()`, no `Math.random()`.
- **Voter UI** (`survey-voter-input.tsx`):
  - `props: { questions, onSubmit, disabled? }`.
  - Vertical form: one input per question.
    - `multiple-choice` → radio buttons (one per option).
    - `open-text` → `<textarea maxLength={maxLength}>`.
    - `rating` → row of `scaleMax` buttons (current selection highlighted).
  - Single submit button at the bottom; on submit, collect responses
    (per-question typed value) and emit `{ kind: 'survey', responses:
    [...] }`. Disable all inputs + button after submit; show "Survey
    submitted".
  - Local state tracks per-question response values.
  - Validation: all required questions must have a response before
    submit is enabled (v1 = all required).

- **Determinism perimeter**: static-fallback pure.
