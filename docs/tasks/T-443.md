# T-443 — Cost-budget surfacing in tool results

**Branch**: `task/T-443-cost-budget-surfacing`

## Goal

When the agent invokes `generate_asset` (T-423), the tool result includes a
`costBudget` summary: the **cost incurred** by the executed adapter plus
the **remaining tenant budget** for the current period. The agent can
then decide to retry with a cheaper provider (via the capability-router's
`rankingPreference: 'cheapest'` from T-425) when its budget is running
low — closing the loop between the Provider Seam's `costPerCall` hints
(T-418) and the planner's adapter-selection strategy.

This is the **eighth cross-cutting integration** in Phase 14 γ
(closing-the-loop on the Provider Seam):

- T-415..T-417: agent SDK core
- T-418..T-422: Provider Seam α
- T-423..T-434: asset-gen handlers β
- T-435..T-437: asset-cache cross-cutting
- T-438..T-442: cross-cutting integrations γ 1–7
- **T-443**: cross-cutting integration γ 8 (this task)

A new tool `query_cost_budget` rounds out the surface: the agent can
inspect remaining budget at any time **without** triggering an adapter
call.

## §13 statement — YES, structural extension; option 3 deferral

T-443 introduces TWO new degrees of freedom in the document/storage model:

1. **`TenantSettings.aiBudget?`** — a new optional field on the

   `{ monthlyAmount: number, currency: 'USD' | ..., periodEnd: string }`.
2. **`TenantCostTrackerStore`** — a new storage facet
   (sibling to `TenantSettingsStore`) tracking accumulated AI-generation

### 2. `TenantCostTrackerStore` — new storage facet

New file `packages/storage/src/tenant-cost-tracker-store.ts`:

```ts
export interface CostRecord {
  readonly tenantId: string;
  readonly adapterId: string;
  readonly amount: number;
  readonly currency: string;
  readonly recordedAt: string;  // ISO datetime
}

export interface TenantCostTrackerStore {
  /** Append a cost record to the tenant's accumulator. */
  recordCost(record: CostRecord): Promise<void>;
  /** Sum the tenant's recorded costs in the current period [start, end). */
  getPeriodTotal(tenantId: string, periodStart: string, periodEnd: string): Promise<number>;
  /** All recorded costs for a tenant (audit-trail / debugging). */
  listCosts(tenantId: string): Promise<readonly CostRecord[]>;
}

export class InMemoryTenantCostTrackerStore implements TenantCostTrackerStore { ... }
```

The store is a stub-tracker for v1 — single-currency per tenant
(enforced at the schema level; the in-memory implementation does
NOT cross-convert). Production wire-up (Postgres / Firebase) lands
downstream; v1 ships the in-memory implementation only.

### 3. `generate_asset` — extended tool result

The successful sync result grows an optional `costBudget` envelope:

```ts
{
  ok: true,
  slideId, elementId, cacheKey, provenance,
  costBudget?: {                                      // <-- new (optional)
    costIncurred: { adapterId, amount, currency },
    budgetRemaining?: { amount, currency, periodEndAt },
    budgetExhausted: boolean,
  },
}
```

When `AssetGenerationContext` wires the new soft seam
`costTrackerStore: TenantCostTrackerStore`, the handler:

1. After successful adapter dispatch, reads the chosen adapter's
   `costPerCall.usd` (default `0` when absent — apache-2.0 / mit
   adapters typically have `0`).
2. Calls `costTrackerStore.recordCost({ tenantId, adapterId, amount,
   currency: 'USD', recordedAt })`.
3. Reads the tenant's `aiBudget` setting (via a new
   `tenantSettingsStore` soft seam; if absent, `costBudget` is omitted
   entirely — i.e., the tenant has no enforced budget).
4. Computes `budgetRemaining = aiBudget.monthlyAmount - periodTotal`.
5. Sets `budgetExhausted = budgetRemaining <= 0`.

When EITHER seam is unwired, `costBudget` is omitted from the result
(back-compat: existing tests that expect the original shape see the
original shape; the new field is purely additive).

### 4. `query_cost_budget` — new tool (canonical bundle 25)

```ts
// Input
{}  // no params; reads tenantId from the soft seam's tenantContext

// Output
{ ok: true, budget: { monthlyAmount, currency, periodEndAt, used, remaining, exhausted } }
| { ok: false, reason: 'cost_budget_unavailable' | 'no_budget_configured' }
```

The tool emits NO patch ops — it is a pure read. It requires the same
soft-seam pair as `generate_asset`'s cost-budget envelope: a wired
`costTrackerStore` AND a wired `tenantSettingsStore`. Absent either,
the tool returns `{ ok: false, reason: 'cost_budget_unavailable' }`.

### 5. Capability-router — verified, NOT modified

The capability-router (T-425) already ranks adapters by
`costPerCall.usd` when called with `rankingPreference: 'cheapest'`.
T-443 makes no changes to the router; the new flow is:

- Agent calls `generate_asset` →
- Sees `costBudget.budgetExhausted: true` →
- Retries with `generate_asset(..., params: { rankingPreference: 'cheapest' })`
  on the next planner step (or, in a future task, the planner reads
  the cost-budget signal directly).

The `rankingPreference` param is already plumbed through the
asset-gen handler bundle and the capability-router; T-443 does NOT
touch that surface.

## Tests

### `tenant-settings.test.ts` additions

- `aiBudget` accepted when shape valid (USD, 100, 2026-06-01).
- Rejects negative `monthlyAmount`.
- Rejects non-ISO-4217 currency code (`"dollars"`, `"$"`).
- Rejects malformed `periodEnd` datetime.
- Rejects unknown keys inside `aiBudget` (strict).
- Roundtrips when `aiBudget` is absent (back-compat).

### `tenant-cost-tracker-store.test.ts`

- `recordCost` → `listCosts` returns the recorded entry.
- `getPeriodTotal` sums only records within `[periodStart, periodEnd)`.
- `getPeriodTotal` returns 0 for an unknown tenant.
- Multi-record accumulator across multiple adapter calls.
- `reset()` clears all state.

### `handlers.test.ts` additions

- `generate_asset` happy path omits `costBudget` when seams absent
  (back-compat).
- `generate_asset` with wired cost-tracker + tenant-settings returns
  `costBudget.costIncurred` matching the chosen adapter's
  `costPerCall.usd`.
- `generate_asset` reports `budgetRemaining` = `monthlyAmount` minus
  cumulative recorded costs.
- `generate_asset` reports `budgetExhausted: true` when remaining ≤ 0.
- `generate_asset` records cost ONLY on adapter success (failed
  fallback chain does NOT record cost).
- `query_cost_budget` returns `{ ok: true, budget }` when both seams
  wired AND `aiBudget` configured.
- `query_cost_budget` returns
  `{ ok: false, reason: 'no_budget_configured' }` when settings exist
  without `aiBudget`.
- `query_cost_budget` returns
  `{ ok: false, reason: 'cost_budget_unavailable' }` when either seam
  is unwired.

- Production-grade Postgres / Firebase `TenantCostTrackerStore`
  implementation (downstream).
- Multi-currency conversion (single-currency per tenant in v1).

  no scheduled job).

  read `costBudget` directly into Planner inputs).

  cache hits do NOT call an adapter, so no cost.
