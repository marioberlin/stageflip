# T-321 — `TitleSequenceClip` (multi-shot compositor)

**Branch**: `task/T-321-title-sequence-clip-primitive`

## Goal

Ship a frame-runtime-bridge clip — `titleSequence` — that renders **multi-shot prestige-TV title sequences** (Stranger Things, Game of Thrones, Squid Game, True Detective, Succession, Severance — all six Cluster D presets). The primitive composites a sequenced timeline of distinct **shots** (`titlePlate` / `letterAnimation` / `creditsBlock` / `colorPanel` / `holdFrame`), each with its own `[startMs, endMs)` window and an optional inline transition (`'cut' | 'fade' | 'dissolve'`) into the next shot. It's the missing primitive that blocks every Cluster D preset (T-348 → T-353).

T-321 is **distinct from every existing bridge clip**. Caption / Lyrics / SubtitleOverlay / NewsTickerBar / OutcomeRow / StandingsTable / MagicWallPanel / BeatSyncedText all render a **single visual register** at a time, animated by frame-derived progress within one window. None composites multiple sequenced shots into a single timeline. T-321's posture is closer to a mini-NLE (non-linear editor) timeline than a single-style text card: the primitive owns the shot dispatch, the cross-shot transition window, and the per-shot render path, while delegating shot-internal style (typography, color jump-cut, per-letter stagger) to a sealed bundle enum.

T-321 is **L-sized**: ~600–800 LOC component + ~250–350 LOC tests + barrel + ~6 LOC catalog/manifest entries + changeset. Bigger than T-316 (M, ~700 LOC caption.tsx with six bundles, single-style dispatch) and T-322 (M, ~300–400 LOC lyrics.tsx with three bundles, single-style dispatch) because the multi-shot timeline introduces (a) a top-level shot-dispatch layer, (b) per-shot-kind render paths (5 distinct rendering paths — `titlePlate` / `letterAnimation` / `creditsBlock` / `colorPanel` / `holdFrame`), (c) a transition window that briefly composites two shots, and (d) the ALL-CAPS letterform-as-environment scaling math (height-fill via per-letter measurement). v1 ships **timeline + 5 shot kinds + 4 style bundles + 3 transition kinds + per-letter staggered entry + scale-to-fill ALL-CAPS letterforms**. Particles / film grain / light leaks / dust / 3D armillary / hyper-real CGI heads / photographic double-exposure are **out of v1 scope** and carve out to follow-up tasks (T-321a/b/c) — see "Out of scope".

The 6 consumer presets (T-348–T-353) need durations spanning **5 s** (squid-game @ 30 fps → 150 frames) to **50 s** (stranger-things @ 24 fps → 1200 frames) to **90 s** (got / succession / true-detective). Pacing is meditative on most; brutalist on squid-game. T-321 supports all of these by accepting any number of shots up to a hard cap, with per-shot ms-windows that the host author lays out. The primitive is dumb about pacing; it renders what the timeline says.

## Architectural decisions

### D-T321-1. Distinct primitive vs. extending existing

T-321 ships a **distinct** primitive (`titleSequence`), NOT an extension of any existing clip. Rationale:

- **No existing clip composites multiple sequenced shots.** Every existing bridge clip renders a single visual register driven by frame-derived progress within one timing window. CaptionClip / LyricsClip / SubtitleOverlay / NewsTickerBar / OutcomeRow / StandingsTable / MagicWallPanel / BeatSyncedText are all single-window. Multi-shot dispatch is foreign to all of them; bolting it on would pollute their style-bundle dispatch and break their existing tests.
- **Shot-kind divergence.** Title sequences require 5 distinct shot-internal render paths (`titlePlate` / `letterAnimation` / `creditsBlock` / `colorPanel` / `holdFrame`), each with its own typography + layout + animation register. No existing primitive has this dispatch shape.
- **ALL-CAPS scale-to-viewport posture.** Stranger Things / Squid Game require letterforms that fill the viewport — the letterform IS the environment. No existing primitive does scale-to-viewport letterform sizing; CaptionClip / LyricsClip render fixed-size text. Building this on top of either would require a new prop axis (`scaleToFill: boolean`) and conditional layout — adding it to CaptionClip would re-define what CaptionClip is.
- **Per-letter staggered entry across a long sequence.** Stranger Things' letters drift in sequentially over 50 s — each letter has an individual entry window. CaptionClip's per-word stagger is per-line-relative and short (~12 frames per word); T-321's letter stagger is sequence-relative and long (multi-second per letter). Different stagger model.

Reviewer demand for merging into any sibling clip → escalate per CLAUDE.md §6. This is L-size for a reason.

### D-T321-2. Maximum shot count — 16

`shots` array bounded `1..16`. Rationale:

- **Stranger Things** (the longest sequence in Cluster D at ~50 s): the canonical structure is ~12 letterform-entry shots + 1 final pose hold + 2 credits passes ≈ 15 shots. 16 covers 100% of consumer stubs with one slot of headroom.
- **Squid Game** (the shortest at ~5 s): the canonical structure is ~3 color-panel jump cuts + 1 title plate + 3 ○ △ □ symbol-entry shots ≈ 7 shots. 16 covers it with margin.
- **GoT / Succession / True Detective / Severance** all sit between these — typically 4–8 shots in T-321's responsibility (the 3D / photographic register lives elsewhere; T-321 owns the title-plate + credits passes + transition shots).
- 16 is the conservative cap pattern (mirrors T-322 D-T322-2 cap-of-40 logic — sized to >95% of consumer stubs with one slot of headroom). Future presets needing >16 are a one-line bump after layout review; long-form decompose naturally per-section.

Higher counts split into multiple `titleSequence` clip instances at compose time. Mirrors the conservative-cap pattern from T-322 / T-355a / T-357a / T-358a.

### D-T321-3. Four style bundles — `'letterform-assemble'`, `'plate-and-credits'`, `'palette-jump-cut'`, `'photographic-overlay'`

Four orthogonal visual registers cover the canonical prestige-TV title posture:

- **`'letterform-assemble'`** — ALL-CAPS letterforms scaled to fill the viewport, each letter entering on its own per-letter ms-window with optional per-letter `staggerMs` between adjacent letters. Past letters render at full opacity in `highlightColor`; upcoming letters do not render. Active letter (within its entrance window) interpolates opacity + optional `translateY` over the entrance window. This is the **Stranger Things / Squid Game posture** — the letterform IS the environment, no decorative chrome. Glow + casing + theme-slot fallback all apply within this bundle.
- **`'plate-and-credits'`** — A title plate (single string, scaled to large but not viewport-filling) + an optional credits block (≤12 lines, smaller type, wider tracking). Title plate sits at `position.y - plateOffset`; credits block sits at `position.y + creditsOffset`. Active shot dispatches between plate-only (`shot.kind: 'titlePlate'`) and credits-only (`shot.kind: 'creditsBlock'`) sub-renders. This is the **Succession / Severance / GoT posture** — typographic authority, no decorative chrome (the chrome lives in the 3D / photographic sister clip).
- **`'palette-jump-cut'`** — Hard-cut color panels (`shot.kind: 'colorPanel'`) cycling through a palette (e.g., pink → teal → black → pink); each panel renders an optional foreground glyph (the title text or a symbol like ○ △ □) on top of the flat color. Transitions are **always** `'cut'` regardless of `shot.transitionOut` — the brutalist register forbids fades. This is the **Squid Game posture** — bold typography against flat colored backgrounds.
- **`'photographic-overlay'`** — Credits-pass-only register where `creditsBlock` shots render text overlaid on a photographic register that lives in a sister clip (composited at compose time, not within T-321). T-321's responsibility in this bundle is the typography pass; the photographic register is the sister clip. This is the **True Detective posture** — typography unobtrusive, photography foreground.

The four bundles dispatch in a single `switch (style)` block in the component; each style maps to a distinct render path. No "hybrid" / configurable per-feature toggle in v1 — the four bundles are sealed. Future styles add via an additive enum extension (no breakage). When a Reviewer pushes for a fifth bundle (e.g., "kinetic-typography" for a hypothetical motion-typography preset) → escalate; that's a follow-up.

### D-T321-4. Shot data shape — discriminated union

Each shot is a discriminated union on `kind`:

```ts
type Shot =
  | { id: string; startMs: number; endMs: number; kind: 'titlePlate'; content: { text: string }; transitionIn?: TransitionKind; transitionOut?: TransitionKind; metadata?: Record<string, unknown> }
  | { id: string; startMs: number; endMs: number; kind: 'letterAnimation'; content: { text: string; staggerMs?: number }; transitionIn?: TransitionKind; transitionOut?: TransitionKind; metadata?: Record<string, unknown> }
  | { id: string; startMs: number; endMs: number; kind: 'creditsBlock'; content: { lines: string[] }; transitionIn?: TransitionKind; transitionOut?: TransitionKind; metadata?: Record<string, unknown> }
  | { id: string; startMs: number; endMs: number; kind: 'colorPanel'; content: { color: string; glyph?: string }; transitionIn?: TransitionKind; transitionOut?: TransitionKind; metadata?: Record<string, unknown> }
  | { id: string; startMs: number; endMs: number; kind: 'holdFrame'; content: { text?: string }; transitionIn?: TransitionKind; transitionOut?: TransitionKind; metadata?: Record<string, unknown> };

type TransitionKind = 'cut' | 'fade' | 'dissolve';
```

`id` is a stable string (per D-T321-10 — host-supplied or shot-index-derived in test scenarios; never `crypto.randomUUID()`). `startMs` / `endMs` define the shot's timing window. `kind` discriminates which render path executes. `content` carries kind-specific data (text / lines / color / glyph). `transitionIn` / `transitionOut` carry the cross-shot transition kind (defaults to `'cut'`). `metadata` is opaque passthrough for downstream tools (e.g., `seasonVariant: 1` for Succession; preset-specific keys live here, not as primitive props).

Schema enforces:
- `startMs < endMs` (positive duration window)
- `creditsBlock.content.lines` length 1..12 (single-page credits cap; long rolls split)
- `colorPanel.content.color` matches `^#[0-9a-fA-F]{6}$`
- `letterAnimation.content.text` length 1..36 letters (after casing transform; ALL-CAPS scaled-to-viewport caps at 36 — covers titles like "STRANGER THINGS" 15 / "SUCCESSION" 10 / "TRUE DETECTIVE" 14 / "SEVERANCE" 9 / "SQUID GAME" 10 / "GAME OF THRONES" 15 with margin)
- `letterAnimation.content.staggerMs` (when present) ≥ 0
- `holdFrame.content.text` optional (a hold can be empty / black)
- `glyph` (when present) length 1..3 characters (covers ○ / △ / □ + occasional 2-char ligatures)

### D-T321-5. Shot rendering — single-shot per frame + 1-shot overlap during transition window

At any given frame, the primitive dispatches **at most two shots**:

1. The **active shot** — the unique shot whose `[startMs, endMs)` window contains the current ms-time.
2. **Optionally**, the **incoming shot** — if the active shot's `transitionOut` is `'fade'` or `'dissolve'`, AND the current ms-time is within the last `transitionDurationMs` (default 300 ms) of the active shot's window, the incoming shot (the next shot in the array) renders simultaneously, with progressive opacity interpolation.

For `transitionOut: 'cut'` (default), no overlap occurs — the active shot renders alone until `endMs`, then the next shot takes over instantly at its `startMs`. This is the brutalist register (squid-game).

For `transitionOut: 'fade'`, the active shot fades out over the transition window (opacity 1 → 0); the incoming shot fades in (opacity 0 → 1) over the same window. Symmetric crossfade.

For `transitionOut: 'dissolve'`, both shots render at opacity 0.5 in the overlap window with a slight horizontal jitter on the outgoing shot — visually equivalent to fade but with a "harder" feel. (v1 implementation: same as fade but with a `transform: translateX(±2px)` jitter on the outgoing layer.)

Rationale for single-active + 1-overlap (not arbitrary N-shot layering):

- **Determinism is simpler.** Two layers max at any frame; no z-order surprises.
- **Stranger Things / Succession / True Detective / GoT** all use simple sequential pacing; no preset stub demands 3+ simultaneous layers.
- **N-layer compositing is a sister-clip job.** If a preset author wants 3 simultaneous layers, they compose three `titleSequence` instances (or other clips) in the runtime; T-321 stays single-timeline.

If a Reviewer demands N-layer overlap → escalate.

### D-T321-6. Letterform scaling — height-fill via per-letter measurement

For `style: 'letterform-assemble'`, the active title scales to fill the viewport height. Implementation:

- `viewport.height` is read from `useVideoConfig().height`.
- Default `scaleFactor: number = 0.7` (configurable via `letterformScale?: number ∈ [0.1, 1.0]`).
- Effective letter height = `viewport.height * scaleFactor`.
- Letter font size = effective letter height (browsers approximate cap height as ~0.7 × font size; for ALL-CAPS we use font size directly as the cap-height proxy).
- Per-letter `<text>` elements positioned in a horizontal row, centered on `position.x` + `position.y`. Letters are spaced according to the font's natural metrics (no manual letter-spacing override unless `font.letterSpacing` is set).

Bound `1..36` letters per `letterAnimation` shot (per D-T321-4 schema). For titles longer than 36 letters, escalate; layouts that wide are out of envelope for v1 single-row letterforms.

For non-letterform styles (`plate-and-credits`, `palette-jump-cut`, `photographic-overlay`), letterform scaling does NOT apply; type renders at standard metrics (per `font.size`).

### D-T321-7. Per-letter staggered entry — per-letter ms-window within letterAnimation shot

For `letterAnimation` shots in `style: 'letterform-assemble'`, each letter has its own entrance window:

```ts
// For letter at index `i` within letterAnimation shot starting at shot.startMs:
const letterStartMs = shot.startMs + i * (shot.content.staggerMs ?? defaultStaggerMs);
const letterFadeWindowMs = letterFadeDurationMs; // default 400 ms
// At currentTimeMs:
const letterProgress = clamp01((currentTimeMs - letterStartMs) / letterFadeWindowMs);
// Opacity interpolates 0 → 1 over the window; before the window, opacity = 0 (letter not visible).
```

Default `staggerMs = 200`. For Stranger Things' 50-s sequence with ~15 letters, that's `15 * 200 = 3000 ms` total stagger ≈ 6% of the sequence — letters drift in over the first 3 s. Configurable per-shot via `shot.content.staggerMs`.

Pure frame-derived (`currentTimeMs = (frame / fps) * 1000`). Mirror caption.tsx's per-word stagger pattern verbatim, swap per-word for per-letter. No `setTimeout` / `Date.now()` / `Math.random()`.

`letterFadeDurationMs` is a primitive constant (not exposed as a prop in v1). If a preset author needs faster / slower per-letter fade, the v2 path adds a `letterFadeDurationMs?: number` prop. v1 keeps it sealed.

### D-T321-8. Optional `glow?` — text-shadow halo via SVG `<filter>` (basic only)

Optional `glow?: { color: string; blur: number }` prop renders a halo around the active title text (and only the active letter / plate / credits — not the incoming shot during transitions). Mirrors T-322 D-T322-6 verbatim.

Implementation: SVG `<filter id="title-glow-${stableShotId}"><feGaussianBlur stdDeviation="..."/><feFlood flood-color="..."/><feComposite/><feMerge/></filter>` applied to the active shot's `<text>` / `<g>` element. Stable filter IDs (shot-id-derived); no `crypto.randomUUID()`. When `glow` absent, no `<filter>` block emits.

`glow.blur` is in canvas-pixel units (interpreted as SVG `stdDeviation`); `glow.color` is a hex string. v1 ships **static glow** — no animated build-up over a duration window (Stranger Things stub line 36 says "Red neon glow builds gradually"; that animated build-up is a v2 enhancement; v1 renders glow at constant intensity once the shot enters its window).

Past / future shots do NOT glow. The glow is a per-shot-active layer, not a global filter.

**Particle / grain / lightLeak / dustParticles register hooks** — these are deferred (carve-outs T-321a/b/c per "Out of scope"). The schema does NOT accept `grain` / `lightLeak` / `dustParticles` props in v1; if a Reviewer demands them, escalate (the carve-outs are the documented path).

### D-T321-9. Theme slots vs explicit prop colors — explicit with theme-slot fallback

Mirrors T-322 D-T322-8 verbatim. Every color prop is **optional**; theme slot fills in when absent. Cluster owners pass explicit hex (e.g., Stranger Things red `#FF0000` / `#CC0000`, Squid Game pink `#E91E63` / teal `#067162`, Succession sepia / contemporary contrast colors) or rely on the theme.

```ts
themeSlots: {
  background: { kind: 'palette', role: 'background' },
  foreground: { kind: 'palette', role: 'foreground' },
}
```

Top-level optional color props: `background?` (overall canvas color when no `colorPanel` shot is active), `foreground?` (default text color — title, credits, letterforms), `highlightColor?` (active emphasis color — the per-letter "lit" color in `letterform-assemble`; the title-plate active color in `plate-and-credits`). Per-shot color overrides live within the shot's `content` (`colorPanel.content.color` is the canonical case; other shot kinds inherit from the top-level color props).

Per-shot per-letter color overrides are NOT supported in v1. If a Reviewer pushes for per-letter color (e.g., "color the K in 'STRANGER THINGS' red and the rest white") → push back; that's the v2 path. If `palette/foreground` or `palette/background` are not defined on the active theme, the bridge's slot resolution falls back per T-131a rules (Implementer verifies; if rules differ from spec, document + adjust).

### D-T321-10. Determinism gate coverage — stable IDs from shot index

Mirrors T-322 D-T322-10 verbatim. `scripts/check-determinism.ts` globs `packages/runtimes/*/src/clips/**/*.{ts,tsx}` — the new file is automatically in scope. No gate plumbing needed.

The clip uses only `interpolate` + `useCurrentFrame` + `useVideoConfig`; none on the deny-list. Stable IDs:

- `shot.id` is host-supplied (a string, e.g., `'shot-0'`, `'shot-stranger-letters'`). The schema enforces `id: z.string().min(1)`.
- Where IDs are generated internally (clipPath / filter / per-letter mask refs), the format is `title-${shot.id}-${kindSpecific}` — purely derived from `shot.id`. No `crypto.randomUUID()`; no `Math.random()`; no per-render UUID generation.
- Per-letter IDs are `title-${shot.id}-letter-${letterIndex}` — derived from shot.id + letter index.
- Verifies via the determinism test (render the same props twice at the same frame; HTML byte-identical).

If the new path somehow falls outside the glob, escalate — the determinism gate must cover this clip.

### D-T321-12. Casing transforms — `'as-is' | 'uppercase' | 'lowercase' | 'title-case'`

Mirrors T-322 D-T322-12 verbatim. Default `'as-is'`. Per the consumer stubs:

- **Stranger Things** (line 31): "ALL CAPS, scaled to fill the viewport" — preset will pass `'uppercase'`.
- **Squid Game** (line 33): "ALL CAPS, scaled to fill" — preset will pass `'uppercase'`.
- **Succession** (line 30): "ALL CAPS, wide tracking" — preset will pass `'uppercase'`.
- **Severance** (line 31): "Bold, ALL CAPS, scaled large" — preset will pass `'uppercase'`.
- **GoT** (line 33): "ALL CAPS, Roman inscription style" — preset will pass `'uppercase'`.
- **True Detective** (line 31): "ALL CAPS or Mixed Case (per credit type)" — preset will pass `'uppercase'` for headlines, `'as-is'` for credits.

Top-level optional `casing?: 'as-is' | 'uppercase' | 'lowercase' | 'title-case'` (default `'as-is'`). Applied to every rendered shot's text via JS string transform at render time (no CSS `text-transform` — keeps the rendered text byte-stable for parity goldens). ### D-T321-15. Entrance per shot — `'none' | 'fade' | 'rise'`, default `'fade'`

Per-shot entrance is computed purely from frame, mirrored from T-322 D-T322-13. Distinct from the shot **timeline transitions** (D-T321-5):

- **Timeline transitions** (`transitionIn` / `transitionOut`) handle the cross-shot cut / fade / dissolve at shot-window boundaries.
- **Per-shot entrance** handles the within-shot opening posture once the shot becomes active (e.g., a `titlePlate` shot fading in over 12 frames within its own window, independent of the cross-shot transition).

Top-level optional `entrance?: 'none' | 'fade' | 'rise'` (default `'fade'`):

- **`'none'`** — every shot renders at full opacity at its `startMs`-derived frame.
- **`'fade'`** (default) — a 12-frame fade-in window starts when each shot enters its visibility window. Opacity interpolates `0 → 1` over `[shotStartFrame, shotStartFrame + 12]`.
- **`'rise'`** — fade + 12 px translate-up over the same window. `translateY` interpolates `12 → 0`.

When the cross-shot transition is `'fade'` / `'dissolve'`, the per-shot entrance is still applied — the two compose multiplicatively (the entering shot's effective opacity is `transitionOpacity * entranceOpacity`). When the cross-shot transition is `'cut'`, only the per-shot entrance applies.

`letterAnimation` shots ignore the per-shot `entrance` prop in favor of the per-letter staggered entry (D-T321-7) — the per-letter stagger IS the entrance for that shot kind. Other shot kinds (`titlePlate` / `creditsBlock` / `colorPanel` / `holdFrame`) use the top-level `entrance` value.

3. **Multi-shot dispatch is the most subtle piece.** At every frame, compute the active shot index by binary-searching `shots[]` on `currentTimeMs`. Then check whether to also render the next shot (transition overlap). Mirror lyrics.tsx's per-line ms-window discipline; swap per-line for per-shot.

7. **Transition overlap window**: when active shot's `transitionOut !== 'cut'` and current ms-time is within `[active.endMs - transitionDurationMs, active.endMs)`, render both the active and next shots simultaneously. Compute outgoing opacity = `(active.endMs - currentTimeMs) / transitionDurationMs` and incoming opacity = `1 - outgoing` (for fade) or both 0.5 (for dissolve). Per-shot entrance composes multiplicatively (per D-T321-15 final paragraph).

All internal IDs derived from `shot.id` + index per D-T321-10.
