T-371a ships a frame-runtime-bridge clip — `link-sticker` (kebab-case file/kind, mirroring `follow-prompt` / `subscribe-button` / `qr-code-bounce` / `breaking-banner` / `lower-third` / `score-bug`) — that renders a rounded-pill Instagram-style link sticker (~200 × 44 px native) with subtle SHIMMER / highlight sweep across the label glyphs (3 s cycle). T-371a is **deliberately distinct from T-317, T-318, and T-319**. T-317 ships a horizontal subscribe pill anchored bottom-right of a 16:9 frame with one-shot entrance bounce and a `platform` enum (4 platforms). T-318 ships a circular avatar with corner badge anchored right-thumb-zone of vertical video, always-present with periodic sustained pulses. T-319 ships a square QR-code rectangle with continuous DVD-screensaver bounce on a pure-black backdrop, single-object-no-enum schema. T-371a ships a fundamentally different visual register: a *rounded-pill link sticker free-form-positioned on a Story frame* with subtle continuous shimmer (no bounce, no entrance-overshoot, no corner-badge); 4 sealed `variant` values (`'white-on-dark' | 'dark-on-white' | 'frosted-glass' | 'brand-color'`) per the `instagram-link-sticker.md` canon line 24; Inter Medium as v1 OFL fallback; theme-bound surfaces / text / shadow / shimmer slots. T-371a is **M-sized**: ~350–500 LOC component + ~200–300 LOC tests + barrel + ~6 LOC catalog/manifest entries + changeset. Comparable to `qr-code-bounce` (~400–600 LOC), slightly leaner than `follow-prompt` (552 LOC) and `subscribe-button` (612 LOC). Lighter than the platform-fan-out siblings because there is no `platform` enum (only `variant`), no per-platform render fan-out, and no entrance / press-dip animation (v1 ships only `'idle'` + `'shimmering'` phases at frame 60 mid-shimmer — the canonical golden frame for parity). ## Architectural decisions

### D-T371a-1. Distinct primitive vs. extending `cta-pulse` / `subscribe-button` / `follow-prompt` / `qr-code-bounce`

T-371a ships a **distinct** primitive (`link-sticker`), NOT an extension of `cta-pulse` (T-202a), `subscribe-button` (T-317), `follow-prompt` (T-318), or `qr-code-bounce` (T-319). Rationale:

- **Visual register diverges from all four siblings.** `cta-pulse` is a generic radial pulse around an arbitrary child. `subscribe-button` is a horizontal pill with a label, anchored bottom-right of a 16:9 frame, with a `platform` enum (4 platforms). `follow-prompt` is a circular avatar with a corner badge, anchored right-thumb-zone of a 9:16 frame. `qr-code-bounce` is a square QR-code rectangle with continuous DVD-screensaver bounce. T-371a is a *rounded-pill link sticker free-form-positioned on a Story frame* — no platform fan-out, no anchor, no bounce, no avatar.
- **Animation lexicon diverges.** `cta-pulse` ships radial pulsing. `subscribe-button` ships entrance-bounce + press-dip. `follow-prompt` ships bounded sustained-pulse + checkmark-morph. `qr-code-bounce` ships continuous 2D position bounce + uniform hue cycling. T-371a ships *closed-form linear shimmer-sweep across glyphs* — a single moving-gradient overlay on the label, no bounce, no scale, no morph. The 2-phase enum (`'idle'` / `'shimmering'`) is also distinct from the others' phases.
- **Schema shape diverges.** T-317 / T-318 dispatch on a sealed `platform` enum (`discriminatedUnion`). T-319 has no enum at all (single object). T-371a takes the middle posture: a single `z.object({ ... }).strict()` with a sealed `variant: z.enum([...])` enum (4 variants), NOT a `discriminatedUnion`. The `variant` enum drives only color / contrast defaults, not render-path fan-out.
- **Presence model diverges.** T-317 is a one-shot entrance. T-318 is always-present with periodic pulses. T-319 is always-moving. T-371a is *always-present and always-shimmering* (continuous shimmer sweep), free-form-positioned (consumer-provided `position: { x, y }` per `instagram-link-sticker.md` line 26).
- **The consumer stub explicitly pins `clipKind: socialMedia`** (`instagram-link-sticker.md` line 4). The clipKind is **already** reserved in `VALID_CLIP_KINDS` (line 73) — verified 2026-05-07. The architectural intent is a dedicated primitive.

Reviewer demand for merging into any sibling primitive → escalate per CLAUDE.md §6.

### D-T371a-2. Approach — single primitive, single Zod object schema with sealed `variant` enum, no `discriminatedUnion`

**Decision**: a single `link-sticker` primitive with a single `z.object({ ... }).strict()` schema and a sealed `variant: z.enum(['white-on-dark', 'dark-on-white', 'frosted-glass', 'brand-color'])` enum. Diverges from T-317 / T-318's `discriminatedUnion` posture (because variant-specific fields are minimal — only `brand-color` may need a `brandColor` prop, but the brand-color slot also fits cleanly as a top-level optional field, not a discriminated arm).

The Orchestrator evaluated three approaches:

- **Approach A (single primitive, single schema, sealed `variant` enum)** — Single `link-sticker` primitive. ~350–500 LOC. `variant` is a flat enum of 4 strings; per-variant defaults applied via a lookup table. `brandColor?` is an optional top-level field (only meaningful when `variant === 'brand-color'`; defaults to a sealed brand color when absent). ALL_BRIDGE_CLIPS grows 55 → 56.
- **Approach B (single primitive, `discriminatedUnion` on `variant`)** — Pre-bake variant-specific fields. ~500–700 LOC. Forces the schema into 4 arms even though three of them share the same prop shape. Adds dispatch surface for marginal benefit.
- **Approach C (separate primitives per variant)** — Four primitives. Excessive duplication; rejected outright.

**Rationale for A**:

1. **YAGNI.** The 4 variants share the same render path (rounded pill with label + shimmer sweep); only the color tokens differ. A flat enum + lookup table is the right shape.
2. **Sealed enum is forward-compatible.** Adding a 5th variant (`'rainbow-gradient'`, etc.) is an additive enum widening — non-breaking.
3. **Brand-color as optional top-level field** is cleaner than a discriminated arm: the schema reads as "you must pick a variant; if you pick `brand-color`, you may optionally override `brandColor`". Per-variant defaults are applied unconditionally.
4. **Smaller LOC budget.** No `discriminatedUnion` → no per-variant render fan-out → no per-variant Zod schema definitions. Single render path with a per-variant tokens lookup.

Reviewer demand for Approach B (`discriminatedUnion`) or Approach C (separate primitives) → escalate; the architectural rule is sealed at A.

### D-T371a-3. Schema shape (Zod) — single object, sealed `variant` enum, strict mode

Top-level Zod schema is a single `z.object({ ... }).strict()`. NO `discriminatedUnion` (per D-T371a-2). Mirrors the Zod discipline (hex-color regex, position schema, strict mode) of `subscribe-button.tsx` / `follow-prompt.tsx` / `qr-code-bounce.tsx` without their union dispatch.

```ts
const HEX_COLOR_RE = /^#[0-9a-fA-F]{6}$/;

/** Sealed variant enum. v1: 4 variants per instagram-link-sticker.md line 24. */
const linkStickerVariantSchema = z.enum([
  'white-on-dark',
  'dark-on-white',
  'frosted-glass',
  'brand-color',
]);

/** Sealed phase enum. v1: 2 phases. tap-depress / preview-card defer to followup. */
const linkStickerPhaseSchema = z.enum(['idle', 'shimmering']);

const positionSchema = z
  .object({
    /** Absolute pixel x within the canvas (top-left of pill). */
    x: z.number(),
    /** Absolute pixel y within the canvas (top-left of pill). */
    y: z.number(),
  })
  .strict();

/** Shimmer config. v1 sealed at light-sweep with closed-form linear math. */
const shimmerSchema = z
  .object({
    /** Cycle period in frames. Default ceil(fps * 3) (3 s per stub line 36). */
    cycleFrames: z.number().int().positive().optional(),
    /** Width of the highlight band in pixels. Default 40. */
    bandWidth: z.number().positive().optional(),
    /** Highlight color hex. Default per-variant (see token table in D-T371a-7). */
    highlightColor: z.string().regex(HEX_COLOR_RE).optional(),
  })
  .strict();

export const linkStickerPropsSchema = z
  .object({
    /** Free-form label text (default: destination domain). */
    label: z.string().min(1).max(80),
    /** Sealed variant — drives color / contrast defaults. */
    variant: linkStickerVariantSchema,
    /** Free-form pill position (top-left in canvas pixels). */
    position: positionSchema,
    /** Phase. v1 sealed at 'idle' | 'shimmering'. Default 'shimmering'. */
    phase: linkStickerPhaseSchema.optional(),
    /** Pill width in pixels. Default 200 (per stub line 23). */
    width: z.number().positive().min(80).max(600).optional(),
    /** Pill height in pixels. Default 44 (per stub line 23). */
    height: z.number().positive().min(28).max(96).optional(),
    /** Font size in pixels. Default 14 (lower bound of 14–16 per stub line 32). */
    fontSize: z.number().positive().min(10).max(24).optional(),
    /** Brand color hex (only meaningful when variant === 'brand-color'). */
    brandColor: z.string().regex(HEX_COLOR_RE).optional(),
    /** Shimmer config. */
    shimmer: shimmerSchema.optional(),
    /** Background color hex override. Default per-variant from token table. */
    background: z.string().regex(HEX_COLOR_RE).optional(),
    /** Text color hex override. Default per-variant from token table. */
    textColor: z.string().regex(HEX_COLOR_RE).optional(),
    /** Drop-shadow color hex override. Default per-variant from token table. */
    shadowColor: z.string().regex(HEX_COLOR_RE).optional(),
  })
  .strict();
```

All optional except `label`, `variant`, and `position`. Strict mode (no extras). Mirrors the Zod posture of the sibling primitives.

T-371a has *three* required top-level fields (`label`, `variant`, `position`) because all three are domain-essential: there is no sensible default label (consumer must provide), the variant is the visual register choice (must be picked), and the position is free-form per stub line 26 (no anchor canon).

### D-T371a-4. Animation lexicon — 2 sealed phases, closed-form linear shimmer

T-371a v1 ships 2 sealed phases:

- `'idle'` — pill renders without the shimmer overlay (label fully opaque, no highlight band moving across).
- `'shimmering'` — pill renders with a moving highlight band sweeping across the label glyphs once per `cycleFrames` (default `ceil(fps * 3)` = 90 frames at fps 30).

Default `phase: 'shimmering'` (the canonical mid-shimmer reference frame is frame 60, per `instagram-link-sticker.md` line 46).

**Shimmer math** (closed-form; deterministic):

```
cycleFrames = shimmer.cycleFrames ?? ceil(fps * 3)
bandWidth = shimmer.bandWidth ?? 40 (px)
travelDistance = pillWidth + bandWidth   // band starts off-left, ends off-right
phaseProgress = (frame % cycleFrames) / cycleFrames   // ∈ [0, 1)
shimmerX = phaseProgress * travelDistance - bandWidth   // ∈ [-bandWidth, pillWidth)
```

The shimmer band is rendered as a CSS `linear-gradient` inside the pill, positioned at `shimmerX` (relative to the pill's left edge). The gradient is `linear-gradient(90deg, transparent 0%, highlightColor 50%, transparent 100%)` with a fixed band width. Pure trigonometry / arithmetic — no `Date.now()`, no `Math.random()`. The math is identical in shape to T-319's bounce-position math (`(frame % cycleFrames) / cycleFrames * range`) but on a single axis with no rebound.

Implementation: use the runtime's `useCurrentFrame()` + `useVideoConfig().fps` (no `Date.now()`, no `Math.random()`). The `shimmerX` is a pure function of `frame`, `cycleFrames`, `pillWidth`, `bandWidth` — fully deterministic. Apply `Math.round()` at the final render step to integer pixels (per T-319's float-drift discipline).

Future v2 might introduce `'pressing'` (tap-depress to 95 % scale) and `'previewing'` (link-preview card expanded) phases. v1 ships without them — the `'pressing'` / `'previewing'` lexicon is carved out to **T-371a-followup** per the Out-of-scope table.

### D-T371a-5. Variant-token lookup table — per-variant default colors

The 4 variants share the same render path; only the color tokens differ. v1 sealed token table (defaults applied when consumer omits `background` / `textColor` / `shadowColor` / `shimmer.highlightColor`):

| variant | background | textColor | shadowColor | shimmerHighlight |
|---|---|---|---|---|
| `'white-on-dark'` | `#000000` (alpha 0.6 → effectively dark translucent in v1; sealed as opaque `#000000` for v1 determinism) | `#FFFFFF` | `#000000` | `#FFFFFF` |
| `'dark-on-white'` | `#FFFFFF` | `#000000` | `#666666` | `#FFFFFF` |
| `'frosted-glass'` | `#FFFFFF` (alpha 0.4 → opaque `#CCCCCC` v1 fallback per D-T371a-blur deferral) | `#000000` | `#888888` | `#FFFFFF` |
| `'brand-color'` | `brandColor` prop or default `#E1306C` (Instagram brand pink) | `#FFFFFF` | `#000000` | `#FFFFFF` |

Implementation: a `VARIANT_TOKENS` constant `Record<LinkStickerVariant, { background: string; textColor: string; shadowColor: string; shimmerHighlight: string }>` defined at module top. Resolution order per slot:

1. Consumer-provided prop (`background?` / `textColor?` / etc.) — wins if hex-validated by schema.
2. Theme-slot lookup (per D-T371a-7 — `surface` / `text` / `shadow` / `shimmer` slots).
3. `VARIANT_TOKENS[variant].<slot>` literal default.

For `'brand-color'`: the `brandColor?` prop overrides the default `#E1306C`. If `brandColor` is provided AND `background` is NOT provided, `background` resolves to `brandColor`. If `background` IS provided, it wins outright (consumer has explicitly chosen).

### D-T371a-6. Geometry — rounded pill, full-pill border-radius

Implementation: outer pill `<div>` styled as `width: <width>px; height: <height>px; border-radius: <height/2>px; background: <resolvedBackground>; box-shadow: 0 2px 4px <resolvedShadowColor>`. Label inside is centered (flex layout).

### D-T371a-9. Determinism

Frame-derived only. No `Date.now()`, no `Math.random()`, no `crypto.randomUUID()`, no `setTimeout`, no `setInterval`, no `fetch`. The shimmer-sweep math is closed-form (per D-T371a-4); the per-variant token lookup is a pure constant-table read; the pill geometry is a pure function of props.

No SVG instance-IDs needed in v1 (the pill renders via plain `<div>` elements with inline CSS `background` / `linear-gradient`). No `<filter id="...">` / `<linearGradient id="...">` / `<clipPath id="...">`. If a future v2 introduces SVG primitives (e.g., for a frosted-glass blur filter when D-T371a-blur lifts), IDs MUST be derived from stable inputs (e.g., `link-sticker-blur-${variant}`), NOT `crypto.randomUUID()`.

Float drift hazards:

- **Shimmer position**: `(frame % cycleFrames) / cycleFrames * travelDistance` is a float. Apply `Math.round()` on the final rendered position to snap to integer pixels.
- **Determinism test**: render the same props twice at the same frame; rendered HTML strings byte-identical (catches accidental float drift, `Date.now()`, `Math.random()`, `crypto.randomUUID()`).
