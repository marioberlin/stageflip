# T-340 — Cluster B (Sports) composer tools

**Branch**: `task/T-340-cluster-b-compose-tools`

## Goal

Ship the `cluster-b-compose` engine handler bundle exposing four agent-callable composer tools that take semantic intent (sport, brand / league / network, teams, scores, period state) and emit a Cluster B preset binding — preset id + complete props payload validated against the chosen preset's resolver-snapshot Zod schema. The tools are **read-only** (no `MutationContext` patches; they return a preset id + payload that the caller — typically a higher-tier orchestrator or the agent's own plan step — feeds to a separate write-tier handler that mounts the corresponding clip). T-340 is the **first M-sized cluster-composer task** and sets the pattern for T-331 (Cluster A news), T-361 (Cluster D ceremonial), T-368 (Cluster F captions). Cluster B is **9/9 substantive + signed** as of 2026-05-06 (T-339 merged); all nine preset bindings are stable on `main` and ready for a composer surface.

The four tools dispatch into the nine ratified Cluster B presets:

- `compose_sports_score` → 6 of 9 (the `scoreBug` consumers): `premier-league-field-of-play` / `fox-nfl-no-chrome` / `nbc-snf-possession-illuminated` / `f1-timing-tower` / `cricket-scorebug` / `wimbledon-green-purple` — plus `espn-bottomline-flipper` (newsTicker bottom-line for live-score scrolls) routed via a sub-mode flag.
- `compose_standings_table` → 1 of 9 (`standings` consumer): `masters-red-under-par` (golf leaderboard).
- `compose_var_call` → 0 of 9 (gap clip `VARBanner` is T-320, not yet shipped). Returns `not_yet_implemented` for all inputs in v1; the input-validation surface is reserved so the agent's tool-router doesn't need to be re-wired when T-320 lands.
- `compose_player_intro` → 0 of 9 (no Cluster B preset binds the `playerIntro` clipKind yet). Returns `not_yet_implemented` for all inputs in v1; reserved for the eventual Cluster B player-intro preset.

The handlers do not touch any clip code, parity-cli, preset markdown, or signed parity goldens. Pure agent-layer wrapping over the existing preset surface.

## Architectural decisions

### D-T340-1. Handler-bundle name + path

**Decision**: Bundle name is `cluster-b-compose`. Handler files live at `packages/engine/src/handlers/cluster-b-compose/`. Mirrors the existing `<category>` segment convention (e.g., `element-cm1/`, `slide-cm1/`, `data-source-bindings/`). The `cluster-b-` prefix signals "cluster-scoped composer" and reserves a parallel naming convention for the four follow-on cluster-compose bundles (`cluster-a-compose` / `cluster-d-compose` / `cluster-f-compose` / etc.).

Reviewer demand for `sports-compose` / `compose-sports` / any non-cluster-keyed name → escalate. The cluster discipline must be preserved across all five compose bundles (T-340 / T-331 / T-361 / T-368 / etc.).

### D-T340-2. Tools are read-only — declare `ToolContext`, NOT `MutationContext`

**Decision**: Each handler's `TContext` parameter is `ToolContext` (the narrowest router context — only the optional `AbortSignal`). The handler signature is:

```ts
const composeSportsScore: ToolHandler<ComposeSportsScoreInput, ComposeSportsScoreOutput, ToolContext> = {
  name: 'compose_sports_score',
  bundle: CLUSTER_B_COMPOSE_BUNDLE_NAME,
  description: '...',
  inputSchema: composeSportsScoreInputSchema,
  outputSchema: composeSportsScoreOutputSchema,
  handle: (input, _ctx) => {
    // pure dispatch — no patchSink.push, no document reads
  },
};
```

Rationale:

1. **No mutation.** The composer's job is to emit a `(presetId, props)` tuple. The downstream caller mounts the clip via a separate write-tier tool (e.g., `add_clip` from `create-mutate`).
2. **No document reads.** Composer dispatch is a pure function of its input; it doesn't read the existing document state.
3. **Determinism rules at `CLAUDE.md` §3 don't apply.** Those rules govern `packages/runtimes/**` / `packages/frame-runtime/**` / `packages/renderer-core/src/clips/**`. The composer lives at `packages/engine/src/handlers/**` — NOT a clip / runtime / renderer-core path. T-340's handlers are still pure (no `Date.now()`, no `Math.random()`, no I/O) by code-review discipline, but the lint rule does not enforce it. This is documented in the file header comment so reviewers don't trip over the absence of determinism comments.

Reviewer demand for declaring `MutationContext` → escalate; the read-only posture is the architectural seal.

### D-T340-5. `compose_sports_score` schema (input)

```ts
const teamScore = z.object({
  code: z.string().min(1).max(8),     // 'ARS' / 'KC' / 'PHI' — 3-letter standard, up to 8 for bespoke
  color: z.string().regex(/^#[0-9a-fA-F]{6}$/),
  score: z.string(),                  // string allows '0' / '21' / '7-3' / '3 (4)' shootout
}).strict();

const composeSportsScoreInput = z.object({
  sport: z.enum(SPORTS),
  brand: z.enum(BRANDS),
  home: teamScore,
  away: teamScore,
  clock: z.string().min(1),           // '02:34' / '67:42'
  period: z.string().min(1),          // 'Q4' / '2H' / '1st' / 'OT'
  // Optional sport-specific extensions (all opaque pass-through):
  possession: z.enum(['home', 'away']).optional(),     // football
  down: z.string().optional(),                          // NFL down-and-distance like '3rd & 7'
  direction: z.enum(['left-to-right', 'right-to-left']).optional(),  // NBC SNF chevrons
  centerCircle: z.boolean().optional(),                 // NBC SNF
  backdropGradient: z.object({
    centerOpacity: z.number().min(0).max(1),
    edgeOpacity: z.number().min(0).max(1),
  }).optional(),                                        // Fox NFL
  // Cricket / racing / tennis are emitted by sibling tools; this tool is football+racing-aware
  // for now via dispatch table (see D-T340-7). Extension to cricket/tennis lands in v2.
}).strict();
```

`backdropGradient` and `centerCircle` are `'football'`-only extensions (per T-332a's schema). They flow through unchanged; the dispatch chooses the preset id and the tool emits a snapshot that the chosen preset's primitive accepts.

The `f1-timing-tower` preset is also reachable through `compose_sports_score` with `sport: 'racing'` + `brand: 'f1'` — it returns the F1 preset id + a fresh empty `rows: []` payload that the caller fills via a follow-up plan step (or via a future `compose_f1_grid` sub-tool — out of scope for T-340).

### D-T340-6. `compose_sports_score` schema (output)

```ts
const composeSportsScoreOutput = z.discriminatedUnion('ok', [
  z.object({
    ok: z.literal(true),
    presetId: z.enum(CLUSTER_B_PRESET_IDS),
    clipKind: z.enum(['scoreBug', 'newsTicker']),
    props: z.record(z.unknown()),     // opaque payload — caller validates against the primitive's schema
  }).strict(),
  z.object({
    ok: z.literal(false),
    reason: z.enum([
      'no_preset_for_sport_brand',
      'sport_not_supported_by_compose_sports_score',
      'invalid_brand_for_sport',
    ]),
    detail: z.string().optional(),
    candidatePresets: z.array(z.enum(CLUSTER_B_PRESET_IDS)).optional(),
  }).strict(),
]);
```

The `props` field is opaque (`z.record(z.unknown())`) at the composer-tool layer — the **primitive's** Zod schema (e.g., `scoreBugPropsSchema` from `score-bug.tsx`) is the authoritative validator at clip-mount time. Validating it twice (once at compose, once at mount) duplicates work and couples this bundle to clip-package internals; we let the mount-time validation catch shape errors. Reviewer demand for tighter typing → escalate; the architectural posture is preset-id + opaque props.

`candidatePresets` is populated when the dispatch returns a partial-match (e.g., `sport: 'football'` + `brand: 'unknown'` returns the three football brand candidates). The error vocabulary is fixed at three reasons — anything else is a programming bug, not an input-data shape.

### D-T340-11. Per-tool schemas live alongside the handler

Each tool's input + output Zod schemas are top-level `const` bindings in `handlers.ts`, named `${camelToolName}Input` + `${camelToolName}Output`. They are NOT exported from the bundle's barrel — they're internal to the handler. The agent-facing input shape is described by the tool's `LLMToolDefinition` JSONSchema in `TOOL_DEFINITIONS`.

This mirrors `element-cm1/handlers.ts`'s posture verbatim. Reviewer demand for splitting schemas into a separate `schemas.ts` → escalate; the colocated style is the architectural seal across all `<category>` handler bundles.

### D-T340-12. Cross-cluster routing (UEFA fullScreen / golf standings)

`compose_sports_score` does NOT route to UEFA fullScreen presets.
