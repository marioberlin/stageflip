## Decisions

### D-T347e-1 — wired via PRESET_ID_BINDINGS (Pattern C override)

Third `weatherMap` consumer. `PRESET_ID_BINDINGS['heat-map-cool-to-warm'] = heatMapCoolToWarmBinding`.

### D-T347e-2 — 8 US regions spanning the Meriam 38-class spectrum

`regions[]` carries 8 entries spanning the canonical thermal range, each with a `paletteIndex` selected from `MERIAM_38_CLASS_HEAT` (0..37). Cities chosen to anchor recognizable US thermal contrasts:

| id | Display | paletteIndex | Palette band |
|---|---|---|---|
| `anchorage` | Anchorage 18°F | 4 | blue (sub-freezing) |
| `minneapolis` | Minneapolis 38°F | 6 | light blue (cool) |
| `seattle` | Seattle 52°F | 11 | green (mild) |
| `denver` | Denver 65°F | 14 | yellow-green |
| `atlanta` | Atlanta 78°F | 18 | yellow (warm) |
| `los-angeles` | LA 85°F | 20 | orange |
| `phoenix` | Phoenix 102°F | 26 | red (extreme) |
| `death-valley` | Death Valley 118°F | 32 | dark maroon |

The `dataValue` strings include both the city name AND temperature (e.g. `'Phoenix 102°F'`); rendered as plain text overlays per the heat-map style branch (NOT colored discs).

### D-T347e-3 — 8 mapPaths with id-match for fill derivation

`mapPaths[]` carries 8 entries, each with `id` matching one of the regions above. `fill` deliberately OMITTED — the primitive's heat-map style branch derives the fill from the matching region's `paletteIndex` via `resolveHeatMapFill(paletteIndex, oscillation)` (per primitive D-T347a-7).

Each polygon is a rough US-state silhouette anchored to the city's screen position. Synthetic geometry — not pixel-accurate cartography — adequate for parity-fixture verification.

### D-T347e-4 — `units: 'F'` per stub default

Per stub line 49 `units: F | C` is consumer-declared. v1 ships F (the dominant US thermal register; cities chosen are US-domestic). The `'C'` alternative is documented in the primitive but ships separately if a metric register is needed.

### D-T347e-5 — `oscillation: true` (Meriam canon)

Per stub line 47 "Light-dark oscillation across classes is intentional — preserves differentiation for color-blind viewers. Don't smooth it." Default `false` in the primitive; T-347e enables it explicitly.

### D-T347e-6 — typography per stub

`font: { family: 'Open Sans, system-ui, ...', weight: 700, size: 18 }` — stub line 35 "Bold, 18-22pt tabular"; mid-range size 18.

### D-T347e-7 — frame 60 single-frame static; parity thresholds 40 / 0.97

Per stub line 51 reference frames `0 / 30 / 60 / 120`, single-frame golden at frame 60 (3-day forecast register; the canonical settled state). PSNR ≥ 40 / SSIM ≥ 0.97 cluster-radar tighter thresholds (gradient is deterministic).

Multi-frame time-lapse cycling (1.5-2s per period per stub line 41) deferred to T-347a-time-lapse.

### D-T347e-8 — promote preset to substantive

Update preset frontmatter `status: stub` → `status: substantive`. Body unchanged.

### D-T347e-9 — §13 (F-30) verification posture: real-render via parity golden

This is the FIRST + ONLY `'heat-map'`-style consumer in v1. Verifies the third weatherMap style branch end-to-end. After T-347e + T-347c + T-347d ship, **all three weatherMap §13 obligations are closed**.

### D-T347e-10 — Pattern D in-PR sign-off

Same as T-347c / T-347d. Single PR.
