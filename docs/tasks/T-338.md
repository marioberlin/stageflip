# T-338 — Preset: `masters-red-under-par` (standings, Cluster B)

**Branch**: `task/T-338-masters-red-under-par`

## Goal

Promote the existing `masters-red-under-par` preset stub from `status: stub` to `status: substantive` and ship it as the **sixth Cluster B (sports) preset to land** AND the **second consumer of the `standings` clipKind** (after T-357 `olympic-medal-tracker` which holds the clipKind-default slot via `standingsBinding` → `standings-table` primitive). The preset captures the canonical Masters Tournament golf-leaderboard register: a compact ranked table of the top 5 players + position + score-to-par + thru-hole on a dark broadcast base with **Augusta National green `#006747` accent** and the **canonical CBS / Chirkinian red-black-green score-to-par color semantic** (red = UNDER par, black = OVER par, green = EVEN par — universal golf canon since the 1950s) plus Inter 600 OFL fallback for the proprietary CBS Sports custom face. Common uses: golf live tournament leaderboards (Augusta-specific palette + register; sister-but-distinct from T-357's neutral Olympic medal-table register on `#0E0E12` background).

T-338 is the **first `standings` `PRESET_ID_BINDINGS` override** — Pattern C from `docs/handover-phase13-mid.md` §2 (n-th-preset-for-clipKind via `PRESET_ID_BINDINGS`). T-357 holds the `standings` clipKind-default slot (`DEFAULT_CLIP_KIND_RESOLVER` `'standings'` arm → `standingsBinding`); T-338 wires its binding via a new `PRESET_ID_BINDINGS['masters-red-under-par']` override that points at the same `standings-table` primitive but with golf-themed snapshot constants (5-row Masters leaderboard; Augusta green accent; Inter 600 fallback). T-357's clipKind-default arm is **NOT** touched. T-333 / T-334 / T-335 / T-337 / T-339a's prior bindings + their respective `PRESET_ID_BINDINGS` entries are **NOT** touched.

T-338 is **M-sized** — same envelope as T-337. ~30–50 LOC binding + snapshot constant + single steady-state parity golden + sign-off in-PR. Slightly over T-335's `score-bug` envelope to carry the `rows` + `columns` arrays; no schema change; no primitive carve-out. Inherits T-357's `standings-table` primitive verbatim; the binding's only delta from T-357's `standingsBinding` is the snapshot rows (Olympic medal counts → golf score-to-par strings), the `columns` descriptor (rank/code/values[3]/total/delta → rank/label[name]/score/thru), and the palette (`#0E0E12` neutral → `#006747` Augusta accent on the dark base).

T-338 is the **first production consumer of the canonical golf red-black-green score-to-par color semantic** (CBS / Chirkinian canon, universal golf canon since the 1950s — RED = under par, BLACK = over par, GREEN = even par — see Visual tokens). Per **D-T338-10** the `standings-table` primitive's column-tinting capability is the surface for this color rule; if the primitive only supports a single `column.color` per column (rather than per-cell color overrides per row), the v1 contract documents the resulting cosmetic divergence (D-T338-11-a) as a primitive-level concern, NOT a T-338 fix.

## Architectural decisions

### D-T338-1. Compass register match — Masters compact bottom-right / dark broadcast base + Augusta National green `#006747` accent / 5-row golf leaderboard (top-5 players + position + score-to-par + thru-hole) / canonical CBS-Chirkinian red-black-green score color (cosmetic divergence per D-T338-10) / Inter 600 OFL fallback

The stub (lines 22–46) defines the canonical Masters leaderboard register:

- **Position**: compact bottom-right or upper-right scorebug (line 23 — "Compact bottom-right or full-panel leaderboard, showing top 5–10 players"). T-338 anchors via `position: { x: 760, y: 80 }` on a 1280×720 canvas — `x = 760` is ~60% from the left (right side of canvas); `y = 80` puts the panel at upper-right. Compact 5-row register at default 64 px row height + 48 px header = ~368 px panel height; comfortably fits the upper-right region clear of common safe-areas. The upper-right register is deliberately distinct from T-337's bottom-left tennis stack AND T-334 / T-335's bottom-center football bars.
- **Augusta National green `#006747` accent** (line 24 — "Augusta National Green `#006747` permeates the broadcast — applied as accent strip, not full fill"): the `standings-table` primitive does NOT expose a dedicated `accentColor` slot. v1 wires `goldColor: '#006747'` (theme-slot mapping to `palette.accent` per primitive D-T357a-6) so the rank column header / column tinting carries the Augusta green; the visible accent-strip register is NOT natively renderable (D-T338-11-d).
- **Canonical score-to-par color semantic** (lines 25–28 — "Red numbers = UNDER par (good); Black = OVER par; Green = EVEN par"). This is **CBS / Frank Chirkinian canon since the 1950s**, universal golf canon. The `standings-table` primitive's `column.color` is single-color-per-column (D-T338-10); per-row VALUE-derived color is NOT natively expressible. v1 wires `column.color` on the score column to white (`#FFFFFF`) and documents the cosmetic divergence under D-T338-11-a. The brand register includes the canonical color but the v1 render is monochrome on the score column.
- **Per-row fields** (line 29 — "Player name + position + score-to-par + thru-hole"):
  - `rank` — integer 1..5 (rank/position in tournament order).
  - `code` — player surname (Mixed-case; Scheffler / McIlroy / Schauffele / Spieth / Bryson). NOTE: `standings-table` primitive's `'label'` column kind reads `row.code` and renders left-align (lines 122–128); the field name `code` is a misnomer for golf (it's "label" semantically) but the primitive's contract uses `code` regardless. Document under D-T338-13.
  - `values` — `[scoreToPar, thruHole]` as 2-element array of strings or numbers? Per primitive's `'numeric'` column kind, `values` is `array(number)` (line 26 — `values: z.array(z.number())`). The score-to-par strings (`-12`, `-10`, `-8`, `E`, `+2`) are NOT expressible as numbers — `E` is non-numeric and `+2` is a signed string. Per **D-T338-10 + D-T338-11-b**, v1 ships the score column as numeric with negative-numbers-rendered (e.g., `-12`, `-10`, `-8`, `0`, `+2` — except `0` doesn't render as `E` and `+2` doesn't render with a leading `+`). Cosmetic divergence: stub register's `E` for even-par renders as `0`; positive-par rendering depends on JS Number-to-string default (no leading `+`). Documented; NOT a T-338 fix.
  - Thru-hole — same numeric encoding; values like `'F'` (finished — non-numeric), `'17'`, `'15'` would need string encoding or a different column kind. Per **D-T338-10 + D-T338-11-b**, v1 ships thru-hole as integer 0..18 (where 0 = "Finished" — divergence) or omits non-numeric thru indicators. Cosmetic divergence documented under D-T338-11-b.
  - `delta` — canonical golf doesn't surface position-change deltas in the same row register as the score; v1 omits the delta column entirely (5 columns: rank / label / score / thru / total) OR flat-defaults all rows to `'flat'` if delta column kept for visual rhythm. Per **D-T338-4** v1 omits the delta column for clarity.
- **Compact 5-player top-5 leaderboard** (line 23 — "showing top 5–10 players"): T-338 ships exactly 5 rows (canonical Masters: Scheffler / McIlroy / Schauffele / Spieth / Bryson). The primitive accepts `rows.length` 1..16 (line 45); 5 fits the cluster-norm + matches T-357's 5-row Olympic snapshot.
- **Player surname strings** (line 31 — "Player surnames: Bold, 18–22 pt, Mixed Case"): `code: 'Scheffler'` / `'McIlroy'` / `'Schauffele'` / `'Spieth'` / `'Bryson'`. The `'label'` column kind renders weight 600 (per primitive line 128) — matches the stub's "Bold" register at primitive default font size (rowHeight 64 × 0.42 = ~27 pt — close to the stub's "18–22 pt" bound).
- **Inter 600 (Semibold) OFL fallback** for proprietary CBS Sports custom (stub frontmatter lines 7–13): `font: { family: 'Inter', weight: 600 }` — but NOTE: the `standings-table` primitive does NOT expose a `font` prop on its propsSchema (lines 43–63; only background/foreground/colors). The font posture is set primitively to `system-ui, -apple-system, BlinkMacSystemFont, sans-serif` (line 80). v1 declares the preset font in frontmatter and the FontManager applies it at render time per the primitive's TSDoc (lines 181–184). Document under D-T338-13.

### D-T338-2. Resolver entry shape — `PRESET_ID_BINDINGS['masters-red-under-par']` (Pattern C); second `standings` consumer; first `standings`-keyed `PRESET_ID_BINDINGS` override

### D-T338-10. **Pivotal decision** — primitive's per-column color is single-color-per-column, NOT per-cell-VALUE-derived; canonical golf score-to-par color semantic is a v1 cosmetic divergence

**Verified during spec drafting** by reading `standings-table.tsx` lines 102–166 (`renderCell`). The primitive's color resolution path:

- For `kind: 'numeric'` cells: `colColor ?? fg` — that is, the `column.color` (single hex per column) OR the foreground default. There is NO `row.colorOverride` map, NO `column.colorRule` semantic, NO per-cell value-derived color.
- For `kind: 'delta'` cells: color depends on direction (`up` → `upColor`, `down` → `downColor`, `flat` → `flatColor`); but NOT on the row's score VALUE.

The canonical golf score-to-par color rule (RED for negative-to-par values, BLACK for positive, GREEN for even — CBS / Chirkinian canon since the 1950s) requires per-cell color derivation from the row's `score` value:

- Scheffler -12 → RED
- McIlroy -10 → RED
- Schauffele -8 → RED
- Spieth 0 (E) → GREEN
- Bryson +2 → BLACK

This is NOT natively expressible in the current `standings-table` primitive. v1 ships the score column with a SINGLE color (white default per `foreground` fallback), and the canonical color rule is documented as a v1 cosmetic divergence (D-T338-11-a).
