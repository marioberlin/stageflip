# T-316 — `CaptionClip` (word-level timed; highlight / stroke / bounce)

**Branch**: `task/T-316-caption-clip`

## Goal

Ship a frame-runtime-bridge clip — `caption` — that renders word-level timed text with six built-in visual registers (`hormozi`, `mrbeast`, `tiktok`, `ali-abdaal`, `netflix`, `karaoke-wipe`) covering the entire Cluster F preset library: T-362 (`hormozi-montserrat-black`), T-363 (`mrbeast-komika-axis`), T-364 (`tiktok-rounded-box`), T-365 (`ali-abdaal-opacity-karaoke`), T-366 (`netflix-invisible`), T-367 (`karaoke-progressive-wipe`). The primitive is **frame-deterministic**: word visibility derives from `(currentTimeMs ∈ [word.startMs, word.endMs))` where `currentTimeMs = (frame / fps) * 1000`; per-word entrance stagger derives from word index. No audio sync, no live transcription, no random, no timer. `WordTiming[]` is a data input — the cluster F preset's `buildProps` shim populates `words` from a canned canonical caption (e.g., a six-word stat line at 200 ms each).

T-316 is **L-sized**: ~400–550 LOC component (six style bundles + per-word stagger + karaoke-wipe progress + stroke + backdrop + casing dispatch) + ~250–350 LOC tests + barrel + ~6 LOC catalog/manifest entries + changeset. Larger envelope than the S carve-outs (T-356a / T-357a / T-358a) because of the six-style breadth, the SVG stroke + backdrop sub-renderer, and the karaoke-wipe `clip-path` math. The same primitive is reusable across Cluster A breaking-news word-by-word reveals, Cluster B sports score callouts, and Cluster G CTA word emphasis — Cluster F is the headline unblock; cross-cluster reuse amortizes the cost.

T-316 ships **only the primitive** — no Cluster F preset markdown, no parity-cli resolver entry, no parity goldens. Those land in the T-362–T-367 retry tasks after this primitive merges (analog of the Cluster E pattern: T-359 → T-359a → T-359b → T-359c shipped infra, then preset-specific resolver entries followed). Single-concern PR.

## Architectural decisions

### D-T316-1. New `caption` clip vs extending `subtitle-overlay`

T-316 ships a **NEW** `caption` clip at `packages/runtimes/frame-runtime-bridge/src/clips/caption.tsx`, NOT an extension of `subtitle-overlay`. Rationale:

- `subtitle-overlay`'s `subtitleOverlayPropsSchema` is `.strict()` and closed: `{ words?, text?, color?, activeColor?, background?, fontSize?, position? }`. T-316 needs a strict superset (style enum, casing, stroke, backdrop, multi-color highlights, per-word entrance stagger, karaoke-wipe progress, font.weight + letterSpacing). Extending `subtitle-overlay` would either (a) bloat its schema with cluster F semantics (anti-pattern; couples a generic subtitle to a caption-styling vocabulary) or (b) break its closed schema (changes `.strict()` mode behavior — touches existing clip's tests).
- `subtitle-overlay`'s `position` is a closed enum (`'top' | 'center' | 'bottom'`); cluster F captions need pixel-precise `{ x, y, width, alignment }` positioning to compose with other clips on a vertical mobile canvas.
- `subtitle-overlay`'s default behavior (auto-time from `text` prop) is anti-deterministic-charter for Cluster F: each preset must provide explicit `words[]`. Forcing this on `subtitle-overlay` would change its existing contract.
- The two primitives serve distinct roles: `subtitle-overlay` is the legacy slidemotion port (broadcast-style subtitle, single styling register), `caption` is the modern social-video caption primitive (six styling registers, strict word data input, advanced effects). They coexist in the bridge.

Naming: `caption`, NOT `subtitle` / `subtitle-2` / `caption-overlay` — keeps the kind clean and avoids any visible collision with `subtitle-overlay` in test failure messages or skill catalogs.

Reviewer demand to merge into `subtitle-overlay` → escalate per CLAUDE.md §6 (the schema-superset argument is the spec's anchor; merging would forfeit it).

`style: 'hormozi' | 'mrbeast' | 'tiktok' | 'ali-abdaal' | 'netflix' | 'karaoke-wipe'` is a **config preset** that maps to a built-in default props bundle. Each style supplies sensible defaults for `font`, `casing`, `foreground`, `highlightColor`, `muteColor`, `strokeColor`, `strokeWidth`, `backdrop`, `entrance`, and `staggerMs`; the user (or cluster F preset's `buildProps` shim) can override any individual prop.

### D-T316-3. Font handling — props-driven; FontManager integration deferred to presets

The clip uses `font.family` from props, falling back to `system-ui, -apple-system, BlinkMacSystemFont, sans-serif` if absent. The clip itself does NOT enforce font registration via `fontRequirements`. Each cluster F preset declares `fontRequirements` in its preset frontmatter (per T-307); the FontManager preloads + applies at render time. Most cluster F default fonts are BYO-proprietary (Montserrat is OFL-clean; Komika Axis is permissively licensed; Netflix Sans is proprietary — preset author must supply the asset or accept the documented fallback).

If a cluster F preset routes a bespoke font that isn't registered, the consultant escalation rule from CLAUDE.md §6 / ADR-004 §D4 applies — per-preset retry task triggers it, not T-316.

### D-T316-4. Word timing source — `WordTiming[]` data input

`words: { text: string; startMs: number; endMs: number; emphasis?: 'normal' | 'highlight' | 'mute' }[]` is a **required** input. Length 1..200 (covers a long-form caption window without bloating the schema; T-316 is one-clip-per-caption-line, not a full transcript).

- `text` is the visible glyph (after casing transform).
- `startMs` and `endMs` are absolute milliseconds within the clip's local time — `currentTimeMs = (frame / fps) * 1000`.
- `emphasis` is the per-word color routing: `'normal'` (renders in `foreground`), `'highlight'` (renders in `highlightColor`; for MrBeast-style cycling, the i-th highlighted word picks `highlightColor[i % len]` if `highlightColor` is a `string[]`), `'mute'` (renders in `muteColor` at the configured opacity — used by Ali Abdaal's "60% opacity for inactive" register).

The clip does NOT auto-time text. The `subtitle-overlay` auto-split-on-whitespace fallback does NOT exist on `caption`. Cluster F preset `buildProps` shims provide explicit `words[]` (e.g., a canonical six-word stat line at 200 ms each). Schema rejects empty `words` and rejects > 200 entries.

Order: word timings must be monotonically non-decreasing in `startMs` (i.e., `words[i].startMs >= words[i-1].startMs`). Schema enforces via Zod refinement (warning, not hard reject — Implementer's call: tests treat as warning OR reject; recommend reject for strict determinism).

### D-T316-5. Karaoke-wipe implementation — per-word `clip-path` driven by within-word progress

The `karaoke-wipe` style needs a left-to-right color front filling each word during its `[startMs, endMs)` window. Implementation:

- Render each word twice in the same coordinate slot:
  - **Base layer**: word in `foreground` color (the "unfilled" color).
  - **Fill layer**: word in `highlightColor`, positioned absolutely on top, `clip-path: polygon(0 0, ${pct}% 0, ${pct}% 100%, 0 100%)` where `pct = clamp((currentTimeMs - word.startMs) / (word.endMs - word.startMs), 0, 1) * 100`.
- Outside the word's window: `pct = 0` before `startMs` (no fill); `pct = 100` after `endMs` (fully filled — past words remain colored).
- Determinism: pure frame-derived; no transitions, no `requestAnimationFrame`; SVG `clip-path` is deterministic across CDP and DOM-test renderers.

The fill layer's `pointer-events: none` + same `font-family` + same `font-size` + same `font-weight` ensures pixel-aligned overlay. Render to SVG `<text>` with `<clipPath>` if DOM `clip-path: polygon(...)` differs across the test renderer + production bake path; document.

### D-T316-6. Multi-line wrapping — single-line v1; CSS flex-wrap fallback; explicit breaks v2

T-316 v1 renders all words in a single horizontal flex container with `flex-wrap: wrap`. The cluster F preset author controls wrap via `position.width` + `font.size` (narrow width forces wrap). Caption author provides exactly the words for one logical caption line; multi-line captions (e.g., 2-line MrBeast captions) compose two `caption` clips at different `y` offsets.

Explicit line-break tokens (`'\n'` in word text, or a `lineBreak: true` flag on a word) are deferred to v2 if a cluster F preset proves the need. Out of v1 envelope.

### D-T316-7. Stroke implementation — SVG `<text>` with paint-order discipline

Heavy strokes (Hormozi 6 px black around yellow fill; MrBeast 5 px) MUST render as SVG `<text>` with `stroke` + `stroke-width` + `paint-order: stroke fill`. DOM `text-shadow` faux-stroke is NOT acceptable for v1 (uneven across glyph corners; renders blurry at high stroke widths; non-deterministic across renderers).

Implementation: each word renders as `<svg><text stroke="..." stroke-width="..." paint-order="stroke fill" fill="...">...</text></svg>` when `strokeWidth > 0`. When `strokeWidth === 0` (TikTok / Ali Abdaal / karaoke-wipe), word renders as plain DOM `<span>` for cheaper layout.

Mixed-mode (some words SVG, some DOM) is acceptable as long as baseline alignment is preserved — Implementer verifies via the `tabular-nums`-style alignment test (render `"I I I"` and `"M M M"` in stroke mode and confirm vertical baselines match plain DOM mode). If alignment drifts, escalate.

### D-T316-8. Backdrop pill / rect — SVG `<rect>` per word OR per word-group

`backdrop: 'none' | 'pill' | 'rect'`:

- `'none'` — no backdrop element rendered.
- `'pill'` — per-word SVG `<rect>` with `rx = height / 2` (full vertical rounding), `padding: 12 px horizontal, 6 px vertical` (defaults; configurable via `backdropPadding`), `fill = backdrop.color` (default `#000000`), `fill-opacity = backdrop.opacity` (default `0.9`). One rect per word slot — the TikTok register draws a rounded box around each individual word.
- `'rect'` — single SVG `<rect>` covering the entire caption bounding box, `rx = 8 px` (configurable), same padding + fill conventions. Used by Netflix register for a caption-wide letterbox.

Per-word backdrop sits behind the word glyph (lower SVG z-order or earlier in DOM order). Backdrop color is configurable via top-level `background` prop (kept distinct from the canvas-fill `background` to avoid collision; see schema in §Files-to-create).

### D-T316-9. Per-word entrance stagger — frame-derived; index-based

When `entrance != 'none'`, each word has an entrance window starting `staggerMs * i` ms BEFORE its `startMs` (so the word is fully settled by the moment it should be visible). Default `staggerMs: 80`.

```ts
const entranceStartFrame = (word.startMs / 1000 - i * staggerMs / 1000) * fps;
const t = interpolate(frame - entranceStartFrame, [0, 12], [0, 1], {
  extrapolateLeft: 'clamp',
  extrapolateRight: 'clamp',
});
```

Per-style entrance shapes (12-frame settle window, 30 fps default):

- `bounce` — overshoots `scale(1.15)` then settles to `scale(1.0)`; opacity `0 → 1`.
- `rise` — `translateY(40 → 0)` + opacity `0 → 1`.
- `slide-from-top` — `translateY(-40 → 0)` + opacity `0 → 1`.
- `slide-from-bottom` — `translateY(40 → 0)` + opacity `0 → 1`.
- `none` — instant visibility; opacity gated only by `currentTimeMs ∈ [startMs, endMs)`.

Pure frame-derived; no `setTimeout`, no `Date.now()`, no `Math.random()`.

### D-T316-11. Theme slots vs explicit prop colors — explicit with theme-slot fallback

Mirrors `outcome-row` (T-358a D-T358a-4) / `news-ticker-bar` (T-356a D-T356a-6) / `standings-table` (T-357a D-T357a-6): every color prop is **optional**; theme slot fills in when absent. Cluster F preset bundles supply explicit hex (Hormozi yellow `#FFD60A`, MrBeast red/yellow/green cycle); host themes provide defaults if the preset omits.

```ts
themeSlots: {
  background: { kind: 'palette', role: 'background' },
  foreground: { kind: 'palette', role: 'foreground' },
  highlightColor: { kind: 'palette', role: 'accent' },
  muteColor: { kind: 'palette', role: 'foreground' },
  strokeColor: { kind: 'palette', role: 'background' },

```

If a preset's `style` bundle supplies a color and a host theme also defines the slot, **bundle wins** (style is the more specific intent). User prop overrides win over both.

## Acceptance criteria

### Primitive shape (AC #1–#13)

1. `packages/runtimes/frame-runtime-bridge/src/clips/caption.tsx` exists with a one-line file header naming the file + purpose.
2. `captionPropsSchema` (Zod) accepts the schema sketched above; `.strict()` mode (rejects unknown keys).
3. `captionClip` is `defineFrameClip<CaptionProps>({ kind: 'caption', component: Caption, propsSchema: captionPropsSchema, themeSlots: { ...per D-T316-11 } })`.
4. The component default-exports nothing (default exports forbidden per CLAUDE.md §3) — named exports: `Caption`, `captionPropsSchema`, `captionClip`, `CaptionProps`.
5. `style` selects a built-in default-props bundle per D-T316-2; user overrides on individual props win over the bundle.
6. Word visibility: a word is visible (rendered in `foreground` / `highlightColor` / `muteColor` per `emphasis`) iff `currentTimeMs >= word.startMs`. Words BEFORE their `startMs` are hidden when `entrance === 'none'`; entrance-window opacity interpolates per D-T316-9 otherwise.
7. Words AFTER their `endMs` remain visible (default — past words stay on screen until clip end). Cluster F register choices control whether past words are dimmed (Ali Abdaal mute) or full opacity (Hormozi).
8. `casing` transforms the rendered glyph: `'as-is'` (no transform), `'uppercase'` (`.toUpperCase()`), `'lowercase'` (`.toLowerCase()`), `'title-case'` (capitalize first letter of each word). Casing affects rendered glyph only, NOT the underlying `word.text` (timing keys remain on raw text).
9. `backdrop: 'pill'` renders one SVG `<rect>` per word with `rx = height / 2`; `'rect'` renders one SVG `<rect>` covering the caption bounding box; `'none'` renders no backdrop. Each backdrop carries `data-testid="caption-backdrop[-${i}]"`.
10. `strokeWidth > 0` renders words as SVG `<text>` with `stroke` + `paint-order: stroke fill` per D-T316-7; `strokeWidth === 0` renders plain DOM `<span>` per word.
11. `karaoke-wipe` style renders per-word fill progress: at `currentTimeMs = (word.startMs + word.endMs) / 2`, the fill layer's `clip-path` width is ~50% of the word's width (within 1 px tolerance per D-T316-5).
12. Per-word entrance stagger: when `entrance !== 'none'`, word `i`'s opacity at `frame = floor((word.startMs / 1000 - i * staggerMs / 1000) * fps)` is `0`; at that frame `+ 12`, opacity is `1`. Stagger settles by `frame ≈ floor((words[words.length-1].startMs / 1000) * fps) + 12`.
13. Frame-deterministic — same `frame` + same props → byte-identical SVG / DOM output. No `Date.now()`, no `Math.random()`, no `setTimeout`, no `setInterval`, no `fetch`, no `crypto.randomUUID()`. SVG `clipPath` IDs derived from word index per D-T316-12.

## Implementer's notes

1. **Read `subtitle-overlay.tsx` and `typewriter-clip.tsx` and `kinetic-text.tsx` and `beat-synced-text.tsx` before writing a line.** All four inform the shape; none provides the full register breadth.
2. **Schema first.** D-T316-2 / D-T316-4 / D-T316-7 / D-T316-8 / D-T316-9 / D-T316-11 all affect schema shape. Conservative defaults (cap 200 words, six closed styles, optional everything except `words` / `style` / `position`).
3. **Style-bundle authoring early — D-T316-2 is the highest-leverage decision.** Author all six bundles as a single `STYLE_BUNDLES` constant keyed by style enum. Component reads `STYLE_BUNDLES[style]` then merges user overrides on top. Keeps the dispatch logic to a single line; six bundles in a table are easier to review than six branches.
4. **Karaoke-wipe is the most subtle piece.** The `clip-path` polygon must be derived from `(currentTimeMs - word.startMs) / (word.endMs - word.startMs)` clamped to `[0, 1]`. Test it explicitly with a mid-word frame (case #13 in the Test plan). If DOM `clip-path: polygon(...)` differs across renderers, fall back to SVG `<clipPath>` with a `<rect>` element (deterministic across CDP and JSDOM).
5. **Stroke MUST be SVG (D-T316-7).** Do not fall back to `text-shadow`. If SVG-stroke baseline alignment drifts from plain DOM mode, escalate; do not silently mix faux-stroke.
6. **`clipPath` IDs must be deterministic.** Use `caption-clip-${i}`, NOT `crypto.randomUUID()`. Determinism gate enforces this.
7. **Determinism is sacred.** No `Date.now()`, no `Math.random()`, no `setTimeout` / `setInterval`, no `requestAnimationFrame`. Only frame-derived inputs are `useCurrentFrame()` + `useVideoConfig().fps`.
8. **DOM over canvas; SVG only for stroke + backdrop + karaoke-wipe.** `<div>` for the caption container; per-word `<span>` (DOM mode) or `<svg><text>` (stroke mode); per-word `<rect>` for pill backdrop; one `<rect>` for rect backdrop; one `<clipPath>` per word for karaoke-wipe fill.
9. **`tabular-nums` is NOT needed for captions.** Words don't need column alignment; this is a standings-table concern only. Don't copy that pattern over.
10. **MrBeast cycling colors** — when `highlightColor` is `string[]`, the i-th HIGHLIGHTED word (count only `emphasis: 'highlight'` words, not all words) picks `highlightColor[i % len]`. Document.
11. **Biome before commit** (memory: `feedback_biome_format_before_commit.md`): `pnpm biome format --write` on every touched TS / MD file before staging.
12. **`git add` discipline** — specific paths only (memory: `feedback_git_add_specific_paths.md`). NEVER `git add -A` / `git add .`. Pre-existing untracked `project_init/` must NOT be swept in.
