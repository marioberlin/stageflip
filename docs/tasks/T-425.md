# T-425 — `AdapterDescriptor` capability-routing engine

**Branch**: `task/T-425-capability-router`

## Goal

Add a new package `@stageflip/capability-router` that ships the
**agent-side decision layer** between an agent's intent and the
`AdapterRegistry` (T-418). The package's public surface is one pure
function:

```ts
routeCapability(input: RoutingInput): RoutingDecision
```

Where `RoutingInput` declares (a) the modality the caller needs, (b) the
required capability constraints, (c) the calling tenant's license
posture / credentials, and (d) a `rankingPreference`; and
`RoutingDecision` is a discriminated union of `ok: true` (with the
ranked eligible-adapter list and per-reason filter telemetry) and
`ok: false` (with the rejection reason).

T-425 is the **final Phase 14 α task**. After it lands, T-426..T-434
(the nine reference adapters) can dispatch in parallel — each one
registers an `AdapterDescriptor` into a shared `AdapterRegistry` at
host boot and the routing engine selects among them per agent call.

T-425 is M-sized: new package with three small modules (filter, ranking,
router) over the existing T-418 contracts; ~150–250 LOC of router glue,
~60–100 LOC of ranking comparators, ~80–150 LOC of filter pipeline. No
schema, parity, or skill drift; no engine / orchestrator changes.

## Out of scope

| Item | Why deferred |
|---|---|
| Per-call capability **validation** (calling `validateTtsCapability` and friends inline) | T-419's per-modality validators check **adapter-side declared capabilities** at registration time. T-425 takes a CALLER-supplied capability filter and a pre-validated registry; the agent-side filter is a different shape (constraints, not a full descriptor). The two never overlap. |
| Adapter **instantiation** / call dispatch | T-425 returns descriptors; the engine handler bundle (T-423) consumes them and invokes the adapter via the per-modality provider interface (T-419). |
| Fallback-chain execution | T-418 already ships `FallbackChainExecutor`; the routing engine produces an ordered list that the executor consumes. T-425 does NOT swallow the executor. |
| Telemetry **emission** | T-425 returns a per-reason rejection tally inside the `RoutingDecision`; the caller decides whether to emit (and to which sink). Keeps the function pure. |
| Modality-specific quality scoring | The `'highest-quality'` ranking falls back to a caller-supplied scorer hook (`qualityScorer?: (a: AdapterDescriptor) => number`), defaulting to alphabetic by `id` for determinism. Custom scorers live with the agent / handler bundle, not in the router. |
| Sandbox-availability check | T-418 declares the sandbox model on every descriptor but the host-capability check (does this process support `sidecar:python`?) is host-shell state, not router state. Caller passes a `hostSandboxKinds: ReadonlySet<SandboxKind>` and the router filters on it; the host-shell wiring is out of scope. |
| `ResearchSessionProvider` pairing | ADR-007 §D5/§D6 / ADR-008 §D7 own the pairing logic; T-425 surfaces `requiresResearchProvider` on descriptors but does NOT resolve it (caller's job). |
| Schema / parity / clip / preset / parity-golden changes | All untouched. |

## Acceptance criteria

1. New package `@stageflip/capability-router` at `packages/capability-router/` with `package.json`, `tsconfig.json`, no extra build/test configs (matches `@stageflip/asset-cache` and `@stageflip/export-router` shape: `tsup` build + `vitest run` test driven by package.json scripts; defaults suffice).
2. Public barrel `src/index.ts` exports `routeCapability`, the `RoutingInput` / `RoutingDecision` types, the per-stage rejection-reason enum, and the helper sub-exports (`buildFilterPipeline`, `RANKING_PREFERENCES`, etc.) that downstream consumers may want to compose.
3. `routeCapability(input)` is a **pure function** — same input → same output; no `Date.now()`, `Math.random()`, `fetch`, `performance.now()`, timers, or workers. The function reads only from the caller-supplied registry snapshot + the caller-supplied tenant context.
4. The function applies three filters **in order**, each emitting a typed rejection-reason tally:
   1. **Modality match** — keep adapters where `descriptor.modality.kind === input.modality`. Rejection reason: `'modality-mismatch'`.
   2. **Capability match** — invoke the caller-supplied capability predicate (one per modality, validated upstream). Default behavior when no predicate is supplied: accept all candidates from stage 1 (logged via `'capability-predicate-absent'` warning in telemetry but does NOT reject). Rejection reason when predicate returns false: `'capability-mismatch'`.
   3. **License / posture match** — invoke `LicenseGate.evaluate(adapter, tenant)`. `'deny'` → reject with reason `'license-denied'`. `'requires-consent'` → reject with reason `'credential-missing'`. `'allow'` → pass through. Additionally: filter by `hostSandboxKinds` — adapters whose `sandbox.kind` is not in the set are rejected with reason `'sandbox-unavailable'`.
5. The eligible-set is stably sorted by `rankingPreference`:
   - `'cheapest'` → ascending `costPerCall.usd ?? Number.POSITIVE_INFINITY`; ties break on ascending `id`.
   - `'fastest'` → ascending `latencyMs.p95 ?? latencyMs.p50 ?? Number.POSITIVE_INFINITY`; ties break on ascending `id`.
   - `'highest-quality'` → descending caller-supplied `qualityScorer(adapter)`; tie-break on ascending `id`. Default scorer = `0` (so tie-break = pure alphabetic).
   - `'balanced'` (default) → descending composite score: `-log10(cost+ε) + -log10(latency+ε) + qualityScorer`; ties break on ascending `id`. Composite scorer documented in TSDoc + tested.
6. `RoutingDecision` discriminated union:
   ```ts
   type RoutingDecision =
     | {
         readonly ok: true;
         readonly candidates: readonly AdapterDescriptor[];
         readonly totalConsidered: number;
         readonly filteredByReason: Readonly<Record<RejectionReason, number>>;
       }
     | {
         readonly ok: false;
         readonly reason: 'no_eligible_adapters';
         readonly detail: string;
         readonly totalConsidered: number;
         readonly filteredByReason: Readonly<Record<RejectionReason, number>>;
       };
   ```
   The `filteredByReason` map is dense — every reason key is present with the count of adapters rejected at that stage (0 when none).
7. `RejectionReason` enum (frozen array + literal-union type): `'modality-mismatch' | 'capability-mismatch' | 'license-denied' | 'credential-missing' | 'sandbox-unavailable'`.
8. **Pipeline ordering invariant**: an adapter rejected at stage N is NOT considered at stages N+1..K. Tested via per-stage counts (e.g., a license-denied adapter that ALSO fails capability is counted once under `'capability-mismatch'`, not twice).
9. Filter pipeline is exposed for composition: `buildFilterPipeline(opts)` returns `(adapters: readonly AdapterDescriptor[]) => { passed: readonly AdapterDescriptor[]; filteredByReason: Record<RejectionReason, number> }`. The router internally uses this; external callers can too (e.g., a debug UI that wants to inspect per-stage drop-off without ranking).
10. Ranking comparators are exposed: `rankCheapest`, `rankFastest`, `rankHighestQuality`, `rankBalanced` (the `(opts) => Comparator<AdapterDescriptor>` shape). Each is independently testable and deterministic.
11. Tests cover (≥85% coverage on changed files):
    - **Filter pipeline (3 stages tested)**: each stage's pass + reject paths, the ordering invariant (rejection at stage N doesn't reach stage N+1), and the all-pass case.
    - **Ranking comparators (3 explicit prefs + balanced + tie-breaker)**: each preference orders adapters as documented; ties break on `id`; missing cost / latency hints sort last (infinity sentinel).
    - **Router integration**: end-to-end `routeCapability()` calls for the happy path (multiple eligible adapters → ranked list), the empty-eligible path (`ok: false`), and the no-adapter-at-all path (empty registry → `ok: false`).
    - **Tenant license / credential cases**: `permit-byo` with + without `credentials` set; `apache-2.0-only` posture filtering out all but `apache-2.0` adapters; `gpl-incompatible` (always denied).
    - **Sandbox filter**: `sidecar:python` adapter under host that supports only `in-process` → `'sandbox-unavailable'`.
    - **Capability predicate absent**: stage 2 passes all stage-1 survivors when no predicate is supplied (the warning code-path is documented as not currently emitted; tested by absence).
12. `pnpm typecheck && pnpm lint && pnpm test && pnpm check-licenses && pnpm check-asset-licenses && pnpm check-remotion-imports && pnpm check-determinism && pnpm check-skill-drift && pnpm gen:tool-skills:check && pnpm skills-sync && pnpm skills-sync:check` all green.
