# T-316a — fix CaptionClip resolveColor to honor muteOpacity for non-tagged past/future words

**Branch**: `task/T-316a-resolveColor-mute-opacity`

## Goal

Unblock T-365 (`ali-abdaal-opacity-karaoke`). T-316's spec D-T316-2 described
the `ali-abdaal` bundle as "subtle opacity karaoke (active word = full
opacity, others = 60%)" — bundle defaults ship `muteOpacity: 0.6` correctly.
The implementation in `packages/runtimes/frame-runtime-bridge/src/clips/
caption.tsx` (`resolveColor`, ~lines 326–346) only applies `muteOpacity` when
`word.emphasis === 'mute'` is explicitly tagged. Non-tagged past/future
visible words fall through to the foreground branch and render at opacity
`1.0`, defeating the entire opacity-karaoke register. Empirically: T-365's
golden PNG shows all 7 visible words at identical alpha=255.

The contract was correct at spec time; only the routing in `resolveColor`
broke it. T-316a is a 1-line patch + 3 regression test cases + a changeset.
After T-316a lands, T-365 retries unchanged.

**Dependencies**: T-316 (the primitive being patched), T-365 (the blocked task).

## Architectural decisions

### D-T316a-1. Branch position — between highlight/active and foreground fallback

The new branch lives **between** the existing highlight/active branch and
the foreground fallback. Final order in `resolveColor`:

1. `word.emphasis === 'mute'` → `{ color: muteColor, opacity: muteOpacity }` (existing — explicit per-word override).
2. `word.emphasis === 'highlight' || isActive` → `{ color: pickHighlightColor(...), opacity: 1 }` (existing — active wins over implicit dim).
3. **NEW**: `resolved.muteOpacity < 1` → `{ color: foreground, opacity: muteOpacity }` (implicit "bundle declares opacity-based emphasis").
4. Default → `{ color: foreground, opacity: 1 }` (existing).

The active branch precedes the new branch so the active word is never
incorrectly dimmed. The explicit-mute branch stays first so a per-word
override always wins.

### D-T316a-2. Boundary check — `muteOpacity < 1` (not `!== 1`)

`muteOpacity` is `z.number().min(0).max(1).optional()`; resolved value is
always in `[0, 1]`. `< 1` reads as "any non-default opacity dimming" and is
symmetric with the schema's dim semantics. `!== 1` behaves identically given
the bound but is less readable. Pick `< 1`.

### D-T316a-3. NO `muteColor` routing change

The new branch dims the **foreground** color via opacity but keeps the
foreground fill (for ali-abdaal, `muteColor === foreground`; the register's
intent is "opacity-only emphasis, no color shift"). Bundles wanting both
color shift AND opacity still route through the explicit per-word
`emphasis: 'mute'` tag. Two paths semantically distinct: implicit bundle-
level dim = opacity-only; explicit per-word `mute` = color + opacity.

### D-T316a-4. Inline doc note in `resolveColor`

Add a brief inline comment near `resolveColor` explaining the two activation
paths for `muteOpacity`: (a) explicit per-word `emphasis: 'mute'` — full
mute color and opacity; (b) bundle-level `muteOpacity < 1` — past/future
visible words dimmed via opacity only.

### D-T316a-5. NO bundled T-365 retry

T-316a stays surgical. T-365's parity render + sign-off follow in T-365's
retry PR (analog of T-359c → T-359b-retry). Bundling lets a primitive-side
bug masquerade as a preset-side issue. The 3 regression tests plus
back-compat verification (D-T316a-6) are sufficient coverage.

### D-T316a-6. Back-compat verification — T-362 / T-363 / T-364 goldens

`hormozi`, `mrbeast`, `tiktok`, `netflix`, `karaoke-wipe` bundles all ship
`muteOpacity: 1`. The new branch is unreachable for them. After the patch,
re-running T-362/T-363/T-364 parity tests confirms byte-identical output.
Implementer runs these as a smoke check before opening the PR. If goldens
drift → escalate; the patch's blast radius is wider than 1 line.

## Test plan

existing `FrameProvider` test wrapper at 30 fps.

1. **AC #1 — bundle `muteOpacity: 0.6` dims past/future visible words.**
   `style: 'ali-abdaal'`, three words at `{startMs:0,endMs:200} / {200,600} / {600,1000}`,
   none tagged. At `frame = 12` (= 400 ms; word 1 active), assert word 0 opacity `0.6` (±0.01),
   word 1 opacity `1.0`, word 2 opacity `0.6`.
2. **AC #2 — bundle `muteOpacity: 1` regression sentinel.** Same render with `style: 'hormozi'`.
   Assert all three words opacity `1.0`. Proves the new branch unreachable when `muteOpacity === 1`.
3. **AC #3 — active word always opacity 1.0 with `muteOpacity: 0.6`.** Same render with
   `style: 'ali-abdaal'`. At the frame where word 1 is active, assert word 1 opacity `1.0`
   (not `0.6`). Proves the new branch sits below the active branch.

Before opening the PR, run T-362 / T-363 / T-364 parity tests per D-T316a-6
to confirm goldens unaffected.
