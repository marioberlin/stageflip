# T-360 — Preset: `big-number-stat-impact` (bigNumber count-up, Cluster E)

**Branch**: `task/T-360-big-number-stat-impact`

## Goal

Promote the existing `big-number-stat-impact` preset stub from `status: stub` to `status: substantive` and ship it as the **third Cluster E preset to land** (after T-359 / `f1-sector-purple-green` and T-358 / `cricket-ball-by-ball-dots`). The preset captures the universal "stat impact reveal" broadcast convention: a large central number with a count-up animation that drives narrative emphasis at the terminal value. Common uses: post-game stats ("3,847 yards passing"), survey results ("87% of Americans"), election totals ("12.4M votes"), benchmark numbers ("0.91s response time").

T-360 is the second `bigNumber`-clipKind preset — it shares the resolver binding wired by T-359a / T-359 (`bigNumber → animated-value`) but parameterizes it differently (different `value` / `decimals` / `suffix`). This forces a **small evolution of the resolver shape**: today maps `clipKind → ONE binding`; T-360 needs `(clipKind, presetId) → binding` to support multiple presets sharing a clipKind. Additive + backward-compatible.

T-360 is **M-sized** (one step up from T-358/T-359's S) because of: (1) the resolver evolution (~15-25 LOC + tests on both branches); (2) richer typography props (prefix/suffix/units beyond plain count-up); (3) distinguishing the "impact" beat (single state with terminal-value settle emphasis) from T-359 (per-state palette swap). Inherits T-359a's multi-variant infra in trivial-arity mode, T-359b's prod renderer pipeline, T-359c's tsx fix, T-358's resolver-extension precedent.

## Architectural decisions

### D-T360-1. On-disk location — modify the existing stub in place

The stub already exists at `skills/stageflip/presets/data/big-number-stat-impact.md` (verified on disk). T-360 **modifies** that file — does NOT create a new one. `id: big-number-stat-impact`, `cluster: data`, `clipKind: bigNumber` stay. Mirrors T-358 / T-359's stub-promotion pattern.

### D-T360-2. Resolver evolution — `(clipKind, presetId)` keyed override with backward-compat fallback

**Today**: `DEFAULT_CLIP_KIND_RESOLVER` in `packages/parity-cli/src/generate-fixture.ts` maps `clipKind → ONE binding`. `bigNumber → bigNumberBinding` (T-359). `scoreBug → scoreBugDotsBinding` (T-358).

**Problem**: T-360 also has `clipKind: bigNumber` but needs different `value` / `decimals` / `suffix` than T-359. With the current shape, both presets render the same `21.412` from `bigNumberBinding.buildProps`.

**Three options**: (a) per-preset override hook keyed by presetId; (b) extend `bigNumberBinding.buildProps` with an internal preset switch (couples binding to preset list); (c) sibling `bigNumberStatImpactBinding` routed via a `(clipKind, presetId)` tuple key.

**Decision**: **(c)** — `(clipKind, presetId)` tuple key, with backward-compat fallback to clipKind-only when no per-preset entry exists. Each binding's `buildProps` stays focused on ONE preset; new presets add one entry; T-359 + T-358 paths unchanged (no per-preset override → fall through to the clipKind-only resolver).

**Resolver shape evolution** (~15-25 LOC):

```ts
export type ClipKindResolver = (
  clipKind: string,
  presetId?: string,
) => ClipKindBinding | undefined;

const bigNumberStatImpactBinding: ClipKindBinding = {
  runtimeId: 'frame-runtime',
  clipName: 'animated-value',
  buildProps() {
    return {
      value: 87.4,
      decimals: 1,
      suffix: '%',
      fontSize: 360,
      fontWeight: 800,
    };
  },
};

const PRESET_ID_BINDINGS: Readonly<Record<string, ClipKindBinding>> = {
  'big-number-stat-impact': bigNumberStatImpactBinding,
};

export const DEFAULT_CLIP_KIND_RESOLVER: ClipKindResolver = (clipKind, presetId) => {
  if (presetId !== undefined && PRESET_ID_BINDINGS[presetId] !== undefined) {
    return PRESET_ID_BINDINGS[presetId];
  }
  if (clipKind === 'bigNumber') return bigNumberBinding;
  if (clipKind === 'scoreBug') return scoreBugDotsBinding;
  return undefined;
};
```

`createGenerateFixtureRenderer` passes `renderArgs.preset.frontmatter.id` as the second arg. **Budget: ~15-25 LOC.** If past 25 LOC (because a deeper refactor of `FixtureRenderArgs` or `PresetForRender` is required), escalate — the preset-PR loop is the wrong place for an infra refactor.

### D-T360-3. Single canonical mid-hold variant; concrete value `87.4%`

ADR-004 §D5 + T-313 specify a single canonical mid-hold reference frame per preset. T-360 ships **one mid-hold fixture** at `frame: 60` with concrete value **`87.4%`** — exercises both `decimals: 1` and `suffix: '%'` (the two non-trivial knobs of `animated-value` T-359's binding leaves at defaults). Familiar poll/approval/penetration shape; Reviewer eyeballs without context. Cluster owners rebrand at compose time; the preset's contract is the **shape** (large heavy-weight numeric centerpiece + suffix unit + count-up + settle), not the literal value.

### D-T360-4. Stylistic "impact" beat — exploit `animated-value`'s underdamped spring; NO new primitive

The stub's `## Animation` pins a "Final-arrival pulse: brief 1.0 → 1.05 → 1.0 scale, 250 ms". This requires a CSS scale-transform pulse `animated-value`'s prop schema (verified) does NOT expose. Adding it is a runtime-clip API change — out of M-size envelope.

**Three options**: (i) overshoot beat from the spring's natural underdamped settle (damping 15, mass 0.8, stiffness 120 produce a small overshoot at the terminal value naturally — no new component, no new prop); (ii) sustained pause for ~30 frames (mirrors T-406; adds nothing visible at frame 60 already in the hold); (iii) flash overlay / scale-pulse (requires API change or new primitive).

**Decision**: **(i) overshoot beat** — the existing spring's underdamped settle IS the impact beat. Pin in `## Animation`: "count-up uses `animated-value`'s default spring; the spring's underdamped settle at the terminal value IS the 'impact' beat. No additional CSS scale-pulse rendered in v1." A `pulseOnSettle` prop is a follow-up if a Reviewer demands broadcast-exact fidelity. The stub's existing "Final-arrival pulse" prose is **revised** in T-360 to match — document the revision so a future reader does not assume the scale-pulse is rendered.
