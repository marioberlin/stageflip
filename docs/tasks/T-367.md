# T-367 — Preset: `karaoke-progressive-wipe` (lyrics, Cluster F)

**Branch**: `task/T-367-karaoke-progressive-wipe`

## Goal

Promote `karaoke-progressive-wipe` from `status: stub` to `status: substantive` and ship it as the **sixth and final Cluster F (creator captions) preset**, closing the cluster to **6/6**. The preset captures the canonical music-video karaoke caption register: line-level lyrics with per-line **progressive left-to-right color wipe** sweeping across the active line as the music plays, three-line stacked layout (previous line dimmed at top, active highlighted in middle with mid-progress wipe, next line preview at bottom), optional outer-glow halo on the active line, ALL-CAPS display-sans typography (Bebas Neue OFL preferred; Anton OFL declared fallback). Common uses: music videos, sing-along graphics, karaoke screens, lyric-explainer cards, music-show / social-music graphics.

T-367 is the **first and only `lyrics`-clipKind preset** in the plan today and binds the **just-merged `LyricsClip` primitive (T-322, PR #339 on `main`)**, NOT `CaptionClip` (T-316). Per the stub's line 44 architectural rule (carved by T-322): *"Use `LyricsClip` (T-322), not `CaptionClip` — they're distinct gap clips because the timing model is musical, not transcription-based."* Wires the resolver as a **clipKind-default** `lyrics → lyrics` entry (mirrors T-362 hormozi's pattern of being the first preset for its clipKind); subsequent lyrics presets, if any, would later use the T-360 per-preset override mechanism.

T-367 is **M-sized** — same envelope as T-362 / T-363 / T-364 / T-365 / T-366. The LyricsClip primitive (T-322), the preset-loader / integrity / parity-sign-off infra (T-304 / T-308 / T-313), and the multi-variant prod-renderer pipeline (T-359a / T-359b / T-359c) are all on `main`. After T-367 lands, Cluster F closes to 6/6 → eligible for the T-381 batch-merge gate.

### D-T367-5. Style bundle — `'karaoke-wipe'`

Three styles are available on the primitive (T-322 D-T322-3): `'karaoke-wipe'`, `'three-line-stack'`, `'highlight-current'`. T-367 picks `'karaoke-wipe'` to match the preset's name and the stub's line-36 rule (*"Defining technique: progressive **left-to-right color wipe**"*). The wipe is per-line, driven by `(currentTimeMs − line.startMs) / (line.endMs − line.startMs)`; past characters render in `highlightColor` (or `wipeColor`), upcoming characters render in `foreground`. Past lines (above the active) render dimmed at `muteOpacity`; next preview line (below the active) renders at preview opacity. The three-line stack is the canonical music-video lyric register.

`'three-line-stack'` (full-line color flip, no within-line wipe) is the ballad / acoustic register; documented in the body §Visual tokens but NOT chosen for the canonical golden. `'highlight-current'` (mono-line, no neighbors) is the high-impact mono-card register; documented but NOT chosen.

### D-T367-6. Canonical lyric text — three-line representative anthemic phrase

Three lines (matches the `maxLinesVisible: 3` register) of short anthemic phrasing that survive a karaoke-wipe parity contract. Original phrasing (NOT a quote from any copyrighted song):

```
Line 1: "Once upon a time"
Line 2: "We were stronger together"
Line 3: "Now we sing alone"
```

Per-line characteristics:
- Short to medium line lengths (4–5 words each; "We were stronger together" is the longest at 5 words / 24 chars).
- Sentence-shape with rhythmic / emotive register (fits music-video lyric aesthetic without being a copyrighted song lyric).
- Distinguishes from sister Cluster F preset canonical text (T-362 / T-363 / T-364 / T-365 / T-366 are all caption text, not lyric text).
- Renders cleanly at the primitive's default `font.size: 96` Bebas Neue caps across `width: 1024` — Bebas Neue 96 px caps with `letter-spacing: 0` averages ~50 px per char for the longest line ("WE WERE STRONGER TOGETHER" → 25 chars × 50 px ≈ 1250 px) — so this exceeds the position width. **Implementer note**: the primitive's container has `flex-wrap` posture per T-322 spec; if the longest line at default size 96 wraps to 2 visual lines, the parity golden still reads (the wipe operates per `<text>` element and the wrap is cosmetic). If the wrap is undesirable, the Implementer may pass `font: { family: 'Bebas Neue, Anton, ${SYSTEM_FONT_STACK}', weight: 700, size: 72 }` in `buildProps` to shrink the type and document. Default: ship at the primitive's default size 96; allow wrap if it occurs; document.

Cluster owners rebrand at compose time; preset contract is **shape** (three-line stack + ALL-CAPS + per-line wipe + glow + dark canvas), not the literal text.

### D-T367-7. Line timing — 2500 ms per line; canonical mid-hold at frame 105 (= 3500 ms)

Three lines × **2500 ms** each = **7500 ms** total. Lines = `[0, 2500)`, `[2500, 5000)`, `[5000, 7500)`. 2500 ms per line is a typical lyric-line duration (anthemic / mid-tempo). Mid-hold = **`frame: 105`** (= `3500 ms` @ 30 fps).

At `currentTimeMs = 3500`:
- Line 0 (0..2500): past — renders above the active in dimmed `muteOpacity` register (`maxLinesVisible: 3`).
- Line 1 (2500..5000): **active** (`2500 <= 3500 < 5000`) — renders in middle in `highlightColor`. Wipe progress = `(3500 − 2500) / (5000 − 2500) = 0.40` → polygon clip-path covers the leftmost **40%** of the line; the wiped portion in `highlightColor` (default `#F3CE32` yellow), the unwiped portion in `foreground` (default `#CCCCCC` light gray). Optional glow halo applies.
- Line 2 (5000..7500): future — renders below the active in preview / `muteOpacity` register.

Net visual: three-line stack with line 0 dimmed at top, line 1 in middle showing 40% left-to-right yellow wipe with white-light glow halo against a dark `#0E0E12` canvas, line 2 preview at bottom. ALL-CAPS Bebas Neue / Anton fallback at the primitive's default size. The 40% wipe progress visually demonstrates the within-line karaoke sweep at a clearly-mid-progress fraction (not 0%, not 100%, not 50% — 40% is unambiguously mid-wipe and readable).

If floating-point drift makes the wipe-progress polygon points read as `40.0%` vs `39.97%`, acceptable — the parity contract is "exactly one line mid-wiping at clearly-non-trivial progress, two neighbors dimmed." Document whatever lands.

Alternative considered: `frame: 60` (= 2000 ms) — line 0 active at 80% wipe progress (no past line above; line 1 below as preview). Picking `frame: 105` gives the **canonical three-line stack** (past + active + next) which IS the preset's stylistic point; frame 60 would degenerate to a one-or-two-line stack and miss the register. Do NOT introduce a second variant.

### D-T367-11. Hand-pin PSNR ≥ 42 dB, SSIM ≥ 0.98 in `thresholds.json`

Generator default is `35 / 0.95`. Match T-362 / T-363 / T-364 / T-365 / T-366's pin (`42 / 0.98`) for cross-cluster consistency. The stub's existing `## Acceptance (parity)` already says `42 / 0.98` — no revision needed; the stub's threshold posture aligns with the cluster-F suite (rare for stubs; flagged but not actionable).

A three-line lyric stack with mid-progress karaoke wipe + glow halo + dark background is **moderately** antialiasing-sensitive: the wipe-edge polygon clip-path produces a hard left-to-right boundary that can jitter at sub-pixel boundaries, the glow filter alpha-composites against the canvas, and the past/next dimmed lines depend on the `muteOpacity` resolution path. `42 / 0.98` should be comfortable.
