# T-323 — Preset: `cnn-classic` (lowerThird, Cluster A)

**Branch**: `task/T-323-cnn-classic`

## Goal

Promote the existing `cnn-classic` preset stub from `status: stub` to `status: substantive` and ship it as the **first Cluster A (news / lower-third) preset to land** AND the **first preset to bind the `lowerThird` clipKind end-to-end** in the parity-CLI resolver. The preset captures the canonical CNN-Classic news lower-third register: white banner, red flag end-cap on the far left, UPPERCASE bold-condensed headline + Mixed Case talent identification on a 1280×720 canvas anchored bottom-left. Common uses: speaker chyrons, on-air talent identification, breaking-news contributor banners (excluding the breaking-banner red-block path which T-324 handles via a separate `breakingBanner` clipKind).

T-323 is the **first `lowerThird` clipKind to be wired into the parity-CLI resolver**. The `lowerThird` kind is already in `VALID_CLIP_KINDS` (verified `scripts/check-preset-integrity.ts:55`, "Cluster A — news" group). What is missing is the resolver entry that maps `clipKind: 'lowerThird'` to a runnable `LowerThird` mount with a canonical-snapshot constant. T-323 lands that wiring AND the parity-golden sign-off in one PR.

T-323 is **M-sized** — on par with T-350 (`squid-game-geometric`) and T-362 (`hormozi-montserrat-black`). Comparable shape: ~25–35 LOC resolver entry + a canonical-snapshot constant + single steady-state parity golden + sign-off in-PR. The `LowerThird` primitive itself is **already merged** (T-183, kind `'lower-third'`, kebab-case, in `packages/runtimes/frame-runtime-bridge/src/clips/lower-third.tsx`), so unlike Cluster F's first wave (which carved out T-322a for primitive bug fixes), T-323 has **no primitive carve-out** — the gap is closed before the preset PR opens. Inherits T-359a's multi-variant infra in trivial-arity mode, T-359b's prod-renderer pipeline, T-359c's tsx fix, T-360's `(clipKind, presetId)` resolver shape (used in clipKind-default mode here per D-T323-2), T-350's first-Cluster-D-preset workflow (the analog template), T-367's in-PR sign-off (Pattern D from `docs/handover-phase13-mid.md` §2).

## Architectural decisions

### D-T323-1. Compass register match — white banner + red flag end-cap + UPPERCASE headline

The stub (lines 22–33, 41–46) defines the canonical CNN-Classic register:

- **Banner**: `#FFFFFF` fill, width ≈ 75 % of frame, ≈ 1400 × 100 px @ 1080p, positioned 60–80 px from bottom (lines 23, 28).
- **End cap**: `#CC0000` flag on the far left (Boston University Red / PMS 2347 C; line 24).
- **Typography**: Headline UPPERCASE Bold Condensed 28–36 pt `#000000`; talent ID Mixed Case Regular 20–24 pt `#000000` (lines 31–32).
- **Rules**: "Use for: urgent-but-ongoing coverage … Do not paint the full banner red; the flag end-cap is the identifier" (lines 42, 45).

T-323 binds these to the existing `LowerThird` primitive's render contract (T-183). The mapping:

| Stub element | Primitive prop | Snapshot value |
|---|---|---|
| White banner background | `background` | `'#FFFFFF'` |
| Red flag end-cap (6 px-wide left bar) | `accent` | `'#CC0000'` |
| Headline UPPERCASE, 28–36 pt, #000000 | `name` (rendered at 34 px / fontWeight 700; primitive default) | `'BREAKING: SUPREME COURT RULES'` (uppercase string) |
| Talent ID, Mixed Case, 20–24 pt | `title` (rendered at 18 px / fontWeight 500) | `'Anderson Cooper · Chief Anchor'` |
| Position 60–80 px from bottom, far left | `insetLeftPx`, `insetBottomPx` | `64`, `64` |
| Headline color #000000 | `textColor` | `'#000000'` |

The primitive's render of the `title` line uses `color: accent` (red) — see D-T323-5 for the trade-off.

### D-T323-2. Resolver entry — clipKind-default `lowerThird → 'lower-third'`; first Cluster A entry

Pattern C from handover §2: "First preset for a clipKind uses clipKind-default; second-and-later share the clipKind via `PRESET_ID_BINDINGS`." T-323 lands a **clipKind-default** entry in the existing `DEFAULT_CLIP_KIND_RESOLVER` switch arm — matches T-362 (`caption`), T-367 (`lyrics`), T-350 (`titleSequence`), T-355 (`fullScreen`), T-358 (`scoreBug`), T-356 (`newsTicker`), T-357 (`standings`), T-359 (`bigNumber`).

Sister Cluster A presets that ALSO map to `lowerThird` clipKind (T-325 `bbc-reith-dark`, T-326 `al-jazeera-orange`, T-329 `netflix-doc-lt`, T-330 `apple-tv-lt`) will add per-preset overrides via `PRESET_ID_BINDINGS` keyed on the preset id (Pattern C). T-324 (`cnn-breaking`) and T-327 (`fox-news-alert`) bind to `breakingBanner` (a different clipKind, separate primitive); T-328 (`msnbc-big-board`) binds to `fullScreen` (already wired). Net: T-323 establishes the `lowerThird` default; four sister presets share it via overrides; two sister presets bind to other clipKinds; one binds to `fullScreen`.

### D-T323-3. v1 scope — steady-state banner only; LIVE bug / CNN bug / ticker strip / wipe deferred to T-323a/b/c/d carve-outs IF Reviewer scrutiny demands

The stub describes a fully-instrumented CNN-Classic broadcast register: white banner + red flag + UPPERCASE headline + talent ID + LIVE bug + CNN bug + ticker strip + red-block-wipe. The `LowerThird` primitive (T-183) supports only the **first four**: banner (`background`), flag (`accent`), headline (`name`), talent (`title`). The remaining four are decorative additions — none of them are part of the primitive's prop surface, and adding them is a primitive-level concern (not a preset-level one).

**Decision**: T-323 v1 ships the **steady-state register** — banner + flag + UPPERCASE headline + Mixed Case talent. The signed parity golden captures the steady-state mid-hold frame. The LIVE bug, CNN bug, ticker strip, and red-block-wipe are **deferred** to follow-up tasks ONLY IF Reviewer scrutiny demands them:

- **`T-323a`** — LIVE-bug slot (red pulsing dot; primitive-level, NOT a preset).
- **`T-323b`** — CNN bug aux element (logo composition; orchestration-level).
- **`T-323c`** — ticker strip (separate `newsTicker`-clipKind preset; T-356 already wired the primitive; this would be a sister Cluster A preset, not a T-323 follow-up).
- **`T-323d`** — red-block-wipe transition (orchestration-layer transition between two `LowerThird` mounts with different `name` text; not a primitive prop).

**Rationale**: The canonical CNN-Classic identity in a single steady-state frame **is** the banner + red flag + UPPERCASE typography. The LIVE bug, CNN bug, ticker, and wipe are decorative additions that are present in some but not all CNN-Classic broadcast frames; a parity golden of the **steady-state lower-third** captures the brand register without overshooting the M-sized envelope. Mirrors T-350's "v1 Latin only; Hangul deferred" posture.

If a Reviewer demands LIVE bug or ticker or wipe inline → escalate per CLAUDE.md §6; that is the carve-out path, not a T-323 expansion.

### D-T323-5. Casing — `'uppercase'` for headline (applied at snapshot string level); talent name as-is (Mixed Case); talent text color trade-off

The primitive does NOT have a `casing` prop (unlike the `TitleSequenceClip` from T-321 which exposes `casing: 'uppercase' | 'as-is'`). Casing is applied **at the snapshot string level**: the headline value is pre-uppercased in `CNN_CLASSIC_PROPS.name = 'BREAKING: SUPREME COURT RULES'`. The talent line (`title`) is left in Mixed Case per stub line 28 / 32: `'Anderson Cooper · Chief Anchor'`.

**Talent text color trade-off** (D-T323-5 lemma): The primitive renders the `title` line at `color: accent` (line 129). With `accent: '#CC0000'`, the talent text reads in CNN red on the white banner — NOT the stub-specified `#000000` black. Two options:

- **(a)** Accept the cosmetic divergence; the talent text reads red on white (still legible at fontSize 18; cosmetically distinct from canonical CNN-Classic which renders talent in black).
- **(b)** Set `accent: '#000000'` so the talent text is black — but then the **flag end-cap is also black**, killing the primitive's brand-signal identity.

**Decision: (a)**. The flag end-cap IS the CNN-Classic brand signal (stub line 24, 45: "the flag end-cap is the identifier"); painting it black to satisfy the talent-text color spec destroys the brand signal. Red talent text on white reads as CNN-adjacent (CNN's lower-third occasionally renders talent role text in red as a stylistic accent). This is a v1 cosmetic divergence; document in PR body. The primitive change to allow independent flag-vs-talent coloring (e.g., a new `titleColor?` prop) is a candidate primitive-level follow-up, NOT a T-323 carve-out.

### D-T323-6. Reference frame for the parity golden — frame 60 (steady-state mid-hold)

The stub line 49 lists candidate frames: "0 (entry complete), 15 (wipe mid-change), 30 (new text settled), 60 (steady-state)". v1 does NOT render the wipe (D-T323-3) — frame 15 is N/A. Frame 0 is the post-entry instant — at fps=30, `enterEnd = ceil(30 * 0.45) = 14`, so frame 0 is **not** post-entry; it's the start of the slide-in. Frame 30 is post-entry (`30 > 14`) but the primitive's exit window starts at `max(15, durationInFrames - ceil(30 * 0.35)) = durationInFrames - 11`. With `durationInFrames = 90` (3 s @ 30 fps default for parity-CLI compositions; verify in the prod-bound script), exit starts at frame 79; frame 60 is comfortably in the steady-state mid-hold (`60 > 14 && 60 < 79`).

**Canonical reference frame: 60**. Steady-state mid-hold; `translatePct == 0`; `opacity == 1`; banner + flag + headline + talent fully settled. Matches the CNN-Classic broadcast register's "the lower-third has appeared and is on screen" reading. Aligns with the parity-fixture-signoff default (`--frame=60` per `docs/ops/parity-fixture-signoff.md` line 18).

If the prod-bound generator's default `durationInFrames` is shorter than 90 (e.g., 60), frame 60 may sit at or past `exitStart`. Verify via the manifest after generation; if the rendered frame shows partial-opacity or partial-translate, shift to frame **30** (well past entry, well before any plausible exit). Document. Do NOT shift before frame 14 (the entry-end-frame).
