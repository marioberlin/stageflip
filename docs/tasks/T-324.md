# T-324 — Preset: `cnn-breaking` (breakingBanner, Cluster A)

**Branch**: `task/T-324-cnn-breaking`

## Goal

Promote the existing `cnn-breaking` preset stub from `status: stub` to `status: substantive` and ship it as the **sixth Cluster A preset to land** AND the **first preset to bind the `breakingBanner` clipKind end-to-end** in the parity-CLI resolver. The preset captures the canonical CNN-Breaking news register: white full-width banner + red `BREAKING NEWS` label badge on the left + red flag end-cap (left edge) + UPPERCASE bold headline in black, anchored at the bottom of a 1280×720 canvas. Common uses: severe-weather alerts, breaking court rulings, breaking-news contributor banners (excluding the persistent-sliver register which T-327 fox-news-alert handles via the same `breakingBanner` primitive's `mode: 'sliver'` arm).

T-324 is the **first `breakingBanner` clipKind to be wired into the parity-CLI resolver** AND the **first production consumer of the just-shipped T-324a `BreakingBanner` primitive** (merged at SHA `136bb11`, kebab-case kind `'breaking-banner'`). The `breakingBanner` clipKind is already in `VALID_CLIP_KINDS` (verified `scripts/check-preset-integrity.ts:56`, "Cluster A — news" group). What is missing is the resolver entry that maps `clipKind: 'breakingBanner'` to a runnable `BreakingBanner` mount with a canonical-snapshot constant. T-324 lands that wiring AND the parity-golden sign-off in one PR.

T-324 is **M-sized** — on par with T-323 (`cnn-classic`, the closest sibling: first `lowerThird` clipKind binding) and T-330 (`apple-tv-lt`). Comparable shape: ~30–40 LOC resolver entry + a canonical-snapshot constant + single steady-state parity golden + sign-off in-PR. The `BreakingBanner` primitive itself was **just merged** (T-324a, kind `'breaking-banner'`), so unlike T-322a → T-367 (which had to wait an additional cycle for primitive bug fixes), T-324 follows the T-324a primitive directly with no further carve-out — Pattern E rebuild is the only operational discipline. Inherits T-359a's multi-variant infra in trivial-arity mode, T-359b's prod-renderer pipeline, T-359c's tsx fix, T-360's `(clipKind, presetId)` resolver shape (used in clipKind-default mode here per D-T324-2), T-323's first-Cluster-A-preset workflow + first-clipKind-default-binding shape (the analog template), T-367's in-PR sign-off (Pattern D from `docs/handover-phase13-mid.md` §2), F-4 hand-pin via `--psnr=42 --ssim=0.98 --mark-signed` flags (T-330 / T-329 precedent — generator-flag-driven, no manual `thresholds.json` edit).

## Architectural decisions

### D-T324-1. Compass register match — white full-width banner + red flag end-cap + red `BREAKING NEWS` label badge + UPPERCASE black headline + horizontal slide entrance

The stub (lines 22–33, 41–46) defines the canonical CNN-Breaking register:

- **Banner**: `#FFFFFF` fill, full-width, ≈ 1920 × 96 px @ 1080p ("Full-width banner" line 23), positioned at the bottom of the frame (post-2023 rounded corners + flatter styling, line 25).
- **End cap**: `#CC0000` flag on the far left (Boston University Red / PMS 2347 C; line 24, "full-height left").
- **Label badge**: `BREAKING NEWS` red `#CC0000` block with white `#FFFFFF` text (line 26, "red `#CC0000` with white text"). Brand-locked — "is not customizable — it's the brand signal" (line 44).
- **Typography**: `BREAKING NEWS` label Bold Condensed UPPERCASE 32–40 pt (line 31); headline Bold Condensed UPPERCASE 36–44 pt black `#000000` (line 32).
- **Animation**: Horizontal slide-in entrance from the left (T-324a D-T324a-5 mirrors `lower-third.tsx`'s X-axis slide); banner mode (full-width) per T-324a D-T324a-3.

T-324 binds these to the just-shipped `BreakingBanner` primitive's render contract (T-324a). The mapping:

| Stub element | Primitive prop | Snapshot value |
|---|---|---|
| White banner background | `background` | `'#FFFFFF'` |
| Red flag end-cap (12 px-wide left bar in banner mode per T-324a `endCapStyle.width = isSliver ? 8 : 12`) | `endCap` | `{ fill: '#CC0000', position: 'left' }` |
| `BREAKING NEWS` red label, white text, UPPERCASE | `label` | `{ text: 'BREAKING NEWS', fill: '#CC0000', color: '#FFFFFF' }` |
| Headline UPPERCASE Bold Condensed 36–44 pt #000000 | `headline` + `headlineColor` + `casing` + `font` | `headline: 'SUPREME COURT RULES UNANIMOUSLY'` (already uppercase but `casing: 'uppercase'` is set defensively per stub line 32 "ALL CAPS"); `headlineColor: '#000000'`; `casing: 'uppercase'`; `font: { family: 'Inter Tight', weight: 800 }` |
| Banner mode (full-width) | `mode` | `'banner'` (default; CNN canonical register) |
| Horizontal slide-in entrance | `slideAxis` | `'horizontal'` (default; CNN canonical register) |
| Position 60–80 px from bottom | `insetBottomPx` | `60` (CNN-Breaking sits closer to the bottom edge than the lower-third's 64 px; flush with frame bottom safe-zone) |

The primitive does NOT take a `borderRadius` for v1 — leaving the default `0` matches the post-2023 "flatter styling" register (line 25); the "rounded corners" claim is cosmetic and primarily applies to the `BREAKING NEWS` label badge edge, which is rendered as a flat red block by the primitive.

### D-T324-2. Resolver entry — clipKind-default `breakingBanner → 'breaking-banner'`; first `breakingBanner` clipKind binding

**Pattern C** from handover §2: "First preset for a clipKind uses clipKind-default; second-and-later share the clipKind via `PRESET_ID_BINDINGS`." T-324 lands a **clipKind-default** entry in the existing `DEFAULT_CLIP_KIND_RESOLVER` switch arm — matches T-323 (`lowerThird`), T-362 (`caption`), T-367 (`lyrics`), T-350 (`titleSequence`), T-355 (`fullScreen`), T-358 (`scoreBug`), T-356 (`newsTicker`), T-357 (`standings`), T-359 (`bigNumber`).

T-327 `fox-news-alert` is the second `breakingBanner` consumer and will land via `PRESET_ID_BINDINGS` override (Pattern C; supplies the sliver-register snapshot). T-324 establishes the default.

  endCap: { fill: '#CC0000', position: 'left' },

### D-T324-3. v1 scope — steady-state banner only; LIVE pulse / ticker strip / red-block-wipe / CNN bug deferred to T-324b/c/d carve-outs IF Reviewer scrutiny demands

The stub describes a fully-instrumented CNN-Breaking broadcast register: white full-width banner + red label badge + red flag end-cap + UPPERCASE black headline + LIVE bug + CNN bug + ticker strip + entry red-block sweep + red-block-wipe text-change. The `BreakingBanner` primitive (T-324a) supports only the **first four** via the canonical mapping (D-T324-1): banner (`background`), label badge (`label`), flag end-cap (`endCap`), headline (`headline` + `headlineColor` + `casing`). The remaining four are decorative additions — none of them are part of the primitive's prop surface (per T-324a D-T324a-12), and adding them is a primitive-level concern (not a preset-level one).

**Decision**: T-324 v1 ships the **steady-state register** — full-width white banner + red flag end-cap (left) + red `BREAKING NEWS` label + UPPERCASE black headline. The signed parity golden captures the steady-state mid-hold frame. The LIVE pulse, CNN bug, ticker strip, red-block-wipe, and staged entrance-sweep are **deferred** to follow-up tasks ONLY IF Reviewer scrutiny demands them:

- **`T-324b`** — LIVE pulse bug (red pulsing dot + "LIVE" badge; primitive-level — `BreakingBanner` would gain an optional `livePulse` prop; NOT a preset-level fix).
- **`T-324c`** — red-block-wipe transition (orchestration-layer transition between two `BreakingBanner` mounts with different `headline`; not a primitive prop).
- **`T-324d`** — CNN bug aux element (logo composition; orchestration-level; sister-clip rather than `breaking-banner` prop).
- **Ticker strip** — composes externally via existing `news-ticker-bar` (T-356a) in adjacent layout slot, NOT a follow-up to T-324.

**Rationale**: The canonical CNN-Breaking identity in a single steady-state frame **is** the white banner + red flag + red `BREAKING NEWS` label + UPPERCASE black headline. The LIVE pulse, CNN bug, ticker, wipe, and staged entrance-sweep are decorative additions that are present in some but not all CNN-Breaking broadcast frames; a parity golden of the **steady-state breaking banner** captures the brand register without overshooting the M-sized envelope. Mirrors T-323's "v1 banner only; LIVE bug / CNN bug / ticker / wipe deferred" posture.

If a Reviewer demands LIVE pulse or ticker or wipe inline → escalate per CLAUDE.md §6; that is the carve-out path, not a T-324 expansion.
