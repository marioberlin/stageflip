# T-357a — `standings-table` runtime-clip primitive (vertical N-row ranked table with K numeric columns + delta arrows)

**Branch**: `task/T-357a-standings-table-primitive`

## Goal

Ship a small generic frame-runtime-bridge clip — `standings-table` — that renders a vertical ranked table of N (1..16) rows with K (2..8) columns of mixed kind (`rank`, `label`, `numeric`, `delta`, `total`), per-column color tinting, delta-arrow glyphs, and a frame-derived staggered fade/slide entrance. The primitive is the missing piece that blocked T-357 (`olympic-medal-tracker`, Cluster E): the Implementer surveyed every existing clip in `packages/runtimes/frame-runtime-bridge/src/clips/` and confirmed none carries the visual register:

- `comparison-table` is a fixed two-column shape (`leftRows` / `rightRows`); the medal-table needs 5–7 columns and a per-row rank.
- `financial-statement` is a hierarchical P&L composite with closed-set `statementType` enum + `semanticRole` enum; no "country" / "rank" semantic role and the row hierarchy doesn't fit a flat ranked list.
- `kpi-grid` is a 2×N or 3×N card grid; not a vertically-ranked tabular row.
- `outcome-row` (T-358a) and `news-ticker-bar` (T-356a) are horizontal-axis primitives — wrong axis for a vertical ranked table.
- All other primitives (dashboard composites, chart family, single-card chyrons, candlestick) carry the wrong geometry or impose props (axes, scales, labels) the standings table doesn't have.

T-357 surfaces the gap first, but the same primitive is needed across multiple clusters: Cluster B sports score crawls (F1 constructors' standings, NBA conference standings, March Madness aggregations, college-football top-25, golf leaderboards, esports ladders), Cluster A breaking-news adjacent (election results tables, polling aggregations), and crypto / financial dashboards (top-N market-cap leaderboards). Building `standings-table` once as a reusable generic amortizes the cost across these clusters; per-cluster prop builders (medal palettes, team colors, party colors) live in `parity-cli` resolver shims, not in this primitive. Same pattern as T-358 → T-358a → T-358-retry and T-356 → T-356a → T-356-retry.

T-357a is **S-sized**: ~250–320 LOC component + ~150–200 LOC tests + barrel + ~6 LOC catalog/manifest entries + changeset. Slightly larger envelope than T-356a because tabular layout is more involved than a horizontal scrolling chyron (header row, per-column kind dispatch, per-row stagger). It does NOT touch T-357's preset markdown, the parity resolver entry, or the parity goldens — those land in the T-357-retry PR after this primitive merges.

## Architectural decisions

### D-T357a-1. Generic `standings-table` vs preset-specific `medal-table`

T-357a ships a **generic** primitive, NOT Olympic-specific `medal-table`. Rationale:

- "Vertical N-row ranked table with K numeric columns + delta arrows" recurs across ≥4 cluster A/B/E families: Olympic medal-table (T-357), F1 constructors' standings, NBA / NCAA / college-football leaderboards, golf leaderboards, esports ladders, election results, polling aggregations, crypto top-N market-cap dashboards. A medal-specific clip would re-implement per cluster.
- Cluster-specific semantics (gold/silver/bronze tinting, team palettes, party colors) belong in the `parity-cli` resolver's `buildProps` shim, not in the runtime primitive. The primitive accepts pre-resolved `{ rank, code, values[], total?, delta? }` rows + per-column `color` overrides.
- Genericity cost is moderate (~250–320 LOC vs the ~150–200 LOC a medal-only clip might need). Reviewer should reject if `StandingsTable` grows cluster knowledge (e.g., `palette: 'olympic' | 'nba'` enums or hard-coded medal column ordering).

Reviewer demand for Olympic-specific naming → escalate per CLAUDE.md §6.

### D-T357a-2. Maximum row count — 16

`rows` array bounded `1..16`. Covers a top-16 leaderboard cut, NBA conference standings (15 teams), an NCAA bracket aggregation, golf-leaderboard cut-line (top-16 advance), and an Olympic medal-table top-16 (covers ~95% of broadcasts). Higher counts are corner cases (full FIFA World Cup table = 32; crypto top-100 dashboards = 100). One-line bump if a future preset proves the need; v1 caps at 16 to keep the schema permissive without forcing the renderer to compute scrollable inner-band geometry.

### D-T357a-3. Column kinds — five (`rank`, `label`, `numeric`, `delta`, `total`)

Each column has a required `kind` selector that drives layout + glyph dispatch: `rank` (right-aligned numeric, permissive ~32–40 px width), `label` (left-aligned text — country code, team name), `numeric` (right-aligned with `tabular-nums`; honors per-column `color` for medal-style tinting), `delta` (center-aligned glyph per D-T357a-4), `total` (right-aligned with **heavy weight** + `tabular-nums`).

Five kinds cover Cluster E (Olympic: rank/label/numeric × 3 + total + delta), Cluster B (sports standings: rank/label/numeric × W-L + numeric pct + delta), Cluster A (election results: rank/label/numeric × votes + numeric pct + delta). v1 is enum-closed; additive kinds (e.g., `flag`, `bar-inline`) are v2 if a future preset proves the need.

### D-T357a-4. Delta representation — both string enum and numeric

The row schema accepts both forms for `delta`:

```ts
delta?: 'up' | 'down' | 'flat' | number
```

The component derives the rendered glyph from sign:

- `'up'` or `delta > 0` → `↑` (UP ARROW, U+2191)
- `'down'` or `delta < 0` → `↓` (DOWN ARROW, U+2193)
- `'flat'` or `delta === 0` → `▬` (BLACK RECTANGLE, U+25AC)

Numeric form lets a preset express magnitude (`delta: -3` = dropped 3 ranks); string form is the simpler / opaque form for presets that don't need magnitude. Both are first-class in v1; the cell renders only the glyph (color from `upColor` / `downColor` / `flatColor`). If a preset needs magnitude as visible text (e.g., `↓3`), that's a v2 enhancement (additive `showDeltaMagnitude?: boolean` prop). Out of v1 envelope.

### D-T357a-5. Per-column color override (medal-color tinting)

Each column carries an optional `color?: string` (hex). When set, the cell text inherits it — used by Cluster E presets to tint gold (`#FFD700`) / silver (`#C0C0C0`) / bronze (`#CD7F32`) medal columns. When absent, falls back to `foreground`.

v1 does NOT introduce `column.kind === 'medal-gold' | 'medal-silver' | 'medal-bronze'` tagged kinds; that would couple the primitive to an Olympic semantic. The preset's parity-cli resolver's `buildProps` shim wires the gold/silver/bronze hex literals into `column.color` slots. Row-level color (e.g., division winner highlight) is a v2 enhancement (additive optional `row.color`). Out of v1 envelope.

### D-T357a-6. Theme slots vs explicit prop colors — explicit with theme-slot fallback

Mirrors `outcome-row` (T-358a D-T358a-4) and `news-ticker-bar` (T-356a D-T356a-6): every color prop is **optional**; theme slot fills in when absent. Cluster owners pass explicit hex (Olympic gold/silver/bronze, F1 team colors) or rely on the theme.

```ts
themeSlots: {
  background: { kind: 'palette', role: 'background' },
  foreground: { kind: 'palette', role: 'foreground' },
  goldColor: { kind: 'palette', role: 'accent' },
  silverColor: { kind: 'palette', role: 'foreground' },
  bronzeColor: { kind: 'palette', role: 'foreground' },
  upColor: { kind: 'palette', role: 'positive' },
  downColor: { kind: 'palette', role: 'negative' },
  flatColor: { kind: 'palette', role: 'foreground' },
}
```

The `goldColor` / `silverColor` / `bronzeColor` top-level props are intentionally retained as named slots even though D-T357a-5 routes per-column color through `column.color`. They serve as theme-derived defaults the preset's resolver can read when `column.color` is absent (a Cluster E preset with no explicit medal hexes inherits theme-slotted "accent" as gold). If `palette/positive` or `palette/negative` aren't defined on the active theme, the bridge's slot resolution falls back per T-131a rules (Implementer verifies; if rules differ from spec, document + adjust).

### D-T357a-7. Font posture — system-ui fallback; no hard-bound font; tabular-nums on numeric cells

The primitive does NOT hard-bind a font family. Presets declare `preferredFont` / `fallbackFont` in frontmatter; the FontManager preloads + applies at render time. The component uses `font-family: 'system-ui, -apple-system, BlinkMacSystemFont, sans-serif'`.

Numeric cells (`kind: 'numeric' | 'rank' | 'total'`) gain `font-variant-numeric: tabular-nums` so column digits align across rows regardless of the fallback font's proportional digits. This is the visible-quality gate — without it, the standings columns look ragged. Deterministic across renderers. Document in TSDoc.

### D-T357a-8. NO T-357 follow-up changes in this PR

T-357a is **surgical**. Does NOT touch `packages/parity-cli/src/generate-fixture.ts` (no `standings → standings-table` resolver entry, no `OLYMPIC_MEDAL_SNAPSHOT`), `skills/stageflip/presets/data/olympic-medal-tracker.md` (no promotion), or `parity-fixtures/data/olympic-medal-tracker/**` (no goldens). T-357-retry picks those up post-merge. Pattern: T-358a → T-358-retry; T-356a → T-356-retry. Single-concern PR keeps the Reviewer's job clean and lets the primitive ship under multi-cluster reusability merit, not as scaffolding for one preset.

### D-T357a-9. Determinism gate coverage

`scripts/check-determinism.ts` line 51 globs `packages/runtimes/*/src/clips/**/*.{ts,tsx}` — the new file is automatically in scope. No gate plumbing needed. The clip uses only `interpolate` + `useCurrentFrame` + `useVideoConfig`; none on the deny-list. If the new path somehow falls outside the glob, escalate — the determinism gate must cover this clip.

### D-T357a-10. Layout strategy — proportional widths via flex with optional override

Columns lay out via CSS flex (or grid — internal choice). Each column can declare `flex?: number` (default `1`); the `rank` and `delta` columns typically take `flex: 0` + a fixed pixel width via `width?: number`. Fixed-pixel widths force preset authors to recompute on canvas resize; proportional is the default. Sample columns (Olympic medal table):

```ts
{ key: 'rank', label: '#', kind: 'rank', width: 40 }
{ key: 'code', label: 'NOC', kind: 'label', flex: 2 }
{ key: 'gold', label: 'G', kind: 'numeric', color: '#FFD700' }
{ key: 'silver', label: 'S', kind: 'numeric', color: '#C0C0C0' }
{ key: 'bronze', label: 'B', kind: 'numeric', color: '#CD7F32' }
{ key: 'total', label: 'T', kind: 'total' }
{ key: 'delta', label: '∆', kind: 'delta', width: 40 }
```

### D-T357a-11. Entrance stagger — frame-derived per-row fade + slide

Each row's entrance is computed purely from frame:

```ts
const delayFrames = (i * staggerMs) / (1000 / fps);
const t = interpolate(frame - delayFrames, [0, 12], [0, 1], { extrapolateLeft: 'clamp', extrapolateRight: 'clamp' });
const opacity = t;
const translateY = (1 - t) * -8;  // -8 → 0 px
```

Default `staggerMs: 80` means at 30 fps the 16th row settles by `frame ≈ 12 + 15 * (80 * 30 / 1000) = 48`. No `setTimeout` / `Date.now()` / `Math.random()`; pure frame-derived.

## Acceptance criteria

### Primitive shape (AC #1–#9)

1. `packages/runtimes/frame-runtime-bridge/src/clips/standings-table.tsx` exists with file header naming the file + purpose.
2. `standingsTablePropsSchema` (Zod) accepts:
   - `rows: { rank: number; code: string; values: number[]; total?: number; delta?: 'up' | 'down' | 'flat' | number }[]` of length 1..16
   - `columns: { key: string; label: string; kind: 'rank' | 'label' | 'numeric' | 'delta' | 'total'; color?: string; width?: number; flex?: number }[]` of length 2..8
   - `rowHeight: number` (default 64; positive)
   - `headerHeight: number` (default 48; positive)
   - `staggerMs: number` (default 80; non-negative; entrance only)
   - `bandPosition: 'overlay' | 'fullscreen'` (default `'fullscreen'`)
   - Optional explicit colors: `background`, `foreground`, `goldColor`, `silverColor`, `bronzeColor`, `upColor`, `downColor`, `flatColor` — all hex strings (`/^#[0-9a-fA-F]{6}$/`). All optional; theme slots fill in defaults per D-T357a-6.
3. `standingsTableClip` is `defineFrameClip<StandingsTableProps>({ kind: 'standings-table', component: StandingsTable, propsSchema: standingsTablePropsSchema, themeSlots: { ...per D-T357a-6 } })`.
4. `StandingsTable` renders a header row of `headerHeight` px showing `column.label` per column, with `column.color` tinting the header label when set.
5. Below the header, N rows of `rowHeight` px each render in `rows` order; each cell dispatches on `column.kind`:
   - `rank` → `row.rank`, right-aligned, tabular-nums.
   - `label` → `row.code`, left-aligned.
   - `numeric` → `row.values[k]` (where `k` is the numeric column's index among numeric columns), right-aligned, `column.color` if set, tabular-nums.
   - `total` → `row.total`, right-aligned, **heavy weight**, tabular-nums.
   - `delta` → glyph (`↑` / `↓` / `▬`) per D-T357a-4, color from direction.
6. Per-row entrance stagger: row `i` becomes fully opaque + settled at `frame ≈ 12 + i * staggerMs / (1000 / fps)`; opacity interpolates `0 → 1`, `translateY` interpolates `-8 → 0` over a 12-frame window per D-T357a-11.
7. `bandPosition: 'fullscreen'` fills the canvas; `'overlay'` constrains to natural table height + centers within the canvas.
8. Numeric cells (kinds `rank`, `numeric`, `total`) carry `font-variant-numeric: tabular-nums` per D-T357a-7.
9. Frame-deterministic — same `frame` + same props → byte-identical SVG / DOM output. No `Date.now()`, no `Math.random()`, no `setTimeout`, no `setInterval`, no `fetch`.

## Test plan

`standings-table.test.tsx` cases (8–12 — Implementer trims to fit coverage):

1. **Schema accepts minimal valid input** — `.parse({ rows: [{ rank: 1, code: 'USA', values: [10, 8, 5] }], columns: [{ key: 'rank', label: '#', kind: 'rank' }, { key: 'code', label: 'NOC', kind: 'label' }] })` does not throw.
2. **Schema rejects empty rows** — `.parse({ rows: [], columns: [...minValid] })` throws (`min(1)`).
3. **Schema rejects over-cap rows** — `.parse({ rows: <17>, columns: [...minValid] })` throws (`max(16)`).
4. **Schema rejects empty / single-column columns** — `.parse({ rows: [...], columns: [] })` throws; same with one column (`min(2)`).
5. **Schema rejects over-cap columns** — `.parse({ rows: [...], columns: <9> })` throws (`max(8)`).
6. **Schema accepts both string and numeric delta** — `.parse({ rows: [{ rank: 1, code: 'USA', values: [1], delta: 'up' }], ... })` passes; same with `delta: -3`.
7. **Render at frame 0 produces N rows with header visible** — render `<StandingsTable rows={<3>} columns={<5>} />` at `frame=0`; assert header row shows three column labels; assert each row's data-testid `standings-table-row-0..2` is present; assert row opacity ≈ 0 at frame 0 due to stagger.
8. **Render at large frame produces all rows fully visible** — render same props at `frame=120` (well past `12 + (rows-1) * staggerMs / (1000/fps)`); assert every row's opacity === 1.
9. **Delta column glyph dispatch** — three rows with `delta: 'up'`, `'down'`, `'flat'`; assert delta cell text content is `↑`, `↓`, `▬` respectively. Same with numeric `delta: 5`, `delta: -3`, `delta: 0`.
10. **Per-column color tints the cell** — column with `color: '#FFD700'`; assert the rendered cell carries that color (style or computed style).
11. **Numeric cells carry `font-variant-numeric: tabular-nums`** — render rank / numeric / total columns; assert each cell's style or class includes `tabular-nums`.
12. **Determinism** — render the same props twice at frame 60; rendered HTML strings byte-identical (catches accidental `Date.now()` / `Math.random()`).

Test environment: `@testing-library/react` + `vitest`; bridge's `FrameProvider` test wrapper (see `outcome-row.test.tsx` and `news-ticker-bar.test.tsx`). `useVideoConfig` mocked / provided via the wrapper; Implementer mirrors those setups.
