# T-444 — Adapter sandbox model

**Branch**: `task/T-444-adapter-sandbox`

## Goal

Third-party (and first-party) adapters now run through a **SandboxRunner**
dispatched by their declared `AdapterDescriptor.sandbox.kind`. Per-adapter
credentials live in a new `TenantAdapterCredentialsStore` facet on
`@stageflip/storage` and are injected scoped to a single adapter — never
exposing tenant-wide credentials to adapter code. Every adapter invocation
emits an `AdapterAuditEvent` (start / complete / failed / killed-for-
resource-limit) for the downstream **T-446 security audit**.

This is the **FINAL Phase 14 γ task** — the dependency-graph blocker for
T-446 (security audit) which in turn gates T-447 (GA readiness). After
T-444 lands, Phase 14 γ is fully complete and δ (Lock-in: T-445/T-446/
T-447) opens.

## §13 statement — YES, structural extension; option 3 deferral

T-444 introduces TWO new degrees of freedom in the descriptor / storage
model:

1. **`AdapterDescriptor.resourceLimits?`** — a new optional field on the
   adapter descriptor:
   `{ maxMemoryMb?: number, maxCpuMs?: number, maxDiskMb?: number }`.
   Only meaningful for `sandbox.kind = 'sidecar'`. Ignored by other
   runners.
2. **`TenantSettings.adapterCredentials?`** — a new optional field on
   the per-tenant settings schema. Shape: `Record<adapterId, {
   apiKey?: string, baseUrl?: string }>`. Backed by a sibling storage
   facet `TenantAdapterCredentialsStore` mirroring T-443's
   `TenantCostTrackerStore`.

Per CLAUDE.md §13 option 3: **pixel-level verification is N/A** because
both fields are metadata — neither participates in the RIR document
tree, threads into a renderer, produces visible output, or alters
parity goldens. Evidence:

- Unit-test roundtrip of the extended `AdapterDescriptor` Zod schema
  (incl. all `resourceLimits` validation cases — bounds, optionals,
  strict-extra-keys rejection).
- Unit-test roundtrip of the extended `TenantSettings` Zod schema
  (incl. all `adapterCredentials` cases).
- Contract tests for `TenantAdapterCredentialsStore` (record / query /
  reset / per-tenant + per-adapter isolation).
- Unit tests for each of the three `SandboxRunner` impls (in-process,
  sidecar, remote-service).
- Unit tests for `AdapterAuditEvent` emitter (in-memory ring buffer).
- Unit tests for `SandboxFactory` (descriptor dispatch).
- Integration tests for `FallbackChainExecutor`'s sandbox-aware mode.

The §13 backstop (`parityFixture-non-blank` in
`scripts/check-preset-integrity.ts`) is N/A — neither `resourceLimits`
nor `adapterCredentials` ever reach a parity fixture.

## Architecture overview

### Three runners, one factory

```
                        ┌────────────────────┐
                        │ FallbackChain      │
                        │ Executor           │
                        └─────────┬──────────┘
                                  │  (per invocation)
                                  v
                        ┌────────────────────┐
                        │  SandboxFactory    │   reads
                        │                    │───► descriptor.sandbox.kind
                        └─────────┬──────────┘
                                  │
              ┌───────────────────┼───────────────────┐
              v                   v                   v
   ┌────────────────────┐ ┌────────────────────┐ ┌────────────────────┐
   │ InProcessSandbox   │ │ SidecarSandbox     │ │ RemoteServiceSand- │
   │ Runner             │ │ Runner             │ │ boxRunner          │
   │ (no-op wrapper)    │ │ (spawn child;      │ │ (HTTPS w/ scoped   │
   │                    │ │  JSON-RPC stdio;   │ │  credentials)      │
   │                    │ │  kill on done +    │ │                    │

                          │ (in-memory ring;   │
                          │  T-446 wires Cloud │
                          │  Logging)          │
                          └────────────────────┘
```

### Trust boundary (v1 — `in-process`)

`InProcessSandboxRunner` is a no-op wrapper — the adapter call runs in
the same Node process as the host. This is intentional: every adapter
shipped today (kokoro, fish-speech, ace-step, yue, stable-audio-open)
is built by StageFlip from Apache-2.0 or MIT models we audit. The
trust boundary is documented at the runner interface; v2 may wrap
`in-process` with `vm.Context` isolation if a third-party Apache-2.0
adapter ever lands in-tree.

### Resource limits (sidecar-only)

When `descriptor.resourceLimits` is set AND `descriptor.sandbox.kind =
'sidecar'`, the `SidecarSandboxRunner` enforces:

- **`maxCpuMs`** — userspace timer; SIGKILLs the child on expiry.
- **`maxMemoryMb`** — best-effort: a userspace memory monitor
  reading `/proc/<pid>/statm` (Linux) or `ps -o rss=` (macOS) every
  500ms. SIGKILLs on overage. Falls back to NO-OP on Windows
  (CI runs on Linux; the macOS / Windows fallback is documented).
- **`maxDiskMb`** — declared in v1; ENFORCEMENT DEFERRED to T-447
  (GA readiness audit; the cgroups-based enforcer needs production
  hardening). The descriptor field is shipped now so adapter
  authors can declare it; the field is validated but not yet
  acted upon.

A kill-for-resource-limit emits an `AdapterAuditEvent` with
`outcome: 'killed-for-resource-limit'` and the offending dimension.

### Credential scoping

`TenantAdapterCredentialsStore.getCredentials(tenantId, adapterId)`
returns the credentials for a SINGLE `(tenantId, adapterId)` pair —
or `null` if none are configured. The host's sandbox dispatcher
calls this and forwards ONLY the resulting `{ apiKey?, baseUrl? }`
to the adapter — the adapter never sees credentials for OTHER
adapters even within the same tenant.

For `RemoteServiceSandboxRunner`, credentials are passed as request
headers (Authorization Bearer + optional `X-Base-URL` override).
For `SidecarSandboxRunner`, credentials are passed via stdin
JSON-RPC `init` message (NOT via env vars, NOT via argv — neither
leaks to `ps` / `/proc/<pid>/environ`).

### Audit events

```ts
export type AdapterAuditEvent =
  | { kind: 'start'; adapterId: string; modality: string; tenantId: string; sandboxKind: string }
  | { kind: 'complete'; adapterId: string; modality: string; tenantId: string; sandboxKind: string; durationMs?: number }
  | { kind: 'failed'; adapterId: string; modality: string; tenantId: string; sandboxKind: string; errorMessage: string }
  | { kind: 'killed-for-resource-limit'; adapterId: string; modality: string; tenantId: string; dimension: 'cpu' | 'memory' | 'disk' };
```

The emitter is pluggable: the default `InMemoryAuditEmitter` keeps a
bounded ring buffer (capacity 1000, drops oldest). T-446 wires Cloud
Logging via a `CloudLoggingAuditEmitter` impl.

## Acceptance criteria

### AC #1 — `AdapterDescriptor.resourceLimits?` schema field

- Field added to the `AdapterDescriptor` interface and Zod schema
  (`packages/adapters-core/src/adapter-descriptor.ts`).
- Shape:
  `{ maxMemoryMb?: number, maxCpuMs?: number, maxDiskMb?: number }` —
  strict object (unknown keys rejected); each dimension nonnegative
  finite number.
- Unit tests round-trip the field (present / absent / partial / all
  three).
- All 9 reference-adapter descriptor tests continue to pass without
  modification (the field is optional).

### AC #2 — `TenantSettings.adapterCredentials?` schema field

- Field added to the `TenantSettings` interface and Zod schema
  (`packages/storage/src/tenant-settings.ts`).
- Shape: `Record<adapterId, AdapterCredential>` where
  `AdapterCredential = { apiKey?: string, baseUrl?: string }` — strict
  object; at least one of `apiKey` / `baseUrl` required when the
  record is present (an empty `{}` is rejected).
- `adapterId` keys validated kebab-case (matching the descriptor
  regex).
- Unit tests round-trip the field.

### AC #3 — `TenantAdapterCredentialsStore` facet

- Interface + in-memory impl
  (`packages/storage/src/tenant-adapter-credentials-store.ts`),
  mirroring `TenantCostTrackerStore`.
- Methods:
  - `getCredentials(tenantId, adapterId): Promise<AdapterCredential | null>`
  - `setCredentials(tenantId, adapterId, credential): Promise<void>`
  - `listAdapterIds(tenantId): Promise<readonly string[]>`
  - `deleteCredentials(tenantId, adapterId): Promise<void>`
- Per-tenant + per-adapter isolation tests pass.
- Empty-credential `{}` rejected at set boundary.

### AC #4 — `SandboxRunner` interface

- New package `@stageflip/adapter-sandbox` exports:
  - `SandboxRunner` interface — `run<TIn, TOut>(invocation): Promise<TOut>`
  - `SandboxInvocation` shape carrying `descriptor`, `tenantId`,
    `credential`, `input`, `auditEmitter`.
- Type-only contract tests prove the interface shape.

### AC #5 — `InProcessSandboxRunner` impl

- Calls a host-supplied `inProcessCallable(descriptor, input)`
  function directly; no isolation in v1.
- Emits `start` + `complete` audit events.
- Emits `failed` audit event on thrown error; rethrows the error.
- Test: round-trip identity for a simple callable.
- Test: error path emits `failed` and rethrows.

### AC #6 — `SidecarSandboxRunner` impl

- Spawns a child process (default `node` for `sandbox.runtime: 'node'`,
  `python` for `'python'`) via test-injected `spawn` seam.
- Implements minimal JSON-RPC over stdio:
  - Host → sidecar: `{ jsonrpc: '2.0', id, method: 'init',
    params: { credential, input } }`
  - Sidecar → host: `{ jsonrpc: '2.0', id, result }` OR
    `{ jsonrpc: '2.0', id, error: { code, message } }`
- Kills the child on completion (clean exit) or on resource-limit
  breach (SIGKILL).
- Resource-limit enforcement:
  - `maxCpuMs` — `setTimeout`-based wall-clock kill (NOT real CPU
    time — documented in the SKILL).
  - `maxMemoryMb` — userspace poll every 500ms via injectable
    `readMemoryRssMb(pid)` seam.
  - `maxDiskMb` — declared but NOT enforced in v1 (T-447).
- Emits `start` / `complete` / `failed` /
  `killed-for-resource-limit` audit events.
- Tests inject a fake spawn + fake stdio; no real child process.

### AC #7 — `RemoteServiceSandboxRunner` impl

- Wraps a host-supplied `httpsCallable(url, headers, input)` seam.
- Reads `baseUrl` from credential (override) OR `descriptor.sandbox.baseUrlEnvVar`
  (default).
- Passes `apiKey` as `Authorization: Bearer <apiKey>` header.
- Emits `start` / `complete` / `failed` audit events.
- Tests inject a fake https callable.

### AC #8 — `AdapterAuditEvent` emitter

- `InMemoryAuditEmitter` — ring buffer (default capacity 1000;
  drops oldest on overflow).
- `emit(event): void` — pure sync (no I/O in v1).
- `events(): readonly AdapterAuditEvent[]` — snapshot for tests.
- `clear(): void` — test seam.
- Tests: ordering preserved; overflow drops oldest; clear resets.

### AC #9 — `SandboxFactory`

- `SandboxFactory.pick(descriptor: AdapterDescriptor): SandboxRunner` —
  dispatches on `descriptor.sandbox.kind`.
- Throws on `'wasm-sandbox'` (not implemented in v1; documented).
- Constructor accepts the three runner instances + `inProcessCallable`
  + `httpsCallable` + `spawnSeam` + `auditEmitter`.
- Tests: each of the 3 kinds returns the matching runner.

### AC #10 — `FallbackChainExecutor` sandbox-aware dispatch

- `execute()` gains an optional `sandboxFactory?` option. When set,
  the executor wraps each `call(adapter)` in
  `sandboxFactory.pick(adapter).run(...)`.
- Backwards-compatible: omitting `sandboxFactory` keeps the existing
  direct-call behavior (test fixtures don't need to migrate).
- Tests: with `sandboxFactory`, audit events emit per call; without,
  no audit events.

### AC #11 — Adapter-regression snapshots stable

- After adding `resourceLimits?` to the descriptor schema and the

## Out of scope

- **Real cgroups enforcement** — userspace memory + cpu timer is v1;
  cgroups lands in T-447 (GA hardening).
- **WASM sandbox impl** — `'wasm-sandbox'` descriptor kind already
  exists from T-418 but no runner ships in T-444. The factory throws
  a clear error if an adapter declares this kind. WASM lands when
  the first WASM-runtime adapter does (post-Phase 14).
- **Production audit transport** — `CloudLoggingAuditEmitter` lands
  in T-446 (which consumes the `AdapterAuditEvent` shape ratified
  here).
- **Credential rotation flow** — the `TenantAdapterCredentialsStore`
  has set + delete; an admin UI for rotation lands later.
- **Sidecar process pool / warm-pool** — every sidecar invocation
  spawns + kills. Pooling is a perf optimization, post-Phase 14.
