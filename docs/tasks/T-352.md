# T-352 — Preset: `succession-home-video` (titleSequence, Cluster D)

**Branch**: `task/T-352-succession-home-video`

## Goal

Promote the existing `succession-home-video` preset stub from `status: stub` to `status: substantive` and ship it as the **fourth Cluster D (titles / opens / bumpers / credits) consumer preset** of the T-321 atmospheric-primitive carve-out roadmap, the **third multi-clip composition** in the parity-CLI (after T-348 `stranger-things-benguiat` introduced `ClipKindBinding.overlays?` and T-351 `true-detective-double-exposure` reused that surface), AND a **secondary consumer of the T-321d `photographic-overlay` primitive** — this time exercising `mode: 'sepia'` end-to-end for the FIRST time in StageFlip parity history (T-348 picked `'fade'`, T-351 picked `'cinematic-lut'`; T-352 picks `'sepia'`). T-352 ships the prestige-TV Succession S1+ canon "home video / dynastic" register: the **grainy 4:3 sepia "home video" footage register** (stub line 24 — childhood privilege scenes intercut with crisp contemporary corporate footage), warm yellow-brown tonal grading via `mode: 'sepia'` at high intensity (~0.70 — sepia must dominate the visual; the home-video tint is the canonical mood signal), heavy film grain at intensity ~0.30 (per stub line 26 "moderate film grain, subtle frame chatter" — VHS-tape chatter requires HIGHER grain than the canonical 0.15 default; `'subtle'` here is relative-to-VHS, NOT relative-to-T-348/T-351), wide-tracking dynastic-stationery typography (Engravers Gothic + Sackers Gothic preferred, commercial-byo; IBM Plex Sans Condensed OFL fallback for v1 rendering), ALL CAPS at +200 to +300 letter-spacing tracking (stub line 32 — signature "minimum +200, often +300").

T-352 is the **fourth Cluster D consumer** of the T-321 carve-out roadmap. Three primitives ship in this composition (mirroring T-351's 3-clip stack but with different mode + heavier grain):

- **T-321** (parent) — `titleSequence` primitive with the `'photographic-overlay'` style register OR `'plate-and-credits'` register (D-T352-6 picks the cleanest match for the canonical credit hold).
- **T-321a** — `grain` primitive (deterministic xxhash32 per-pixel film-grain noise; **HIGH intensity 0.30** — VHS-tape chatter per stub line 26; opposite posture from T-348/T-351 which used the canonical 0.15 subtle default).
- **T-321d** — `photographic-overlay` primitive (`mode: 'sepia'` for the warm yellow-brown home-video tint per stub line 26; intensity ~0.70 — sepia register must dominate the visual; secondary consumer of the primitive after T-351 was the PRIMARY consumer).

Cluster D is **3/6 signed** as of `main` HEAD `156c5393` (T-348 stranger-things-benguiat + T-350 squid-game-geometric + T-351 true-detective-double-exposure all merged; T-349 / T-352 / T-353 remain). **T-352 brings Cluster D to 4/6 signed.** After T-352, Cluster D will be one ThreeSceneClip-dependent task (T-349 got-trajan-clockwork) plus one more video-shot-dependent task (T-353 severance-surreal-3d, also ThreeSceneClip) away from full closeout.

T-352 is **L-sized** (matching T-348 / T-351 envelope; L is driven by the same multi-clip composition surface, lowered thresholds, photographic-overlay register exercise, AND the documented v1-vs-canon divergence around the deferred VHS video element). The L-size envelope is driven by:

## Why v1 ships sepia-photographic-overlay-only (NO actual VHS video element)

The Succession home-video register's most distinctive technical feature is the **video element scoped to a shot's [startMs, endMs] window** — actual VHS-tape footage rendered inside the title-sequence's timeline (stub line 41: "preset compose accepts a `sepiaSource: VideoRef` for custom footage with the period look applied via a film-grade layer"). Implementing this requires extending the `titleSequencePropsSchema` shot enum with a 6th `kind: 'videoShot'` discriminator AND modifying `title-sequence.tsx`'s per-shot dispatch to render a `<video>` element with frame-windowed playback math.

**Per `docs/tasks/T-321-carveout-audit.md` carve-out #6** — this is documented as a `titleSequence` modification deferred to consumer T-352. The audit identifies three integration paths:

1. **Ship T-352 with full video-shot integration** — modifies `title-sequence.tsx`, extends shot enum, adds video element rendering, scoped playback math. **L+ scope; bleeds into primitive-side modification.**
2. **Ship T-352 as photographic-overlay-only register** — no actual video footage; renders as sepia-graded styled image overlay over the existing canvas. **Simpler L scope; defers VHS-video-element work to T-352-followup.**
3. **Defer T-352 entirely** — wait for a separate "extend titleSequence with videoShot kind" task before consumer ships.

**T-352 picks option (2)**, documented as D-T352-1. This mirrors T-351's deferral of the silhouette-as-window double-exposure technique (T-351 D-T351-9-b — also a register that requires primitive-side work; T-351 also chose to ship the photographic tonal layer only and defer the structural compositing technique to a follow-up). Both deferrals enable the cluster to close more quickly while honoring the canon partially. The visual register that ships in v1 is "sepia-graded credit hold over a placeholder background with heavy VHS-grade grain" — captures the canonical home-video MOOD without the canonical home-video MEDIUM. **Reviewer should NOT demand actual VHS video element rendering in this PR.**

## Architectural decisions

### D-T352-1. Composition strategy — option (2) per `T-321-carveout-audit.md`: ship v1 as photographic-overlay sepia + grain register; defer actual VHS video element to T-352-followup

The `T-321-carveout-audit.md` (carve-out #6) identifies three integration paths for the canonical home-video VHS register. **T-352 picks option (2)** — ship v1 as a photographic-overlay-only sepia-graded register; NO actual `<video>` element rendering; NO modification to `title-sequence.tsx`. Document the VHS-video-element integration as **T-352-followup carve-out** (will need primitive-side `videoShot` shot-kind extension separately specced + impl'd).

**Rationale**:

1. **Sticks to the established multi-clip composition pattern.** T-348 / T-351 both ship as multi-clip overlay compositions; option (2) keeps T-352 in the same architectural shape. Reuses `ClipKindBinding.overlays?` verbatim. Zero new structural surface.
2. **Mirrors T-351's documented-divergence posture.** T-351 deferred the silhouette-as-window double-exposure technique to T-351-followup (a primitive-side modification). T-352 deferring the videoShot shot-kind to T-352-followup is the structurally identical move — both presets ship the photographic tonal layer only and document the structural compositing technique as a follow-up.
3. **Closes Cluster D faster.** Option (1) would require a primitive-side modification on top of the consumer preset work — bleeding T-352 into L+ scope and blocking on primitive-side review cycles. Option (2) ships within standard L envelope.
4. **Documents the gap clearly.** D-T352-9 enumerates four documented divergences (a/b/c/d) so the gap is obvious to any future Reviewer or successor task. The follow-up's spec can lift the divergence list directly into its required-reading.
5. **The visual register that ships in v1 honors the canonical mood.** Sepia tonal grading + heavy VHS-grade grain captures the home-video MOOD; only the home-video MEDIUM (actual video footage) is deferred. The mood-without-medium register is a reasonable v1 ship for parity-golden purposes — the parity golden tests visual-pixel fidelity, NOT temporal video playback.

If a Reviewer demands option (1) — full videoShot integration in this PR — escalate per CLAUDE.md §6; the audit explicitly identifies this as L+ scope and recommends consumer-driven deferral. The proper venue for the videoShot integration is a separate primitive-side modification PR (T-352-followup) that lands BEFORE the T-352-followup consumer task.

If a Reviewer demands option (3) — defer T-352 entirely until videoShot is impl'd — escalate per CLAUDE.md §6; the audit recommends shipping the consumer preset with documented divergences (option 2) rather than blocking the cluster on a primitive-side modification.
