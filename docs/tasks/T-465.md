# T-465 — `LiveQuizClip`

**Branch**: `task/T-465-live-quiz-clip`

## Goal

Ship the **LiveQuizClip** family. Multi-question competitive quiz —
the host advances through questions; for each question, voters pick
one option, server records latency for the T-473 quiz-fairness
arbitration (lands later); the aggregation tracks per-question vote
distributions + the currently-active question.

Per-kind shapes (per ADR-010 §D2 / §D3 + already in `@stageflip/audience-contract`):

- Vote: `{ kind: 'live-quiz', questionId: string, optionIndex: number }`.
- Aggregation: `{ activeQuestionId: string | null, questionResults: [{
  questionId, optionCounts: readonly number[], correctOptionIndex,
  totalVotes }, ...] }`.
- Rendering:
  - **Active-question display**: shows the active question + its
    options as a horizontal bar chart (live counts per option).
    Correct option highlighted ONLY after the question's voting window
    closes (the static-fallback variant always shows correctness — it
    renders the FINAL state).
  - **Idle / between-questions**: shows "Waiting for next question…"
    placeholder.
  - **Final-round snapshot** (the static-fallback shape): renders
    ALL questions' results in a vertical scroll, each as a mini
    bar chart with the correct option highlighted in green +
    incorrect in muted gray.
- Voter UI: when the active question is set, render its options as
  buttons; tap submits + disables. When no active question, show
  "Waiting for next question…" placeholder.

§13 verification is option-1 — `render-e2e.test.ts` drives the
static-fallback with a known multi-question final snapshot + asserts
on observable DOM ordering, correct-option highlight, count badges,
and pixel-bucket non-blankness.

## Implementation notes

- **Schema**: `props: { questions: z.array(z.object({
  id: z.string().min(1),
  text: z.string().min(1),
  options: z.array(z.string().min(1)).min(2).max(6),
  correctOptionIndex: z.number().int().nonnegative(),
  timerSeconds: z.number().int().positive().max(120).optional()
  })).min(1).max(50), sessionId: z.string().optional() }`.
  - Validate at the schema level: each question's `correctOptionIndex
    < options.length` (use a Zod `.refine`).
  - `permissions: z.tuple([z.literal('audience-network')])`.
  - `provenance: audienceProvenanceSchema.optional()`.
- **Static-fallback rendering** (final-round shape):
  - For each `questionResults[i]`:
    - Render a question-result block.
    - Inside: question text (looked up from `clip.props.questions`
      by `questionId`); a horizontal mini bar chart (one bar per
      option); bar widths proportional to `optionCounts` (normalize to
      max within the block, not `totalVotes`); correct option's bar
      gets `data-correct="true"` + accent color (e.g., green); other
      bars get muted gray.
    - Total badge: `${totalVotes} votes`.
  - Pure function. No `Date.now()`, no `Math.random()`. The
    `correctOptionIndex` comes from the snapshot.
- **Live-mount rendering** (active-question shape):
  - When `activeQuestionId !== null` AND that questionId resolves to a
    `questionResults` entry, render that entry as the active panel —
    bars WITHOUT correctness highlight (correctness reveals only at
    final). Show countdown if `timerSeconds` set (the timer comes from
    the host's admin-command path; T-465 just renders if a `timerEndsAt`
    field were on the aggregation, but currently isn't — emit a hint
    in the spec for T-473 to add).
  - Idle when `activeQuestionId === null`: "Waiting for next
    question…" placeholder.
- **Voter input UI** (`live-quiz-voter-input.tsx`):
  - `props: { questions, activeQuestionId, onSubmit, disabled? }`.
  - When `activeQuestionId === null`: show "Waiting for next question…".
  - When `activeQuestionId !== null` AND resolves: render that
    question's options as buttons; tap submits `{ kind: 'live-quiz',
    questionId, optionIndex }`; disable all after submit; surface
    "Answer submitted" + lock until next `activeQuestionId` change
    (which clears local memo).
- **Mirror T-461..T-464 exactly** for layout / tests / dispatcher
  registration.
- **Determinism perimeter**: same as prior — static-fallback pure;
  factory's `runAudienceClient` is the only non-deterministic surface.
