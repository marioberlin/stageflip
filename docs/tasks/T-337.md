# T-337 — Preset: `wimbledon-green-purple` (scoreBug, Cluster B)

**Branch**: `task/T-337-wimbledon-green-purple`

## Goal

Promote the existing `wimbledon-green-purple` preset stub from `status: stub` to `status: substantive` and ship it as the **fifth Cluster B (sports / score-bug) preset to land** AND the **sixth consumer of the `scoreBug` clipKind** in the parity-CLI resolver AND the **first production consumer of T-332a's `'tennis'` style bundle** (after four prior `'football'`-style consumers — T-333 PL / T-334 Fox NFL / T-335 NBC SNF — and the T-358 cricket-dots clipKind-default which binds the `outcome-row` primitive). The preset captures the canonical Wimbledon scoreboard register: a **compact bottom-left two-player stack** on Wimbledon green `#006633` with purple `#4B0082` accent, white text, mixed-case surnames, ALL-CAPS country codes, an active-server yellow dot on the serving player's row, three set-score columns (canonical Wimbledon final mid-match — 2 sets played + 3rd in progress with tiebreak scores), per-player game-score column, and Montserrat 500 OFL fallback for the proprietary Gotham face. Common uses: live tennis match overlays where the bottom-left compact two-player stack + green/purple palette + sets-with-game-score canonical layout is the brand signal — sister-but-distinct from T-333's PL upper-left rectangular chrome AND T-334 / T-335's bottom-center horizontal football bars.

T-337 is the **fifth** preset to bind the `scoreBug` clipKind. T-358 (`cricket-ball-by-ball-dots`) holds the **clipKind-default** slot (`scoreBug → scoreBugDotsBinding`; binds `outcome-row` primitive, NOT `score-bug` — predates T-332a). T-333 (`premier-league-field-of-play`, merged at 7f990ab), T-334 (`fox-nfl-no-chrome`, merged at 35d97ff), and T-335 (`nbc-snf-possession-illuminated`, merged at 6a1f7c0) added the **first three `PRESET_ID_BINDINGS` overrides** keyed on `'premier-league-field-of-play'` / `'fox-nfl-no-chrome'` / `'nbc-snf-possession-illuminated'`, each binding the `score-bug` primitive's `'football'` style branch. T-337 wires its binding via a **fourth `PRESET_ID_BINDINGS` override** keyed on `'wimbledon-green-purple'` — Pattern C from `docs/handover-phase13-mid.md` §2 (n-th-preset-for-clipKind via `PRESET_ID_BINDINGS`). Mirrors T-335's resolver-binding shape verbatim, swapping `nbc-snf-possession-illuminated → wimbledon-green-purple` AND substituting Wimbledon-specific snapshot constants AND swapping the `'football'` discriminant for `'tennis'`. T-358's clipKind-default arm is **NOT** touched. T-333 / T-334 / T-335's prior bindings + their respective `PRESET_ID_BINDINGS` entries are **NOT** touched.

T-337 is the **first production consumer of T-332a's `'tennis'` style branch** — the four prior Cluster B `scoreBug` consumers (T-333 / T-334 / T-335 — football style; T-339a uses a different clipKind / primitive entirely) all bind the `'football'` branch. T-337 first-exercises the `'tennis'` branch's: 2-player stack render shape (`renderTennis` in `score-bug.tsx` lines 607–676); `players: [TennisPlayer, TennisPlayer]` array (length-2 strict via Zod `length(2)`); per-player `surname` / `countryCode` / `seed` / `sets` / `gameScore` field set; `activeServerIndex: 0 | 1` server-dot rendering (yellow `#ffd700` 8 × 8 px disc); `anchor` enum (`'top-left' | 'top-right' | 'bottom-left' | 'bottom-right'`); the primitive's hard-coded country-code uppercase normalization (line 650 — `player.countryCode.toUpperCase()`, applied REGARDLESS of `casing`).

T-337 is **M-sized** — same envelope as T-335 / T-334 / T-333. ~30–50 LOC binding + snapshot constant + single steady-state parity golden + sign-off in-PR. Slightly over T-335's envelope to carry the `players` array (2 nested objects with 5 fields each) but no schema change; no primitive carve-out. Inherits T-335's resolver shape end-to-end (`PRESET_ID_BINDINGS` override path; clipKind fall-through unchanged).

## Architectural decisions

### D-T337-1. Compass register match — Wimbledon compact bottom-left / Wimbledon green `#006633` + purple `#4B0082` / 2-player stack with country code + seed + 3 set columns + game score + active-server dot / Montserrat 500 OFL fallback

The stub (lines 22–46) defines the canonical Wimbledon scoreboard register:

- **Position**: compact bottom-left scorebug (line 23). T-337 anchors at `position: { x: 60, y: 580 }` on a 1280×720 canvas — `x = 60` is ~5% inset from the left edge; `y = 580` puts the ~72 px-tall tennis bug ~68 px above the bottom edge (well clear of common safe-areas). The bottom-left anchor is deliberately register-distinct from T-334 / T-335's bottom-center football bars AND from T-333's PL upper-left rectangular chrome.
- **Compact two-player stack** (line 25 — "Two player rows, ≈ 350–400 × 80 px @ 1080p — deliberately small to preserve court visibility"): the `'tennis'` branch's default render is `400 × 72 px` (rowHeight 32 × 2 + 8 padding) — matches the stub's "350–400 × 80 px" register at the lower bound. Restraint is the signature; do not override `position.width` / `position.height`.
- **Per-player fields** (line 26 — "Player surname, country flag, seed number, set columns (1–5), current game score"):
  - `surname` — Mixed-case (Djokovic / Alcaraz); `casing: 'as-is'` leaves untouched.
  - `countryCode` — 3-letter IOC code (`'SRB'` / `'ESP'`); primitive hard-uppercases regardless of `casing` per line 650.
  - `seed` — bracketed integer (`[1]` / `[2]`); rendered when present.
  - `sets` — array of 3 set-score strings (canonical mid-match Wimbledon final: 2 sets played + 3rd in progress with tiebreak scores). Schema accepts 1–5.
  - `gameScore` — current game score string (`'40'` / `'30'`); rendered when present.
  - **Country flag rendering**: stub mentions "country flag" but primitive renders only `countryCode` text, not flag images — see D-T337-11-d.
- **Active-server yellow dot** (line 27 — "small yellow / green dot indicator"): `activeServerIndex: 0` — Djokovic serving; primitive renders an `8 × 8 px` round `#ffd700` yellow disc on the player[0] row per line 642. **First production consumer of `activeServerIndex`**.
- **2025 update** (line 28 — "full previous-set scores shown for the first time in ~20 years"): T-337 exercises this via the `sets` array containing 3 entries — the 2 completed sets PLUS the in-progress set are all shown, validating the post-2025 register against the primitive's variable-length `sets` column rendering (`player.sets.map` on line 655).

- **Mixed-case surnames + ALL-CAPS country codes** (lines 31–32 — "Surnames: Mixed Case", "Country codes: ALL CAPS"): `casing: 'as-is'` (surnames pass through unchanged — `'Djokovic'` / `'Alcaraz'` Mixed-case as supplied); the primitive force-uppercases `countryCode` REGARDLESS of `casing`, satisfying the ALL-CAPS rule unconditionally.
