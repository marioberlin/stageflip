# T-460 — Schema `AudienceProvenance` type

**Branch**: `task/T-460-audience-provenance-schema`

## Goal

Land the **canonical schema-side `AudienceProvenance` declaration** in
`@stageflip/schema`, matching the preview T-452 shipped in
`@stageflip/audience-contract`. Per the T-452 spec & the file's TSDoc:
"The full element-base merge + canonical Zod schema lands in T-460
(`@stageflip/schema` extension)."

The audience analog of `MediaProvenance` (T-421 / ADR-008 §D2). Carries
two concerns:

1. **`packages/schema/src/elements/audience-provenance.ts`**:
   - Canonical `audienceProvenanceSchema` Zod declaration + `AudienceProvenance`
     inferred type. Strict; matches the T-452 preview verbatim — same
     fields, same Zod constraints, same discriminator on `aggregation`.
   - Schema source: `@stageflip/audience-contract` is the authoritative
     home for the discriminator + per-kind payload shapes; the schema
     module imports `aggregationValueSchema` + `AUDIENCE_SNAPSHOT_POLICIES`
     + `AUDIENCE_CLIP_KINDS` from the contract and composes the
     element-side schema. Single source of truth — no shape drift.
   - Re-exports `AudienceProvenanceKind`-style enums for downstream
     consumers (the audience-clip element schemas in T-461..T-471 will
     import the schema module, not the contract directly).
2. **`packages/schema/src/elements/audience-provenance.test.ts`**:
   - Roundtrip every snapshot policy + every audience clip kind through
     the schema; verify accept/reject behavior matches the T-452 preview.
   - Type-level test: `AudienceProvenance` from `@stageflip/schema`
     must be assignment-compatible with the T-452 preview type — verifies
     the two shapes don't drift.
3. **`packages/schema/src/elements/index.ts`** — export the new symbols.
4. **`packages/schema/src/index.ts`** — re-export at the package
   surface so consumers can do `import { audienceProvenanceSchema } from
   '@stageflip/schema'` (matches the `MediaProvenance` re-export
   pattern).

**Strict scope** — schema-side declaration + tests + re-exports only.
NO new audience-clip RIRElement variants (T-461..T-471 ship the per-kind
clip schemas + their `provenance?: AudienceProvenance` slot wiring). NO
modification of the `RIRDocument.elements` discriminated union (the
existing union accepts the audience-clip kinds when T-461..T-471 add
them). NO changes to the contract package (T-452 — frozen). NO render
surface (no clip implementations). NO renderer-core dispatcher updates.
NO migration scripts (the schema slot is additive + optional;
pre-existing documents round-trip unchanged).

## §13 (structural extension) statement

**THIS IS A STRUCTURAL EXTENSION.** This task adds a new optional slot
type to the schema layer that the audience-clip element schemas
(T-461..T-471) plug into. Per CLAUDE.md §13, render verification is
required.

**Verification mechanism: Option 3 (explicit deferral note).** T-460
ships ONLY the schema declaration; no element variant references it
yet (T-461..T-471 will). Pixel-level verification is therefore gated
on the downstream consumers:

- **Per-clip render verification** — owned by T-461..T-471. Each clip
  family's PR ships an integration test driving its element variant
  through the renderer (via T-454's `StaticFallbackRenderer` for the
  staticFallback path) and asserts on observable output.
- **Cross-cluster render verification** — owned by T-476 (Cluster I
  parity fixtures) + T-486 (Cluster I preset cluster). PO ratification
  of those fixtures provides the cross-cluster sign-off per §13
  option 2 (reference preset/fixture flow + visual inspection).

The roundtrip test in this PR (`audience-provenance.test.ts`) verifies
the SCHEMA layer is non-breaking + matches the T-452 contract preview.
That test is necessary but explicitly NOT sufficient for §13 — it's the
T-348-class wiring test the regression doc (`docs/handover-cluster-d-regression.md`)
warns against. The deferral above pushes the §13 obligation to the
named consumer tasks; reviewers on this PR confirm the deferral note +
the consumer task ID list, NOT pixel-level evidence.

## Implementation notes

- **Schema-source**: import `aggregationValueSchema` +
  `AUDIENCE_SNAPSHOT_POLICIES` + `AUDIENCE_CLIP_KINDS` from
  `@stageflip/audience-contract`. The new schema module composes the
  element-side schema from those primitives. This keeps the
  discriminator single-sourced; no shape drift.
- **Type-level drift test**: in the test file, declare a value of one
  type + assign to the other (both directions) under
  `expectTypeOf<...>()` or with a `// @ts-expect-no-error` block. If
  the contract preview ever drifts from the schema declaration, this
  test fails at compile time.
- **NO modification of T-452's preview file**: `packages/audience-contract/src/audience-provenance.ts`
  remains unchanged — the contract's preview was sealed by T-452. T-460
  adds the canonical schema-side declaration in parallel; downstream
  consumers (T-461..T-471) will import from `@stageflip/schema` per
  the existing element-schema pattern.
- **No renderer-side wiring** in this PR. T-461..T-471 each declare
  `provenance?: z.infer<typeof audienceProvenanceSchema>` on their
  element variant + thread through to the renderer dispatcher.
- **§13 deferral note** at the top of the schema module's TSDoc:
  "Render verification deferred to consumers — per CLAUDE.md §13
  option 3: T-461..T-471 (per-clip integration tests) + T-476 (Cluster
  I parity fixtures + PO ratification)."
