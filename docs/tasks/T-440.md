# T-440 — Provenance-aware export: video exporter watermark

**Branch**: `task/T-440-video-ai-watermark`

## Goal

The video exporter (`@stageflip/export-video`) is extended with a
**provenance-aware AI-content watermark + sidecar** pipeline that mirrors
T-439's IAB display disclosure for video output. When the tenant
**opts in** to AI-watermarking, the exporter:

1. Walks the document's MediaElements at export time and flags any
   element whose `provenance.kind` indicates AI-generated content (one
   of `tts`, `video-gen`, `music-gen`, `sfx`, `three-d`, `image-gen`,
   plus T-438's non-terminal `'asset-gen-pending'`).
2. Emits an `ai-content.json` sidecar describing every AI element
   (provider, modality, prompt, cacheKey, element id, optional frame
   range). The sidecar shape mirrors T-439's `AiContentDisclosure`
   manifest field and is jurisdiction-agnostic (FTC + EU AI Act +
   future regimes can consume it).
3. Emits an FFmpeg `drawtext`-compatible **watermark plan** describing
   the textual watermark a downstream renderer composites onto frames
   that contain AI-generated content. Default: bottom-right corner,
   10% opacity, white text "Made with AI", 12px sans-serif.

The watermark plan is **renderer-agnostic data** — the orchestrator does
NOT pixel-composite frames itself. Concrete `VariantRenderer`
implementations (CDP host bundle, bake tier) consume the plan and apply
the watermark via their compositor of choice (FFmpeg drawtext for the
bake tier; a CSS overlay for the live preview). This keeps the
orchestrator deterministic and free of FFmpeg integration concerns.

## Opt-in posture (vs T-439's auto-mark)

T-439's IAB exporter **auto-marks** AI content for FTC + EU AI Act
ad-tech compliance: ad networks must disclose. The watermark is on
by default because the regulatory floor for display advertising is
strict.

T-440 inverts the posture: the watermark is **opt-in**. Video output
spans many contexts (artistic content, internal training, social
media, broadcast) and the FTC's "clear and conspicuous" prong is
less stringent for non-endorsement content. Forcing a watermark
on every AI-influenced video would over-disclose for legitimate
creative uses where AI is one tool among many.

Tenant opts in via `ExportVideoOptions.aiWatermark.enabled = true`.
Default: disabled. When disabled, the `ai-content.json` sidecar is
also suppressed (no surface emitted at all). When enabled with no
AI elements present, the sidecar is still suppressed but the
watermark plan is `undefined`.

## Function

The new `provenance-aware-export` entry point (additive — old
`exportMultiAspectInParallel` is unchanged) accepts:

```ts
interface ProvenanceAwareExportInput {
  readonly document: Document;
  readonly variants: readonly VariantTarget[];
  readonly renderer: VariantRenderer;
  readonly aiElements?: readonly AiVideoElementInputRow[];
  readonly aiWatermark?: Partial<AiWatermarkConfig>;
  readonly concurrency?: number;
  readonly signal?: AbortSignal;
}

interface AiVideoElementInputRow {
  readonly elementId: string;
  readonly provenance?: MediaProvenance;
  /** Optional half-open frame range [startFrame, endFrame) over which
   *  the element is visible. When absent, the renderer treats the
   *  element as present for the entire timeline.
   */
  readonly frameRange?: { readonly startFrame: number; readonly endFrame: number };
}

interface AiWatermarkConfig {
  /** Master switch — opt-in. Default `false`. */
  enabled: boolean;
  /** Watermark text. Default `'Made with AI'`. */
  text: string;
  /** Corner position. Default `'bottom-right'`. */
  position: 'top-left' | 'top-right' | 'bottom-left' | 'bottom-right';
  /** Opacity 0..1. Default `0.10`. */
  opacity: number;
  /** Font color CSS string. Default `'#fff'`. */
  color: string;
  /** Font size in px. Default `12`. */
  fontSize: number;
}
```

The entry point returns:

```ts
interface ProvenanceAwareExportResult {
  readonly multiAspect: MultiAspectExportResult;       // unchanged outcomes
  readonly aiContent?: AiContentManifest;              // sidecar payload
  readonly watermarkPlan?: AiWatermarkPlan;            // renderer instructions
}
```

Where `AiContentManifest` mirrors T-439's `AiContentDisclosure`:

```ts
interface AiContentManifest {
  readonly elements: readonly AiContentManifestElement[];
  readonly watermark: {
    readonly enabled: boolean;
    readonly text: string;
    readonly position: 'top-left' | 'top-right' | 'bottom-left' | 'bottom-right';
    readonly opacity: number;
  };
}

interface AiContentManifestElement {
  readonly elementId: string;
  readonly provider: string;        // 'tts-kokoro' / etc.; 'unknown' when absent
  readonly modality: MediaProvenanceKind;
  readonly cacheKey?: string;
  readonly prompt?: string;
  readonly frameRange?: { readonly startFrame: number; readonly endFrame: number };
}
```

And `AiWatermarkPlan` carries the per-frame-range watermark
instructions a renderer applies (FFmpeg drawtext / canvas overlay /
CSS overlay — the choice is the renderer's):

```ts
interface AiWatermarkPlan {
  readonly config: AiWatermarkConfig;
  /** Frames on which the watermark should appear. Sorted, non-overlapping. */
  readonly frameRanges: readonly { readonly startFrame: number; readonly endFrame: number }[];
}
```

When **no** AI element is present OR the tenant opted out (default),
both `aiContent` and `watermarkPlan` are `undefined` and the result
collapses to `{ multiAspect }` — byte-identical to today's
`exportMultiAspectInParallel` path.

## Frame-range merging

The walker collapses overlapping / touching frame ranges:

- Inputs `[{0..30}, {25..60}, {100..150}]` →
  Output `[{0..60}, {100..150}]`.
- Inputs `[{10..20}, {20..30}]` → Output `[{10..30}]` (touching ranges
  merge; the half-open interval contract preserves the property
  `endFrame_a === startFrame_b` ⇒ joined).
- An input row with `frameRange === undefined` → the merged plan
  treats it as `{ startFrame: 0, endFrame: Number.MAX_SAFE_INTEGER }`
  (always-on). The result becomes `[{0..MAX_SAFE_INTEGER}]` (covering
  the entire timeline).

## Shared types between T-439 and T-440

T-439's `AiContentDisclosure` and T-440's `AiContentManifest` share
~80% of their shape. We **deliberately duplicate** the per-element
row type at T-440 with one addition (`frameRange?`) instead of
extracting a shared package, because:

1. The disclosure summary differs: T-439's `disclosure: { ftc, euAiAct }`
   is ad-tech compliance signaling; T-440's `watermark: { enabled,
   text, position, opacity }` is renderer-facing data.
2. Extracting a shared `@stageflip/ai-disclosure-shared` package now
   would block T-440 on a separate refactor PR and increase blast
   radius across two exporters.
3. A future task (T-441, slide exporter) will produce a third near-
   identical surface; at that point a single refactor PR can extract
   all three to a shared package with full test coverage.

The duplication is small (~25 LOC of type definitions) and the
trade-off favors shipping T-440 cleanly now.

## Tenant-configurable watermark

`AiWatermarkConfig` defaults (`DEFAULT_AI_WATERMARK`):

```ts
{
  enabled: false,
  text: 'Made with AI',
  position: 'bottom-right',
  opacity: 0.10,
  color: '#fff',
  fontSize: 12,
}
```

Tenant config flows in through `ProvenanceAwareExportInput.aiWatermark?:
Partial<AiWatermarkConfig>` (full or partial — the orchestrator merges
with `DEFAULT_AI_WATERMARK`). `enabled: true` is required to opt in.

## Architectural seals

- **Pure addition**: NEW orchestrator entry point + sidecar emission +
  watermark plan; existing `exportMultiAspectInParallel` untouched
  for non-AI elements. Every existing `multi-aspect.test.ts`
  assertion passes byte-identically.
- **Opt-in by default**: `aiWatermark.enabled === false` is the
  default; nothing emitted in the opt-out path.
- **Renderer-agnostic data**: orchestrator produces a watermark
  *plan* (frame ranges + style config), not pixels. Concrete
  renderers consume the plan.
- **§13 statement**: NOT a structural extension — T-440 adds an
  export-time walk + opt-in sidecar / plan; no schema changes, no
  new RIRElement, no new ClipKindBinding field, no compositing
  changes in any runtime, no new runtime kind. Existing render
  paths are unchanged for non-AI elements and unchanged for AI
  elements when the tenant opts out. Render verification N/A — the
  watermark composition is a renderer-side concern (the CDP host
  bundle and bake-tier renderers consume the plan; T-440 ships only
  the plan + sidecar + walk).
- **Back-compat**: existing `exportMultiAspectInParallel` callers
  see byte-identical behavior. The new entry point is additive.
- **Determinism preserved**: walk + plan + sidecar serialization
  are pure (no `Date.now()` / `Math.random()`); JSON serialization
  uses stable key ordering so two runs produce byte-identical bytes.
- **Strict provenance read**: T-421's `mediaProvenanceSchema` uses
  `.strict()`; T-440 reads `provenance.kind` against the known
  discriminator and treats unknown kinds defensively (defaults to
  non-AI to avoid over-disclosing under future schema extension).

## Regulatory references

The opt-in posture means T-440 surfaces compliance hints but doesn't
auto-enforce them:

- **FTC** — "Endorsement Guides" (16 CFR Part 255) require clear and
  conspicuous disclosure of material AI generation when an ad implies
  endorsement. Tenants producing FTC-regulated video MUST enable the
  watermark.
- **EU AI Act** — Article 50(2) requires AI-generated content
  marking. The `ai-content.json` sidecar serves the machine-readable
  prong even when the watermark is disabled (the sidecar is still
  suppressed in opt-out; tenants targeting EU-regulated distribution
  MUST opt in).
- **Other jurisdictions** — China's Generative AI Service Measures
  (effective 2023-08-15) require labeling; tenants distributing
  there MUST opt in.
