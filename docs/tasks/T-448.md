# T-448 — Phase 14 documentation pass (user-manual + skill index + apps/docs)

**Branch**: `task/T-448-p14-docs-pass`

## Goal

Refresh `docs/user-manual.md`, the top-level skill-tree index, and the
`apps/docs` Astro Starlight surface so that public-facing documentation
reflects everything that landed in **Phase 14** (T-415..T-447).

The user-manual on `main` was last touched by T-412 at the end of
Phase 13. It still has no surface coverage for any of:

- **ADR-007 / ADR-008** — Provider Seam Pattern + Asset Generation
  Contract (T-415, T-416).
- The **9 reference adapters** (T-426..T-434: Kokoro, Fish Speech,
  Tripo, Meshy, Seedance, Runway, ACE-Step, YuE, Stable Audio Open).
- The **`asset-generation` handler bundle** (T-423) and its
  `generate_asset` / `list_asset_providers` / `query_asset_cache`
  tools.
- **Cost-budget surfacing** (T-443) on `generate_asset` tool results.
- The **adapter-sandbox model** (T-444) with per-kind `SandboxRunner`
  + `TenantAdapterCredentialsStore`.
- **Per-modality usage telemetry** (T-445) and the
  `query_usage_telemetry` tool.
- **Per-adapter data-flow security manifests** (T-446) and the
  `check-data-flow-security` CI gate.
- **TTS→captions bypass** (T-436), **3D→ThreeSceneClip GLB mount**
  (T-437), **provenance-aware exporters** (T-439 display IAB,
  T-440 video MP4 sidecar, T-441 PPTX `<a:extLst>`).
- **Optimistic placeholders** (T-438) and **streaming agent events**
  (T-442) for async asset-gen UX.

A user installing the plugin or CLI today would have no path from the
manual to any of those surfaces.

T-448 also refreshes the top-level skill index (`skills/stageflip/
index/SKILL.md`) so that the Phase 14 concept SKILLs are reachable
from the index, and verifies the `apps/docs` Astro Starlight site
builds cleanly with the new Phase 14 concept / tool / reference
SKILLs in its auto-generated sidebar.

This is **pure docs**. No code, no new package, no new CI gate. The
inaugural Category 8 GA-readiness criterion **8.10** (Phase 14
documentation pass spec present) should flip from WARN → PASS for
T-448 after this PR merges; the GA-readiness report itself is
re-generated by `pnpm check-ga-readiness` and committed in this PR
(consistent with T-412 / T-410 behaviour).
