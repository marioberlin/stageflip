# T-476 — Cluster I parity fixtures

**Branch**: `task/T-476-cluster-i-parity-fixtures`

## Goal

Ship parity-fixture goldens for all 11 audience clip kinds'
static-fallback paths. Carries the **§13 end-to-end render
verification** obligation that T-451 (ADR-010) deferred to this
task — per its §13 statement: "T-476 Cluster I parity fixtures + the
PO ratification sign-off carry the end-to-end render verification per
CLAUDE.md §13 means-of-verification (option 2 — reference preset /
fixture sign-off via standard parity-fixture flow)."

Carries three concerns:

1. **Per-clip-kind fixture directory** at
   `parity-fixtures/audience/<clip-kind>/`:
   - 11 directories — one per `AudienceClipKind`.
   - Each contains `manifest.json` + `snapshot.json` (the input
     `AggregationValue` driving the static-fallback render) +
     `thresholds.json` + (initially) NO golden PNG (gets rendered on
     first CI run + signed off).
2. **Parity-fixture generator extension** in `scripts/`:
   - The existing `scripts/generate-preset-parity-fixture.ts` is
     preset-based. T-476 either extends it OR ships a parallel
     `scripts/generate-audience-clip-parity-fixture.ts` that takes a
     `--clip-kind=<kind>` argument and renders the static-fallback
     with the fixture's `snapshot.json` as the input.
   - The renderer reuses the same parity-render pipeline (delegates
     to `pnpm parity:prime`) with the audience runtime registered.
3. **Sign-off infrastructure**:
   - The fixtures land UNSIGNED. PO inspection signs them off via the
     standard `pnpm parity:sign --fixture=audience/<kind>` flow OR via
     the `mark-signed` flag in the generator.
   - `scripts/check-preset-integrity.ts` (or its equivalent — `check-preset-integrity`)
     should EITHER skip audience fixtures OR extend to recognize them
     with a `frontmatter.signOff.parityFixture: 'unsigned' | 'signed:<date>'`
     marker — pick the simpler path.
   - For v1, document that audience fixtures are "review-pending" +
     the PO ratification process kicks off after this PR merges.

**Strict scope** — fixture directory creation + generator extension
+ snapshot.json data per kind. NO Cluster I preset cluster (T-486 —
separate task). NO video/IAB export fixtures (out of v1 scope for
audience). NO multi-frame golden sequences (single mid-hold frame
per clip kind).

## §13 (structural extension) statement

**NOT a structural extension** at the schema / binding level. This
task adds parity-fixture artifacts + a generator extension. The
*purpose* of the artifacts is to provide the §13 verification
deferred from T-451 (ADR-010); the fixture-signing process itself
carries the verification.

Render verification per §13: this PR DOES verify rendering — each
clip kind's static-fallback path is exercised by the fixture
generator + the rendered golden becomes the parity-comparison
artifact for future regressions. **PO ratification of the goldens
post-merge is the formal §13 sign-off.**

## Implementation notes

- **Snapshot values per kind** — use the same data as the render-e2e
  tests for consistency:
  - `live-poll-multiple-choice`: `{ optionCounts: [10, 5, 3], totalVotes: 18 }`.
  - `live-poll-open-text`: top-3 entries `[{ great talk: 5 }, ...]`.
  - `live-poll-rating`: `{ scoreCounts: [2, 3, 5, 7, 4], totalVotes: 21, mean: 3.38 }`.
  - `live-qa`: 3-question snapshot from T-464.
  - `live-quiz`: 3-question final-round snapshot from T-465.
  - `leaderboard`: 5-row ranking from T-466.
  - `word-cloud`: 5-word frequency from T-467.
  - `survey`: 3-question mixed-type from T-468.
  - `heatmap`: 4-tap snapshot from T-469.
  - `reaction-stream`: 3-emoji counts from T-470.
  - `audience-ai-prompt`: final-state 3-prompt + cacheKey from T-471.
- **Manifest shape**: same as existing parity fixtures:
  ```json
  {
    "name": "live-poll-multiple-choice",
    "cluster": "audience",
    "kind": "live-poll-multiple-choice",
    "description": "Parity fixture for audience clip 'live-poll-multiple-choice' (static-fallback path)",
    "composition": { "width": 1920, "height": 1080, "fps": 30, "durationInFrames": 150 },
    "referenceFrames": [75],
    "goldens": { "dir": ".", "pattern": "golden-frame-${frame}.png" },
    "fonts": { ... },
    "auditTagged": "T-476: Cluster I parity fixtures; unsigned awaiting PO ratification"
  }
  ```
- **Generator CLI**: `scripts/generate-audience-clip-parity-fixture.ts`
  - Accepts `--clip-kind=<kind>` arg.
  - Reads `parity-fixtures/audience/<kind>/snapshot.json`.
  - Builds an audience-clip element with the snapshot as its
    `provenance.aggregation`.
  - Invokes the parity-render pipeline (same one `parity:prime` drives).
  - Outputs `golden-frame-75.png` per the manifest's
    `referenceFrames`.
- **Determinism**: scripts/** is OUT of CLAUDE.md §3 scope. The
  generator may use Date.now in audit comments but the render output
  is deterministic per the static-fallback's purity.
- **Pre-empt skills-sync drift**.
- **Biome format ONLY touched dirs**.
- **NEVER `git add -A`**.
