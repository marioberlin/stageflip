# T-355 — Preset: `magic-wall-drilldown` (fullScreen, LiveDataClip, Cluster E)

**Branch**: `task/T-355-magic-wall-drilldown`

## Goal

Promote the existing `magic-wall-drilldown` preset stub from `status: stub` to `status: substantive` and ship it as the **sixth and final Cluster E preset to land** (after T-359 / `f1-sector-purple-green`, T-358 / `cricket-ball-by-ball-dots`, T-360 / `big-number-stat-impact`, T-356 / `bloomberg-ticker`, T-357 / `olympic-medal-tracker`). The preset captures **the broadcast "magic wall" drilldown style** popularized by election-night coverage (CNN's John King, Fox / MSNBC's election boards): a fullscreen interactive panel where a presenter walks through layered hierarchical data — zoom into a state → zoom into a county → show vote shares per precinct — with party-color shading, percentage labels, and smooth pan/scale transitions. The visual register is **fullscreen panels with hierarchical data + zoom transitions + theatrical pop-in**. Common uses: election broadcasts (state → county → precinct), sports playoff brackets (region → matchup), weather radar drilldown, scientific data exploration.

T-355 is the **third Cluster E preset to bind `LiveDataClip`** (after T-356 / T-357) AND the **first preset to ship using `clipKind: fullScreen`** with a parity-bound resolver entry. Per ADR-003 §D2, `live-data` is an interactive-tier family with two render paths — `liveMount` (host fetches an election-results endpoint, renders live with periodic refresh) and `staticFallback` (deterministic snapshot for parity goldens, exports, screenshots). T-355 covers the **staticFallback path** end-to-end (parity golden + signed sign-off); the liveMount path + the runtime drilldown zoom transitions are documented in prose only — host responsibility per ADR-003 §D2.

T-355 is **L-sized** — the largest cluster E preset — because of: (1) the **near-certain primitive carve-out** (D-T355-2) — none of the existing bridge primitives carries a fullscreen layered hierarchical-data panel cleanly; the closest candidate (`animated-map`) is an SVG grid + route simulation per its file header, not a drilldown UX; (2) the conceptual breadth — magic-wall is a state machine over layered data (state → county → precinct), but parity captures one frame in that hierarchy and the prose contract documents the layering; (3) a new resolver entry for `fullScreen` (~20–30 LOC) plus a non-trivial canonical-snapshot constant (US-states-style payload with party shading + percentage labels + electoral-count totals); (4) the LiveDataClip-vs-parity bypass (D-T355-12); (5) closing the cluster to **6/6** unlocks batch-merge eligibility (T-380 parity-batch sign-off ladder). Inherits T-359a's multi-variant infra in trivial-arity mode, T-359b/T-359c's prod-renderer pipeline, T-356a / T-357a / T-358a's primitive-carve-out precedents, T-360's multi-preset-per-clipKind resolver shape, and T-356 / T-357's LiveDataClip-bypass posture.

### D-T355-2. **Pivotal decision** — primitive fit: NO existing primitive fits; carve out `T-355a magic-wall-panel` follow-up

**Verified during spec drafting** (read `packages/runtimes/frame-runtime-bridge/src/clips/animated-map.tsx` lines 1–11 plus the rest of the bridge clip catalog):

- **`animated-map.tsx`** — file header explicitly states "FALLBACK-ONLY. The reference clip conditionally initialises `mapbox-gl` when a `mapboxToken` prop is passed; the bridge deliberately does NOT ship that path." The implementation is a generic SVG grid + decorative route line + lat/lng coordinate readout + camera-pan progress (`startCenter` / `endCenter` / `startZoom` / `endZoom`). It does **not** model regions, does not render party-shaded territory polygons, does not surface percentage labels, does not carry a drilldown hierarchy, does not render electoral-count or vote-tally bars. The schema (`startCenter` / `endCenter` / `style: 'dark'|'light'|'satellite'` / `title`) cannot represent a US-states electoral panel without a complete schema rewrite. Wrong shape.
- **Dashboard family** (`marketing-dashboard`, `okr-dashboard`, `hr-dashboard`, `product-dashboard`, `sales-dashboard`) — multi-card composite chrome (KPI tiles + chart strips + headline bands). The shape is "executive dashboard", not "broadcast magic-wall electoral panel". Wrong domain.
- **`kpi-grid.tsx`** — fixed 2/3-column card grid composed of `AnimatedValue` cards. Not a region-shaded map. Wrong shape.
- **`comparison-table.tsx`** — fixed two-column data table. Wrong arity, wrong geometry.
- **`financial-statement.tsx`** — hierarchical P&L / balance-sheet / cash-flow composite with `statementType: 'pnl'|'balance_sheet'|'cash_flow'` enum. The shape is "financial statement", not "geographic data panel". Wrong domain.
- **`outcome-row` / `news-ticker-bar` / `standings-table`** (the cluster E sibling carve-outs) — horizontal chip strip / horizontal scrolling chyron / vertical ranked table. None is a fullscreen geographic-region panel.
- **All other bridge clips** (verified via `index.ts`): single-card chyrons (`lower-third`, `pull-quote`, `testimonial-card`); chart family (`chart-build`, `pie-chart-build`, `line-chart-draw` — single-chart geometry, not a region-shaded map); single-content overlays (`video-background`, `image-gallery`, `product-carousel`, `gif-player`); audio / motion primitives; the new `caption` family (T-316). None carry the broadcast-magic-wall fullscreen drilldown geometry.

**Decision**: the magic-wall fullscreen drilldown shape requires a **new generic primitive** — `magic-wall-panel` — that renders a fullscreen panel of N (1..56) labeled, color-shaded region tiles arranged in a configurable grid (or absolute-positioned), each tile carrying an electoral / vote-count / percentage label payload, with frame-driven entrance stagger. T-355a (analog of T-356a → news-ticker-bar, T-357a → standings-table, T-358a → outcome-row) carves this out as a separate small primitive PR. T-355's own PR is **paused** at the preset-markdown stage until T-355a merges, then the resolver entry + parity golden land in the T-355 retry PR.

**Mandated check at implementation start**: the Implementer re-verifies (a) `animated-map.tsx`'s file header still pins the SVG-fallback-only posture (lines 1–11) and (b) no fullscreen-layered-region-panel primitive has appeared in `packages/runtimes/frame-runtime-bridge/src/clips/` since spec-drafting time. If either is false (a fitting primitive exists OR has appeared), document the find and skip the carve-out — wire directly. If both hold (almost certain), STOP IMMEDIATELY and escalate per CLAUDE.md §6 with a one-line spec sketch for `T-355a magic-wall-panel`:

**Do NOT** try to shoehorn the magic-wall shape onto `animated-map` (wrong shape; SVG-fallback grid + decorative route, no region geometry, no party shading, no labels), `kpi-grid` (fixed grid, wrong domain), or any other existing primitive. ### D-T355-3. Resolver entry shape — clipKind-default keyed by `fullScreen`, with cached-snapshot constant

T-360 D-T360-2 evolved the resolver to `(clipKind, presetId)` keyed lookups with backward-compat fallback. T-355 lands a **clipKind-default** entry (matches T-356's `newsTicker → news-ticker-bar` posture, NOT a per-preset override): the `fullScreen` clipKind is generic enough that future fullscreen presets across clusters A (`msnbc-big-board`), B (`uefa-starball-refraction`), C (`twc-retrocast-8bit`, `twc-immersive-mixed-reality`) can share the binding when their visual register matches the magic-wall shape, OR layer per-preset overrides via `PRESET_ID_BINDINGS` (T-360 mechanism) when their register diverges (UEFA refraction palette, TWC pixel-font 8-bit nostalgia). The clipKind-default is a deliberate first-mover posture: T-355 is the first `fullScreen` preset to ship substantively, and it sets the default that subsequent presets either inherit or override.

### D-T355-4. Static-fallback content — `MAGIC_WALL_CANONICAL_SNAPSHOT` constant; eight representative region entries

The cached snapshot is the parity-golden payload. Per D-T355-3 the constant ships **eight entries** — CA / TX / FL / NY / PA / OH / GA / AZ — chosen to:

- **Mix all four party colors**: three Dem (CA, NY, AZ), three Rep (TX, FL, OH), one tied (PA), one undecided (GA). Exercises the full color contract in a single frame.
- **Be recognizable**: the eight states are familiar electoral-night markers (the swing-state cluster + the population-weight giants). Reviewers eyeball without lookup.
- **Fit the canvas**: at 1920×1080 with a 4×2 grid layout (D-T355-3) the tiles sit at 460×380 px each with 80 px outer padding — readable labels + percentage + electoral count per tile.
- **Sum to a parity-checkable total**: 54 + 40 + 30 + 28 + 19 + 17 + 16 + 11 = 215 electoral votes (a meaningful fraction of 538) — verifies the totals contract end-to-end.

Eight is a meaningful subset, not the full 50-state map (which would require real geometry per D-T355-6). The preset's parity contract is the **shape** (region tile + party color + label + percent + electoral-count → fullscreen layered-data panel), not the literal entries. Cluster owners rebrand at compose time. Document the constant with TSDoc citing this decision.

**Why a constant + not a JSON file**: the preset's parity contract is the **shape** (region with ID + label + value + percent + party → styled tile), not the literal values. Inlining as a TS constant keeps the resolver self-contained and obvious to a Reviewer; a JSON file would invite drift between the preset prose and the renderer. Mirrors T-356 D-T356-4 / T-357 D-T357-4.

### D-T355-5. Single canonical mid-hold variant; concrete frame `60`

ADR-004 §D5 + T-313 specify a single canonical mid-hold reference frame per preset. T-355 ships **one mid-hold fixture** at `frame: 60` (consistent with all five sister Cluster E presets — universal cluster-E convention). At 30 fps and a 60 ms per-tile stagger (D-T355-3) the eighth tile settles by `frame ≈ 12 + 7 × (60 × 30 / 1000) = 24.6` (round to 25); frame 60 is well past stagger end, sitting in the steady-state hold window.

If frame 60 lands on a "transition flicker" (e.g., the stagger interpolation overshoots into a non-deterministic float at exactly that frame), the Implementer adjusts the canonical frame to 75 (still well past stagger end) and documents the choice. Do NOT introduce a second variant — the preset's stylistic point is the layered fullscreen drilldown shape at one level of the hierarchy, not a per-state palette swap or a per-frame zoom-transition snapshot. The stub's prose mentions four reference frames (0 / 60 / 120 / 180 across the zoom hierarchy); v1 parity captures only frame 60 at the top level (state-level), and the lower-level (county / precinct) frames are documented in the prose contract for runtime use, not parity.

### D-T355-6. Region geometry — placeholder rectangles in v1; real state-shape SVG paths are a follow-up

The magic-wall canon is **regional geometry** — actual state outlines, county shapes, precinct polygons. Real outlines exist as license-clean SVG / TopoJSON data on Wikimedia Commons (US states are public-domain; county / precinct boundaries are census-derived and PD). Adopting them requires:

- An SVG asset pipeline (asset checksum + license attribution + preload registration).
- A projection helper (lat/lng → SVG-pixel space; Albers-USA for the canonical US map).
- A topology-data dependency (`us-atlas` or equivalent — license check required; not currently in the workspace).

This is **out of v1 envelope**. T-355 (and T-355a's primitive) ships **placeholder geometry**: each region is a rectangular tile positioned on a configurable grid (4×2 for the canonical 8-region snapshot per D-T355-3). ### D-T355-11. LiveMount vs staticFallback in the prose contract — both documented; only staticFallback ships goldens

T-355's `## Rules` documents BOTH render paths per ADR-003 §D2:

- **liveMount**: host fetches an election-results endpoint (e.g., AP election feed, Decision Desk HQ, in-house tabulator); a refresh policy of 10–60 s ticks the per-region values; the per-tile color and percentage update on each tick; a tally count-up animation runs on update (referenced from `big-number-stat-impact` per stub); the drilldown zoom (state → county → precinct) is operator-driven (presenter taps a region; the hierarchy descends with a 600 ms ease-in-out pan/scale). **Host owns this entirely.** The preset documents the endpoint shape contract (`{ id, label, value?, percent?, party? }[]` + `totals?` + `hierarchyLevel?`) but does not implement fetching, authentication, rate-limiting, or the runtime drilldown state machine.
- **staticFallback**: the `MAGIC_WALL_CANONICAL_SNAPSHOT` constant (D-T355-4) substitutes for the endpoint payload. The deterministic frame-runtime path renders the constant via the bound `magic-wall-panel` primitive at the top level of the hierarchy. The preset's frontmatter does NOT today carry a structured `interactiveTier` / `liveMount` / `staticFallback` block — the schema (`packages/schema/src/presets/frontmatter.ts`) does not expose those fields (verified). ### D-T355-12. LiveDataClip-vs-parity integration — bypass the LiveDataClip wrapper; mount the inner `magic-wall-panel` directly

`packages/runtimes/interactive/src/clips/live-data/static-fallback.ts` ships `defaultLiveDataStaticFallback` — a generic Element[] generator that emits a header `TextElement` (endpoint summary) + a body `TextElement` (JSON-pretty-printed snapshot body). This is **NOT** a styled magic-wall panel; it is a generic developer-facing fallback for any LiveData clip without a custom renderer.

T-355's parity flow **bypasses** the LiveDataClip wrapper and `defaultLiveDataStaticFallback`. The resolver returns a binding to `magic-wall-panel` (a frame-runtime-bridge primitive); the renderer mounts `magic-wall-panel` directly with the `MAGIC_WALL_CANONICAL_SNAPSHOT` payload (D-T355-4) inlined as props. The wrapper's job (host the live mount, emit telemetry, route to staticFallback on failure, run the drilldown zoom state machine) is a runtime concern that does not surface in the parity flow.

**Rationale**: the parity golden's purpose is to verify the **rendered visual** matches the stub's prose contract. Routing through the LiveDataClip wrapper would bring its telemetry surface, its endpoint-prop validation, its placeholder-on-missing-snapshot fallback, and its drilldown state machine into the parity render — none of which contribute to the visual output and all of which would couple the parity golden to wrapper behavior that legitimately changes between releases (T-391/T-392 evolution + future drilldown-zoom landings). The bypass keeps the parity contract focused on **the visual**, not the integration mechanism. Mirrors T-356 D-T356-11 + T-357 D-T357-12 verbatim.

Document this bypass in the preset's `## Rules` AND the resolver entry's TSDoc so a future reader does not assume the parity path exercises LiveDataClip end-to-end. The integration is exercised by T-391/T-392's own tests; T-355 is not the right harness for that surface.
