# T-447 — Phase 14 GA readiness checklist

**Branch**: `task/T-447-p14-ga-readiness`

## Goal

Extend the existing T-410 GA-readiness audit
(`scripts/check-ga-readiness.ts`) with **Phase 14 GA-specific
criteria** as a new **Category 8 — Phase 14 GA readiness**, and
regenerate `docs/ga-readiness-report.md` as the **inaugural Phase 14
GA report**. The audit surfaces the Phase 14 punch list the
Orchestrator uses to ratify GA.

T-447 is the **third** Phase 14 δ (Lock-in) task. It is preceded by
T-445 (usage telemetry) and T-446 (data-flow security audit), and is
itself a hard gate criterion in the existing T-446 spec
("8.3 — All 9 adapters have SecurityManifest").

T-447 is **S-sized** — pure extension of an existing audit script.
No new package, no new CI gate, no new infrastructure. The work is:

1. ~150–250 LOC added to `scripts/check-ga-readiness.ts` for Category 8
   (~11 criteria covering ADRs, the 9 adapters, sandbox, telemetry,
   security audit, CI gate wiring, and P14 closeout / docs).
2. Tests covering each Category 8 criterion's pure helper.
3. Run `pnpm check-ga-readiness` to regenerate
   `docs/ga-readiness-report.md` and commit the regenerated report.

## §13 statement — NOT a structural extension

## Category 8 — Phase 14 GA readiness

Eleven criteria, listed below. Each criterion is implemented as a
pure helper exposed for unit-testing alongside the existing
`runCategoryN` per-category helpers.

### 8.1 — ADR-007 + ADR-008 ratified

**Check**: for each of `ADR-007`, `ADR-008`, locate the file under
`docs/decisions/`. Parse the frontmatter `**Status**:` marker. PASS
only when both ADRs are `Accepted`. Otherwise FAIL (with the actual
status reported).

**Current state**: both ADRs are `Proposed` as of 2026-05-11 HEAD —
will FAIL on inaugural run. This is **expected** — the punch list
shows the Orchestrator that the two Phase 14 α ADRs still need
ratification at the phase boundary.

### 8.2 — All 9 reference adapters present

**Check**: for each of the 9 declared adapter ids (`kokoro`,
`fish-speech`, `tripo`, `meshy`, `seedance`, `runway`, `ace-step`,
`yue`, `stable-audio-open`), verify the corresponding
`packages/<name>/package.json` exists with a `@stageflip/<name>` name.
Map adapter ids to package directories:

```
kokoro             → packages/tts-kokoro
fish-speech        → packages/tts-fish-speech
tripo              → packages/3d-tripo
meshy              → packages/3d-meshy
seedance           → packages/video-seedance
runway             → packages/video-runway
ace-step           → packages/music-acestep
yue                → packages/music-yue
stable-audio-open  → packages/sfx-stable-audio
```

PASS when all 9 present. FAIL with the list of missing.

### 8.3 — All 9 adapters have `security.json` sidecar

**Check**: for each adapter package directory above, verify the
sidecar `security.json` exists at the package root. PASS when all 9
present. FAIL with the list of missing.

Does NOT validate the manifest contents — `pnpm check-data-flow-security`
already enforces shape consistency. This is a presence check.

### 8.4 — AdapterRegistry wire-up covers all 9 adapters

**Check**: `packages/adapter-regression/src/canonical-input.ts`'s
`ADAPTER_IDS` constant lists all 9 declared adapter ids. The constant
is the single source of truth for "what adapters T-435 regresses
against." Verifying it contains all 9 ids confirms the adapter
registry is end-to-end wired.

PASS when all 9 ids appear. FAIL with the list of missing.

### 8.5 — T-422 license-gate script present

**Check**: `scripts/check-asset-licenses.ts` exists, AND
`package.json scripts['check-asset-licenses']` exists, AND
`.github/workflows/ci.yml` contains a step named `Gate -
check-asset-licenses`.

PASS when all three present. FAIL otherwise (with the list of
missing pieces).

### 8.6 — T-435 adapter-regression script present

**Check**: `scripts/check-adapter-regression.ts` exists, AND
`package.json scripts['check-adapter-regression']` exists, AND
`.github/workflows/ci.yml` contains a step named `Gate -
check-adapter-regression`.

PASS when all three present. FAIL otherwise.

### 8.7 — T-444 adapter-sandbox package present

**Check**: `packages/adapter-sandbox/package.json` exists with
name `@stageflip/adapter-sandbox`.

PASS when present. FAIL otherwise.

### 8.8 — T-445 usage-telemetry package present

**Check**: `packages/usage-telemetry/package.json` exists with
name `@stageflip/usage-telemetry`, AND the
`query_usage_telemetry` tool registration string appears in
`packages/engine/src/handlers/asset-generation/handlers.ts`.

PASS when both present. FAIL otherwise.

### 8.9 — T-446 data-flow security audit gate wired

**Check**: `scripts/check-data-flow-security.ts` exists, AND
`package.json scripts['check-data-flow-security']` exists, AND
`.github/workflows/ci.yml` contains a step named `Gate -
check-data-flow-security`.

PASS when all three present. FAIL otherwise.

### 8.10 — T-448 documentation pass

**Check**: `docs/tasks/T-448.md` exists.

WARN when missing (Phase 14 documentation pass is a downstream
deliverable; may not yet be drafted at GA-readiness audit time).
PASS when present.

### 8.11 — T-449 Phase 14 closeout handover

**Check**: presence of `docs/tasks/T-449.md` AND
`docs/handover-phase14-complete.md`.

Per `feedback_phase_closeout_timing.md` (MEMORY): phase-N closeout
writes at phase-N+1 start, not at phase-N end. **Auto-WARN** with
note documenting the policy. PASS only when both files exist.

## Acceptance criteria

- [AC1] Category 8 added to `runAudit` with 11 criteria in stable
  ordering (8.1..8.11).
- [AC2] Per-category audit helpers for each 8.x criterion are pure
  + unit-tested (no I/O — paths injected, results returned).
- [AC3] `pnpm check-ga-readiness` runs end-to-end and writes
  `docs/ga-readiness-report.md` including Category 8.
- [AC4] The committed `docs/ga-readiness-report.md` reflects the
  Phase 14 GA inaugural state — i.e. each Category 8 criterion's
  PASS/FAIL/WARN status from a real run against the current
  worktree.
- [AC5] `scripts/check-ga-readiness.test.ts` includes:
  - A real-corpus smoke test asserting 8 categories with criteria.
  - At least one per-category-8 PASS assertion against current main
    (e.g. 8.2 — 9 adapters present).
  - At least one synthetic-tree FAIL assertion (e.g. an empty repo
    fails 8.1 + 8.2 + 8.3).
- [AC6] No touch outside `scripts/`, `docs/tasks/T-447.md`,
  `docs/ga-readiness-report.md`, `.changeset/`.

## Failure modes the new criteria catch

- ADR-007 / ADR-008 stay `Proposed` past the phase boundary (8.1).
- An adapter package gets dropped or renamed without updating the
  T-435 registry (8.2 + 8.4 disagree).
- A `security.json` sidecar gets deleted or never created for a new
  adapter (8.3 catches the gap before T-446's gate fires).
- A CI gate is added to `package.json` scripts but never wired into
  the workflow (8.5 / 8.6 / 8.9).
- The Phase 14 closeout handover gets forgotten (8.11).
