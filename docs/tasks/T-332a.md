# T-332a — `scoreBug` primitive (Cluster B; 6 sport registers)

**Branch**: `task/T-332a-score-bug-primitive`

## Goal

Ship a frame-runtime-bridge clip — `score-bug` (kebab-case file/kind, mirroring `breaking-banner` / `news-ticker-bar` / `lower-third`) — that renders six divergent broadcast-sports score-bug registers from a single primitive dispatched by a sealed `style: 'football' | 'racing' | 'cricket' | 'tennis'` enum. The primitive is the missing piece that blocks every Cluster B sport-bug preset:

- **T-332 `f1-timing-tower`** — `clipKind: scoreBug`; vertical 20-driver tower on the LEFT side of the frame; per-row team-color stripe + position number + 3-letter driver code + gap delta + sector colors (purple session-best / green personal-best / yellow slower). Style binding: `'racing'`.
- **T-333 `premier-league-field-of-play`** — `clipKind: scoreBug`; compact upper-left rectangular scoreclock; PL purple `#34003A` + green `#00FC8A`; two team boxes + score + minute. Style binding: `'football'`.
- **T-334 `fox-nfl-no-chrome`** — `clipKind: scoreBug`; bottom-center, NO container chrome; team-color background boxes behind 3-letter codes; score; down-and-distance; gradient backdrop. Style binding: `'football'`.
- **T-335 `nbc-snf-possession-illuminated`** — `clipKind: scoreBug`; horizontal bar bottom-center; center circle (clock + quarter + NBC); flanking team sections with possession-side illumination; directional chevron `<<` for play direction. Style binding: `'football'`.
- **T-336 `cricket-scorebug`** — `clipKind: scoreBug`; top-of-screen complex multi-row register; team color + runs/wickets + overs + run rate + batsmen + bowler; ball-by-ball dot row context. Style binding: `'cricket'`.
- **T-337 `wimbledon-green-purple`** — `clipKind: scoreBug`; compact bottom-left ~350×80 px; Wimbledon green `#006633` + purple `#4B0082`; two player rows with surname / country / seed / set columns / current game score; active-server dot. Style binding: `'tennis'`.

T-332a is **distinct from every existing bridge clip**. `breaking-banner` (T-324a) renders a single horizontal label + headline pair with slide entrance — not a team-vs-team bar with score / clock / possession state. `news-ticker-bar` (T-356a) is a scrolling marquee — not a static team-vs-team layout. `outcome-row` (T-358a) is the existing parity-cli binding for the `scoreBug` clipKind via Pattern C resolver dispatch (see D-T332a-11) but it renders a flat row of N color-coded chips — none of the team-vs-team / vertical-tower / multi-row cricket layouts. `standings-table` (T-357a) is a vertical ranked table — overlaps superficially with the F1 tower but the cricket / football / tennis registers are foreign to it. T-332a's posture is closer to a 4-style-bundle dispatch primitive (style enum routes to a distinct render path per sport family) than a single-style anchored card.

T-332a is **M/L hybrid sized**: ~500–800 LOC component + ~200–300 LOC tests + barrel + ~6 LOC catalog/manifest entries + changeset. Comparable to `title-sequence.tsx` (T-321, ~810 LOC component with 4 style bundles + 5 shot kinds + 3 transition kinds) but with simpler intra-style rendering (each style is a static layout, not a multi-shot timeline). Bigger than `news-ticker-bar` / `breaking-banner` (each ~300–400 LOC, single-mode dispatch with mode/style enum). It does NOT touch any of T-332..T-337's preset markdown, parity resolver, or parity goldens — those land in the consumer-retry PRs after this primitive merges.

## Architectural decisions

### D-T332a-1. Distinct primitive vs. extending sibling

T-332a ships a **distinct** primitive (`score-bug`), NOT an extension of `outcome-row` (T-358a), `standings-table` (T-357a), `news-ticker-bar` (T-356a), or any other sibling. Rationale:

- **No existing primitive renders the team-vs-team / multi-row-cricket / vertical-driver-tower / two-player-tennis layouts.** `outcome-row` is a flat row of N chips; `standings-table` is a single ranked column; `news-ticker-bar` is a scrolling marquee; `breaking-banner` is a label-headline pair. Bolting team-vs-team or multi-row cricket onto any of them pollutes their style-bundle dispatch and breaks their existing tests.
- **Six consumer stubs explicitly pin `clipKind: scoreBug`** (`f1-timing-tower.md`, `premier-league-field-of-play.md`, `fox-nfl-no-chrome.md`, `nbc-snf-possession-illuminated.md`, `cricket-scorebug.md`, `wimbledon-green-purple.md`). The `'scoreBug'` clipKind is **already** reserved in `VALID_CLIP_KINDS` (line 58). The architectural intent has always been a dedicated primitive; the current `scoreBug → outcome-row` Pattern C binding is a placeholder that T-332a (with consumer-retry PRs) replaces.
- **Style divergence is wide enough to demand a sealed dispatch.** The 4 style bundles (`'football'` / `'racing'` / `'cricket'` / `'tennis'`) carry fundamentally different layouts — horizontal vs vertical primary axis, team-vs-team vs N-driver-list vs multi-row, score vs runs/wickets vs sets-and-games. Reusing any single existing primitive's dispatch shape would smear the divergence across irrelevant code paths.

Reviewer demand for merging into any sibling clip → escalate per CLAUDE.md §6.

### D-T332a-2. Approach — single primitive with style-bundle dispatch (Approach A)

**Decision**: **Approach A** — a single `score-bug` primitive with sealed `style: 'football' | 'racing' | 'cricket' | 'tennis'` enum dispatching to four distinct render paths within one component.

The Orchestrator evaluated three approaches:

- **Approach A (single primitive, style-bundle dispatch)** — Single `score-bug` primitive with `style` enum. Each style branches to a distinct render path. ~500–800 LOC. Mirrors `caption.tsx` 6-style + `title-sequence.tsx` 4-style dispatch precedents. ALL_BRIDGE_CLIPS grows 51 → 52.
- **Approach B (generic primitive + slot-based composition)** — A `score-bug` primitive that exposes layout primitives (panels, rows, team-section, clock-section, glyph-slots) and presets compose them. ~400–500 LOC primitive + meaningful per-preset composition logic in `parity-cli` resolver. Smaller primitive but pushes layout concerns into resolver code.
- **Approach C (split into multiple primitives)** — `score-bug-football`, `score-bug-racing`, `score-bug-cricket`, `score-bug-tennis` — 4 separate primitives. Breaks 1-clipKind = 1-primitive convention; clip count grows 51 → 55.

**Rationale for A**:

1. **Established pattern.** `caption.tsx` (6 STYLE_BUNDLES), `lyrics.tsx` (3 style bundles), `title-sequence.tsx` (4 sealed style bundles) all use single-primitive style-bundle dispatch. Each style render path is a separate function (`renderFootball` / `renderRacing` / `renderCricket` / `renderTennis`) called from a top-level `switch (style)` block — keeps dispatch clean even when intra-style render paths diverge sharply.
2. **One clipKind = one primitive.** Pattern C of the resolver maps `clipKind: scoreBug` → primitive `kind: 'score-bug'`. Approach C breaks this convention; Approach B pushes layout into the resolver where it doesn't belong (the resolver should map to a primitive + props, not own visual layout).
3. **ALL_BRIDGE_CLIPS stays at 52.** Approach C bloats the catalog with four entries that share most of their schema surface; the consolidation discipline is part of the bridge's identity.
4. **The 3 football presets share enough structure** that they all bind to `'football'` and differentiate via per-preset color / font / mode flag overrides — a fifth "premier-league-football" / "fox-nfl-football" / "nbc-snf-football" enum value is unwarranted.

Reviewer demand for Approach B (slot-based) or Approach C (split) → escalate; the architectural rule is sealed at A.

### D-T332a-3. Style bundle enum — `'football' | 'racing' | 'cricket' | 'tennis'`

Four sealed bundles cover the canonical broadcast-sports register space:

- **`'football'`** — Horizontal team-vs-team bar. Serves T-333 (Premier League), T-334 (Fox NFL), T-335 (NBC SNF). All three are team-vs-team layouts with a centered clock/period element flanked by team sections (codes + scores). Per-preset variation is via color + font overrides, optional `possession`, optional `down`, optional `centerCircle`, optional `backdropGradient`. NOT a soccer-only bundle — covers American football, association football, rugby, etc. The name reflects the layout register (two opposing teams across a horizontal bar), not a specific sport.
- **`'racing'`** — Vertical N-driver tower (anchored to a frame edge, default left). Serves T-332 (F1). One row per driver with: position number, optional team-color stripe, 3-letter code, gap delta, optional sector-time cells, optional tire-compound glyph. Rows stacked vertically; row count 1..24.
- **`'cricket'`** — Multi-row complex panel anchored top-of-screen (or any corner). Serves T-336 (cricket scorebug). Densest register: team line (code + runs + wickets + overs + run rate) + batsmen rows (1..2) + optional bowler line + optional partnership line. Stacked vertically within a single panel.
- **`'tennis'`** — Two-row stack (one per player). Serves T-337 (Wimbledon). Compact partial-width panel anchored to a corner. Per-player row: surname + country code + seed + N set columns (1..5) + current game score + optional active-server dot.

The four bundles dispatch in a single `switch (style)` block in the component; each style maps to a distinct render path (`renderFootball` / `renderRacing` / `renderCricket` / `renderTennis`). No "hybrid" / configurable per-feature toggle in v1 — the four bundles are sealed. Future styles add via additive enum extension (no breakage). When a Reviewer pushes for a fifth bundle (e.g., `'basketball'` for an NBA scoreboard preset, `'hockey'` for an NHL preset) → escalate; that's a v2 follow-up.

### D-T332a-4. Schema shape (Zod) — discriminated union on `style`

Top-level Zod schema is a discriminated union on `style`. Each variant carries the common base props + the style-specific shape. Mirrors `title-sequence.tsx`'s `Shot` discriminated union pattern verbatim, lifted to the top-level props level.

```ts
const baseProps = {
  /** Anchor position (canvas pixel coordinates). Sub-style determines defaults. */
  position: z
    .object({
      x: z.number(),
      y: z.number(),
      width: z.number().positive().optional(),
      height: z.number().positive().optional(),
    })
    .strict(),
  /** Common backdrop fill. Defaults to theme palette/background. */
  background: z.string().optional(),
  /** Common foreground text color. Defaults to theme palette/foreground. */
  foreground: z.string().optional(),
  /** Common accent (highlights, stripes). Defaults to theme palette/accent. */
  accent: z.string().optional(),
  /** Optional font family + weight override. Default 'Plus Jakarta Sans, sans-serif' weight 700. */
  font: z
    .object({
      family: z.string(),
      weight: z.number().optional(),
      tabularNums: z.boolean().optional(),
    })
    .optional(),
  /** Casing transform applied to non-numeric text fields. Default 'as-is'. */
  casing: z.enum(['as-is', 'uppercase', 'lowercase', 'title-case']).optional(),
  /** Border-radius (px). Default 0. */
  borderRadius: z.number().nonnegative().optional(),
  /** Backdrop opacity (0..1). Default 1. */
  backdropOpacity: z.number().min(0).max(1).optional(),
};

const teamShape = z
  .object({
    code: z.string().min(1).max(8),  // 3-letter standard, up to 8 for bespoke registers
    color: z.string().regex(/^#[0-9a-fA-F]{6}$/),
    score: z.string(),  // string to allow '0', '21', '7-3', '3 (4)' shootout, etc.
  })
  .strict();

const footballShape = z.object({
  style: z.literal('football'),
  ...baseProps,
  home: teamShape,
  away: teamShape,
  clock: z.string(),
  period: z.string(),  // '1st' / 'Q2' / '34:12' / '2H' / 'OT' — string-typed for sport variation
  possession: z.enum(['home', 'away']).optional(),
  down: z.string().optional(),  // NFL down-and-distance like '3rd & 7'
  direction: z.enum(['left-to-right', 'right-to-left']).optional(),  // NBC SNF chevrons
  centerCircle: z.boolean().optional(),  // NBC SNF center circle render
  backdropGradient: z
    .object({
      centerOpacity: z.number().min(0).max(1),
      edgeOpacity: z.number().min(0).max(1),
    })
    .optional(),  // Fox NFL radial gradient
}).strict();

const racingRowShape = z
  .object({
    position: z.number().int().min(1).max(99),
    code: z.string().min(1).max(4),  // 3-letter driver code; 4 for some series
    teamColor: z.string().regex(/^#[0-9a-fA-F]{6}$/).optional(),
    gap: z.string().optional(),  // '+0.124' — truncated, not rounded
    sectorTimes: z.array(z.string()).max(3).optional(),  // ['+0.124', '+0.084', '+0.221']
    sectorColors: z
      .array(z.enum(['session-best', 'personal-best', 'slower', 'neutral']))
      .max(3)
      .optional(),  // matches sectorTimes length
    tireCompound: z.enum(['soft', 'medium', 'hard', 'inter', 'wet']).optional(),
    highlighted: z.boolean().optional(),  // F1 "smart glass" highlight
  })
  .strict();

const racingShape = z.object({
  style: z.literal('racing'),
  ...baseProps,
  rows: z.array(racingRowShape).min(1).max(24),
  anchor: z.enum(['left', 'right']).optional(),  // tower anchored left (default) or right
  rowHeight: z.number().positive().optional(),  // default 30
  showSectorBars: z.boolean().optional(),  // default true
}).strict();

const batsmanShape = z
  .object({
    name: z.string().min(1).max(40),
    runs: z.number().int().min(0).max(999),
    balls: z.number().int().min(0).max(999).optional(),
    onStrike: z.boolean().optional(),
  })
  .strict();

const cricketShape = z.object({
  style: z.literal('cricket'),
  ...baseProps,
  battingTeam: z
    .object({
      code: z.string().min(1).max(4),
      color: z.string().regex(/^#[0-9a-fA-F]{6}$/),
      runs: z.number().int().min(0).max(9999),
      wickets: z.number().int().min(0).max(10),
      overs: z.string(),  // '14.3' — over.ball convention
    })
    .strict(),
  bowlingTeam: z
    .object({
      code: z.string().min(1).max(4),
      color: z.string().regex(/^#[0-9a-fA-F]{6}$/),
    })
    .strict()
    .optional(),
  runRate: z.string().optional(),
  requiredRunRate: z.string().optional(),
  batsmen: z.array(batsmanShape).min(0).max(2).optional(),
  bowler: z
    .object({
      name: z.string().min(1).max(40),
      figures: z.string(),  // '3-42'
    })
    .strict()
    .optional(),
  partnership: z.string().optional(),  // '47 (38)'
  anchor: z.enum(['top-left', 'top-center', 'top-right']).optional(),  // default 'top-center'

  .object({
    surname: z.string().min(1).max(40),
    countryCode: z.string().min(2).max(3),
    seed: z.number().int().min(1).max(128).optional(),
    sets: z.array(z.string()).min(1).max(5),  // ['6', '4', '7-6']
    gameScore: z.string().optional(),  // '15' / '30' / '40' / 'AD' / ''
    flag: z.string().optional(),  // emoji or URL — opaque passthrough
  })
  .strict();

const tennisShape = z.object({
  style: z.literal('tennis'),
  ...baseProps,
  players: z.tuple([tennisPlayerShape, tennisPlayerShape]),  // exactly 2
  activeServerIndex: z.union([z.literal(0), z.literal(1)]).optional(),
  anchor: z.enum(['top-left', 'top-right', 'bottom-left', 'bottom-right']).optional(),
}).strict();

export const scoreBugPropsSchema = z.discriminatedUnion('style', [
  footballShape,
  racingShape,
  cricketShape,
  tennisShape,
]);
```

Discriminated-union approach (vs single-shape with all-optional fields) chosen because:
- TypeScript narrows via `props.style` cleanly into each render path — no per-field non-null assertions.
- Schema validation rejects nonsensical cross-style combinations (e.g., `style: 'football'` + a `rows` field) at parse time.
- Mirrors `title-sequence.tsx`'s `Shot` discriminated union — established pattern.
