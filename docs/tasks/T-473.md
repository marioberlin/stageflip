# T-473 — Quiz fairness

**Branch**: `task/T-473-quiz-fairness`

## Goal

Layer fair quiz scoring on top of the T-465 LiveQuizClip + T-466
LeaderboardClip pair. Three concerns:

1. **Time-bonus scoring** (Kahoot canon): correct answers score more
   when faster:
   - `score = 0` for incorrect answers OR answers after timer expiry.
   - `score = base + bonus * (1 - latencyMs / timerMs)` for correct
     answers, with `base = 500` + `bonus = 500` (1000 max).
   - Tie-breaking is implicit: faster correct answer → higher score.
2. **Late-joiner posture** (locked at question N): a voter who joins
   the session AFTER question N has already advanced cannot vote on
   prior questions; their score starts at 0 and accumulates only
   from question N+1 onwards.
3. **Disconnect/reconnect** (resume at current question): a voter
   whose WebSocket disconnects + reconnects resumes at the
   currently-active question. Their prior-question scores are
   preserved (server-side scoreboard).

Carries four implementation concerns:

1. **`packages/audience-contract/src/quiz-fairness.ts`** — NEW pure
   scoring helpers (the contract package is the natural home — these
   functions are deterministic primitives consumed by the server
   AND by clip-tier renderings):
   - `computeQuizScore({ isCorrect, latencyMs, timerMs }): number`.
   - `applyLateJoinerLock({ voterToken, joinedAtQuestionIndex,
     currentQuestionIndex }): { canVote: boolean }`.
2. **`apps/api/src/routes/audience-quiz-state.ts`** — NEW server-side
   quiz state machine:
   - Tracks per-session: active question index + per-voter scores +
     per-voter `joinedAtQuestionIndex`.
   - On `submitVote` for `kind: 'live-quiz'`: validate voter is
     allowed (late-joiner check) + compute score via
     `computeQuizScore` + persist to the audience-results store.
   - Quiz state is in-memory + persisted via `AudienceResultsStore.appendEvent`
     for durable replay.
3. **`packages/storage/src/audience-results.ts`** — EDIT to add
   per-voter score tracking on the session doc:
   - New optional field on `AudienceSessionDoc`:
     `quizState?: { activeQuestionIndex: number, scores: Map<string, number>,
     joinedAt: Map<string, number> }` — voter-token-keyed.
4. **WebSocket vote-handler integration** at
   `apps/api/src/routes/audience-ws.ts` — for `live-quiz` vote
   messages, route through the quiz state machine + emit per-voter
   `LF-AUDIENCE-VOTER-RATE-LIMITED` if the late-joiner check rejects.

**Strict scope** — server-side scoring + late-joiner + reconnect
posture. NO new schema slot (we already have LiveQuizClip's data
model). NO LeaderboardClip-side integration (T-466 already renders
the ranking; the server-side scoring just populates the
LeaderboardAggregation's `ranking` field). NO timer enforcement
on the server (the client + presenter-side admin command path
advances; T-473 reads the timer's deadline from the question's
`timerSeconds`).

## Implementation notes

- **`computeQuizScore`** is the canonical Kahoot-style formula:
  ```ts
  export function computeQuizScore(args: {
    readonly isCorrect: boolean;
    readonly latencyMs: number;
    readonly timerMs: number;
  }): number {
    if (!args.isCorrect) return 0;
    if (args.latencyMs > args.timerMs) return 0;
    if (args.timerMs <= 0) return args.isCorrect ? 500 : 0;
    const bonusFraction = Math.max(0, 1 - args.latencyMs / args.timerMs);
    return Math.round(500 + 500 * bonusFraction);
  }
  ```
  - Tests cover boundaries; result is integer for stable leaderboards.
- **`applyLateJoinerLock`** is a simple comparison:
  ```ts
  export function applyLateJoinerLock(args: {
    readonly voterToken: string;
    readonly joinedAtQuestionIndex: number;
    readonly currentQuestionIndex: number;
  }): { readonly canVote: boolean } {
    return { canVote: args.currentQuestionIndex >= args.joinedAtQuestionIndex };
  }
  ```
- **Quiz state machine** (`audience-quiz-state.ts`):
  - In-memory map `sessionId → QuizState`.
  - `QuizState = { activeQuestionIndex, scores: Map<voterTokenHash, number>, joinedAt: Map<voterTokenHash, number> }`.
  - `recordVote(sessionId, voterTokenHash, questionId, optionIndex,
    latencyMs, questions)`:
    - Look up `currentQuestionIndex` from `sessionId`'s state.
    - Look up `joinedAtQuestionIndex` (initialize to current if first
      vote).
    - Apply `applyLateJoinerLock`; if rejected, emit
      `LF-AUDIENCE-VOTER-RATE-LIMITED` with abuseLevel: 'late-joiner-lock'
      (re-use existing code) + return `{ accepted: false }`.
    - Compute score via `computeQuizScore`.
    - Update `scores` map.
    - Return `{ accepted: true, score, totalScore: scores.get(voter) }`.
- **WebSocket integration**: in `audience-ws.ts`'s vote handler, when
  the active session's `clipKind === 'live-quiz'`, route through
  `audience-quiz-state.recordVote` instead of the generic vote
  acceptor.
- **`AudienceSessionDoc.quizState`**: optional field. The
  `InMemoryAudienceResultsStore.openSession` accepts it via the doc
  argument; `updateQuizState(sessionId, mutator)` allows in-place
  mutation per question advancement.
