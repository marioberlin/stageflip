## Architectural decisions

### D-T321d-1 — Composition model: separate clipKind (Option A; consistent with T-321a/T-321b/T-321c precedents)

Mirror established carve-out pattern: `'photographicOverlay'` is its own clipKind, NOT a titleSequence prop. Cluster D presets compose multiple atmospheric clips (grain + light-leak + particles + photographic-overlay) via z-stack ordering at the host-html level. Consumers wire via PRESET_ID_BINDINGS to supply per-preset props.

### D-T321d-2 — File path: kebab-case `photographic-overlay.tsx`

`packages/runtimes/frame-runtime-bridge/src/clips/photographic-overlay.tsx`. Verified does not exist on main 2026-05-08.

### D-T321d-3 — Determinism scope: clip code; binds CLAUDE.md §3

No `Math.random()` / `Date.now()` / `setTimeout` / `setInterval` / `requestAnimationFrame` / `fetch`. v1 ships static (non-frame-driven) so animation primitives don't apply.

SVG filter primitives operate deterministically per the SVG 1.1 spec §15.3 (Filter Effects). `<feColorMatrix>` and `<feComponentTransfer>` are pure pixel-level functions of input pixel × static matrix/curve — no randomness, no time-dependent state. Output is byte-identical across CDP versions.

### D-T321d-4 — Sealed mode enum: 4 modes

`mode: 'sepia' | 'cross-process' | 'cinematic-lut' | 'fade'` — sealed at 4 well-known canonical film registers. Extensibility to additional modes (e.g. `'noir'`, `'kodachrome'`, `'polaroid'`) defers to T-321d-modes follow-up.

### D-T321d-5 — Schema: single `z.object().strict()` (NOT discriminatedUnion)

```ts
const photographicOverlayPropsSchema = z
  .object({
    mode: z.enum(['sepia', 'cross-process', 'cinematic-lut', 'fade']),
    intensity: z.number().min(0).max(1).optional(), // alpha-blend the filter onto the underlying; default 1
    position: positionSchema.optional(), // full-frame default
    // No theme slots — modes are pre-tuned canonical curves.
  })
  .strict();
```

Single object (not discriminatedUnion) because all 4 modes share identical prop surface; only the underlying SVG filter primitives differ. Mirrors T-319 qr-code-bounce single-schema posture.

### D-T321d-6 — Render approach: SVG `<filter>` (not canvas+ImageData; not CSS filter)

Three render approaches considered:

1. **CSS `filter: sepia(...)` etc.** — concise but only standard CSS filters available; cross-process / cinematic-LUT / fade not directly available. Custom values via `filter: url(#...)` referencing inline SVG, which is equivalent to option 3 with an extra layer. Cross-browser variance possible.
2. **Canvas + ImageData pixel-by-pixel** — full control but expensive; per-pixel processing across full frame is heavy.
3. **SVG `<filter>` with `<feColorMatrix>` / `<feComponentTransfer>`** — declarative; deterministic per SVG 1.1 §15.3; cheap (browser GPU-accelerated); concise; well-supported across CDP.

**Chosen: option 3 (SVG `<filter>`).** Rationale: deterministic across CDP, cheap to render, declarative (per-mode static matrices/curves embedded in JSX), no per-pixel loops needed. Document `color-interpolation-filters="sRGB"` attribute on the filter element to pin sRGB color space.

### D-T321d-7 — Per-mode SVG filter primitives

**Sepia** (warm-yellow tonal shift):
```xml
<feColorMatrix type="matrix" values="
  0.393 0.769 0.189 0 0
  0.349 0.686 0.168 0 0
  0.272 0.534 0.131 0 0
  0     0     0     1 0
"/>
```
Canonical sepia matrix (well-established; 5×4 affine; widely cited).

**Cross-process** (cyan-shadows + magenta-highlights):
```xml
<feComponentTransfer>
  <feFuncR type="table" tableValues="0.1 0.2 0.5 0.8 1.0"/>
  <feFuncG type="table" tableValues="0.0 0.3 0.5 0.7 1.0"/>
  <feFuncB type="table" tableValues="0.2 0.4 0.6 0.7 0.9"/>
</feComponentTransfer>
```
Curve-based; lifts shadows on R/B, suppresses G mid-tones.

**Cinematic-LUT** (teal-and-orange contrast bias):
```xml
<feColorMatrix type="matrix" values="
  1.10 0.05 -0.05 0 0
  0.00 1.05  0.05 0 0
 -0.05 0.05  1.10 0 0
  0    0     0    1 0
"/>
```
Boosts R/B (orange/teal), suppresses cross-channel mixing.

**Fade** (lifted blacks + lowered highlights):
```xml
<feComponentTransfer>
  <feFuncR type="linear" slope="0.85" intercept="0.10"/>
  <feFuncG type="linear" slope="0.85" intercept="0.10"/>
  <feFuncB type="linear" slope="0.85" intercept="0.10"/>
</feComponentTransfer>
```
Linear shift: black→0.10, white→0.95; classic faded-film register.

These are pre-tuned canonical values; document them as constants at the top of `photographic-overlay.tsx`.

### D-T321d-8 — Static (no frame counter)

v1 ships static overlays — the filter is a constant per-mode applied uniformly across the render. Document deliberate deviation from T-321a (frame-driven canvas write) and the existing T-131b.2 light-leak (frame-driven sin/cos animation). Static is sufficient for the canonical photographic registers; animation defers.

### D-T321d-9 — Theme slots: NONE

Per-mode color matrices/curves are pre-tuned canonical values. No `themeSlots`. Different from T-321a (which has 4 theme slots) and T-321b/T-131b.2 (which has color1/2/3). Document the deliberate choice: photographic registers are tonal CANON, not brand canvas.

### D-T321d-10 — Intensity scaling

Optional `intensity?: number (0-1, default 1)` — alpha-blend the filter overlay onto the underlying. Implemented via `<feMerge>` between source-graphic and filtered output, with the filter output's alpha multiplied by `intensity`. Document the math.

### D-T321d-11 — Position posture

Optional `position?: Position` — default full-frame (1280×720). Configurable for partial-frame applications. Mirror T-321a's position handling.

### D-T321d-12 — LOC budget: ~250-400 LOC component + ~150-200 LOC tests

Comparable to T-321a grain (~245 LOC component + ~290 LOC tests) but simpler (no canvas+ImageData; declarative SVG); more like T-319 qr-code-bounce in shape (~358 LOC component).

### D-T321d-13 — Resolver posture: impl PR does NOT touch parity-cli

The `socialMedia` clipKind / `lowerThird` clipKind / etc patterns: consumer preset PRs flip the resolver. T-321d ships the primitive; T-348/T-351 preset PRs (separate task) wire `photographicOverlay` clipKind via `PRESET_ID_BINDINGS`.
