# T-419 — `@stageflip/asset-gen-contract`

**Branch**: `task/T-419-asset-gen-contract`

## Goal

Ship `@stageflip/asset-gen-contract` — the per-modality interfaces +
Zod schemas + capability validators that ADR-008 (T-416 / PR #479,
merged 2026-05-11) specifies. T-418 (`@stageflip/adapters-core`) ships
the substrate (`AdapterDescriptor`, `AdapterRegistry`,
`CapabilityDescriptorParser`); T-419 ships the per-modality plug-ins
that bind into `CapabilityDescriptorParser` and that reference adapters
(T-426..T-434) implement.

The package ships three concerns:

1. **Five β modality contracts** per ADR-008 §D5 + §D6:
   - `TTSProvider`
   - `VideoGenerationProvider`
   - `MusicGenerationProvider`
   - `SFXProvider`
   - `ThreeDAssetProvider`
2. **Seven source-grounded provider class interfaces** per ADR-008 §D9
   (the asset-gen-tier extensions of ADR-007's seam):
   - `SlideDeckGenerationProvider`
   - `MindMapGenerationProvider`
   - `TableGenerationProvider`
   - `QuizGenerationProvider`
   - `FlashcardGenerationProvider`
   - `ReportGenerationProvider`
   - `InfographicGenerationProvider`
3. **`TenantVoiceConsentStore` facet interface** per ADR-008 §D4 — the
   storage facet TTS adapters that clone real voices consult on every
   call. Mirrors the `TenantSettingsStore` carve-out pattern from
   T-411a (`packages/storage/src/tenant-settings-store.ts`). Concrete
   adapter implementations (in-memory, Firebase, Postgres) are
   downstream and triggered by T-427 (`@stageflip/tts-fish-speech`).

Every provider interface extends `AdapterDescriptor` (T-418); each
modality exports a capability Zod schema + a `CapabilityValidator`
function the host wires into `CapabilityDescriptorParser` at boot.

**Strict scope** — interfaces + Zod schemas + capability validators
ONLY. NO concrete adapters (T-426..T-434). NO storage adapter
implementations (downstream). NO `MediaProvenance` schema (T-421). NO
`Document.research?` schema wiring (T-421 also handles via T-419's
forward-declared types). NO loss-flag code additions (downstream;
covered by ADR-008 §D11 inventory but the consumer task that creates
the first violation owns the LF code addition — `loss-flags.code` is
string-typed per the package contract, no closed-union edit needed).

## Implementation notes

### Capability Zod schema convention

Every modality follows the same shape: a `xxxCapabilityDescriptorSchema`
exported alongside a `XxxCapabilityDescriptor` type and a
`validateXxxCapability` function. The validator wraps the Zod parse:

```ts
import type { CapabilityValidator } from '@stageflip/adapters-core';

export const validateTtsCapability: CapabilityValidator = (capability) => {
  const result = ttsCapabilityDescriptorSchema.safeParse(capability);
  if (result.success) {
    return { ok: true, capability: result.data as Record<string, unknown> };
  }
  return { ok: false, error: result.error.message };
};
```

Hosts wire validators into `CapabilityDescriptorParser` at boot:

```ts
import { CapabilityDescriptorParser, buildValidatorMap } from '@stageflip/adapters-core';
import {
  validateTtsCapability,
  validateVideoGenCapability,
  validateMusicGenCapability,
  validateSfxCapability,
  validateThreeDCapability,
  // ...source-grounded...
} from '@stageflip/asset-gen-contract';

const parser = new CapabilityDescriptorParser(buildValidatorMap({
  tts: validateTtsCapability,
  'video-gen': validateVideoGenCapability,
  // ...
}));
```

### Modality `kind` literals

Every β modality interface MUST declare `readonly modality: { kind: '<lit>' }`
matching its modality kind exactly (e.g., `TTSProvider.modality.kind === 'tts'`).
This narrows the discriminated union from `AdapterDescriptor.modality` so
downstream consumers can branch on interface type.

### `MediaProvenance` + `ResearchSessionRef` cross-reference

ADR-008 §D2 / §D3 specify the canonical shapes. T-421 lands them in
`@stageflip/schema`. T-419 keeps a local placeholder file
(`provenance-placeholder.ts`) so the source-grounded provider interfaces
(D9) compile against an accurate shape today. T-421's PR will:

1. Add `MediaProvenance` + `ResearchSessionRef` to `@stageflip/schema`.
2. Switch T-419's barrel to re-export from `@stageflip/schema` instead
   of from the placeholder file.
3. Delete `provenance-placeholder.ts`.

The placeholder shape MUST match the §D2 / §D3 shape verbatim so the
swap is a one-line import flip.

### `TenantVoiceConsentStore` enforcement is per-call

Per ADR-008 §D4 D-VOICE-CONSENT-3, the TTS adapter's pre-call hook
calls `tenantVoiceConsentStore.assertActive(...)`; if it throws
(revoked / absent), the adapter refuses with the loss flag
`LF-VOICE-CONSENT-MISSING`. Per-session caching is rejected — a
revocation must take effect immediately. T-419 ships only the
interface; the in-memory adapter (downstream) is the v1 trigger.

The `assertActive` method signature is the only one in the facet that
throws — `get` returns `undefined` on miss, `listForTenant` returns an
empty array. Throwing on `assertActive` is intentional: it forces
adapters to handle the refusal explicitly and prevents accidental
fall-through-to-success.

### Library voices vs. cloned voices (ADR-008 §D4)

`TtsVoice.origin: 'library' | 'cloned-per-tenant'` distinguishes the
two cases. Library voices are pre-trained and bypass consent; cloned
voices require a `TenantVoiceConsentRow.assertActive` check on every
call. The `TtsCapabilityDescriptor.supportsVoiceClone: boolean` flag
mirrors §D12's plugin-manifest validation rule (marketplace gate
refuses voice-clone adapters without a declared consent UX surface).

### Source-grounded interfaces and `requiresResearchProvider`

Per ADR-008 §D9, each source-grounded provider class is a discrete
interface. The seven interfaces extend `AdapterDescriptor` AND declare
their `modality.kind` as one of the `slide-deck-gen` / `mind-map-gen` /
`table-gen` / `quiz-gen` / `flashcard-gen` / `report-gen` /
`infographic-gen` literals (already enumerated in T-418's
`AdapterModality` discriminated union).

Whether a given concrete adapter is source-grounded is a property of
its descriptor (`sourceGrounded: true` + `requiresResearchProvider:
'<provider-name>'`), not the interface. The same interface body works
for both source-grounded and creative implementations; the routing
engine reads the descriptor flag.

### Test posture

Each interface file ships a focused test file. Tests cover:

- Capability schema round-trip on the minimal valid shape.
- Capability schema rejects an invalid shape (wrong type / missing
  required field / extra field via `.strict()`).
- `validateXxxCapability` returns `{ ok: true }` on valid input.
- `validateXxxCapability` returns `{ ok: false, error: <string> }` on
  invalid input.
- Type-level test (compile-time): a mock object satisfying the
  provider interface assigns to the interface type — proves the
  interface compiles against `AdapterDescriptor`.

Every new source file begins with the path + a one-line purpose
comment per CLAUDE.md §3.

## Risks

- **Capability schemas may need refinement** as concrete reference
  adapters (T-426..T-434) land. ADR-008 §D5 / §D6 give the canonical
  shapes; T-419 ships them verbatim. If a reference adapter discovers
  a missing capability discriminator (e.g., a new SFX category), it
  raises an ADR-008 amendment + T-419 follow-up rather than slipping
  the field in silently.
- **`TenantVoiceConsentStore` vs. `TenantSettingsStore` placement**:
  the storage facet itself ships with the asset-gen contract package
  rather than `@stageflip/storage` because the voice-consent contract
  is asset-gen-tier semantics (only TTS-clone adapters consult it). If
  a future facet (e.g., `TenantConsentStore` for non-voice consent
  surfaces) generalises this, the interface may move into a shared
  consent package; for v1, co-locating with the asset-gen contract
  matches §D4's "asset-gen contract carries the voice-consent
  contract" framing.
- **`MediaProvenance` placeholder drift**: if T-421 lands a different
  shape than ADR-008 §D2 specifies, T-419's source-grounded providers
  will need updating in T-421's PR. The risk is mitigated by the
  one-line import-flip swap; T-421 reviewers should diff the
  placeholder against `@stageflip/schema/src/elements/provenance.ts`
  before merging.
