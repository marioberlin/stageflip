# T-453 — Audience backend service

**Branch**: `task/T-453-audience-backend-service`

## Goal

Ship the **audience backend service** the second post-hard-gate Phase 15
β task — extending `apps/api` with the `/v1/audience/*` route family that
ADR-009 (T-450 / PR #512) specifies. Carries six concerns:

1. **`TenantSettings.features.audience` extension** per ADR-009 §D3 / §D5:
   - Sub-namespace `{ enabled: boolean, motionNativeEnabled: boolean,
     maxIngestRateHz: number, maxConcurrentVotersPerSession: number,
     retentionDays: number }`.
   - Zod schema additions to `tenant-settings.ts` (strict; defaults
     materialise at the API layer per the T-411a posture for absent
     rows).
   - `TenantSettingsStore` contract unchanged (the schema extension is
     non-breaking — the new `audience` key is optional on `features`).
2. **REST routes** at `/v1/audience/*` per ADR-009 §D1:
   - `POST /v1/audience/sessions` → open session for a clip-kind + tenant
     (presenter-authenticated; returns `sessionId` + voter-join URL).
   - `POST /v1/audience/sessions/:sessionId/close` → close session
     (presenter-authenticated; returns `FinalSnapshot`).
   - `GET /v1/audience/sessions/:sessionId/state` → snapshot
     (presenter-authenticated; returns current `AggregationSnapshot`).
   - `POST /v1/audience/sessions/:sessionId/join` → mint voter token
     (anonymous-OK; per-IP rate-limited per ADR-009 §D8).
3. **WebSocket multiplexer** at `/v1/audience/ws/:sessionId` per ADR-009
   §D1 / §D6:
   - Handshake validates voter-token (subprotocol header) or
     presenter-token (`Authorization` header).
   - Message types: `vote`, `snapshot`, `admin-command` (open / close /
     advance / lock), `error`.
   - Close codes: 4000 session-closed, 4001 unauthorized, 4002 rate-cap,
     4003 server-shutdown.
   - Reconnect budget enforced server-side (6 retries × max 30s — the
     client implements the backoff; the server enforces the budget by
     tracking voter-token reconnect attempts).
4. **Firestore `audience-results` collection contract** per ADR-009 §D5:
   - `AudienceResultsStore` interface (modeled on T-411a's
     `TenantSettingsStore`) — 5 methods: `openSession` / `closeSession`
     / `appendEvent` / `readSnapshot` / `setTtl`.
   - `InMemoryAudienceResultsStore` implementation — for tests + the
     default-process-local fallback (the Firestore-backed impl is T-474).
   - Voter-token SHA-256 hashing with per-tenant pepper (the pepper is
     held in the audience-backend service config; rotation invalidates
     reconnect continuity but preserves aggregation).
   - Session doc shape: `{ sessionId, tenantId, clipKind, openedAt,
     closedAt?, voterCount, snapshot, ttlAt }` + `events/{eventId}`
     sub-collection (append-only).
   - TTL field: `ttlAt = closedAt + 90 days` (closed) /
     `ttlAt = createdAt + 24 hours` (orphan); tenant override via
     `TenantSettings.features.audience.retentionDays`.
5. **Rate-limit middleware** per ADR-009 §D3:
   - Per-tenant token bucket on `TenantSettings.features.audience.maxIngestRateHz`
     (default 100 Hz; bursts up to `2× rate`).
   - Per-voter token bucket (hardcoded 10 Hz / voter — vendor adapters
     inherit the vendor's policy).
   - Per-session voter cap via
     `TenantSettings.features.audience.maxConcurrentVotersPerSession`
     (default 1000).
   - Refusal returns `{ accepted: false, rejectReason }`; emits the
     corresponding `LF-AUDIENCE-*` flag.
6. **Loss-flag emission** for the seven server-side
   `LF-AUDIENCE-*` codes per ADR-009 §D11:
   - `TENANT-RATE-LIMITED` / `VOTER-RATE-LIMITED` / `SESSION-CLOSED` /
     `CAPACITY-CAP` / `ADAPTER-UNAVAILABLE` / `VENDOR-API-FAILURE` /
     `SNAPSHOT-MISSING`. The eighth code (`CONNECTION-LOST`) is
     client-side per ADR-009 §D11 — T-454 emits.
   - Emission via existing loss-flag plumbing; the sealed `const` array
     imported from `@stageflip/audience-contract` (T-452).

**Strict scope** — server-side audience backend only. NO concrete
`AudienceBackendProvider` implementation (T-478 ships the
`@stageflip/audience-native` provider that uses the
`AudienceResultsStore` from this PR). NO clip implementations
(T-461..T-471). NO audience runtime (T-454). NO CI permission rule
(T-455). NO voter landing page (T-456). NO Firestore-backed
`AudienceResultsStore` (T-474 — this PR ships only the in-memory store +
interface). NO vendor adapter bridges (T-479..T-483).

  default + tenant override via `retentionDays`; orphan sweep sets
  `ttlAt = createdAt + 24 hours` if `closedAt` absent + 24h elapsed.

  emits at the documented trigger (test asserts emitter called with
  correct code).

## Implementation notes

- **TenantSettings extension is additive + optional**: `features.audience`
  is `.optional()` on the schema; absent means "audience disabled"
  (default-deny per the T-411a posture for absent rows). The API layer
  materialises the defaults when the row exists but the sub-namespace
  is absent.
- **`AudienceResultsStore` interface mirrors `TenantSettingsStore`**:
  one in-memory impl in `packages/storage/src/audience-results-store.ts`;
  the Firestore impl lands in `packages/storage-firebase/` in T-474. The
  `apps/api/src/server.ts` config takes an optional store override; the
  default is the in-memory impl (matching the T-411a pattern).
- **WebSocket primitive choice**: use `ws@^8.18.0` (MIT) — Hono doesn't
  ship a first-party WebSocket adapter for `@hono/node-server`; the
  Node.js HTTP server upgrades to WebSocket via the `ws` library. Mount
  the upgrade handler on the same HTTP server `serve()` returns; route
  by URL pattern.
- **Voter-token hashing**: SHA-256 with per-tenant pepper. The pepper
  lives in service config (env var); the test suite uses a fixed pepper.
  Hashing happens at every event append + at every reconnect attempt
  check.
- **Rate-limit clock**: inject `now: () => number` into the limiter
  constructor so tests can advance time deterministically (do NOT call
  `Date.now()` inside the limiter — the apps/api server is not inside
  the determinism perimeter, but injecting the clock makes tests
  deterministic and matches the T-411a pattern).
- **WebSocket close codes** per ADR-009 §D6: 4000 session-closed (graceful
  close on server), 4001 unauthorized (bad token at handshake or
  mid-session), 4002 rate-cap (voter exceeded reconnect budget — 6
  retries × 30s), 4003 server-shutdown (graceful shutdown drains).
- **Admin commands**: presenter-token-authed only; the WebSocket
  handshake records the principal; per-message authz check rejects
  voter-token-originated admin commands with 4001.
- **No `console.log`** in route handlers (CLAUDE.md §3); use the Hono
  `logger()` middleware (already wired in `server.ts`) + structured-log
  helpers if needed.
- **Pre-empt skills-sync drift**: this PR does not add any tools or
  handler bundles, so `pnpm gen:tool-skills:check` is N/A. But run
  `pnpm skills-sync` once to verify no drift; the storage facet
  additions update no skill page directly (the audience-runtime SKILL is
  T-454's owner).
- **NEVER `git add -A`**: stage specific paths per memory; the
  workspace generates untracked build artifacts.
