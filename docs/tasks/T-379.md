# T-379 — Cluster H (AR overlays) composer tools

**Branch**: `task/T-379-cluster-h-compose-tools`

## Goal

Ship the `cluster-h-compose` engine handler bundle exposing **three** agent-callable composer tools that take a semantic AR / VAR / swim-lane brief (sport, content, camera-track, brand) and emit a Cluster H preset binding — preset id + opaque pass-through `props` payload. The tools are **read-only** (`ToolContext`, NOT `MutationContext`); the caller mounts the clip via a separate write-tier tool (`add_clip` from `create-mutate`).

T-379 is the **sixth + final M-sized cluster-composer task** and follows the pattern established by T-340 (Cluster B), T-331 (Cluster A), T-361 (Cluster E), T-368 (Cluster F), T-374 (Cluster G), and T-347 (Cluster C). Cluster H is **4/4 ELIGIBLE** as of #464 (T-378 nba-ar-replay, 2026-05-11); all four preset bindings are stable on `main` and ready for a composer surface. **This PR closes Cluster H's agent surface.**

The three tools dispatch across the four ratified Cluster H presets:

| Preset id | clipKind | binding (PRESET_ID_BINDINGS) | Sub-task |
|---|---|---|---|
| `sky-sports-ar-formations` | `arOverlay` | clipKind-default arm (PR #461) | T-375 |
| `hawkeye-var-3d-skeletal` | `arOverlay` | PRESET_ID_BINDINGS override | T-376 |
| `olympic-swim-lane-track` | `arOverlay` | PRESET_ID_BINDINGS override (`permissions: ['network']`) | T-377 |
| `nba-ar-replay` | `arOverlay` | PRESET_ID_BINDINGS override | T-378 |

The handlers do not touch any clip code, parity-cli, preset markdown, or signed parity goldens. Pure agent-layer wrap.

**Note on tool count**: Cluster H ships **3 tools, not 4** (per `skills/stageflip/presets/ar/SKILL.md` lines 36–38). Unlike Cluster C's 4-tool surface, Cluster H's compass-cited register is narrower — `compose_ar_overlay` is the umbrella by-sport-and-brand dispatcher; `compose_var_skeletal` is the Hawk-Eye register (works alongside Cluster B's `compose_var_call`); `compose_swim_lane_track` is the Olympic register.

## Architectural decisions

### D-T379-1. Handler-bundle name + path

**Decision**: Bundle name is `cluster-h-compose`. Handler files live at `packages/engine/src/handlers/cluster-h-compose/`. Mirrors the existing `cluster-{a,b,c,e,f,g}-compose/` convention. Reviewer demand for a non-cluster-keyed name (e.g., `ar-compose`) → escalate; cluster discipline is the architectural seal across all six compose bundles.

### D-T379-2. Tools are read-only — declare `ToolContext`, NOT `MutationContext`

**Decision**: Each handler's `TContext` parameter is `ToolContext` (the narrowest router context). Verbatim posture from D-T347-2 / D-T374-2. The composer's job is to emit a `(presetId, props)` tuple — no patch sink, no document reads. The downstream caller mounts the clip via a separate write-tier tool (`add_clip` from `create-mutate`).

The determinism gate at `CLAUDE.md` §3 covers `packages/runtimes/**` / `packages/frame-runtime/**` / `packages/renderer-core/src/clips/**` only — composer paths are out of its globs. The handlers are still pure (no `Date.now()`, no `Math.random()`, no I/O) by code-review discipline.

### D-T379-3. Bundle directory layout


### D-T379-4. Top-level type definitions

```ts
export const CLUSTER_H_COMPOSE_BUNDLE_NAME = 'cluster-h-compose';

export const CLUSTER_H_PRESET_IDS = [
  'sky-sports-ar-formations',
  'hawkeye-var-3d-skeletal',
  'olympic-swim-lane-track',
  'nba-ar-replay',
] as const;
export type ClusterHPresetId = (typeof CLUSTER_H_PRESET_IDS)[number];
```

Sealed enums (per-tool):

- `SPORTS = ['soccer', 'football', 'basketball', 'swimming', 'tennis', 'cycling']` — sealed at sports the 4 presets span (soccer/football → sky-sports; basketball → nba-ar-replay; swimming → olympic-swim — surfaced via dedicated tool; tennis/cycling reserved for typed-error responses pointing at escalation).
- `AR_BRANDS = ['sky-sports', 'nba', 'fox-sports', 'espn', 'tnt']` — sealed at AR-overlay-eligible broadcast brands. Only `sky-sports` and `nba` route to ratified presets; the rest return typed error.
- `VAR_BRANDS = ['hawkeye', 'premier-league', 'uefa-cl']` — sealed at Hawk-Eye-register brands. All three route to `hawkeye-var-3d-skeletal` (the only Cluster H VAR consumer).
- `SWIM_BRANDS = ['olympic', 'omega', 'fina', 'world-aquatics']` — sealed at Olympic-swim register brands. All four route to `olympic-swim-lane-track` (the only Cluster H swim consumer).
- `AR_CONTENT_KINDS = ['formation', 'shot-arc', 'player-tracking', 'replay']` — sealed AR content discriminator (forwarded into props as a sub-mode hint).
- `DISPLAY_TIERS = ['broadcast', 'mobile']` — per cluster SKILL line 46 ("AR is broadcast-first, not mobile-first"); mobile tier auto-reduces complexity at the primitive layer.

The brand enums are tight to what the 4 ratified presets span. Each value is documented in TSDoc with the preset it routes to.

### D-T379-5. `compose_ar_overlay` schema + dispatch

```ts
const composeArOverlayInput = z.object({
  sport: z.enum(SPORTS),
  content: z.enum(AR_CONTENT_KINDS),
  brand: z.enum(AR_BRANDS),
  cameraTrack: z.object({
    feed: z.enum(['live', 'pre-baked']),
    provider: z.string().min(1).max(80).optional(),  // 'Zero Density' / 'Stype' / NHK proprietary; informational
  }).strict().optional(),
  displayTier: z.enum(DISPLAY_TIERS).optional(),
  label: z.string().max(120).optional(),
}).strict();
```

Dispatch (sport + brand):

- `(sport ∈ {'soccer', 'football'}, brand: 'sky-sports')` → `sky-sports-ar-formations`
- `(sport: 'basketball', brand: 'nba')` → `nba-ar-replay`
- Otherwise → `{ ok: false, reason: 'no_preset_for_sport_brand', detail: '<helpful suggestion>' }`

`compose_ar_overlay` does NOT route to `hawkeye-var-3d-skeletal` (that's `compose_var_skeletal`'s register) or `olympic-swim-lane-track` (that's `compose_swim_lane_track`'s register) — keeping the dispatch matrix tight per cluster SKILL conventions.

Output: `z.discriminatedUnion('ok', [...])` per D-T379-9.

### D-T379-8. Output shape — opaque props per cluster-compose precedent

Every output is a `z.discriminatedUnion('ok', [...])` with the `ok: true` arm carrying:

- `presetId: z.enum([...])` — narrowed to the subset reachable from this tool
- `clipKind: z.literal('arOverlay')` — all 4 Cluster H presets share the same clipKind
- `props: z.record(z.unknown())` — opaque pass-through

The primitive's Zod schema is the authoritative validator at clip-mount time. Validating twice duplicates work and couples the engine package to clip internals. Reviewer demand for tighter typing → escalate per D-T347-9 / D-T374-6.

### D-T379-9. Cluster H presets all bind `arOverlay` clipKind

All four Cluster H presets share `clipKind: 'arOverlay'` (sky-sports = clipKind-default arm; the rest = `PRESET_ID_BINDINGS` overrides via Pattern C). The composer surfaces this as `clipKind: z.literal('arOverlay')` on every `ok: true` arm — a tighter contract than Cluster G (which spans 5 clipKinds across 5 presets).

### D-T379-10. Per-preset prop defaults

A `const PRESET_DEFAULTS: Record<ClusterHPresetId, Record<string, unknown>>` map at the top of `handlers.ts` documents per-preset canonical defaults sourced from each preset's `PRESET_ID_BINDINGS` entry in `packages/parity-cli/src/generate-fixture.ts` AND each preset's frontmatter. Values are deep-merged with caller-supplied input. T-379 keeps the defaults shallow / sparse — the bindings already pin canonical fonts / palette / staticFallback labels; the composer mainly forwards.

For Cluster H the per-preset defaults are minimal (the binding's `staticFallback.label` + colors are baked in at parity-cli time; the composer does NOT re-emit them):

- `sky-sports-ar-formations`: `{}` — primitive binding pins navy backdrop + Premier League purple accent.

- `olympic-swim-lane-track`: `{}` — primitive binding pins pool-blue backdrop + Olympic-gold accent.
- `nba-ar-replay`: `{}` — primitive binding pins hardwood-warm backdrop + NBA-red accent.

### D-T379-11. v1 routes through static-fallback rendering

Live-mount via `ThreeSceneClip` is gated on Track A T-397+. Each handler's TSDoc documents this so callers understand the v1 limitation without spelunking through the primitive.
