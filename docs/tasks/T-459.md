# T-459 — Result-export

**Branch**: `task/T-459-result-export`

## Goal

Ship the **post-event analytics download endpoint** that lets
presenters export an audience-session's full event log + final
aggregation snapshot as CSV or JSON, per the implementation-plan T-459
entry. Carries one concern:

1. **`GET /v1/audience/sessions/:sessionId/export?format=csv|json`** in
   `apps/api/src/routes/audience-sessions.ts`:
   - Presenter-authenticated (uses existing `authMiddleware`).
   - Tenant rate-limited (uses existing `TenantRateLimiter`).
   - Reads `audienceResultsStore.readSnapshot(sessionId)` for session
     metadata + final aggregation; reads the events sub-collection (or
     equivalent for the in-memory store) for per-vote rows.
   - **JSON format**: returns
     `{ session: AudienceSessionDoc, events: AudienceEventDoc[] }`
     content-type `application/json`. The `events` array is ordered
     by `appendedAt` ascending.
   - **CSV format**: returns one header row + one row per event:
     `eventId,sessionId,clipKind,voterTokenHash,kind,appendedAt,payload`.
     `payload` is JSON-stringified and CSV-quoted. Content-type
     `text/csv`. The CSV preserves voter-token hashing (per ADR-009 §D5
     — durable log carries no plaintext tokens) so the export is
     consistent with the audit posture.
   - Format defaults to `json` if the query string is absent or
     unrecognized (with a `Vary: format` header to make the routing
     explicit).
2. **`AudienceResultsStore.listEvents(sessionId, opts?)` extension**:
   - The T-453 `AudienceResultsStore` interface has `appendEvent` +
     `readSnapshot`; T-459 adds `listEvents(sessionId, opts?:
     { limit?: number, after?: string })` returning
     `Promise<readonly AudienceEventDoc[]>` ordered by `appendedAt` asc.
   - `InMemoryAudienceResultsStore` impl: trivial — return the array
     stored under `sessionId`'s events bucket. The Firestore-backed
     impl (T-474) reads the `events/` sub-collection; pagination via
     `after` returns events with `appendedAt > after`.
3. **CSV-encoding helper** at
   `apps/api/src/routes/audience-export-csv.ts`:
   - Pure function `encodeAudienceEventsCsv(events: readonly
     AudienceEventDoc[]): string`.
   - RFC 4180-compliant quoting (double-quote any cell containing
     `,`, `"`, `\n`, or `\r`; escape internal `"` as `""`).
   - Pure function — no I/O, no external deps.

**Strict scope** — the export endpoint + `listEvents` + CSV helper.
NO presenter-side UI (T-456's `<AudienceJoinModal>` may add a download
button in a follow-up). NO Firestore-backed `listEvents` (T-474 lands
the production impl; T-459 ships only the in-memory impl + interface
extension). NO export to spreadsheet formats (XLSX); CSV + JSON only
per the plan. NO export of vote-stream aggregations (the snapshot
is on the session doc; the events are the audit log).

## Implementation notes

- **CSV header row**: `eventId,sessionId,clipKind,voterTokenHash,kind,appendedAt,payload`.
  Document the schema at the top of the new module + in the endpoint's
  TSDoc.
- **Payload column**: `JSON.stringify(event.payload)` then RFC 4180
  quoted (the JSON contains commas + quotes, so the cell is always
  quoted in practice).
- **`Vary: format` header**: the standard `Vary` header is used for
  cache-key invalidation; mention `format` in `Vary` so any HTTP cache
  treats `?format=csv` and `?format=json` as distinct.
- **Pagination**: `listEvents(sessionId, { after, limit })` returns at
  most `limit` events with `appendedAt > after`. Default `limit` is
  10000; the export endpoint pages through if the session has more
  events. Document the loop in TSDoc.
- **Streaming response**: a session with 100k events would produce a
  ~10MB CSV; for v1, the endpoint returns the full body in one
  response. Streaming via Hono's response API is a future
  optimization; document the limit.
- **Voter-token hashing posture**: the export's
  `voterTokenHash` column is the hashed value already stored in the
  events sub-collection (ADR-009 §D5). NO un-hashing — the audit
  posture is preserved.
- **No `console.log`** in route handlers (use Hono `logger()`).
