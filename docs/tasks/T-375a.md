# T-375a — `arOverlay` bridge-clip primitive

First-of-six PR opening **Cluster H (AR overlays)**. This is the **shared primitive** that all 4 Cluster H presets (T-375 sky-sports-ar-formations / T-376 hawkeye-var-3d-skeletal / T-377 olympic-swim-lane-track / T-378 nba-ar-replay) bind to via `clipKind: arOverlay`.

Per cluster SKILL convention, Cluster H presets depend on `ThreeSceneClip` from the merged interactive runtime (T-384, PR #272, commit `6cfbb4c4`). The primitive is a thin frame-runtime-bridge wrapper: its v1 dispatch always renders the static-fallback poster; live-mount via `ThreeSceneClip` is GATED on Track A finale (T-397+ — not yet merged) and is not exercised in this PR.

This spec follows the T-347a / T-347b / T-347g / T-347h **single-style v1 primitive** posture for cluster-shared primitives.

## Decisions

### D-T375a-1 — new bridge primitive `arOverlay` (single-style v1)

Single-object schema (no `discriminatedUnion`). The 4 Cluster H presets share one prop surface; per-sport canon (markers, lines, skeletons, lane graphics, shot arcs) is supplied as caller-side `staticFallback` content + (when live) an author-defined `setupRef` ThreeSceneClip mount. Future variants (e.g. `register: 'pitch-anchored' | 'court-anchored' | 'water-anchored'`) would extend additively to a sealed enum then; v1 ships as a flat single-style object schema.

The primitive is registered as a frame-runtime-bridge clip with `kind: 'arOverlay'`. Per the T-328 / T-339 / T-347g / T-347h precedent, downstream presets may keep their `clipKind: arOverlay` declaration (matching the natural clip kind) — no `PRESET_ID_BINDINGS` override is necessary because the kind already matches the primitive.

### D-T375a-2 — v1 ships static-fallback rendering ONLY (live-mount gated on Track A T-397+)

Per the cluster SKILL line 53 ("If the tenant has not enabled the frontier posture for interactive clips (ADR-005 §D3), AR presets cannot mount live; they fall back to their `staticFallback` composite") and per the T-347h IMR precedent (D-T347h-1 — static-fallback canon explicit; live `ThreeSceneClip` rendering deferred to a Track A follow-up), v1 of this primitive renders the **static-fallback path only**.

The live-mount API surface (`setupRef`, `permissions`) is **declared on the props schema** for forward compatibility — the schema accepts these fields so preset bindings can already author them — but the v1 dispatch ignores `setupRef` at render time and always renders the static-fallback poster.

When Track A finale T-397+ lands, a downstream task (T-375a-live-mount or equivalent) will wire the `ThreeSceneClip` integration; this PR reserves the schema slot for that wire-up without exercising it.

### D-T375a-3 — sealed canonical palettes: NONE at the primitive level

Unlike T-347a `weatherMap` (which baked NEXRAD / Mark-Allen / Meriam palettes as static module constants) or T-347h `imrStaticFallback` (which baked storm-grays / danger-reds), `arOverlay` does NOT bake canonical palettes. AR overlays composite OVER existing video / sport context; the palette is **preset-specific, not primitive-specific** — per-sport color canon (Sky Sports navy + PL purple, Hawk-Eye PL purple + green offside lines, Olympic gold/red WR-line flash, NBA orange) lives in the per-preset binding, not in this primitive.

Per cluster SKILL "AR is broadcast-first, not mobile-first" — palettes are broadcaster-licensed canon, not engine canon.

### D-T375a-4 — static-fallback content surface

The static-fallback poster surface mirrors the most-common Cluster H static fallback shape (per the 4 preset stubs):

```ts
{
  // Sealed v1 — the static-fallback path is the only render path.
  // Future variants (live-mount, hybrid) extend additively.
  staticFallback: {
    // Either an inline poster image (data: URL or absolute URL) OR
    // a structured 2D placeholder. For v1, we ship the structured
    // 2D placeholder ONLY — image-asset loading lives in renderer-
    // core via existing ImageElement plumbing, not here.
    label: string;          // e.g. "AR FORMATION OVERLAY" / "VAR — CHECKING"
    sublabel?: string;      // e.g. "4-3-3 LINEUP" / "Loading review"
    backgroundColor?: string; // hex; defaults to #1A1A1A neutral broadcast dark
    foregroundColor?: string; // hex; defaults to #FFFFFF
    accentColor?: string;     // hex; per-preset broadcaster accent
    // Optional placeholder badge — simple rectangle marker indicating
    // "AR overlay would appear here in live-mount path"
    showLiveMountIndicator?: boolean; // default true
  };

  // Live-mount surface — declared but NOT exercised in v1. Reserved
  // schema slot for forward compatibility per D-T375a-2.
  setupRef?: {
    module: string;   // <package>#<Symbol> per componentRefSchema
    symbol?: string;  // optional explicit symbol override
  };
  permissions?: ReadonlyArray<'camera-tracking' | 'live-data' | 'network' | 'audio'>;

  // Optional displayTier hint per cluster SKILL "AR is broadcast-
  // first, not mobile-first" — primitive does NOT auto-reduce
  // complexity in v1 (preset author governs); reserved for future
  // adaptive rendering.
  displayTier?: 'broadcast' | 'mobile';

  // Optional canvas position (defaults to full canvas).
  position?: { x: number; y: number; width: number; height: number };
  font?: { family: string; weight?: number; size?: number };
}
```

### D-T375a-5 — static-fallback render: centered card on neutral backdrop

Renders an absolutely-positioned card centered on the canvas:

- Backdrop: `staticFallback.backgroundColor` (default `#1A1A1A` neutral broadcast dark) filling the position region.
- Optional 1px border in `accentColor` if supplied (signals broadcaster brand color).
- Centered card (60% width × 40% height of region):
  - `staticFallback.label` ALL CAPS, Bold 48px, color `foregroundColor` (default `#FFFFFF`).
  - Optional `sublabel` Regular 22px below, 70% opacity.
  - When `showLiveMountIndicator !== false` (default true): a small bottom-right badge "AR · STATIC FALLBACK" in 14px monospace, 50% opacity — signals to the operator that the live-mount path is gated.

Per `mixBlendMode` posture: the v1 static-fallback renders an OPAQUE card on an opaque backdrop; **`mixBlendMode` is NOT declared** on the clip definition. When live-mount lands (post-T-397), this posture may need revisiting (transparent compositing over background video) — see "Future-task notes" below.

### D-T375a-6 — frame-deterministic (closed-form; no `useEffect`)

Per CLAUDE.md §3 (determinism gate APPLIES — file is in `packages/runtimes/**/src/clips/**`):

- No `Date.now()` / `new Date()` / `performance.now()` / `Math.random()` / `crypto.*`.
- No `setTimeout` / `setInterval` / `requestAnimationFrame` / `addEventListener`.
- No `fetch` / `XMLHttpRequest` / `navigator.sendBeacon` / `Worker`.
- The static-fallback render is a pure function of `(props)` — same input → byte-identical inner HTML across renders + across frames.

### D-T375a-7 — theme slots

Standard fallback per the T-347h precedent:

- `backgroundColor` → `palette.background`
- `foregroundColor` → `palette.foreground`
- `accentColor` → `palette.accent`

(Nested `staticFallback.{backgroundColor,foregroundColor,accentColor}` is the prop surface; theme-slot resolution applies to the top-level surface only — the static-fallback nested object is resolved by the caller before binding. Document this posture in the schema TSDoc.)

### D-T375a-8 — fontRequirements: omit (preset-driven)

Per the T-347g `weatherStar4000Panel` and T-347h `imrStaticFallback` precedent (both omit `fontRequirements` since their fonts are preset-driven), `arOverlayClip` does NOT declare `fontRequirements`. Each cluster H preset binds its own font (Sky Sports Sans + Inter fallback / Premier Sans + Space Grotesk fallback / Games-specific + Atkinson Hyperlegible fallback / NBA brand + Inter fallback) at the preset level.

## Architectural decisions (CLAUDE.md §13 structural-extension rule)

This PR adds the new `'arOverlay'` clipKind to the open `RIRElement` discriminator (the schema `clipKind` field is currently typed as `z.string().min(1)` — open string, no enum-narrowing change required). It also adds a new clip kind to `ALL_BRIDGE_CLIPS` and to the static `LIVE_RUNTIME_MANIFEST`.

**§13 deferral note** — Per CLAUDE.md §13 acceptable evidence option 3, this PR ships a new clipKind (`arOverlay`) plumbed into the bridge runtime + manifest + SKILL.md table. **Pixel verification is deferred to PR2 (T-375 `sky-sports-ar-formations`)**, which is the first downstream consumer and will sign off via the standard parity-fixture flow + PO visual inspection. Unit tests in this PR verify the wired-up shape (props validation, schema rejections, render dispatch shape, ALL_BRIDGE_CLIPS membership, manifest sync); pixel-level assertions land with PR2's first parity golden.

This deferral is justified because:

1. The primitive ships only the static-fallback path (no live-mount surface to render).
2. The static-fallback render is a deterministic function of props — unit tests on inner HTML stability + element membership are sufficient to verify the wiring.
3. PR2 (T-375 sky-sports-ar-formations) is queued as the immediate next task and will produce the first parity golden + PO ratification within the same PR sequence.

The §13 box is checked in the PR template with the deferral citation.
