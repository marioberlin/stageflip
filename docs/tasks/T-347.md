# T-347 — Cluster C (Weather) composer tools

**Branch**: `task/T-347-cluster-c-compose-tools`

## Goal

Ship the `cluster-c-compose` engine handler bundle exposing four agent-callable composer tools that take a semantic weather-segment brief (condition, severity, regions, days, brand) and emit a Cluster C preset binding — preset id + opaque pass-through `props` payload. The tools are **read-only** (`ToolContext`, NOT `MutationContext`); the caller mounts the chosen clip via a separate write-tier tool (`add_clip` from `create-mutate`).

T-347 is the **fifth M-sized cluster-composer task** and follows the pattern established by T-340 (Cluster B sports), T-331 (Cluster A news), T-361 (Cluster E data), T-368 (Cluster F captions), and T-374 (Cluster G CTAs / social). Cluster C is **6/6 substantive + ratified** as of #456 (T-347h, 2026-05-09); all six preset bindings are stable on `main` and ready for a composer surface.

The four tools dispatch across the six ratified Cluster C presets:

| Preset id | clipKind | binding clipName | Sub-task |
|---|---|---|---|
| `bbc-mark-allen-clouds` | `weatherMap` | `weatherMap` (mark-allen-clouds style) | T-347c |
| `doppler-dbz-standard` | `weatherMap` | `weatherMap` (doppler-radar style) | T-347d |
| `heat-map-cool-to-warm` | `weatherMap` | `weatherMap` (heat-map style) | T-347e |
| `nhc-cone-of-uncertainty` | `stormTracker` | `stormTracker` | T-347f |
| `twc-retrocast-8bit` | `fullScreen` | `weatherStar4000Panel` | T-347g |
| `twc-immersive-mixed-reality` | `fullScreen` | `imrStaticFallback` | T-347h |

The handlers do not touch any clip code, parity-cli, preset markdown, or signed parity goldens. Pure agent-layer wrap.

## Architectural decisions

### D-T347-1. Handler-bundle name + path

**Decision**: Bundle name is `cluster-c-compose`. Handler files live at `packages/engine/src/handlers/cluster-c-compose/`. Mirrors the existing `cluster-{a,b,e,f,g}-compose/` convention. Reviewer demand for a non-cluster-keyed name (e.g., `weather-compose`) → escalate; cluster discipline is the architectural seal across all six compose bundles.

### D-T347-2. Tools are read-only — declare `ToolContext`, NOT `MutationContext`

**Decision**: Each handler's `TContext` parameter is `ToolContext` (the narrowest router context). Verbatim posture from D-T340-2 / D-T361-7. The composer's job is to emit a `(presetId, props)` tuple — no patch sink, no document reads. The downstream caller mounts the clip via a separate write-tier tool (`add_clip` from `create-mutate`).

The determinism gate at `CLAUDE.md` §3 covers `packages/runtimes/**` / `packages/frame-runtime/**` / `packages/renderer-core/src/clips/**` only — composer paths are out of its globs. The handlers are still pure (no `Date.now()`, no `Math.random()`, no I/O) by code-review discipline.

### D-T347-3. Bundle directory layout

```
packages/engine/src/handlers/cluster-c-compose/
  handlers.ts          # NEW — BUNDLE_NAME + 4 ToolHandler objects + barrels (~280–380 LOC)
  handlers.test.ts     # NEW — vitest, ~12–16 cases (~200–280 LOC)
  register.ts          # NEW — registerClusterCComposeBundle (~25 LOC)
  register.test.ts     # NEW — 3+ cases (~50 LOC)
```

No additional sub-files. Dispatch tables live as top-level `const ... as const` records in `handlers.ts`.

### D-T347-5. `compose_weather_alert` schema + dispatch

```ts
const composeWeatherAlertInput = z.object({
  condition: z.enum(WEATHER_CONDITIONS),
  regions: z.array(z.string().min(1).max(80)).min(1).max(50),
  severity: z.enum(WEATHER_SEVERITIES),
  brand: z.enum(ALERT_BRANDS),
  headline: z.string().max(160).optional(),
}).strict();
```

Dispatch (severity + brand + condition):

- `severity: 'warning'` + `brand: 'nhc'` + `condition ∈ {'hurricane', 'tropical-storm'}` → `nhc-cone-of-uncertainty` (stormTracker)
- `severity ∈ {'warning', 'watch'}` + `brand: 'twc'` + `condition ∈ {'severe-thunderstorm', 'tornado'}` → `twc-immersive-mixed-reality` (fullScreen → imrStaticFallback static-fallback register per T-347h binding)
- Otherwise → `{ ok: false, reason: 'no_preset_for_condition_severity_brand', detail: '<helpful suggestion>' }`

Output: `z.discriminatedUnion('ok', [...])` per D-T347-6.

### D-T347-6. `compose_forecast_map` schema + dispatch

```ts
const composeForecastMapInput = z.object({
  regions: z.array(z.string().min(1).max(80)).min(1).max(50),
  days: z.number().int().min(0).max(14),  // 0 = current/instantaneous; 14 = two-week outlook
  brand: z.enum(FORECAST_BRANDS),
  register: z.enum(FORECAST_REGISTERS).optional(),  // sub-mode disambiguator
}).strict();
```

Dispatch (brand + days + register):

- `brand: 'bbc'` → `bbc-mark-allen-clouds` (weatherMap; rotating 3D globe register)
- `brand ∈ {'doppler', 'nexrad', 'nws'}` → `doppler-dbz-standard` (weatherMap; reflectivity dBZ palette)
- `brand: 'twc'` + `register === 'retrocast'` → `twc-retrocast-8bit` (fullScreen → weatherStar4000Panel)
- `brand: 'twc'` + `days <= 1` (and not `register: 'retrocast'`) + `register === 'radar'` → `doppler-dbz-standard` (radar register; TWC short-range routes to canonical Doppler palette)
- `brand: 'twc'` + `days >= 2` (or `register === 'multi-day'`) → `twc-immersive-mixed-reality` (fullScreen → imrStaticFallback; multi-day animated forecast register routes to IMR static-fallback)
- Otherwise → `{ ok: false, reason: 'no_preset_for_brand_register', detail: '<suggestion>' }`

### D-T347-7. `compose_storm_track` schema + dispatch

```ts
const composeStormTrackInput = z.object({
  storm: z.object({
    name: z.string().min(1).max(80),  // 'HURRICANE MARGOT' / 'TROPICAL STORM ANA'
    advisoryNumber: z.number().int().positive().optional(),
  }).strict(),
  path: z.array(z.object({
    lat: z.number().min(-90).max(90),
    lon: z.number().min(-180).max(180),
    intensity: z.enum(['D', 'S', 'H', 'M']).optional(),  // depression / storm / hurricane / major
    timestamp: z.string().optional(),
  }).strict()).min(1).max(20).optional(),
  brand: z.enum(STORM_BRANDS),
  disclaimerText: z.string().max(120).optional(),  // composer does NOT inject; primitive default is canonical NHC text
}).strict();
```

Dispatch:

- `brand ∈ {'nhc', 'noaa'}` → `nhc-cone-of-uncertainty` — only stormTracker consumer
- Otherwise → `{ ok: false, reason: 'no_preset_for_brand', detail: 'Cluster C stormTracker only carries the NHC cone preset; suggest brand: nhc' }`

**NHC cone disclaimer** is mandatory per cluster SKILL line 46 ("impacts extend beyond the cone"). The `stormTracker` primitive enforces this at the primitive layer (default text per generate-fixture.ts:1773). The composer MUST NOT inject the disclaimer (it would clobber the primitive default if the caller omits `disclaimerText`); this is documented in TSDoc and tested per AC #21.

### D-T347-9. Output shape — opaque props per cluster-compose precedent

Every output is a `z.discriminatedUnion('ok', [...])` with the `ok: true` arm carrying:

- `presetId: z.enum([...])` — narrowed to the subset reachable from this tool
- `props: z.record(z.unknown())` — opaque pass-through

The primitive's Zod schema is the authoritative validator at clip-mount time. Validating twice duplicates work and couples the engine package to clip internals. Reviewer demand for tighter typing → escalate per D-T340-6 / D-T361-8.

### D-T347-10. Cluster C palettes are public-interest standards, NOT brand

Per cluster SKILL line 45: "Color palettes are standard, not brand." The composer MUST NOT accept palette overrides. The primitives (`weatherMap` doppler-radar style, `weatherMap` heat-map style) reject palette overrides at the primitive layer too. Documented in TSDoc on every handler and re-stated in this spec for the historical record.

### D-T347-11. NHC cone disclaimer is mandatory but composer-transparent

Per cluster SKILL line 46 + D-T347-7: "Every cone preset must carry the disclaimer 'impacts extend beyond the cone.'" The `stormTracker` primitive enforces this at the primitive layer (default text). The composer:

- DOES accept `disclaimerText: string?` for legitimate translation / regional override use cases.
- DOES NOT inject the default text; the primitive's default flows through unchanged when the caller omits the field.
- DOES test (AC #21) that omitting `disclaimerText` in the input results in NO `disclaimerText` key in the output `props` payload (so the primitive default is used).

### D-T347-12. Per-preset prop defaults

A `const PRESET_DEFAULTS: Record<ClusterCPresetId, Partial<Record<string, unknown>>>` map at the top of `handlers.ts` documents per-preset canonical defaults sourced from each preset's `PRESET_ID_BINDINGS` entry in `packages/parity-cli/src/generate-fixture.ts`. Values are deep-merged with caller-supplied input. T-347 keeps the defaults shallow / sparse — the bindings already pin canonical fonts / palette enums; the composer mainly forwards.

For Cluster C the per-preset defaults are minimal:

- `bbc-mark-allen-clouds`: `{ style: 'mark-allen-clouds' }` (the weatherMap primitive style discriminator)
- `doppler-dbz-standard`: `{ style: 'doppler-radar' }`

- `nhc-cone-of-uncertainty`: `{}` (no defaults; primitive defaults are canonical)
- `twc-retrocast-8bit`: `{}`
- `twc-immersive-mixed-reality`: `{}`
