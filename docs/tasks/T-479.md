# T-479 — `@stageflip/audience-slido`

**Branch**: `task/T-479-audience-slido`

## Goal

Ship `@stageflip/audience-slido` — the first of five vendor
`AudienceBackendProvider` adapters per ADR-009 §D8. Slido is the
canonical incumbent in the audience-engagement vertical; this adapter
translates Slido's API surface into the ADR-009 §D2 four-method
contract.

Mirrors T-478 (`@stageflip/audience-native`) verbatim, with these
per-vendor differences:

1. **Descriptor**:
   - `id: 'audience-slido'`.
   - `name: 'StageFlip Audience — Slido'`.
   - `license.kind: 'proprietary-byo'` (Slido is a SaaS; bring-your-own
     API credentials).
   - `sandbox.kind: 'remote-network'` (calls Slido's hosted API).
   - `supportedClipKinds`: per the ADR-009 §D8 vendor parity matrix —
     `['live-poll-multiple-choice', 'live-poll-open-text',
     'live-poll-rating', 'live-qa', 'live-quiz', 'leaderboard',
     'word-cloud', 'survey']` (omits the three motion-native:
     heatmap / reaction-stream / audience-ai-prompt).
   - `supportsMotionNative: false`.
   - `maxConcurrentVoters: 5000` (Slido enterprise plan cap).
   - `snapshotCadenceHz: 5` (Slido push cadence; lower than native's
     30 Hz).
   - `costPerCall.usd > 0` is a vendor-level concern handled via the
     TenantAdapterCredentialsStore (T-444); the descriptor declares
     `{ usd: 0 }` since the per-call cost is variable + tenant-billed
     out of band (Slido's own contract).
2. **Provider**: stub-mode implementation. The 4 methods call into a
   stub HTTP client; production wire-up to Slido's REST API is
   deferred to a follow-up task (T-479a) once Slido's enterprise
   credentials are clearance-audited.
3. **Security manifest**: declares `perimeter: 'remote-network'`,
   tenant-id LEAVES the perimeter (the Slido API call includes the
   tenant's poll-id which is correlated with Slido's tenant model),
   no voter PII leaves (voter tokens are hashed before transmission).

**Strict scope** — stub-mode descriptor + provider + security
manifest. NO Slido API integration (T-479a). NO clearance ADR (the
license whitelist for `audience-backend` modality already admits
`proprietary-byo`).

## Implementation notes

- **Stub provider**: throws `NotYetImplementedError` for production
  calls (mirrors `KokoroTtsProvider`'s stub pattern). In-memory store
  delegation is NOT applicable for vendor adapters — they call OUT to
  the vendor API; tests stub the API client.
- **`security.json`**: `perimeter: 'remote-network'`,
  `dataLeavingPerimeter.tenantId: true` (vendor needs to correlate),
  `dataLeavingPerimeter.prompt: false` (no LLM prompts in audience
  modality), `pii.userContent: false` (voter tokens hashed),
  `dataRetention.providerRetainsInput: true` (Slido's contract;
  StageFlip cannot control retention on the vendor side),
  `dataRetention.retentionPolicy: 'provider-specific'`.
- **Pre-empt skills-sync drift**.
- **Biome format ONLY touched dirs**.
- **NEVER `git add -A`**.
