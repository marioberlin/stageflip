# T-472 — Static-fallback consolidation

**Branch**: `task/T-472-static-fallback-consolidation`

## Goal

Consolidate the static-fallback paths across all 11 audience clip kinds
into a single export-time **frame-snapshot** mechanism. Currently the
PPTX exporter (`packages/export-pptx/src/parts/template-elements.ts`)
emits a stub `<p:sp>` + `LF-PPTX-EXPORT-UNSUPPORTED-ELEMENT` loss flag
for every `audience-*` element type (per the fallthrough T-461..T-471
each added). T-472 replaces that with real per-kind SVG output.

Carries three concerns:

1. **`AudienceExportFrame` shape + `renderAudienceExportFrame(snapshot,
   element, ctx)` dispatch** in `@stageflip/runtimes-audience`:
   - `AudienceExportFrame = { svg: string, width: number, height: number, voterCountAtCapture: number }`.
   - Pure function — deterministic per `(snapshot, element)`.
   - Dispatcher keyed by `AudienceClipKind`; one implementation per
     clip family.
2. **11 per-clip-kind `export-frame.ts` modules** alongside each clip
   family's existing `static-fallback.ts`:
   - Each emits an SVG string approximating the static-fallback DOM
     output. The SVG is intentionally LOW-FIDELITY for canvas-based
     clips (Heatmap raster simplifies to a discrete circle-per-tap
     overlay; ReactionStream shader output simplifies to colored
     dots based on `emojiCounts`).
   - Layout clips (LivePoll variants / LiveQA / LiveQuiz / Leaderboard
     / WordCloud / Survey / AudienceAiPrompt) emit faithful SVG of
     their DOM bar-chart / list / card layouts.
3. **PPTX exporter integration** at
   `packages/export-pptx/src/parts/template-elements.ts`:
   - For each `audience-*` element case, call `renderAudienceExportFrame`
     to get the SVG + dimensions, then embed via a new
     `<p:sp>` containing the SVG-as-bitmap-fallback (or the existing
     `<p:pic>` machinery if PPTX supports inline SVG). For v1, render
     to a base64-encoded PNG-fallback via a deterministic conversion.
     The simplest path: emit a `<p:pic>` with a stub PNG + the SVG
     stashed as a sibling resource. The exact PPTX wiring is
     implementation-specific; **the priority is replacing the
     unconditional loss-flag with a real per-kind output**.

**Strict scope** — SVG export-frame emitters per clip kind + PPTX
exporter wiring. NO video exporter changes (T-440 is the video
exporter; T-472 can add a hook but defer the per-kind plumbing if it
expands scope too much). NO display IAB exporter changes (T-439 is
display; similar deferral). NO native canvas-to-PNG conversion at
export time (could be added in a follow-up). NO new audience clip
kinds (the 11 are frozen).

## Implementation notes

- **SVG output convention**: each export-frame returns a complete
  `<svg viewBox="0 0 W H" xmlns="http://www.w3.org/2000/svg">…</svg>`
  string. NO embedded `<script>` or `<style>` (PPTX consumers reject
  these). Text elements use `font-family="sans-serif"` for
  cross-platform consistency.
- **Per-kind shape**: each `export-frame.ts` exports:
  ```ts
  export function renderLivePollMultipleChoiceExportFrame(
    snapshot: LivePollMultipleChoiceAggregation,
    element: LivePollMultipleChoiceClipElement,
  ): AudienceExportFrame { ... }
  ```
  - Returns SVG + width/height (default 1920×1080 unless element
    has its own dims).
  - Pure. No Date.now, no Math.random.
- **Layout clips (8 of 11)**: emit faithful SVG of bar charts /
  cards / lists. Mirror the static-fallback's DOM layout structure.
- **Canvas clips (3 of 11 — Heatmap, ReactionStream, AudienceAiPrompt
  with asset)**: emit LOW-FIDELITY SVG approximations:
  - Heatmap: `<circle>` per tap with radius proportional to intensity
    + color from the same blue→red colormap used by `rasterize.ts`.
  - ReactionStream: `<circle>` cluster per emoji, colored per the
    fragment shader's emojiColor formula.
  - AudienceAiPrompt: for the final state, a placeholder `<rect>`
    with `data-cache-key` attribute (PPTX consumers can substitute);
    for voting/generation, the layout SVG.
- **PPTX integration**: replace each `case 'audience-*':` in the
  fallthrough switch with a block that:
  1. Calls `renderAudienceExportFrame(snapshotPlaceholder, el)` —
     since template-tier elements don't carry a live snapshot, use
     a synthesized "empty" snapshot per clip kind (`emojiCounts: []`,
     `prompts: []`, etc.) OR look up the provenance's
     `aggregation` if present.
  2. Embeds the SVG into the PPTX `<p:sp>`. PPTX 2007 supports SVG
     via `<a:graphicFrame>` + `<svg:svg>` (modern Office) OR
     base64-encoded PNG fallback. For v1, emit the SVG directly with
     the `<p:custData>` extension carrying the raw SVG markup — the
     exporter can grow PNG rasterization later.
