# T-359c — fix tsx ↔ gsap ESM/CJS interop so the prod-bound parity generator is runnable

**Branch**: `task/T-359c-tsx-gsap-interop`

## Goal

Unblock T-359b. `pnpm tsx scripts/generate-preset-parity-fixture-prod.ts --help`
crashes at module load with `SyntaxError: The requested module 'gsap' does not
provide an export named 'gsap'`, originating at
`packages/runtimes/gsap/dist/index.js:5` (`import { gsap } from "gsap";`,
emitted verbatim from `packages/runtimes/gsap/src/host.tsx`). Plain `node`
loads the same dist cleanly because gsap's `exports."."` map serves
`./index.js` (ESM) which exposes the `gsap` named export. tsx 4.21.0's
esbuild loader strips that named re-export and only `default` survives.

Outcome: T-359b runs end-to-end. No new functionality. No API change.
Likely 1–5 LOC source change + a rebuild + a regression CI step.

**Dependencies**: T-359a (introduced the prod-bound entry point), T-359b
(blocked on this).

## Architectural decisions

### D-T359c-1. Interop pattern — `import gsapDefault from 'gsap'; const { gsap } = gsapDefault;`

Three forms:

- **(a)** `import { gsap } from 'gsap'` — current; broken under tsx.
- **(b)** `import gsapDefault from 'gsap'; const { gsap } = gsapDefault;` —
  default-then-destructure; portable across Node/tsx/esbuild/vite/webpack.
- **(c)** `import * as gsapPkg from 'gsap'; const gsap = gsapPkg.gsap ?? gsapPkg.default?.gsap ?? gsapPkg.default;` —
  defensive triple-fallback; noisy.

Pick **(b)**. Smallest diff. Unconditional. gsap's vendored types
(`gsap/types/index.d.ts`) carry both default and named shapes; (b)
typechecks without an ambient declaration. The `gsap.core.Timeline`
namespace type referenced elsewhere in `host.tsx` continues to resolve.

### D-T359c-2. Regression test — CI shell smoke step, not vitest

Two sites:

- **(a)** vitest test that imports the package under a tsx-equivalent
  harness. Bug is at module-load under tsx's esbuild loader, which doesn't
  run inside vitest workers. Faking it = spawning child `tsx -e ...`,
  which is the shell check below dressed as a vitest test.
- **(b)** CI shell step running `pnpm tsx scripts/generate-preset-parity-fixture-prod.ts --help`
  asserting exit code 0. Five-second check. Direct reproducer.

Pick **(b)**. The bug IS a CLI invocation; the most faithful regression
is the CLI invocation. Add the step to whichever existing workflow file
already runs `pnpm tsx ...` smoke checks; do NOT create a new workflow
file (escalation trigger if no obvious home exists).

### D-T359c-3. NO tsx pin / tsconfig change / package `type` flip

Source-level fix is the smallest blast radius. A tsx upgrade affects
every `pnpm tsx ...` script; a tsconfig change cross-cuts every package;
a package `type` change forces a dist-shape rewrite and breaks every
consumer. If D-T359c-1 doesn't clear the crash, escalate — do NOT
silently pivot to one of these.

### D-T359c-4. Scope is narrow — only the gsap chain

If a second tsx-interop bug surfaces in another runtime package
(`lottie`, `three`, `frame-runtime-bridge`) when T-359b's full mount
path runs, T-359c does NOT fix it. Document in the PR body + open a
tracking issue. Each second-bug fix is its own surgical task so the
audit trail stays clean.

### D-T359c-5. NO committed `dist/` rebuild

`packages/runtimes/gsap/dist/` is gitignored. T-359c rebuilds locally to
verify the safe form lands in emitted output, but does NOT commit
`dist/`. CI's build pipeline regenerates it.

### D-T359c-6. NO end-to-end T-359b run inside this PR

T-359c is surgical. T-359b's operational sign-off (ADR-004 §D5,
operator-driven) stays separate. Bundling lets a renderer-side bug
masquerade as an interop bug. The CI smoke check (D-T359c-2) is
sufficient regression coverage.

### D-T359c-7. Source-level fix vs. bin-shim — pick source-level

A `packages/parity-cli/bin/parity-generate-fixture-prod.js` Node-shim
parallel to `bin/parity.js` would also unblock T-359b (plain Node honors
gsap's `exports` map). T-359c picks the source-level fix because:

- The shim leaves the latent bug in `host.tsx`; every other tsx-driven
  script that imports the gsap runtime stays broken. Future authors
  hit the same crash.
- 1–5 LOC source edit beats new shim file + bin entry + workflow
  plumbing.
- Source fix matches a portability invariant: workspace packages should
  load cleanly under any standards-compliant ESM loader.
- The fix is a strict superset; a bin-shim can still be added later
  if a downstream concern requires it.

If the source fix turns out non-trivial at implementation time (e.g.,
type-position drift the destructure breaks), reconsider; document the
choice in the PR body.
