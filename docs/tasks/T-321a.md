# T-321a — `Grain` primitive carve-out

**Branch**: `task/T-321a-grain-primitive`

## Goal

T-321a is the **first of five primitive carve-outs** from the parent T-321 `TitleSequenceClip` (shipped 2026-05-06, 50th bridge clip). T-321 explicitly listed *optical film grain*, *light leaks*, *atmospheric dust particles*, *photographic double-exposure*, and *3D armillary / hyper-real CGI heads* as out-of-scope and carved them to follow-ups (T-321 "Out of scope" table; D-T321-8 final paragraph: "the schema does NOT accept `grain` / `lightLeak` / `dustParticles` props in v1; if a Reviewer demands them, escalate (the carve-outs are the documented path)"). T-321a fulfills the grain slot. The five carve-outs route as: **T-321a grain** (this task) → T-321b lightLeak → T-321c particles → T-321d photographic-overlay → T-321 ThreeSceneClip integration. Plus a future video-shot kind for T-352 succession-home-video and a `T-321e` curved-text follow-up if needed. T-321a does NOT modify `title-sequence.tsx`; it ships an independent overlay primitive that consumer presets compose alongside `titleSequence` at host-html z-stack time.

T-321a ships a new frame-runtime-bridge clip — `grain` (kebab-case file `grain.tsx`, kebab-case kind `'grain'`) — that renders a deterministic per-pixel film-grain noise overlay computed from `(x, y, frame, seed)` via a closed-form integer hash. Single Zod `object().strict()` schema with `intensity`, `cellSize`, `seed`, and `position` props — NO `discriminatedUnion` and NO style enum (mirroring T-319 `qr-code-bounce` posture). The primitive is mandatory for T-348 `stranger-things-benguiat` per its compass canon line 45 ("Optical film grain is mandatory; clean digital looks wrong") and reusable across Cluster D presets that need grain (T-348 stranger-things, T-351 true-detective, T-353 severance) without coupling grain logic to the titleSequence primitive. v1 ships **luminance-only grain** at a single intensity / cellSize / seed; tinted grain (warm / cool color tints), blue-noise tile variants, and Perlin / simplex noise models defer. With T-321a merged, the bridge's `ALL_BRIDGE_CLIPS` count grows 56 → **57 (T-321a is the 57th bridge clip)**.

## Architectural decisions

### D-T321a-1. Composition model — separate clip kind (`'grain'`), NOT a `TitleSequenceClip` prop

T-321a ships a **separate clip kind** (`'grain'`), NOT an extension of `TitleSequenceClip`'s props. Two options were evaluated; Option A (separate clipKind) is chosen.

- **Option A — separate `'grain'` clipKind**. Standalone overlay clip with its own props (`intensity`, `cellSize`, `seed`, `position`). Composes onto a base render via z-stack ordering at the host-html level (e.g., `titleSequence` at z-1 + `grain` at z-2). Pro: clean composition; testable in isolation; reusable across non-titleSequence clips (T-351 true-detective + T-353 severance + future Cluster D / atmospheric needs); matches the established carve-out pattern (T-371a, T-356a, T-358a all introduced new clipKinds). Adding a new clipKind is a one-line bump in `VALID_CLIP_KINDS`. Cluster D presets that need multiple effects (grain + lightLeak + particles) compose them as separate clips at host-html level — no coupling between effects.
- **Option B — `TitleSequenceClip` prop extension**. Extend T-321's props with optional `grain: { intensity, cellSize, seed }` block. Pro: tight integration; no new clipKind. **Con**: violates T-321's documented out-of-scope table (line 63 explicitly carves grain to "T-321a — `grainOverlay` sister primitive"); concentrates Cluster D effect logic into titleSequence (won't reuse for any other clip — light-leak, particles, photographic-overlay each become a separate prop, ballooning the schema); the schema strict-mode posture forbids opt-in extension without a Reviewer-pivot to L-size; T-321 v1 schema rejects unknown props.

**Decision: Option A.** Matches established carve-out pattern. Decouples atmospheric effects from the titleSequence primitive. Reusable across Cluster D consumers + future presets. The composition model is "host-html z-stack ordering": consumers wire `grain` as a sibling clip in their preset config, not as a nested prop. Reviewer demand for Option B → escalate per CLAUDE.md §6; the sealed posture is Option A.

### D-T321a-2. Approach — single primitive, single Zod object schema, NO enum, NO `discriminatedUnion`

**Decision**: a single `grain` primitive with a single `z.object({ ... }).strict()` schema and no `variant` / `style` / `register` enum. Mirrors T-319 `qr-code-bounce` posture. Diverges from T-371a (which has a sealed `variant` enum) and T-317 / T-318 (which have a sealed `platform` enum + `discriminatedUnion`).

The Orchestrator evaluated three approaches:

- **Approach A (single primitive, single object schema, no enum)** — Single `grain` primitive. ~250–400 LOC. All variation expressed via numeric props (`intensity ∈ [0, 1]`, `cellSize ≥ 1`, `seed ∈ ℤ`). Single render path: hash-based per-pixel noise applied with the configured intensity / cell-size / seed.
- **Approach B (single primitive, sealed `variant` enum — `'fine' | 'coarse' | 'film' | 'digital'`)** — Pre-bake variant-specific defaults table (à la T-371a). Adds dispatch surface for marginal benefit. The 4 hypothetical variants would mostly differ in `cellSize` + `intensity` defaults — those can be defaults, not enum-dispatched arms.
- **Approach C (separate primitives per noise model — `grain-hash`, `grain-blue-noise`, `grain-perlin`)** — Excessive split for v1; rejected outright. Multi-noise-model surfaces in T-321a-noise-quality follow-up if needed.

**Rationale for A**:

1. **YAGNI.** v1 has only one noise model (hash-based per-pixel). Adding an enum is premature optimization.
2. **Numeric-prop axes are clean.** `intensity` + `cellSize` cover the visual register. `seed` covers determinism / variation.
3. **Forward-compatible.** Adding a sealed `model: 'hash' | 'blue-noise' | 'perlin'` enum later is a non-breaking additive extension when v2 introduces alternative noise models.
4. **Smaller LOC budget.** No `discriminatedUnion` → no per-variant render fan-out → no per-variant Zod schema definitions. Single render path with numeric configuration.

Reviewer demand for Approach B / C → escalate; the architectural rule is sealed at A.

### D-T321a-3. Schema shape (Zod) — single object, strict mode

Top-level Zod schema is a single `z.object({ ... }).strict()`. Mirrors T-319 / T-371a Zod discipline (hex-color regex where used, position schema, strict mode).

```ts
const HEX_COLOR_RE = /^#[0-9a-fA-F]{6}$/;

const positionSchema = z
  .object({
    /** Absolute pixel x within the canvas (top-left of grain region). */
    x: z.number(),
    /** Absolute pixel y within the canvas (top-left of grain region). */
    y: z.number(),
    /** Width of the grain region in canvas pixels. */
    width: z.number().positive(),
    /** Height of the grain region in canvas pixels. */
    height: z.number().positive(),
  })
  .strict();

export const grainPropsSchema = z
  .object({
    /** Grain intensity ∈ [0, 1]. 0 = no grain; 1 = full-amplitude white-noise per cell. Default 0.15. */
    intensity: z.number().min(0).max(1).optional(),
    /** Cell size in canvas pixels. 1 = per-pixel noise; higher = blockier grain. Default 1. */
    cellSize: z.number().int().positive().min(1).max(16).optional(),
    /** Integer seed for the hash mixer. Default 0. Different seeds yield decorrelated noise fields. */
    seed: z.number().int().optional(),
    /** Optional region; defaults to the full canvas (1920 × 1080 sealed at runtime). */
    position: positionSchema.optional(),
  })
  .strict();
```

All fields are optional. Strict mode (no extras). The schema is intentionally minimal — every field has a sensible default; the consumer can render `<Grain />` with zero props and get a faithful subtle film-grain layer.

There are NO required fields in v1. Diverges from T-371a (which requires `label`, `variant`, `position`) because grain has no domain-essential content. The default cellSize 1 + intensity 0.15 + seed 0 + full-canvas region produces the canonical Stranger Things-grade subtle grain.

### D-T321a-4. Animation lexicon — frame-derived noise field (no phase enum)

T-321a v1 has NO phase enum. Diverges from T-371a (`'idle' | 'shimmering'`) and T-318 (`'idle' | 'pulsing' | 'followed'`). The noise field is **always animated**: each frame's noise values derive from `(x, y, frame, seed)` via the closed-form hash, so the frame counter shifts the noise field every frame, producing the perceived "moving grain" register.

There is no opt-out "static" mode in v1. If a Reviewer demands a static-grain phase (e.g., `phase: 'still'`), escalate; that's a v2 enhancement once a preset demonstrates the need.

**Noise math** (closed-form integer hash; deterministic):

```
function hash(x: number, y: number, frame: number, seed: number): number {
  // Pure integer mixer (xxhash32-style). All operations bitwise.
  // Inputs are coerced to uint32 via `>>> 0`.
  let h = (seed | 0) >>> 0;
  h = (Math.imul(h ^ x, 374761393) >>> 0);
  h = (Math.imul(h ^ y, 668265263) >>> 0);
  h = (Math.imul(h ^ frame, 1597334677) >>> 0);
  h = ((h ^ (h >>> 13)) >>> 0);
  h = (Math.imul(h, 1274126177) >>> 0);
  h = ((h ^ (h >>> 16)) >>> 0);
  return h & 0xff; // uint8 in [0, 255]
}
```

The hash is a small bitwise mixer with three multiplicative rounds. Pure JS integer arithmetic via `Math.imul` (for 32-bit-safe multiplication) and `>>>` (for unsigned coercion). No `Math.random()`, no `Date.now()`, no `crypto.subtle`. The output is uint8 ∈ [0, 255], converted to a luminance offset via:

```
luminance(x, y, frame, seed, intensity) = ((hash(x, y, frame, seed) / 255) - 0.5) * 2 * intensity * 255
// → signed offset ∈ [-intensity * 255, +intensity * 255] applied to all 3 RGB channels
```

For `cellSize > 1`, the `(x, y)` are first floor-divided by `cellSize` before passing to the hash — producing blocky cells of identical noise value within each cellSize × cellSize tile.

The noise field is fully deterministic. Same `(x, y, frame, seed, intensity, cellSize)` → same byte. Same render at the same frame → byte-identical DOM output (per AC #15).

Reference implementation pseudocode for the per-frame render:

```ts
function renderGrainFrame(width: number, height: number, frame: number, seed: number, intensity: number, cellSize: number): ImageData {
  const data = new Uint8ClampedArray(width * height * 4);
  for (let py = 0; py < height; py++) {
    for (let px = 0; px < width; px++) {
      const cx = Math.floor(px / cellSize);
      const cy = Math.floor(py / cellSize);
      const noise = hash(cx, cy, frame, seed); // 0..255
      const offset = ((noise / 255) - 0.5) * 2 * intensity * 255; // signed
      const i = (py * width + px) * 4;
      data[i] = 128 + offset;     // R
      data[i + 1] = 128 + offset; // G
      data[i + 2] = 128 + offset; // B
      data[i + 3] = Math.round(intensity * 255); // alpha — composite via blend
    }
  }
  return new ImageData(data, width, height);
}
```

The output is rendered as an `<img>` or `<canvas>` element with CSS `mix-blend-mode: overlay` (or similar) for compositing onto the underlying titleSequence render. See D-T321a-5 for the rendering surface choice.

### D-T321a-5. Rendering surface — `<canvas>` with `ImageData` (NOT SVG `<rect>` matrix, NOT `<feTurbulence>`)

T-321a v1 renders the noise field via a single `<canvas>` element with `ImageData` written via `ctx.putImageData(...)`. Diverges from typical bridge clips (which render via `<div>` / `<svg>`) — but the per-pixel noise scale (1920 × 1080 = ~2M pixels) makes any DOM-element-per-pixel approach prohibitively expensive (an `<svg>` with 2M `<rect>` elements is a non-starter).

Three approaches were evaluated:

- **`<canvas>` + `ImageData`**: write the per-pixel noise to a `Uint8ClampedArray`, set on the canvas via `putImageData`. **Chosen.** Pro: O(W × H) write performance; deterministic byte output; trivial parity-golden capture (canvas is part of the DOM); the canvas element itself has stable shape independent of pixel content.
- **SVG `<feTurbulence>` filter**: render an SVG with a single `<rect>` filled via `<feTurbulence>`. **Rejected.** Cons: `<feTurbulence>` parameters (baseFrequency, numOctaves, seed, type) are interpreted at render time by the SVG engine, NOT by deterministic JS code. Different Chrome / WebKit / CDP versions produce subtly different turbulence outputs (verified hazard analogous to T-371a's `backdrop-filter: blur(...)` rejection). Determinism risk is unacceptable for parity goldens.
- **SVG `<rect>` matrix**: ~2M `<rect>` elements with per-rect fill. **Rejected outright.** DOM size; render cost; parity-golden capture latency.

**Decision**: `<canvas>` + `ImageData`. The canvas element is created via React's `useRef` + `useEffect` writing the ImageData. Per CLAUDE.md §3, `useEffect` is acceptable for DOM-write-only side effects (no timers, no `Date.now()`, no `Math.random()`); the effect re-runs on every frame change (which `useCurrentFrame()` triggers via its internal subscription).

**Determinism caveat**: `useEffect` itself is fine, but the effect MUST be a pure function of `(frame, props)` — no `Math.random()`, no `Date.now()`, no `setTimeout`. The hash function (D-T321a-4) is pure integer arithmetic; the effect just writes the hash output to canvas pixels. Same `(frame, props)` → byte-identical pixel data. Document this discipline in a code comment at the top of the component.

For low-resolution test environments (e.g., 100 × 100 fixture canvases used in unit tests), the canvas approach scales linearly. v1 sets a hard upper bound on `position.width × position.height ≤ 1920 × 1080` (sealed via Zod refinement) to prevent runaway compute on degenerate inputs.

### D-T321a-6. Determinism

Frame-derived only. No `Date.now()`, no `Math.random()`, no `crypto.randomUUID()`, no `setTimeout`, no `setInterval`, no `fetch`, no `navigator.*`. The noise field math is closed-form (per D-T321a-4); the hash mixer is pure integer arithmetic via `Math.imul` + `>>>`. The `<canvas>` write happens via `useEffect` (pure-function side effect).

`scripts/check-determinism.ts` globs `packages/runtimes/*/src/clips/**/*.{ts,tsx}` — the new file is automatically in scope. No gate plumbing needed.

Float drift hazards:

- **Noise output**: hash mixer outputs uint32 (via `>>> 0`); luminance offset uses float arithmetic but is `Math.round()`-snapped at the final pixel write. No drift.
- **`Math.imul`** is bit-exact across V8 versions (specified by ECMAScript). Safe.
- **Cell-coordinate division**: `Math.floor(px / cellSize)` is exact when `cellSize` is a positive integer (enforced by Zod `z.number().int().positive()`).

`useEffect` discipline:

- Effect must be deterministic — pure function of `(frame, intensity, cellSize, seed, position)`.
- No timers / no async work / no event listeners inside the effect.
- The canvas write is the only side effect; reading from any DOM API outside the canvas is forbidden.

**Determinism test**: render the same props twice at frame 60; both renders produce byte-identical canvas `ImageData` (catches accidental `Date.now()` / `Math.random()` / float drift). Verified in AC #29.

### D-T321a-9. Geometry — full-canvas default with optional region

Default geometry: full canvas region (consumer-defined via `useVideoConfig().width × .height` at runtime; defaults to 1920 × 1080 when present in the schema as an explicit `position`). The `position?` prop is optional; when absent, the grain fills the entire canvas.

```ts
const position = props.position ?? {
  x: 0,
  y: 0,
  width: useVideoConfig().width,
  height: useVideoConfig().height,
};
```

When `position` is provided, grain renders only within the specified region (e.g., `{ x: 100, y: 200, width: 800, height: 600 }`).

## Implementer's notes

1. **Read `qr-code-bounce.tsx` first** before writing a line. It is the primary template for the single-object-Zod posture (no `discriminatedUnion`), the closed-form deterministic-math discipline, and the integer-pixel rendering pattern. T-321a mirrors its file shape, swapping the bounce-physics math for closed-form integer-hash noise. LOC yardstick: leaner than qr-code-bounce (~250–400 LOC vs. ~400–500).
2. **Read `title-sequence.tsx` second** for the parent-primitive lineage anchor. T-321a does NOT modify it; read only the file header + the "Out of scope" portion of `docs/tasks/T-321.md` to understand the carve-out posture.
3. **Read `link-sticker.tsx` third** for the most recent carve-out template. T-321a mirrors its file structure + Zod-discipline + lowercase-changeset-filename convention.
4. **Schema first.** D-T321a-3 / D-T321a-4 (math) all affect schema shape. Conservative defaults: `intensity: 0.15`, `cellSize: 1`, `seed: 0`. All fields optional; full-canvas when `position` absent.
5. **Single-object + no-enum discipline.** Use `z.object({ ... }).strict()` directly with no enums. NO `z.discriminatedUnion(...)`. Mirror `qr-code-bounce.tsx`'s strict-mode posture without any enum overlay.
6. **Hash mixer**. Implement helper `hash(x: number, y: number, frame: number, seed: number): number` per D-T321a-4 using `Math.imul` and `>>>` only. Pure function; deterministic; bit-exact across V8. Test it directly in unit tests AC #29 and per Test plan items 8–10.
7. **Cell-based noise**. When `cellSize > 1`, floor-divide `(px, py)` by `cellSize` before passing to the hash. All pixels within a cellSize × cellSize tile share the same noise byte. This is the "blockier grain" register (Stranger Things canonical is `cellSize: 1` for the finest grain; coarser `cellSize: 2`–`4` registers are reserved for true-detective / severance use cases).
8. **Canvas rendering** (per D-T321a-5). Use a single `<canvas>` element with `useRef` + `useEffect` writing `ImageData` via `ctx.putImageData(...)`. The effect re-runs on every frame change (driven by `useCurrentFrame()` updating). The effect MUST be a pure function of `(frame, props)` — no timers, no async, no `Math.random()`, no `Date.now()`.
9. **Integer-pixel rendering**. The luminance offset uses float math; apply `Math.round()` at the final pixel-write step (writing to the `Uint8ClampedArray`). The `Uint8ClampedArray` itself does the clamping to [0, 255], but `Math.round()` is still required to avoid float-drift hazards in subsequent diffs.
10. **Region clipping**. The canvas is sized to `position.width × position.height`; pixels outside the region are NOT rendered (the canvas element itself only covers the region). Position the canvas via `style={{ position: 'absolute', left: position.x, top: position.y, width: position.width, height: position.height }}`.
11. **Empty theme slots**. Register `themeSlots: {}` (empty object) per D-T321a-8. NO `fontRequirements`. The `defineFrameClip` API accepts both as optional / empty.
12. **Determinism is sacred.** No `Date.now()`, no `Math.random()`, no `crypto.randomUUID()`, no `setTimeout` / `setInterval`, no `addEventListener`, no `fetch`. 23. **Hash collision awareness**. The hash mixer is a small bitwise function; collisions (different inputs → same uint8 output) are statistically expected (~1/256 of input pairs collide on output). Tests for "different frame produces different output" (item 9) must use a known-distinct pair, not a random pair. Document this in the test file.
24. **Performance note**. At 1920 × 1080 = ~2M pixels per frame, the inner render loop runs 2M iterations per frame. JS bitwise ops are fast (~5–10 ns each); 2M × 10 ns ≈ 20 ms per frame, which is acceptable for offline-render parity but may stress live-preview at 24 fps. v2 may swap to a Web Worker or pre-rendered tile cache; v1 ships the simplest deterministic path.
