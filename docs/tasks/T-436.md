# T-436 — TTS→captions bypass-Whisper integration

**Branch**: `task/T-436-tts-captions-bypass`

## Goal

Wire the just-merged Phase 14 β TTS adapters (T-426 Kokoro + T-427 Fish
Speech) so synthesized audio's word-timestamps populate
`CaptionSegment[]` **directly**, bypassing the Whisper call on
TTS-provenanced audio. Whisper costs ~$0.006/min; eliminating it on
AI-generated narration saves ~30 % on the captions cost line for
TTS-bearing decks.

The bypass is **provider-aware**: it triggers only when the audio's
recorded provenance points at a TTS adapter whose
`TtsCapabilityDescriptor.emitsWordTimestamps === true` and the supplied
`TtsResult.wordTimestamps` is structurally valid. Live-recorded,
imported, or generated-without-timestamps audio continues through the
existing Whisper path unchanged.

## Function

1. Phase 14 β TTS adapters (Kokoro, Fish Speech) emit
   `TtsResult.wordTimestamps: { word, startS, endS }[]` whenever the
   adapter descriptor advertises `emitsWordTimestamps: true` — both
   reference adapters declare this.
2. A new entry point `transcribeAndPackWithTtsBypass()` accepts an
   optional `ttsProvenance` argument carrying the produced audio's
   provenance + the adapter's own `wordTimestamps`. When the provenance
   names a whitelisted TTS provider AND the timestamps validate, the
   bypass skips both the cache lookup and the `TranscriptionProvider`
   call: it converts seconds→ms, builds a synthetic `Transcript`, and
   feeds it straight to `packWords()`. The pipeline result carries
   `cacheHit: false` and a new `viaTtsBypass: true` marker (consumers
   inspect this to render "Auto-generated from TTS provider X" UX).
3. Fallback is silent: if the provenance is non-whitelist, or
   `wordTimestamps` is absent/malformed, the path falls through to the
   existing Whisper-backed `transcribeAndPack()` call without raising.
4. The existing `transcribeAndPack()` entry point is **untouched**;
   bypass is opt-in via the new wrapper.

## Whitelist

Initial whitelist of TTS adapter ids that emit Whisper-quality
word-timestamps:

```
['kokoro', 'fish-speech']
```

These match the two reference adapter descriptors merged in T-426 +
T-427. Adding a third whitelist entry is a one-line code change inside
`tts-bypass.ts` paired with a captions skill update.

The whitelist is intentionally narrower than "every adapter that
declares `emitsWordTimestamps`": the host must vouch for each adapter's
timestamp quality before captions trust them blindly. A future task
(call site: ADR-008 §D5 follow-up) may promote the whitelist into a
runtime registry consulted via the adapter registry, but T-436 ships
the static-array form for inspectability.

## Architectural seals

- **Pure addition**: the existing Whisper code path is byte-for-byte
  identical. The bypass is a new wrapper layered above
  `transcribeAndPack()`.
- **Provider-aware**: the whitelist check rejects unknown providers
  even when `wordTimestamps` look valid — the host's trust signal is
  the provider id, not the data shape.
- **Fail-soft fallback**: malformed timestamps fall through to Whisper.
  The bypass never throws on data-shape mismatch.
- **No new runtime dep**: `@stageflip/captions` does not import from
  `@stageflip/tts-kokoro`, `@stageflip/tts-fish-speech`, or
  `@stageflip/asset-gen-contract`. The bypass consumes only the
  structural shape of `wordTimestamps` (a positional `{ word,
  startS, endS }` array) via a locally-mirrored type. The adapter
  packages remain leaf dependencies; the captions package remains
  consumable from the editor shell without dragging in TTS adapter
  bundles.
- **CaptionSegment immutability**: the `CaptionSegment` schema
  (`{startMs, endMs, text}` strict) is unchanged. Bypass provenance
  metadata is reported on the `CaptionPipelineResult` wrapper, not on
  individual segments.

## §13 statement

**Not a structural extension.** T-436 adds a new code path in the
captions package that consumes the existing
`MediaProvenance` + `TtsResult.wordTimestamps` shapes from prior
shipped specs. No new schema fields, no new RIR elements, no new
runtime kinds, no new compositing modes. Render verification N/A.
Unit-test coverage of the bypass + fallback paths is sufficient per
CLAUDE.md §13.

## Test scenarios

`packages/captions/src/tts-bypass.test.ts`:

1. `extractTtsBypassWords` returns words when provenance is whitelist + timestamps valid (kokoro).
2. Returns `undefined` when provenance kind is not `'tts'`.
3. Returns `undefined` when provenance provider is not whitelisted.
4. Returns `undefined` when `wordTimestamps` is absent.
5. Returns `undefined` when `wordTimestamps` is malformed (negative time, end ≤ start, non-string word).
6. Seconds → ms conversion is integer-floored deterministically.
7. Returns `undefined` on empty word list (let Whisper run; bypass not applicable).
8. Whitelist includes both `'kokoro'` and `'fish-speech'`.

`packages/captions/src/transcribe.test.ts` (added):

9. `transcribeAndPackWithTtsBypass` with kokoro provenance → bypass triggers; provider.transcribe is NOT called; `viaTtsBypass: true`.
10. Same with fish-speech provenance → bypass triggers.
11. Provenance from non-whitelist provider → falls through to provider; `viaTtsBypass` absent.
12. Whitelist provider but missing `wordTimestamps` → falls through to provider; `viaTtsBypass` absent.
