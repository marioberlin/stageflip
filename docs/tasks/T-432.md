# T-432 — `@stageflip/music-acestep` (ACE-Step music adapter; stub-mode v1)

**Branch**: `task/T-432-music-acestep`

## Goal

Ship the **seventh reference adapter** in the Phase 14 β sequence
(T-426..T-434): `@stageflip/music-acestep`. Wraps the ACE-Step music
generation model (community MIT; 5-minute track in <10s on RTX 3090;
edge-deployable on GPU; state-of-the-art per benchmarks beating Suno
v4.5) behind the `MusicGenerationProvider` interface from T-419,
declares an `AdapterDescriptor` per T-418, and exposes a stable shape
that the asset-generation handler bundle (T-423) + capability router
(T-425) consume.

T-432 is the **first `music-gen` modality adapter** — new modality
opened. It clears the `pnpm check-asset-licenses` gate for the music
branch of the per-modality whitelist (ADR-008 §D13 line 655:
`music-gen` admits `apache-2.0`, `mit`, `cc-by`, `proprietary-byo`,
`proprietary-vendored`). MIT is already in the whitelist on `main` —
no whitelist extension is required.

T-432 follows the **same structural template** as T-426 (Kokoro TTS):
in-process + permissive-license + edge-deployable + stub-mode posture.
Both adapters declare `sandbox.kind: 'in-process'` (ACE-Step ONNX is
in-process-runnable on supported hardware; Kokoro likewise sub-100MB
checkpoint).

T-432 ships in **stub mode**: the `generate()` body emits a
deterministic silent-WAV byte payload at the declared sample rate +
returns a shaped `MusicGenResult`. Production wire-up (ACE-Step
checkpoint → ONNX runtime → real audio) is gated on a follow-up task
(T-432a) to keep this PR's blast radius tight + let downstream
consumers (T-436 captions/music sync; bundle T-438) develop against
the deterministic stub.

T-432 is M-sized: one new package, ~250–400 LOC across 3 src modules
(descriptor / provider / stub-audio) + matched tests, ~250–400 lines of
spec, no schema / parity / clip / preset changes.

## Out of scope

| Item | Why deferred |
|---|---|
| **Production wire-up to a real ACE-Step library** (ACE-Step npm package — if it exists; ONNX runtime over a pinned checkpoint; Python sidecar) | The ACE-Step ecosystem in May 2026 is fresh — checkpoint release stability, ONNX export quality, license-clean redistribution, and edge-runtime compatibility (Cloudflare Workers / Vercel Edge) need a separate audit. Deferring to **T-432a** keeps T-432's blast radius tight + lets downstream consumers (T-436 captions/music sync; T-438 bundle marketplace) develop against the deterministic stub. The `descriptor` shape declared here is the contract the production wire-up MUST match; T-432a only swaps the body, never the shape. |
| **MP3 / FLAC output** | Stub-mode declares `outputFormats: ['wav', 'mp3']` matching the spec but the synthesizer ONLY emits WAV in stub mode (calling with `outputFormat: 'mp3'` throws). MP3 emission is gated on production wire-up + an encoder dependency audit (lame / fdk-aac license). |
| **Structure-controllable generation** (`intro/verse/chorus/bridge/outro` directives) | `descriptor.capability` declares `supportsStructure: true` as a differentiator-surface flag (the agent UI surfaces; the routing layer reads), but the v1 stub-mode body does NOT interpret structure directives — the `MusicGenCall` shape from T-419 carries `prompt` + `genre` + `durationS` + `outputFormat` + `seed`; structure is part of the prompt envelope. Production wire-up may add a typed structure surface in a follow-up. |
| **Attribution-required output** | `descriptor.capability.outputLicense = 'permissive'` — ACE-Step's MIT-licensed model emits commercially-usable output with no attribution. `MusicGenResult.attribution` is absent. The `'attribution-required'` branch is exercised by a future YuE adapter (T-433/T-434 territory). |
| **Adapter-side caching** | `generate()` derives the canonical `cacheKey` per ADR-008 §D1 + returns it in `MusicGenResult.cacheKey`, but the adapter does NOT consult `AssetCacheStore` itself. The orchestrator (handler bundle T-423) is the cache owner. |
| **Telemetry / cost-metering** | Descriptor declares `costPerCall.usd = 0` + `latencyMs.{p50,p95}` hints; no per-call telemetry emission. Telemetry lives at the orchestrator boundary. |
| **AssetStorage upload** | `generate()` returns `url` as an inline `data:` URI for the silent-WAV stub. Production wire-up uploads to an `AssetStorage` adapter + returns the storage URL; the shape stays identical. |
| **Capability-validator hook into `CapabilityDescriptorParser`** | T-419 ships `validateMusicGenCapability`; T-432 declares a capability that satisfies it but does NOT register the validator into a host-shell parser (host-shell wiring is out of scope). Tests assert the strict descriptor subset passes `validateMusicGenCapability` directly. |
| **Schema / parity / clip / preset / parity-golden changes** | All untouched. |

## Acceptance criteria

1. New package `@stageflip/music-acestep` at `packages/music-acestep/`
   with `package.json`, `tsconfig.json` (matches the
   `@stageflip/tts-kokoro` + `@stageflip/video-runway` shape: no
   per-package `tsup.config.ts` / `vitest.config.ts` — defaults via
   package.json scripts suffice).
2. Public barrel `src/index.ts` exports:
   - `aceStepDescriptor` (the canonical `AdapterDescriptor`),
   - `descriptor` (alias of `aceStepDescriptor`; named export the
     T-422 discovery walker reads),
   - `aceStepMusicGenCapability` (strict `MusicGenCapabilityDescriptor`
     subset that passes `validateMusicGenCapability`),
   - `AceStepMusicProvider` (the class implementing
     `MusicGenerationProvider`),
   - `AceStepProviderMode` (`'stub' | 'production'`),
   - `AceStepMusicProviderOptions`,
   - `NotYetImplementedError` (thrown by `production` mode),
   - `generateSilentWavDataUri` (re-exported from `./stub-audio.js`),
   - `ACE_STEP_GENRES`, `ACE_STEP_MAX_DURATION_S`,
     `ACE_STEP_SAMPLE_RATE_HZ`.
3. **Descriptor shape** (verbatim from ADR-007 §D1 + ADR-008 §D6):
   ```ts
   {
     id: 'ace-step',
     modality: { kind: 'music-gen' },
     capability: {
       // Strict MusicGenCapabilityDescriptor subset:
       genres: ['electronic', 'pop', 'rock', 'classical', 'hip-hop', 'jazz', 'ambient', 'folk'],
       maxDurationS: 300,             // 5-minute track
       outputFormats: ['wav', 'mp3'],
       outputLicense: 'permissive',   // MIT model → commercial OK, no attribution
       // T-424 catalog-summary fields (read by skills-sync's
       // capabilitySummary helper):
       maxDurationSec: 300,
       sampleRateHz: 44100,
       // Differentiator-surface fields (descriptive; agent UI surfaces;
       // routing layer does NOT filter on them in v1):
       supportsStructure: true,
       qualityHint: 'high',
     },
     license: { kind: 'mit' },
     sandbox: { kind: 'in-process' },
     costPerCall: { usd: 0 },
     latencyMs: { p50: 8_000, p95: 10_000 },   // "5-min track in <10s" claim
   }
   ```
   `maxDurationSec` + `sampleRateHz` are extra capability fields the
   T-424 catalog generator reads; the strict T-419
   `musicGenCapabilityDescriptorSchema` is `.strict()` and would
   reject them — so the descriptor uses a capability shape that
   passes the T-418 envelope's `z.record(z.unknown())` but tests
   pass the validator a SUBSET stripped of the extras.
4. **`AceStepMusicProvider` class** implements
   `MusicGenerationProvider`:
   - Constructor takes `{ mode: AceStepProviderMode }` (defaults to
     `'stub'`).
   - `id` / `modality` / `capability` / `license` / `sandbox` /
     `costPerCall` / `latencyMs` are passed through from
     `aceStepDescriptor` (so the class instance is itself a valid
     `MusicGenerationProvider`).
   - `generate(call: MusicGenCall): Promise<MusicGenResult>`:
     - Validates `call.prompt` is non-empty (after trim); throws
       `Error('AceStepMusicProvider.generate: prompt must be non-empty')`.
     - Validates `call.outputFormat === 'wav'` (only stub-supported
       format in v1; `'mp3'` is declared on the descriptor but the
       stub body throws); throws on mismatch.
     - Validates `call.durationS > 0` AND `call.durationS <= 300`;
       throws on out-of-range.
     - Validates `call.genre`, when present, is in
       `aceStepDescriptor.capability.genres`; throws on unknown genre
       (genre is optional — absent genre passes).
     - In `'stub'` mode: synthesizes a deterministic silent-WAV byte
       payload (`generateSilentWavDataUri(call.durationS, 44100)`),
       derives a canonical `cacheKey` via
       `deriveCacheKey({ modality: 'music-gen', model: 'ace-step',
       prompt: call.prompt, params: {outputFormat, durationS, genre?},
       seed? })`, emits `cacheKeyString(key)`, returns
       `{ cacheKey, url, durationS }`. `attribution` is absent
       (`outputLicense === 'permissive'`).
       `url` = `data:audio/wav;base64,<base64-of-silent-wav>`.
     - In `'production'` mode: throws `NotYetImplementedError(
       'AceStepMusicProvider.generate: production wire-up deferred to
       T-432a (ACE-Step ONNX runtime audit pending)')`.
5. **`generateSilentWavDataUri(durationS, sampleRate)`** in
   `src/stub-audio.ts`:
   - Pure function. No `Date`, no `Math.random`, no `fetch`, no timers.
   - Returns a `data:audio/wav;base64,...` URI for a mono 16-bit PCM
     WAV file with the specified duration + sample rate, where every
     PCM sample is `0` (silent).
   - WAV header is built per the standard `RIFF/WAVE/fmt /data` chunk
     layout (44 bytes; 16-bit mono PCM). Tests assert:
     (a) the URI starts with `data:audio/wav;base64,`;
     (b) the decoded bytes start with `RIFF` (offset 0..3) +
     `WAVE` (offset 8..11) + `fmt ` (offset 12..15);
     (c) the sample-rate field at offset 24..27 (little-endian
     uint32) equals `sampleRate`;
     (d) the data-chunk size at offset 40..43 equals
     `Math.floor(durationS * sampleRate) * 2` (16-bit mono);
     (e) all PCM samples (offset 44..end) are zero;
     (f) two calls with identical inputs return byte-identical URIs
     (determinism).
6. **`NotYetImplementedError`** is a regular `class extends Error`
   with `name = 'NotYetImplementedError'`. Exported from the barrel.
7. Tests cover (≥85% coverage on changed files):
   - **Descriptor**: passes `parseAdapterDescriptor()`; `id === 'ace-step'`;
     `modality.kind === 'music-gen'`; `license.kind === 'mit'`;
     `sandbox.kind === 'in-process'`; capability subset passes
     `validateMusicGenCapability()`; declared genres include the
     8 ACE-Step canonical genres; `maxDurationS === 300`;
     `outputLicense === 'permissive'`; `supportsStructure === true`.
   - **Stub-audio**: see AC #5 (a)..(f).
   - **Provider**:
     - `mode: 'stub'` constructor returns a working provider; `id`,
       `modality`, `capability`, `license`, `sandbox` all match
       `aceStepDescriptor`.
     - `generate()` returns a `MusicGenResult` whose `url` starts with
       `data:audio/wav;base64,`, `cacheKey` matches
       `music-gen/<64-hex>` shape, `durationS` matches the input.
     - `attribution` is absent (permissive output license).
     - Two `generate()` calls with identical input → identical
       `cacheKey` (determinism).
     - `generate()` with empty / whitespace-only prompt throws.
     - `generate()` with non-`'wav'` `outputFormat` throws.
     - `generate()` with `durationS > 300` throws.
     - `generate()` with `durationS <= 0` throws.
     - `generate()` with unknown `genre` throws.
     - `generate()` with absent `genre` succeeds.
     - Different prompts / durations / genres / seeds produce different

## Stub-mode vs production-mode contract

The `AceStepProviderMode` discriminator gates the `generate()` body
behavior **only**. Every other surface (descriptor, capability,
genre list, validation, error throwing, cache-key derivation) is
identical between modes. The production wire-up (T-432a) MUST:

1. Keep `aceStepDescriptor` byte-identical (no new genres added to
   v1; genre expansion lands in T-432b at earliest).
2. Replace the `generate()` `mode === 'production'` branch with a
   real ACE-Step library call (ACE-Step npm package — pending license
   + edge-runtime audit — or ONNX runtime over a pinned model
   checkpoint).
3. Keep the input validation paths (empty prompt / wrong format /
   out-of-range duration / unknown genre → throw) byte-identical.
4. Keep the cache-key derivation byte-identical (so cached results
   from the stub-mode era + production-mode era share the same
   keyspace; the orchestrator's `AssetCacheStore` does not need a
   per-mode bucket).
5. NOT widen the `MusicGenResult` shape (no new fields; `attribution`
   remains absent for permissive output license).

Anything in the production wire-up that conflicts with this contract
is a spec change — file an ADR.
