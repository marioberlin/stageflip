# T-356a — `news-ticker-bar` runtime-clip primitive (horizontal scrolling chyron of symbol+price+delta+arrow chips)

**Branch**: `task/T-356a-news-ticker-bar-primitive`

## Goal

Ship a small generic frame-runtime-bridge clip — `news-ticker-bar` — that renders a horizontal band of N (1..24) ticker entries (symbol + price + delta + ▲/▼/▬ arrow) translating left at a frame-derived offset, looping continuously. The primitive is the missing piece that blocked T-356 (`bloomberg-ticker`): the Implementer surveyed every existing clip in `packages/runtimes/frame-runtime-bridge/src/clips/` and confirmed none carries the visual register:

- `stock-ticker` is a **vertical candlestick chart** with header text — wrong geometry; no scroll knob, no chip-row composition.
- `outcome-row` (T-358a) is a static row of fixed chips — no scroll, no symbol/price/delta tri-token shape.
- `lower-third` / `subtitle-overlay` are static text overlays — no entries array, no X-axis animation.
- All other primitives (dashboards, grids, single-content overlays, chart family) carry the wrong geometry or impose props (axes, scales, labels) the chyron doesn't have.

A `grep -iE 'ticker|chyron|news|scroll|marquee'` across the clips directory returned only `stock-ticker.{test.tsx,tsx}` — no fitting primitive exists.

T-356 surfaces the gap first, but the same primitive is needed by Cluster A breaking-news tickers (`fox-news-alert`, possible `cnn-breaking` companions), Cluster B's `espn-bottomline-flipper` (T-339a), sports score crawls, and crypto / multi-asset financial dashboards. Building `news-ticker-bar` once as a reusable generic amortizes the cost across multiple presets; per-cluster prop builders (Bloomberg green/red, ESPN team palette, etc.) live in `parity-cli` resolver shims, not in this primitive. Same pattern as T-358 → T-358a → T-358-retry.

T-356a is **S-sized**: ~120–160 LOC component + ~100–140 LOC tests + barrel + ~4 LOC catalog/manifest entries + changeset. It does NOT touch T-356's preset markdown, the parity resolver entry, or the parity goldens — those land in the T-356-retry PR after this primitive merges.

## Architectural decisions

### D-T356a-1. Generic `news-ticker-bar` vs preset-specific `bloomberg-ticker-bar`

T-356a ships a **generic** primitive, NOT Bloomberg-specific `bloomberg-ticker-bar`. Rationale:

- "Horizontal band of N chips translating left at a frame-derived offset" recurs across ≥4 cluster A/B/E families: Bloomberg market chyrons (T-356), ESPN BottomLine sports score crawls (T-339a), CNN/Fox breaking-news lower-band, crypto / multi-asset dashboards. A Bloomberg-specific clip would re-implement per cluster.
- Cluster-specific semantics (palette, symbol rebranding) belong in the `parity-cli` resolver's `buildProps` shim, not in the runtime primitive. The primitive accepts pre-resolved `{ symbol, price, delta, direction }` entries + explicit color/geometry props.
- Genericity cost is zero (~120–160 LOC). Reviewer should reject if `NewsTickerBar` grows cluster knowledge (e.g., `palette: 'bloomberg' | 'espn'` enums).

Reviewer demand for Bloomberg-specific naming → escalate per CLAUDE.md §6.

### D-T356a-2. Maximum entries count — 24

`entries` array bounded `1..24`. Covers a long NFL-Sunday-slate sports crawl (~16 games + highlights), a top-20 crypto dashboard, or a comprehensive market-open chyron. At 1920 px canvas / ~200 px chip / 60 px gap, ~7–8 chips are visible at once with the rest cycling — 24 entries ≈ 3 visible revolutions per scroll cycle. Below the cap the schema is permissive (uniform spacing). One-line bump if a future preset needs 32+.

### D-T356a-3. Direction icons — Unicode glyphs `▲ ▼ ▬`

Three direction glyphs as plain Unicode codepoints rendered inline:

- `up` → `▲` (BLACK UP-POINTING TRIANGLE, U+25B2)
- `down` → `▼` (BLACK DOWN-POINTING TRIANGLE, U+25BC)
- `flat` → `▬` (BLACK RECTANGLE, U+25AC)

No SVG paths (keeps LOC small), no font-icon dependency (no FontAwesome / Material Icons / custom icon fonts), deterministic across renderers (Chromium / Firefox / Safari render identical given the same font; cross-renderer parity is a FontManager concern). If `▬` reads as too visually heavy for "flat", alternatives `–` (U+2013) or `•` (U+2022) — Implementer picks + documents.

### D-T356a-4. Scroll behavior — true continuous loop (modulo row width)

Chips translate left at `scrollSpeed` px/sec, wrapping back to the right edge after the row has exited left. Bloomberg / ESPN BottomLine / CNN crawl all loop; a one-shot exit would not match the broadcast convention.

```ts
// Pure derivation from frame + fps + scrollSpeed + row width.
// rowWidth = entries.length * (chipWidth + chipGap)
const offsetPxRaw = (frame * scrollSpeed) / fps;
const offsetPx = offsetPxRaw % rowWidth;     // wrap into [0, rowWidth)
const translateX = -offsetPx;                // negative = leftward
```

For seamless wrap, the row renders **twice** (two adjacent copies of `entries`) so that as the first copy exits left the second is already in view; once `offsetPx` exceeds `rowWidth` the modulo resets cleanly. Standard "doubled-row marquee" pattern, fully deterministic.

Recommendation: **fixed uniform `chipWidth: number` prop, default 220 px** — keeps the math simple and the determinism story watertight (no per-chip text-measurement heuristics that drift across renderers). Implementer may choose measured widths if they document the determinism guarantee; the wraparound-at-large-frame test validates either path.

### D-T356a-5. Direction-driven color (NOT per-chip color override)

Each entry's color is driven by its `direction` field:

- `'up'` → `upColor` (theme slot `palette/positive` → `palette/accent` fallback)
- `'down'` → `downColor` (theme slot `palette/negative` → `palette/accent` fallback)
- `'flat'` → `flatColor` (theme slot `palette/foreground`)

NO per-entry `color` field. Keeps entries shape simple (three strings + one enum); cluster owners parameterize the up/down/flat palette at the clip level (Bloomberg = green/red, ESPN = team colors). If a future preset needs per-chip override (e.g., sports ticker with home-team coloring), that's a v2 enhancement (additive optional `color` field winning over direction). Out of v1 envelope.

### D-T356a-6. Explicit prop colors with theme-slot fallback

Mirrors `outcome-row` (T-358a D-T358a-4): every color prop is **optional**; theme slot fills in when absent. Cluster owners pass explicit hex (Bloomberg's `#00D26A` / `#FF3C3C` / `#0A0A0A`) or rely on the theme.

```ts
themeSlots: {
  background: { kind: 'palette', role: 'background' },
  foreground: { kind: 'palette', role: 'foreground' },
  upColor: { kind: 'palette', role: 'positive' },
  downColor: { kind: 'palette', role: 'negative' },
  flatColor: { kind: 'palette', role: 'foreground' },
}
```

If `palette/positive` or `palette/negative` aren't defined on the active theme, the bridge's slot resolution falls back per T-131a rules (Implementer verifies; if rules differ from spec, document + adjust — likely `palette/accent`).

### D-T356a-7. Font posture — system-ui fallback; no hard-bound font

The primitive does NOT hard-bind a font family. Presets declare `preferredFont` / `fallbackFont` in frontmatter; the FontManager preloads + applies at render time. The component uses `font-family: 'system-ui, -apple-system, BlinkMacSystemFont, sans-serif'`.

Hard-binding `IBM Plex Mono` (T-356's fallback) would couple to one preset; a Cluster A breaking-news preset might pin Helvetica Neue Bold; a sports score crawl might pin Roboto Condensed. Presets own font posture; primitives stay font-neutral. Document in TSDoc.

### D-T356a-8. NO T-356 follow-up changes in this PR

T-356a is **surgical**. Does NOT touch `packages/parity-cli/src/generate-fixture.ts` (no `newsTicker` resolver entry, no `BLOOMBERG_CANONICAL_SNAPSHOT`), `skills/stageflip/presets/data/bloomberg-ticker.md` (no promotion), or `parity-fixtures/data/bloomberg-ticker/**` (no goldens). T-356-retry picks those up post-merge. Pattern: T-358a → T-358-retry; T-359c → T-359b. Single-concern PR keeps the Reviewer's job clean and lets the primitive ship under multi-cluster reusability merit, not as scaffolding for one preset.

### D-T356a-9. Determinism gate coverage

`scripts/check-determinism.ts` line 51 globs `packages/runtimes/*/src/clips/**/*.{ts,tsx}` — the new file is automatically in scope. No gate plumbing needed. The clip uses only `interpolate` + `useCurrentFrame` + `useVideoConfig`; none on the deny-list. If the new path somehow falls outside the glob, escalate — the determinism gate must cover this clip.

## Acceptance criteria

### Primitive shape (AC #1–#7)

1. `packages/runtimes/frame-runtime-bridge/src/clips/news-ticker-bar.tsx` exists with file header naming the file + purpose.

## Escalation triggers (CLAUDE.md §6)

- The primitive's component code grows beyond ~200 LOC (kicks the task to M-size; signals the schema or scroll math is over-scoped — push back with a narrower v1).
- The continuous-loop scroll math produces non-deterministic output (e.g., sub-pixel float drift across frames; chip positions shift between consecutive renders at the same frame). Root-cause; do not silence. May require a sub-pixel snap discipline (e.g., `Math.round(translateX)`).
- The theme-slot integration breaks an existing `frame-runtime-bridge` test (a test asserts the slot map shape and the new entry collides; or `palette/positive` is not a recognized role on the bridge's theme resolution).
- `pnpm check-determinism` fails on the new clip path (unexpected — the file is in glob scope and the clip uses only safe primitives; if it fails, root-cause, do not silence).
- The skill-drift gate requires schema-source-truth changes outside `news-ticker-bar` scope (e.g., the catalog table format changed since the spec was drafted; the manifest schema added a required field).
- Reviewer demands a Bloomberg-specific name (`bloomberg-ticker-bar`) instead of generic `news-ticker-bar` — escalate; the multi-cluster reuse argument is the spec's anchor and renaming would forfeit it.
- A `KNOWN_KINDS` table or equivalent gate has appeared in `packages/cdp-host-bundle/**` since spec-time and the new clip can't be added in S-size.
- The doubled-row marquee pattern produces visible seams (chips appearing to "jump" at the modulo reset point) — root-cause; may require a different wrap strategy (e.g., a triple-row buffer or a pixel-precise per-chip wrap). If unresolved within S-size, escalate.
