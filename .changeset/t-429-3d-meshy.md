T-429 — New package `@stageflip/3d-meshy` shipping the **fourth reference adapter** in the Phase 14 β sequence (T-426..T-434), the **second 3D adapter**, and the **second `proprietary-byo` license posture** to clear the `pnpm check-asset-licenses` gate (Tripo3D was the first via T-428). Wraps the Meshy commercial AI 3D model generator (props + environment + vehicles + hard-surface objects; triangle-soup topology; **no** auto-rigging; GLB output; ~1 min per asset; tenant-supplied API credentials) behind the `ThreeDAssetProvider` interface from T-419 and declares an `AdapterDescriptor` per T-418. Public surface: `meshyDescriptor` (and its `descriptor` alias for the T-422 `check-asset-licenses` discovery walker), `meshyThreeDCapability`, `MeshyThreeDProvider`, `MeshyProviderMode` (`'stub' | 'production'`), `MeshyThreeDProviderOptions`, `NotYetImplementedError`, `generateStubGlbDataUri`, plus the `MESHY_MAX_VERTICES` / `MESHY_BASE_URL_ENV_VAR` constants. The descriptor declares `outputFormats: ['glb']`, `topology: 'triangle-soup'`, `supportsAutoRigging: false`, `maxVertices: 30_000` (the strict T-419 capability subset) plus the catalog-summary fields `formats: ['glb']` / `maxPolyCount: 30_000` the T-424 generator reads. License `proprietary-byo` clears the per-modality whitelist (ADR-008 §D13 line 657: `three-d` admits `apache-2.0`, `mit`, `proprietary-byo`, `proprietary-vendored`). Sandbox `{ kind: 'remote-service', baseUrlEnvVar: 'MESHY_API_BASE_URL' }` — that env var is the production wire-up's credentials anchor (T-429a; the stub mode never reads it). `costPerCall.usd: 0.2` (paid; tenant pays Meshy); `latencyMs: { p50: 60_000, p95: 90_000 }` (batch tier per skills-sync's `latencyTier` bucketing; ~1 min typical). Ships in **stub mode**: `generate()` validates the prompt (empty / whitespace-only → throw), then emits a deterministic minimal valid GLB `data:model/gltf-binary;base64,...` URI built by a pure `generateStubGlbDataUri()` (12-byte glTF 2.0 header + JSON chunk + BIN chunk; regular icosahedron with 12 vertices and 20 triangular faces via 60 indices; **no** skin / joints / weights — capability declares no rigging and triangle-soup topology is rigging-ineligible per ADR-008 §D6 regardless), derives the canonical cache key per ADR-008 §D1 via `deriveCacheKey()` from `@stageflip/asset-cache` (model `'meshy:prop-environment'`; params include `outputFormat`, `topology`, `rig: false` FORCED — different prompts / seeds produce different cache keys; the `rig` caller-flag is ignored at the cache-key layer because the capability does not support rigging; the GLB bytes are byte-identical for ANY input so cache-key roundtrip tests are trivially satisfied), and returns `{ cacheKey, url, vertices: 12, rigged: false }`. The icosahedron stub is byte-distinct from Tripo's unit-cube stub (sanity check that diff readers can tell adapter outputs apart at a glance). Production mode throws `NotYetImplementedError` — wire-up to the real Meshy HTTPS API (job submit, polling, GLB download, AssetStorage upload) is deferred to T-429a (Meshy public API surface still iterating). Side-effect-free import — adapters-core uses an instance-based per-tenant registry, so the host shell owns registration timing; `scripts/sync-skills.ts` registers `meshyDescriptor` alongside `kokoroDescriptor`, `fishSpeechDescriptor`, and `tripoDescriptor` into `buildAssetProvidersPkg()` and the T-424 catalog auto-gen picks up the row (Meshy now appears as the fourth row in `skills/stageflip/reference/asset-providers/SKILL.md`). NOT a structural extension (CLAUDE.md §13) — implements existing T-418 / T-419 contracts (consumer of the existing `ThreeDAssetProvider` interface); render verification N/A.
