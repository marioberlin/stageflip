# F1 Pro — driver-position register (timing tower)

## Visual tokens
- Base bar: carbon-black `#15151E` — F1's broadcast canon dark, slightly bluer than the `#1A1A1A` NBA/NFL/MLB register chrome to evoke the F1 Display's tech-modern register over the carbon-bodywork backdrop. Distinct from T-332 F1 Timing Tower's `#0D0D0F` carbon (T-332 picks pure-black-leaning carbon; T-515 sits one step lighter to differentiate the network-neutral driver-position register from the timing-tower deep-detail register). The `score-bug` primitive (T-332a) accepts `background` as a single hex string with no opacity channel; v1 renders at 100 % opacity. Production F1 broadcasts run the register at ~88 % over track footage; the flat-color parity canvas reads at 100 % (see "Trade-offs").
- Driver-position rows via `'racing'` style branch: vertical N-driver tower (primitive line 99–105 + render line 427–503). Each row is a `racingRowSchema` entry — `position` (P1, P2…), `code` (HAM, VER, NOR), `teamColor` (the constructor's livery accent — the row's left border per the primitive's `borderLeft: '4px solid <teamColor>'`), `gap` (gap-to-leader: `LEADER`, `+2.31s`), and optional `sectorTime` / `sectorColors` / `tireCompound`. T-515 ships a 5-driver tower (top-5 broadcast canon: leaders' detail is the focus; the bottom 15 cars roll into the timing-tower deep-register T-332 covers). Five rows × 30 px = 150 px tall.
- Primary brand red `#E10600` — used as the `accent` slot (the modern F1 logo red — 2018+ logo refresh red, not the legacy 2017-and-prior `#E32229` neon). Surfaces in tooling chrome (per-row sector-bar highlight in the broadcast register when wired); v1 register doesn't paint the accent visibly on the parity frame (the `'racing'` branch's `accent` is reserved for primitive-side animation hooks per the D-T332a-3 staticFallback posture; sector-color flashes / lead-change red flash are deferred animation carve-outs).
- Secondary white `#FFFFFF` — the row foreground (`foreground` prop), tabular numeric column-edge alignment of position numbers (`1` / `2` / `3` / `4` / `5`) + driver codes (`HAM` / `VER` / `NOR` / `LEC` / `SAI`) + gap times (`LEADER` / `+0.124` / `+0.487` / `+0.789` / `+1.234`).
- Tertiary dark `#15151E` — the base bar (above). The dark-on-white-text contrast is the F1 broadcast register signature; the team-color left-border stripe (4 px) is the per-row livery identifier per the primitive's racing-row layout.
- Bar anchored top-left at `position: { x: 60, y: 60 }` on a 1280×720 canvas — matches the T-332 F1 Timing Tower anchor norm. F1 broadcast canon places the driver-position tower flush against the top-left edge during race flow, leaving the right side of the frame for the live race feed.
- Card auto-fits via the `'racing'` style branch — vertical column of 5 rows. Width is the primitive's default 220 px (no `position.width` override). Snapshot constants live in `F1_PRO_REGISTER_PROPS` (exported from `@stageflip/parity-cli` at the cluster-B composer task's binding-wire step — sister to the existing `F1_TIMING_TOWER_PROPS`).

## Typography
- Driver codes (`row.code`): UPPERCASE 3-letter broadcast tokens (`HAM` / `VER` / `NOR` / `LEC` / `SAI`) — strict FIA convention. The FIA mandates a 3-letter UPPERCASE driver code per driver across all broadcast registers + on-screen overlays + telemetry feeds. The primitive renders `row.code` via `applyCasing` short-circuit on numeric leading character (D-T332a-12); driver codes are non-numeric and respond to the `casing: 'uppercase'` prop, but v1 snapshot uses already-uppercase strings to skip the transform. `casing: 'as-is'` (matches T-332 F1 Timing Tower + T-512 / T-513 / T-514 scoring-strip-register norm).
- Position number (`row.position`): numeric `1` / `2` / `3` / `4` / `5` rendered as a `<span>` at primitive line 454 (`width: 24, textAlign: 'right'`). The primitive renders the raw `number` via JSX coercion; no "P" prefix is auto-prepended (the primitive's racing-row schema is `position: z.number().int().positive()` — pure number, no string). To render as "P1 / P2 / P3" the binding wire step would need to repurpose the `code` slot — `'P1 HAM'` style — or accept the bare numeral. v1 ships the bare numeral matching the T-332 F1 Timing Tower precedent (the broadcast canon allows either; the position-number-only column reads cleanly with the team-color stripe identifying the driver row).
- Gap-to-leader (`row.gap`): broadcast-canon tokens — `LEADER` for P1, `+0.124` / `+0.487` / `+0.789` / `+1.234` for P2..P5 (3-decimal gap times — F1 broadcast convention is millisecond precision to 3 decimal places). The primitive renders `gap` at primitive line 478 (`marginLeft: 'auto', fontVariantNumeric: 'tabular-nums'`); right-aligned with tabular numerics so the gap column edges align across all rows regardless of gap-time magnitude.
- Lap count: NOT directly representable in the `'racing'` style branch (no `lap` slot — see "Trade-offs"). v1 accepts the implicit broadcast convention: lap count appears on the production broadcast adjacent to the tower (top-right Lap-X-of-Y indicator) but is OUT of the `'racing'` branch's prop surface. Adding a `lap?: { current: number; total: number }` slot is a candidate `T-332b`-family primitive-level follow-up.
- Tightly-tracked broadcast-bold body: `Inter Display` weight 700 (the OFL fallback declared in frontmatter) — primitive default-overridden via `font: { family: 'Barlow Condensed', weight: 700 }` to match F1's broadcast tech-modern register identity. Barlow Condensed is the OFL family that approximates the F1 Display proprietary family (BYO when a tenant supplies the licensed Formula1 Display Bold file). Identical fallback choice to T-332 F1 Timing Tower (same proprietary-BYO substitution path).
- Rendered family v1: `Barlow Condensed` weight 700 — the OFL fallback. The primitive's `font` prop is honored at render time (primitive lines 286–303); the rendered family in this case IS the OFL fallback. Bespoke `Formula1 Display Bold` (proprietary BYO; the F1-broadcast tech-modern condensed signature) declared in frontmatter exists for the type-design batch review (sister cluster-B composer task) and is the BYO substitution when a tenant supplies the licensed file.

## Animation
- Slide-in from the right over `ceil(fps * 0.30)` frames easing `EASE_OUT_QUART`; mid-race indefinite live-update hold; slide-out to the right over the last `ceil(fps * 0.20)` frames easing `EASE_IN_QUART`. At 30 fps: ~300 ms entrance, ~200 ms exit — sharper than the T-512 NBA Pro / T-513 NFL Pro / T-514 MLB sports-register 350 ms / 250 ms timings to match F1's broadcast pace (the fastest-moving cars on television; the register itself communicates urgency through transition speed). Identical right-side anchor pattern to F1 broadcast: the driver tower slides in from the right edge of the frame, settles into the top-left anchor, and slides out back to the right when the broadcast cuts away.
- Steady-state mid-hold: `translatePct == 0`, `opacity == 1`. The parity golden captures this state at frame 60 (= 2000 ms @ 30 fps composition) — matches T-332 F1 Timing Tower + T-333 / T-334 / T-335 / T-512 / T-513 / T-514 score-bug parity-fixture frame-pinning norm.
- The `score-bug` primitive (T-332a) is static in v1 — entrance/exit choreography is provided by the composing `frame-clip` envelope at the binding wire step, NOT by the primitive itself. Position-change row-slide (when a driver overtakes mid-race; tower rows reorder), sector-record purple pulse (when a driver sets the session-best in a sector), tire-compound-change flash, lead-change red flash (`#E10600` brand-red pulse on the new leader's row), DRS-activation chevron, and live-update mid-hold timing-feed (millisecond-level gap updates) are deferred (see "Out of scope").

## Rules
- Use when an F1-broadcast driver-position register is called for — top-of-frame driver-position tower on live race footage, qualifying sessions, sprint races, practice sessions, post-session classifications. F1 Pro register sits within Cluster B's sports-broadcast family next to T-333 Premier League (football horizontal), T-334 Fox NFL (American-football chrome-less), T-335 NBC SNF (American-football center-circle + network-mark), T-332 F1 Timing Tower (the 20-driver deep-detail timing register), T-512 NBA Pro (basketball quarter-period), T-513 NFL Pro (American-football network-neutral), and T-514 MLB (baseball inning-half). Choose F1 Pro for the **network-neutral 5-driver top-of-tower register** (broadcast-canon leaders' focus; vs T-332's 20-driver deep-detail register which is the per-network detail tower). F1 Pro is the more digestible register a tenant uses when they want F1 driver-position context without the full timing-tower depth.
- Do not use for non-motorsport disciplines (use `nba-pro-register` for basketball / `nfl-pro-register` for American football / `mlb-register` for baseball / `premier-league-field-of-play` for association football). For other open-wheel + closed-cockpit motorsport (IndyCar / WEC / WRC / NASCAR / Formula E) the `'racing'` style branch applies but the register conventions differ (e.g. NASCAR uses 2-digit car numbers + driver short codes; IndyCar uses 2-digit car numbers + sponsorship branding). Future presets under T-515a-family carve-outs.
- Do not paint the full bar F1 brand red `#E10600`. The brand red is reserved for sector-color flashes + lead-change pulses + tooling chrome accents (the `accent` prop's role); pulling the base bar to brand red would saturate the register, destroy the team-color stripe identity (the per-row left-border 4 px stripe is the constructor identifier — orange-papaya `#F58020` for McLaren, Mercedes petronas-cyan `#6CD3BF`, Ferrari `#ED1C24`, Red Bull `#1E5BC6`), and break the F1-Display tech-modern dark-chrome register.
- UPPERCASE 3-letter driver codes are mandatory (NOT 2-letter, NOT Mixed-Case). The FIA convention is strict — every driver registered with the FIA receives a unique 3-letter UPPERCASE code (HAM / VER / NOR / LEC / SAI / RUS / ALO / OCO / GAS / TSU / BOT / ZHO / PIA / HUL / STR / MAG / PER / RIC / DEV / SAR). The driver-position-register row is space-constrained; full driver names (`Hamilton` / `Verstappen` / `Norris`) appear on the production broadcast in graphical pop-ups elsewhere on the frame, NOT in the tower itself.
- Tower-row count fixed at 5 rows (P1..P5) for the F1 Pro register. The `'racing'` branch's schema allows `rows.max(24)` (primitive line 103); v1 uses 5 to match the network-neutral broadcast-canon top-of-tower focus. Per-binding overrides at the wire step can expand to top-10 (10-row deep register) or full 20-driver tower (use T-332 F1 Timing Tower instead — purpose-built for the deep register).
- Team-color stripe (`row.teamColor`) is REQUIRED for every row. F1 broadcasts always show the constructor's livery accent on the row — omitting it would read as a non-F1 register (the stripe is the F1-specific data the football / basketball / baseball registers don't use). Snapshot pins canonical 2024 mid-season team colors: VER `#1E5BC6` Red Bull / NOR `#F58020` McLaren / HAM `#6CD3BF` Mercedes / LEC + SAI `#ED1C24` Ferrari.
- Designed for live F1 race footage across the regular season + sprint races + qualifying + practice + post-session — same legibility requirements as the T-332 F1 Timing Tower preset (driver codes ≥ 14 pt; primitive's racing-row 14 px default satisfies — see Trade-offs for the broadcast-canon font-size mismatch).

## Trade-offs (v1 cosmetic divergences from the compass register)
- **No "P" prefix on position numbers.** F1 broadcast canon often renders position as `P1` / `P2` / `P3` (with the "P" prefix denoting "Position"); the primitive's `'racing'` branch schema is `position: z.number().int().positive()` (pure number — primitive line 86). Rendering "P1" would require either repurposing the `code` slot (e.g. `'P1 HAM'` — readable but loses semantic separation) or a primitive-level slot addition. v1 ships the bare numeral matching T-332 F1 Timing Tower precedent. Adding a `positionPrefix?: string` slot is a candidate `T-332b`-family primitive-level follow-up.
- **No lap-count display.** F1 broadcasts always show `Lap X / Y` adjacent to the driver tower (typically top-right). The `'racing'` branch has no `lap` slot. v1 ships without the lap-count token; the binding wire step can layer a separate `lower-third` clip above the tower for lap context. Adding a `lap?: { current: number; total: number }` slot is a candidate `T-332b`-family primitive-level follow-up.
- **Reuses `style: 'racing'` (no F1-specific sub-discriminant).** The primitive's `'racing'` style branch is shared across all motorsport disciplines. F1-specific decorations (the constructor logo glyph, the tire-compound color-coded circle — partially supported via `tireCompound` enum — the DRS-activation chevron, the pit-stop indicator) are not all surfaced. v1 ships without `tireCompound` for the F1 Pro 5-row register to keep the chrome minimal — the timing-tower T-332 deep-register is the place for tire detail.
- **Sector colors omitted.** The `'racing'` branch supports `sectorColors` (purple session-best / green personal-best / yellow slower / gray neutral — primitive lines 197–202) but v1 F1 Pro register doesn't include them — the network-neutral driver-position register is intentionally chrome-minimal vs the T-332 timing-tower deep register where sector colors are the focus. Per-binding overrides at the wire step can enable.
- **Team-color stripes are 2024 mid-season canon, not live-feed-pinned.** Canonical 2024 livery colors are pinned in the snapshot: Red Bull `#1E5BC6`, McLaren `#F58020`, Mercedes `#6CD3BF`, Ferrari `#ED1C24`. The composer-task wire step is the place to override per-season as teams update liveries (Red Bull's 2026 RB22 livery shift, for example). v1 ships the 2024 canon as the default snapshot — matches T-332 F1 Timing Tower precedent.
- **No tire-compound circle on F1 Pro rows.** The `'racing'` branch supports `tireCompound: 'soft' | 'medium' | 'hard' | 'inter' | 'wet'` rendered as a colored circle per row (primitive line 479–498). v1 F1 Pro register doesn't pin tireCompound — keeps the register chrome-minimal. Per-binding wire-step overrides can enable per-row. The T-332 F1 Timing Tower IS the place for full tire detail (it pins tireCompound on every row).
- **Background opacity rendered at 100 %, not the production ~88 %.** The primitive's `background` prop accepts a single hex string with no opacity channel. Pre-blending against an assumed track-color is wrong on arbitrary footage; the 88 % spec is a production-time tunable for video-overlay legibility. v1 parity renders at 100 % on the flat-color parity canvas. Adding a `backgroundOpacity?` prop is a candidate primitive-level follow-up under the `T-332b`-family label (shared with T-512 / T-513 / T-514).
- **No DRS-activation chevron / pit-stop indicator / fastest-lap purple flash.** F1 broadcast canon decorations specific to the in-session live state — primitive-level slot additions under the `T-332b`-family label.

- Tire-compound-change flash (when a driver pits and rejoins on a fresh compound; the tire circle flashes the new compound's color) — primitive-level animation enum addition.

- Fastest-lap purple flash (the purple text-color flash on the row whose driver just set the fastest lap of the session) — primitive-level animation enum addition.
- Lap count (`Lap X / Y`) companion — semantically a sister `lowerThird` or `infoBadge` preset (future Cluster B follow-up; the lap-count token doesn't naturally belong inside the driver tower).
- Constructor logo glyph on each row — image-asset slot addition under the `T-332b`-family label.
- 10-row + 20-row tower variants — use T-332 F1 Timing Tower for the deep register; T-515 F1 Pro is the network-neutral 5-row top-of-tower preset.
