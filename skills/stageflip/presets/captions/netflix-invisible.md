# Netflix Invisible — strict-accessibility long-form-video subtitle

Netflix's strict-accessibility long-form-video subtitle register: Netflix Sans / Inter weight 500 sentence-case white on a translucent black rectangle backdrop, 1 px black stroke for canvas-bleed contrast, NO entrance animation, and a **near-total active-only visibility model** — only the active word renders at full opacity (`1.0`); past and future visible words render at zero opacity (`muteOpacity: 0`), making them effectively invisible. The strictest active-word emphasis in the cluster F register space. Common uses: long-form-video accessibility captions, hard-of-hearing-audience subtitles, deaf-audience compliance per FCC / Netflix style-guide rules, infrastructure-grade subtitling where the captions exist to be read, not seen.

This preset is the **fifth Cluster F preset to land** AND the **first Cluster F preset to render `muteOpacity: 0` strict-accessibility active-only visibility** (the only Cluster F preset where past / future visible words drop to zero opacity — distinguishing from T-365's faint-ghost `muteOpacity: 0.6` opacity-karaoke and from T-362 / T-363 / T-364's no-mute `muteOpacity: 1` registers) AND the **first Cluster F preset to use `backdrop: 'rect'`** (a translucent black rectangle behind the active word's region, distinct from T-364's `'pill'` per-word rounded-rect backdrop). It is the **strict-accessibility extreme** of the cluster — past / future words contribute zero visible pixels; the parity golden's stylistic point IS the single-active-word visibility with no ghost of past words. T-362's `hormozi-montserrat-black` took the clipKind-default `caption → caption` slot; T-363 / T-364 / T-365 introduced the per-presetId override pattern; T-366 follows that pattern (`PRESET_ID_BINDINGS['netflix-invisible']`) because the `'netflix'` style bundle differs from T-362's `'hormozi'` along every axis (font Netflix Sans + Inter fallback vs Montserrat; weight 500 vs 800; size 56 vs 96; casing as-is vs uppercase; **`muteOpacity: 0` vs 1**; strokeWidth 1 vs 6; `backdrop: 'rect'` opacity 0.7 vs `'none'`; entrance none vs rise; staggerMs 0 vs 80) and cannot share T-362's `captionBinding`. The successor Cluster F preset (T-367 karaoke-progressive-wipe) follows the same per-presetId override pattern.

## Visual tokens

The active-only visibility model IS the message. Layout (1280×720 default; vertical compositions preserve the bottom-of-frame anchor below the speaker's torso):

- **Caption block** sits at the **bottom of frame** — `position: { x: 128, y: 540, width: 1024, alignment: 'center' }` on the parity composition (10% inset, 75% down, 80% width). At 56 px font size the five-word phrase fits comfortably one-line; longer transcripts flex-wrap automatically via the primitive's inner `flex-wrap: wrap` container. Sits BELOW T-362 / T-365's lower-third (y=432) and T-364's center (y=360) and T-363's upper-center (y=200) — the bottom-of-frame anchor is canonical for Netflix-style accessibility captions, where the player chrome reserves the lowest band but the captions sit immediately above it (the parity composition has no platform-UI overlay, so the anchor reads as 75% down).
- **Text** renders in `#FFFFFF` (white, the bundle's `foreground`). The active word renders at opacity `1.0`; past / future visible words render at opacity `0.0` (effectively invisible). The `'netflix'` bundle ships `highlightColor: #FFFFFF` AND `muteColor: #FFFFFF` — both equal to `foreground` — so there is **no color shift** between active and rest words. The only delta between active and rest is opacity (1.0 active vs 0.0 muted past / future). T-316a's just-merged `muteOpacity` routing fix is the path that makes this contract flow through (`props.muteOpacity ?? bundle.muteOpacity` resolves to 0 for non-active visible words, rendering them at zero pixel-coverage). This IS the strict-accessibility active-only visibility contract the preset name promises.
- **1 px black stroke** around glyphs. `strokeWidth: 1`, `strokeColor: '#000000'`. Subtle — not the heavy 6 px Hormozi or 5 px MrBeast broadcast register; just enough black halo for canvas-bleed contrast against whatever color the host canvas defaults to. The bundle assumes a dark Netflix-player chrome (`background: '#000000'` declared); the parity-fixture canvas is whatever the host generator emits, so the 1 px stroke supplies minimum legibility regardless.
- **Translucent black rectangle backdrop.** `backdrop: 'rect'`, `backdropOpacity: 0.7`. A black rectangle renders behind the active word's region at 70% opacity, providing local contrast for the active word against any canvas color. Distinct from T-364's `'pill'` (per-word rounded-rect at 0.9 opacity) — `'rect'` is straight-edged and full-line-region. Words 1–3 (past, opacity 0) contribute no visible glyphs but the rect backdrop's geometry follows the active-word region, so the rect itself is visible behind word 4 only.
- **No drop shadow / no glow.** The bundle ships none; `captionPropsSchema` does not expose shadow. The original stub described a "30–40% opacity black drop shadow (one or the other, not both)" alternative to the stroke; the bundle ships stroke unconditionally — pick stroke. Document; the alternative is aspirational.
- **Background** is the canvas backdrop — captions overlay on video at compose time. The CaptionClip primitive's container is `transparent`; the bundle's `background: '#000000'` is declared but only honored when `backdrop !== 'none'` is full-line (not the case for `backdrop: 'rect'`, which renders a localized rectangle behind the active word, NOT a full-canvas backdrop). The parity golden therefore renders against the host bundle's default canvas color. Black-bundle-on-canvas posture is the same as T-362 / T-363 (D-T366-11 — canvas-bleed quirk inherited symmetrically); the bundle's intended dark-canvas register is degraded against a non-black canvas but the translucent rect backdrop + 1 px stroke supply enough local contrast that the active word remains identifiable.
- **No "user-configurable black background bar" option.** The original stub described a "user-configurable: black background bar option; configurable text size for accessibility" knob; the bundle ships `backdrop: 'rect'` unconditionally at `0.7` opacity AND `size: 56` as a fixed constant. Aspirational; out of v1 scope. Documented absence so a future Reviewer doesn't expect to find them.

## Typography

- **`preferredFont: Netflix Sans`** (Netflix in-house typeface, `proprietary-byo`). Netflix Sans is a proprietary display sans designed for Netflix's player chrome and player UI — license is BYO (tenants embedding this preset commercially must obtain the face from Netflix's brand-licensing channels; the StageFlip pipeline does not preload it). The bundle's `font.family` ships `'Netflix Sans, Inter, ${SYSTEM_FONT_STACK}'` so hosts that don't preload Netflix Sans fall back to Inter, then to the system stack.
- **`fallbackFont: Inter`** (SIL OFL 1.1 via Google Fonts, Rasmus Andersson), weight `500`. Reconciled from the original stub's `weight: 400` per D-T366-7: the bundle's `NETFLIX_FONT` ships `Inter` at weight `500` (medium), NOT `400` (regular). Inter is the OFL face the bundle actually renders when Netflix Sans is not preloaded; declaring it as the fallback at weight 500 aligns the frontmatter with the implementation. Inter at weight 500 is metrically close to Netflix Sans at weight 500 — both are humanist sans-serifs with similar x-height and letterforms — so the parity register survives the substitution. If a Reviewer prefers leaving Inter weight 400 (closer to body-text reading weight; the stub's prose says "Regular (400)"), the Implementer may keep `weight: 400` and document the bundle's `weight: 500` as a known T-316 follow-up. Default posture: switch to Inter 500 for tighter implementation alignment (T-365 D-T365-7 precedent).
- **`fontSize: 56`** (the bundle's default). Smaller than T-362's 96 px Hormozi, T-363's 108 px MrBeast, T-364's 72 px TikTok, and T-365's 64 px Ali Abdaal — the Netflix register is infrastructure-grade subtitling, not creator-style emphasis. At 1280 px composition width, five short / medium words (longest is `accessibility` at 13 chars) at 56 px Inter 500 fit comfortably one-line for the canonical phrase; longer transcripts flex-wrap automatically. Netflix's canonical "42 chars per line, 2 lines max" style-guide rule is the production constraint; the parity snapshot's five-word single-line composition stays well within it.
- **`casing: 'as-is'`** (the bundle's default). Sentence case (mixed case). NOT uppercase — the Netflix accessibility register depends on standard reading case for legibility (uppercase reduces reading speed for hard-of-hearing audiences). Applied at render time via the primitive's `applyCasing` helper (`caption.tsx`); the underlying `WordTiming.text` payload preserves authored case for transcript editing. The original stub's "Mixed Case" typography note aligns with the bundle's `'as-is'` posture.
- **Comfortable reading width**: 42 chars per line / 2 lines max for the canonical Netflix style-guide rule. The five-word T-366 snapshot is short for demonstration; production transcripts split at sentence / phrase boundaries (one CaptionClip mount per ~one-line segment), with the host pipeline enforcing the line-length rule upstream.
- **Tabular numerals are not relevant** — text-heavy register; numeric content uses the bigNumber preset family (Cluster E).

## Animation

- **`entrance: 'none'`** (the bundle's default). Words appear at their settled position with NO per-word translate / scale / opacity interpolation. The entrance routing branch in the primitive short-circuits the `'rise'` / `'bounce'` / `'slide-from-bottom'` interpolation when the bundle's `entrance` is `'none'`: words pop in at their `startMs` boundary at full opacity (then immediately drop to opacity 0 in the next frame if they are no longer the active word, per `muteOpacity: 0`). `staggerMs: 0` — no entrance offset. The original stub described "Entire subtitle event appears at once, no word-by-word" + "No fades on entry / exit — clean appearance / disappearance"; the bundle's actual behavior is per-word snap-on at `startMs` (not full-event-at-once), but the no-fade contract holds — the snap-on / snap-off is an intentional infrastructure-grade aesthetic ("subtitles are infrastructure, not decoration"). The container-level fade of the host composition still applies if declared; the bundle ships none.
- **Active-word state** is the only animation per word. A word becomes active when `currentTimeMs >= word.startMs && currentTimeMs < word.endMs`. At the parity reference frame 45 (= 1500 ms) word 4 (`'for'`, `startMs: 1200, endMs: 1600`) is active. The active word picks `{ color: highlightColor, opacity: 1 }` and the non-active visible words pick `{ color: muteColor, opacity: muteOpacity }`. Because `muteColor === highlightColor === foreground === '#FFFFFF'` for the `'netflix'` bundle AND `muteOpacity === 0`, the **active word renders at opacity 1.0; non-active visible words render at opacity 0** (effectively invisible). This is the strict-accessibility active-only visibility register the preset name promises.
- **No color cycle.** Hormozi swaps white → yellow on active; MrBeast cycles red / yellow / green on emphasis-tagged words; the Netflix bundle does neither. `highlightColor: '#FFFFFF'` makes the highlight render identically to the foreground; the active word's distinguishing feature is opacity 1.0 vs the muted siblings' opacity 0.0.
- **No active-word scale pulse, no bounce, no slide.** No per-word geometric animation. Words are static once visible (and instantly invisible once past).
- **No word-exit animation.** Past words drop to opacity 0 in the next frame after they cease being active — they don't fade out, slide off, or unmount. The unmount of the entire CaptionClip mount happens when the host pipeline replaces it with the next phrase (snap-cut, no cross-fade).
- **Snap-cut between caption events.** A fresh CaptionClip mount per ~one-line segment with snap-cut replacement (no cross-fade). Synced precisely to audio word-level timestamps in production. The host pipeline (or tool agent) emits the `WordTiming[]` from a transcript-with-timings source (Whisper word-level, ElevenLabs alignment); the primitive consumes the array as data per T-316 D-T316-4 — no audio decoding inside the primitive.

## Rules

- **Bound primitive**: `caption` from `@stageflip/runtimes-frame-runtime-bridge` (`packages/runtimes/frame-runtime-bridge/src/clips/caption.tsx`, exported as `Caption` + `captionClip`). The `caption` `clipKind` is in `VALID_CLIP_KINDS` (per T-316 D-T316-13, `scripts/check-preset-integrity.ts`); the v1 resolver in `packages/parity-cli/src/generate-fixture.ts` routes `netflix-invisible` via `PRESET_ID_BINDINGS['netflix-invisible']` (T-366 D-T366-4) — the per-presetId override path established by T-360 D-T360-2. Composing tools should mount `Caption` with `style: 'netflix'`, a `WordTiming[]` payload, and a `position` — the bundle supplies font / casing / foreground / muteColor / muteOpacity / strokeWidth / backdrop / entrance / stagger defaults.
- **Word-level timing is mandatory.** The primitive consumes `WordTiming[]` (`{ text, startMs, endMs, emphasis? }`); sentence-level captions break the active-only visibility register because the active-vs-mute opacity routing depends on per-word `startMs`/`endMs` boundaries. Tenants without word-level timestamps must split sentences upstream.
- **`style: 'netflix'` is the canonical enum value.** Per-prop overrides (custom `font`, `muteColor`, `muteOpacity`, `entrance`) win over the bundle defaults but break the visual register; document any override in the composition's authoring metadata. The bundle's defaults are the contract.
- **`muteOpacity: 0` strict-accessibility (NOT `muteOpacity: 0.6` faint-ghost) is the signature.** Don't switch to a non-zero `muteOpacity`. The whole point of this register is the absence of past-word ghosts — past words contribute zero visible pixels, distinguishing it cleanly from T-365's opacity-karaoke (where past words remain visible at 0.6). A reviewer who sees ghosted past words in the parity golden should flag the rendering as a regression — likely T-316a's routing fix did not flow through, or the host bundle is rendering an outdated `STYLE_BUNDLES['netflix']` snapshot.
- **Sentence case (NOT uppercase) is the canon.** Netflix's accessibility-caption register uses standard reading case for legibility. The bundle's `casing: 'as-is'` honors authored case; tenants must not normalize transcripts to title-case or uppercase.
- **Translucent rect backdrop is the only backdrop.** `backdrop: 'rect'` at `0.7` opacity. No per-word pill (TikTok register, T-364), no panel, no glow, no shadow. Tenants who want a full-line solid backdrop should pick a different preset; tenants who remove the rect backdrop break the canvas-bleed contrast contract for hard-of-hearing audiences.
- **1 px stroke is the minimum legibility floor.** `strokeWidth: 1`, `strokeColor: '#000000'`. Removing the stroke (e.g., overriding to `strokeWidth: 0`) loses the canvas-bleed contrast against light-canvas video frames; document any override.
- **Bottom-of-frame anchor.** The default `position.y` is the bottom band (y=540 on the 1280×720 parity composition); tenants on vertical compositions re-anchor to the bottom band above the platform UI overlay. Netflix's accessibility-caption convention places captions immediately above the player-chrome reserved band — captions read as infrastructure-grade transcript, not creator-style overlay.
- **Theme slot mapping**: `background`, `foreground`, `highlightColor`, `muteColor`, `strokeColor` map to palette roles per `captionClip.themeSlots`. Tenant theme overrides flow through these slots at composition time without touching the preset; tenants overriding `highlightColor` to a non-`#FFFFFF` shade reduce accessibility legibility (color-blind audiences depend on the white-on-rect register) and should reconsider whether the `'netflix'` register is the right preset.
- **Reference frame for parity is mid-hold (frame 45)** — `currentTimeMs = 1500 ms` at 30 fps. By the primitive's word-visibility rule four words are "visible" (1–4 — past + active); by the active rule word 4 (`'for'`, `startMs: 1200, endMs: 1600`) is active; word 5 (`'everyone'`, `startMs: 1600`) is below its `startMs` and not yet rendered. Past words 1–3 render at opacity 0 (per `muteOpacity: 0`) so they contribute zero visible pixels; the parity golden documents the strict-accessibility "active word only" pattern with one visible word and a translucent rect behind it — the maximum-contrast demonstration of the active-only visibility delta in a single frame.
- **No live data.** The `permissions` array is empty; no network call, no telemetry source. Audio sync / live transcription is a host concern.
- **No 42-char / 2-line / ≥833 ms / ≤7 s validator in v1.** The original stub described a strict-mode validator enforcing Netflix's style-guide rules ("42 characters per line maximum, 2 lines per event maximum, 5/6 second minimum, 7 second maximum — these are FCC and Netflix style guide rules. The validator enforces them; failure is a hard error, not a warning"); the `captionPropsSchema` exposes no length / duration validator fields. Aspirational; out of v1 scope. The host pipeline is responsible for enforcing the line-length / duration rules upstream of the primitive.
- **No "user-configurable accessibility text-size" knob in v1.** The original stub described a tenant-configurable text-size accessibility option; the bundle ships `size: 56` as a fixed constant. Out of v1 scope.

If floating-point drift makes word 3 (`'accessibility'`) just-past-active or word 4 boundary-edge, acceptable — the parity contract is "exactly one Netflix-styled word visible mid-phrase, translucent rect backdrop behind it, 1 px black stroke, NO ghost of past words." Document whichever word lands active.

Thresholds: **PSNR ≥ 42 dB**, **SSIM ≥ 0.98** (stricter than the generator default `35 / 0.95`; mirrors the cluster-E / cluster-F sister presets per D-T366-9). Revised down from the stub's original `44 / 0.99` posture for cross-cluster consistency. The preset-driven-thresholds follow-up flagged during T-359b is the formal mechanism for per-preset deviation; for now the threshold values are hand-pinned in `parity-fixtures/captions/netflix-invisible/thresholds.json` post-generation. A no-entrance / single-active-word / translucent-rect-backdrop / 1 px-stroke caption is moderately antialiasing-sensitive (the 1 px stroke can jitter at glyph edges; the translucent rect alpha-composites against the canvas); `42 / 0.98` should be comfortable. If it fails after hand-pinning, escalate (likely a Netflix Sans / Inter font-fallback render-mismatch on the host system, OR rect-edge-antialiasing variance).
