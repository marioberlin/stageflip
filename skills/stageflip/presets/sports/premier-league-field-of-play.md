# Premier League Field of Play — scoreBug

The Premier League's 2017+ broadcast canon: a compact upper-left rectangular scoreclock with PL purple `#34003A` chrome, PL green `#00FC8A` accent, white text, 3-letter team codes (ARS / CHE) on kit-color team boxes, tabular-numeric scores, a match clock, and a period token. Common uses: live football match overlays; pre-match / mid-match / settled-state scoreboards on a flat broadcast canvas where the PL purple+green register is the brand signal. The preset's stylistic point is the **steady-state scoreclock register** — purple chrome + kit-colored team boxes + tabular `'67:42'` clock + `'2H'` period — as the persistent on-screen anchor for a 90-minute football broadcast.

This preset is the **first Cluster B preset to land**, the **second `scoreBug` clipKind consumer** (after `cricket-ball-by-ball-dots` from Cluster E which holds the clipKind-default arm via the `outcome-row` primitive — a different primitive entirely), and the **first production consumer of T-332a's `score-bug` primitive AND its `'football'` style branch**. Wired via `PRESET_ID_BINDINGS['premier-league-field-of-play']` per Pattern C — the `'scoreBug'` arm in `DEFAULT_CLIP_KIND_RESOLVER` stays UNCHANGED at `scoreBugDotsBinding` (T-358's cricket-ball-by-ball-dots binding via the `outcome-row` primitive); T-333 lands a per-preset override keyed on the preset id that binds the `score-bug` primitive's `'football'` style branch (T-332a) directly.

## Visual tokens

The Premier League brand pair (purple `#34003A` + green `#00FC8A`) is canonical and locked: per-tenant brand-recolor of the chrome / accent is forbidden in v1 — the PL purple chrome IS the broadcast signal. Per-team kit colors are explicit prop input (kit-color = instant-ID per stub line 43); the canonical Arsenal vs Chelsea fixture exercises the kit-color-as-instant-ID rule with two distinct, high-contrast kit signals (Arsenal red `#EF0107` vs Chelsea blue `#034694`).

- **Background / chrome** PL purple `#34003A` solid (no transparency per stub line 29; designed for legibility "from across fan-filled bars"). Passed to the primitive's `background` prop, which renders as the root element's `backgroundColor` per `rootStyle()` (lines 285–303 of `score-bug.tsx`).
- **Accent** PL green `#00FC8A` — declared in frontmatter for theme-slot mapping (`accent → palette/accent` per primitive lines 689–693) but **NOT bound to a per-render-element on the football style branch** in v1. The `'football'` branch's render contract has no green-stripe / green-divider / green-clock-underline slot (D-T333-11-c). Cosmetic divergence from the stub; documented as a `T-332b`-family follow-up. The green is preserved for theme-pipeline integration even though the steady-state football render does not visibly use it.
- **Foreground / text** white `#FFFFFF` for the clock and period text. NOTE: team-box code + score text is **hard-bound** to `#ffffff` in the primitive regardless of the `foreground` prop (line 314 of `score-bug.tsx` — `color: '#ffffff'` inside `teamSectionStyle`); only the central clock + period lines obey `foreground`. Aligns with stub since the target text color is white anyway.
- **Per-team kit colors** Arsenal red `#EF0107` (home box fill) + Chelsea blue `#034694` (away box fill) — the canonical PL fixture pairing; both teams have distinct, high-contrast kit signals (red vs blue) that exercise the kit-color-as-instant-ID rule of the preset (stub line 43). Each team box renders the kit color as the **whole tile background fill** rather than a 6 px outer-edge stripe (D-T333-11-a — primitive-level cosmetic divergence; the brand signal is preserved at the area level instead of the stripe level).
- **Position** anchored at upper-left `(60, 60)` — 60 px in from canvas top-left edges per stub line 23 (compact rectangular scoreclock, upper-left). The primitive renders at `position: { x, y }` via `rootStyle()` absolute-positioning. Default size `720 × 80` (primitive lines 339, 285) since `position.width` / `position.height` are not provided.
- **Layout shape** horizontal flex row with three children — `score-bug-football-home` (Arsenal-red team box; left), `score-bug-football-clock` (clock + period stack; center), `score-bug-football-away` (Chelsea-blue team box; right). Home box reads `code` then `score` left-to-right (`'ARS' '2'`); away box reads `score` then `code` (`'1' 'CHE'`) — the inversion mirrors broadcast convention, anchoring the score numerals adjacent to the central clock for column-edge alignment with the running clock.
- **Solid background, no transparency** per stub line 29 — primitive renders at 100% opacity by default; aligns with stub. The compact dense register is designed for in-bar legibility, NOT for slick semi-transparent overlay.

The kit-color tile fill IS the message — applied uniformly to the team-box background. Code text and score text stay white across both kit-color states; the eye locks onto the kit-colored tile body as the salient signal.

## Typography

- **`preferredFont: Premier Sans`** (`proprietary-byo` per ADR-004 §D3). The PL's brand-licensed face, designed by Robin Hill (DesignStudio) for the 2017 brand refresh. Tenants with a PL licensing agreement slot it in via the FontManager (T-072); the bespoke numerals (line 33 of stub: "distinct numeral design preserved") are part of the brand register. Cluster B IS in `TYPE_DESIGN_REQUIRED_CLUSTERS` (per `scripts/check-preset-integrity.ts` line 122 — verified during T-333 D-T333-6), so `signOff.typeDesign` MUST be `'pending-cluster-batch'` or `'signed:YYYY-MM-DD'`, NOT `'na'`. T-333 holds at `pending-cluster-batch`; the cluster-B type-design batch review (cluster-composer task) flips this field across all nine Cluster B presets in one downstream PR.
- **`fallbackFont: Space Grotesk`** weight `600` (OFL, SIL Open Font License 1.1 via Google Fonts). Substituted automatically by the FontManager on every rendering medium where the BYO `Premier Sans` face is not cleared. `Space Grotesk 600` (SemiBold) provides the geometric-sans heavy-weight register that approximates Premier Sans's display character. License-cleared in `THIRD_PARTY.md`.
- **Team abbreviations** (3 letters: `ARS`, `CHE`) at the primitive's default 28 px / weight 800 (line 320 of `score-bug.tsx`); rendered in the active font family. Stub line 32 calls for "Bold, 14–16 pt, tabular" — the primitive's 28 px default is larger than the stub's print-canon size to suit a 1280×720 broadcast canvas; the relative hierarchy (heavy-weight bold tabular team codes) is preserved.
- **Scores** (`'2'` / `'1'`) at the primitive's default 28 px / weight 800 alongside the team codes (same `teamSectionStyle`). Stub line 33 calls for "Bold, 24–30 pt, tabular — distinct numeral design preserved" — the primitive renders score numerics in the active font family with the snapshot-supplied `font.tabularNums: true` flag for column-edge alignment. **The bespoke numerals from Premier Sans cannot render in the OFL fallback** (D-T333-11-b); whatever the typeface ships becomes the numeral form. Cosmetic divergence; documented.
- **Match clock + period** (`'67:42'` / `'2H'`) — clock at 20 px / weight 700 (line 332 of `score-bug.tsx`); period at 12 px / opacity 0.85 (line 406). Stub line 34 calls for "Minute / period: Regular, 12–14 pt"; the primitive renders both heavier than the stub's Regular but in the same hierarchical neighborhood relative to the team-box text.
- **Tabular numerals** explicitly required by stub lines 32–33 for both team codes and scores. The `font.tabularNums: true` flag is passed via the primitive's `font` prop; column-edge alignment of single-digit scores in adjacent team boxes is the broadcast-canon expectation.
- **Casing** `'as-is'` — snapshot strings (`'ARS'`, `'CHE'`, `'2'`, `'1'`, `'67:42'`, `'2H'`) are already in target casing; the primitive's `applyCasing` helper (lines 231–249) applies `'as-is'` as a no-op transform. NOTE: `applyCasing` short-circuits leading-numeric strings (`/^\d/`) regardless of the casing prop (lines 233–235), so `'67:42'`, `'2'`, and `'1'` would render verbatim under any casing. The period token `'2H'` would also pass uppercase under `casing: 'uppercase'` but `'as-is'` matches the snapshot string already.
- **No italic, no underline, no strikethrough.** Football broadcast graphics never use them.

The frontmatter schema accepts a single `preferredFont` and a single `fallbackFont` entry (extending it to a font-pair is a preset-system change — out of envelope), so a single typographic family covers both team codes and clock numerals; the v1 fallback is `Space Grotesk` 600 across the board. The bespoke-font invariant 6 is satisfied: `Premier Sans` is `proprietary-byo` and the OFL `Space Grotesk` fallback is declared in frontmatter.

## Animation

- **Steady-state register only in v1 per D-T333-3.** The `'football'` style branch of T-332a renders a **static layout** — there is no entrance animation, no score-pulse on score change, no goal-celebration flourish, no per-team variant choreography, no companion-motion language. The reference frame for the parity golden is mid-hold steady-state at frame 60.
- **2 s `cubic-bezier(.55, 0, .1, 1)` entrance with 1 s delay** (per stub line 38) is **out of v1 scope per D-T333-3**. Adding a primitive-level entrance enum (slide-in / fade-in / drop-in) with cubic-bezier params is a primitive-level concern. Candidate `T-332b`-family carve-out IF Reviewer scrutiny demands. v1 captures the steady-state mid-hold frame; the entrance is a frame 0 → frame 60 ramp that the static-frame parity golden cannot capture in a single PNG.
- **Score-change goal-celebration flourish** (per stub line 39) is **out of v1 scope per D-T333-3**. The 2024/25 PL canon introduced team-specific goal animations (Arsenal cannon, Brighton seagulls, United devils-and-pitchforks); each requires asset bundles + per-team component switch. Candidate v2 territory; documented in stub for runtime composition. NOT a T-333 follow-up; a future implementation-plan task.
- **Per-team goal-celebration variants** (Arsenal cannon / Brighton seagulls / United devils-and-pitchforks per stub line 39) are **out of v1 scope per D-T333-3**. The `'football'` branch has no `goalAnimation: { team, variant }` slot in T-332a. Asset-bundle + per-team component switch concern; explicit v2 territory.
- **"Field of Play" companion motion language** (colored blocks rising / falling / sliding referencing passes, long balls, corners, dribbles per stub line 40) is **out of v1 scope per D-T333-3 / stub line 46**. The stub itself notes that this motion "applies to ancillary graphics (matchday opens, transitions), not the persistent scoreclock." Semantically a separate composition (a montage of `panel` / animated-value clips), not a `score-bug` prop axis. NOT a candidate `T-333x` carve-out — distinct from the scoreclock preset; would be its own implementation-plan task.
- **Score-change pulse / chrome-flash on score update** is **out of v1 scope per D-T333-3**. No `scoreChange: { animation, frame }` slot in T-332a's `'football'` branch. Candidate `T-333a` carve-out IF Reviewer scrutiny demands; primitive-level addition (entrance + score-pulse).
- **Mid-hold steady-state at frame 60** (per ADR-004 §D5 and D-T333-5). Parity fixture snapshots at this frame. The football branch is a static layout so any post-mount frame produces an identical render; frame 60 is the cluster-norm reference (T-323 / T-325 / T-326 / T-327 / T-328 / T-329 / T-330 all use 60).
- **No state-transition animation in v1.** State transitions (entrance ramp, goal-celebration flourish, per-team variant choreography, "Field of Play" companion motion, score-pulse, chrome-flash) belong to the live-mount surface where the data source streams updates AND to the runtime composition where the host orchestrates the broadcast pacing.
