# ESPN BottomLine — two-line flipper ticker

The post-2018 ESPN BottomLine register: a full-width persistent band at the absolute bottom of frame on a deep dark `#1A1A1A` charcoal base; two stacked rows, top + bottom, each ~50 px tall on a 100 px band; pair-of-entries advances every 4500 ms (mid-canon "4–5 s per segment" cadence); ESPN Red `#CC0000` brand-locked accents on losing-team chips; Yellow `#FFD700` score highlights on winning-team / leads chips; white `#FFFFFF` text + FINAL / halftime status tokens; sports payload of NBA team-vs-team scores exercising up / down / flat chip-color paths; Roboto Condensed + Inter (Apache-2.0 + OFL) as the OSS fallback for the proprietary ESPN A2 Beckett + Klavika pairing. Common uses: live NFL / NBA / MLB match overlays where the bottom-of-frame full-width persistent two-row flipper register is the brand signal — sister-but-distinct from T-356's `bloomberg-ticker` (continuous-marquee `mode: 'scroll'` register on the same primitive).

This preset is the **fourth Cluster B preset to land** AND the **second `newsTicker` clipKind consumer** (after T-356's clipKind-default `bloomberg-ticker`) AND the **first production consumer of T-356b's `mode: 'flip'` two-row stacked register** on the `news-ticker-bar` primitive. Wired via `PRESET_ID_BINDINGS['espn-bottomline-flipper']` per Pattern C — the `'newsTicker'` arm in `DEFAULT_CLIP_KIND_RESOLVER` stays UNCHANGED at `newsTickerBinding` (T-356); T-333's `premierLeagueFopBinding` + T-334's `foxNflNoChromeBinding` + T-335's `nbcSnfBinding` stay UNCHANGED. First non-`scoreBug`-clipKind Cluster B preset (T-333 / T-334 / T-335 all bound `scoreBug`).

## Visual tokens

The post-2018 ESPN BottomLine register is canonical and locked: bottom-of-frame full-width band, dark base, two stacked rows that flip pair-by-pair on a 4500 ms cadence, white text + Yellow up-color score highlights + ESPN Red down-color accents + white flat-color FINAL / halftime tokens, sports score chip mix exercising all three direction paths.

- **Background / dark base** `#1A1A1A` — deep-near-black solid. Passed to the primitive's `background` prop. The stub line 27 calls for "dark charcoal `#333333` → black `#1A1A1A` gradient"; the primitive's `background` prop accepts a single hex (line 45 of `news-ticker-bar.tsx`) — v1 picks the gradient end (`#1A1A1A` deep-near-black; visually closest to most BottomLine reference frames at the bottom edge). Carving out a `backgroundGradient` axis is `T-356c`-family (D-T339a-11-c).
- **Foreground / text** `#FFFFFF` for the chip symbol + price spans (`news-ticker-bar-chip-symbol` / `news-ticker-bar-chip-price` testids). Per stub line 28 — white text.
- **Up-color (Yellow score highlights / wins)** `#FFD700` — Yellow per stub line 28. The primitive renders `▲ +N` in `upColor` for `direction: 'up'` entries (chips with leads / wins). At frame 60 the top-row NYK `+5` chip exercises this color path.
- **Down-color (ESPN Red brand-locked accent)** `#CC0000` — ESPN Red per stub line 26. The primitive renders `▼ -N` in `downColor` for `direction: 'down'` entries (chips with losses / deficits). The LAL `-3` chip exercises this color path in pair-window 1 (NOT visible at frame 60). The logo-box ESPN Red usage on the left edge is deferred (D-T339a-11-b).
- **Flat-color** `#FFFFFF` — white. Used for FINAL `'F'` / halftime `'H'` status tokens with `direction: 'flat'`; the primitive renders the `▬` flat arrow + the literal token in `flatColor`. At frame 60 the bottom-row BOS `F` chip exercises this color path.
- **Two-row stacked flipper register** `mode: 'flip'`. **First production consumer of T-356b's `mode: 'flip'`**. Per stub line 30 — "two-line flipper format (post-2018 canon)." The primitive's flip-mode render path (lines 160–198 of `news-ticker-bar.tsx`) splits the band into two rows of `bandHeight / 2` each; `pairIdx = floor(currentTimeMs / flipDurationMs)`; `topEntry = entries[(pairIdx * 2) % entries.length]`; `bottomEntry = entries[(pairIdx * 2 + 1) % entries.length]`. **Steady-state per pair window** — no within-window flip animation in v1 (T-356b explicitly defers the 350 ms ease-in-out flip transition to a v2 `T-356c` follow-up).
- **Segment cadence** `flipDurationMs: 4500` — mid-canon between the stub's "4–5 s per segment" range AND matches the primitive's own `DEFAULT_FLIP_DURATION_MS = 4500` default. Setting it explicitly documents intent at the binding site even though it equals the primitive default.
- **Band height** `bandHeight: 100` — primitive splits this into two 50 px rows in flip-mode, approximating the stub's 40 px BottomLine + 60 px topic-bar combined height. The topic-bar companion layer is deferred (D-T339a-11-a); the 100 px band gives flip-mode legible team-vs-team chips.
- **Band position** `bandPosition: 'bottom'` — bottom-of-frame full-width per stub line 23. The primitive renders `position: absolute; left: 0; width: 100%; bottom: 0` for `bandPosition: 'bottom'`.
- **Sports payload** six-entry NBA team-vs-team score mix: `NYK 102 +5 ▲` (Knicks lead by 5; up), `BOS 97 F ▬` (Celtics final; flat), `LAL 88 -3 ▼` (Lakers deficit; down), `PHX 91 F ▬` (Suns final; flat), `PHI 24 +2 ▲` (76ers up at half; up), `DAL 22 F ▬` (Mavericks at half; flat). At frame 60 (= 2000 ms @ 30fps; pair window 4500 ms), `pairIdx = 0` → top row = NYK `+5` yellow / bottom row = BOS `F` white. Both up + flat color paths exercise in the single mid-segment golden.
- **Topic-bar companion layer omitted** (D-T339a-11-a). Stub line 24 calls for "≈ 1920 × 60 px optional companion layer above the BottomLine"; the `news-ticker-bar` primitive renders a single horizontal band — no topic-bar slot. Compose externally as a separate clip in a layered host timeline if required. Carving out a `companionBar` axis is `T-356c`-family.
- **Logo box on left edge omitted** (D-T339a-11-b). Stub line 29 calls for "ESPN Red rounded rectangle ~120 × 40 px on the left edge"; the primitive does not have a per-row branded leading element. v1 ships without the logo box; the ESPN Red brand register is preserved via the `downColor` chip path on losing-team chips. Carving out a `leadingLogo` axis is `T-356c`-family.

The two-row stacked flipper layout IS the message — at frame 60 the eye locks onto the top row (NYK `102 ▲ +5` with `▲ +5` in yellow) above the bottom row (BOS `97 ▬ F` with `▬ F` in white) on the dark band. The pair-by-pair advancement on the 4500 ms cadence is the post-2018 ESPN canonical UX gesture; T-356's bloomberg-ticker uses the same primitive but in continuous-marquee `mode: 'scroll'` — the cluster's distinguishing feature is the flip-mode register.

## Typography

- **`preferredFont: ESPN A2 Beckett + Klavika`** (`proprietary-byo` per ADR-004 §D3). ESPN's brand-licensed pairing for the SportsCenter / BottomLine identity — A2 Beckett is the proprietary tall condensed display family used for team abbreviations + scores; Klavika is the proprietary bold sans family used for headlines / status tokens. Tenants with both licensing arrangements slot them in via the FontManager (T-072). Cluster B IS in `TYPE_DESIGN_REQUIRED_CLUSTERS` (verified during T-333 / T-334 / T-335 spec drafting), so `signOff.typeDesign` MUST be `'pending-cluster-batch'` or `'signed:YYYY-MM-DD'`, NOT `'na'`. T-339a holds at `pending-cluster-batch`; the cluster-B type-design batch review (cluster-composer task) flips this field across all nine Cluster B presets in one downstream PR.
- **`fallbackFont: Roboto Condensed + Inter`** weight `700` (Apache 2.0 + OFL via Google Fonts). Roboto Condensed approximates A2 Beckett's tall condensed numerals on team codes + scores; Inter approximates Klavika's bold sans headline geometry on FINAL / halftime tokens. The Bold (700) weight matches the stub's "Bold Condensed, 18–22 pt + Bold Mixed Case 18–22 pt" register on team abbreviations + scores + headlines (lines 33–36). Substituted automatically by the FontManager on every rendering medium where the BYO ESPN A2 Beckett + Klavika faces are not cleared.
- **Chip text** the primitive applies `system-ui, -apple-system, BlinkMacSystemFont, sans-serif` regardless of preset; the FontManager attaches Roboto Condensed + Inter at render time based on the preset's `fallbackFont` field. The bound props do NOT carry a `font` axis — the `news-ticker-bar` schema has no font slot (lines 31–68 of `news-ticker-bar.tsx`); typography flows through the preset's frontmatter into the FontManager preload list.
- **Flip-mode chip-internal font** at `bandHeight: 100` → row height = 50 px → chip font size = `round(50 * 0.42) = 21 px`; chip font weight = 600; letter-spacing = `'0.02em'`; whiteSpace = `'nowrap'` (primitive lines 172–185). The 21 px sits inside the stub's "18–22 pt" range on team abbreviations / scores / headlines.
- **Casing** snapshot strings (`'NYK'`, `'BOS'`, `'LAL'`, `'PHX'`, `'PHI'`, `'DAL'`, `'102'`, `'97'`, `'88'`, `'91'`, `'24'`, `'22'`, `'+5'`, `'-3'`, `'+2'`, `'F'`) are already in target casing per stub line 33 ("ALL CAPS" team codes; tabular numerals on scores). The primitive does NOT apply a casing transform on `news-ticker-bar` chips — the literal strings render verbatim.
- **Distinct numeral design** Roboto Condensed numerals on team scores + Inter numerals on status tokens are the OFL+Apache-2.0 fallback render. ESPN A2 Beckett's tall condensed numerals + Klavika's brand-derived numerals (proprietary-byo) cannot render in the parity golden. Cosmetic divergence (D-T339a-11-e); same posture as T-333 D-T333-11-b / T-334 D-T334-11-c / T-335 D-T335-11-d.
- **No italic, no underline, no strikethrough.** ESPN BottomLine broadcast graphics never use them.

The frontmatter schema accepts a single `preferredFont` and a single `fallbackFont` entry. The `proprietary-byo` license string on `preferredFont` is accepted shape (verified — the schema does not parse the license string into separate axes); the Apache-2.0 + OFL `Roboto Condensed + Inter` 700 fallback satisfies the bespoke-font invariant 6 fallback half.

## Animation

- **Steady-state register only in v1 per D-T339a-3.** The `mode: 'flip'` branch of T-356b renders a **static layout per pair window** — there is no entrance animation, no within-window flip transition, no score-flash, no scale-pulse, no topic-bar, no logo-box. The reference frame for the parity golden is mid-segment steady-state at frame 60 (= `pairIdx = 0`).
- **350 ms ease-in-out within-window flip transition** (per stub line 40 — "vertical flip transition, 350 ms ease-in-out") is **out of v1 scope per D-T339a-3 / D-T339a-11**. T-356b's primitive shipped the **steady-state pair render** explicitly, deferring the within-window flip animation to a v2 `T-356c` follow-up per the primitive's own header comment (line 165). v1 inherits the steady-state-only posture; at frame 60 the render is the first pair (NYK / BOS) without animation. Candidate `T-356c`-family carve-out — extend the flip-mode render to drive the 350 ms top-to-bottom flip animation around segment-window boundaries.
- **200 ms yellow flash on score-update** (per stub line 41 — "brief yellow flash on the segment containing the changed game") is **out of v1 scope per D-T339a-3 / D-T339a-11**. The primitive has no `scoreFlash` slot, no frame-driven flash, no per-entry `changedAt` timestamp. Candidate `T-356c`-family carve-out — extend the chip render to drive a 200 ms yellow opacity flash on entries with a recent change-flag.
- **350 ms scale-pulse on TD / wicket / goal** (per stub line 42 — "longer flash + scale pulse 1.0 → 1.04 → 1.0, 350 ms") is **out of v1 scope per D-T339a-3 / D-T339a-11**. Same posture as the score-flash above — primitive-level concern, NOT in T-356a or T-356b's prop surface. Candidate `T-356c`-family carve-out.
- **400 ms ease-out initial slide-up entrance** (per stub line 44 — "slide up from bottom, 400 ms ease-out") is **out of v1 scope per D-T339a-3 / D-T339a-11**. The flip-mode render is **static layout** — no entrance animation per the T-356b posture (parity goldens always land mid-segment). Candidate `T-356c`-family carve-out.
- **Persistent during programming** (per stub line 47 — "stays on screen almost permanently during programming") is a **host-scene composition posture** — the parent timeline holds the clip on-screen for the duration. NOT a primitive-level concern. v1 inherits the steady-state-frame-60 mid-segment render; the persistence is the host scene's responsibility. NO divergence to document.
- **Mid-segment steady-state at frame 60** (per ADR-004 §D5 and D-T339a-5). At 30 fps, frame 60 = 2000 ms; with `flipDurationMs: 4500`, `pairIdx = floor(2000 / 4500) = 0`; top row = entries[0] (NYK `+5` yellow), bottom row = entries[1] (BOS `F` white). The flip-mode render is steady-state per pair window (T-356b); any frame in `[0, 4500)` ms produces an identical render. Cluster-norm consistency (T-333 / T-334 / T-335 / T-323 / T-325 / T-326 / T-327 / T-328 / T-329 / T-330 all use frame 60) AND the operator-default `--frame=60` are the deciding factors.
- **No state-transition animation in v1.** State transitions (within-window flip, score-flash, scale-pulse, entrance, topic-bar reveal, logo-box illumination) belong to the live-mount surface where the data source streams updates AND to the runtime composition where the host orchestrates the broadcast pacing.

Carving out a `kind: 'finance' | 'sports'` discriminant on entries (with sports-specific field names like `team` / `score` / `status`) is `T-356c`-family. NOT a T-339a fix.
