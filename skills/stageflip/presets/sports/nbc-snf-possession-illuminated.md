# NBC SNF Possession-Illuminated — scoreBug

The NBC Sunday Night Football register: a horizontal bar bottom-center on a deep-near-black `#0A0A0A` base; a centered black `48 × 48 px` circle hosting the NBC mark above the clock; team-color flanks left (KC red `#E31837` home — Kansas City Chiefs) and right (BUF navy `#00338D` away — Buffalo Bills, the canonical Sunday Night AFC matchup); white text; tabular-numeric scores; match clock + period + first-down with directional chevrons (`'08:14'` / `'Q2'` / `'<< 1st & 10'`); home-team possession brightness highlight; Public Sans 600 (SemiBold) as the OFL fallback for the proprietary Sweet Sans Pro + NBC Tinker pairing. Common uses: live NFL match overlays where the bottom-center horizontal bar + dark base + center NBC circle + directional chevrons register is the brand signal — sister-but-distinct from T-333's PL upper-left rectangular chrome AND T-334's Fox NFL chromeless gradient.

This preset is the **third Cluster B preset to land**, the **fourth `scoreBug` clipKind consumer** (after T-358's clipKind-default `cricket-ball-by-ball-dots` via the `outcome-row` primitive, T-333's `premier-league-field-of-play` first override, and T-334's `fox-nfl-no-chrome` second override), the **third production consumer of T-332a's `'football'` style branch** (T-333 was first; T-334 was second), and the **first production consumer of three optional fields** on the `'football'` schema: `centerCircle` (round black centroid hosting a glyph), `direction` (play-direction enum), and `networkLogo` (the glyph rendered inside the circle). Wired via `PRESET_ID_BINDINGS['nbc-snf-possession-illuminated']` per Pattern C — the `'scoreBug'` arm in `DEFAULT_CLIP_KIND_RESOLVER` stays UNCHANGED at `scoreBugDotsBinding` (T-358); T-333's `premierLeagueFopBinding` + T-334's `foxNflNoChromeBinding` stay UNCHANGED.

## Visual tokens

The NBC SNF register is canonical and locked: a horizontal bar bottom-center, dark base, center black circle hosting the NBC mark above the clock, kit-colored team flanks, possession illumination on the team in possession, and directional chevrons baked into the down-and-distance text. The visual signal is "horizontal bar + center NBC circle + kit-colored team flanks + directional chevrons + possession illumination" rendered against a deep-near-black base.

- **Background / dark base** `#0A0A0A` — deep-near-black solid. Passed to the primitive's `background` prop, which renders as the root element's `backgroundColor` per `rootStyle()` (lines 285–303 of `score-bug.tsx`). The stub line 26 calls for "≈ 75% opacity" semi-transparent base; the `'football'` branch's `background` prop paints opaque hex (no opacity slot). v1 ships opaque `#0A0A0A` to approximate the visible darkening (D-T335-11-a). Carving out an `opacity` axis is `T-332b`-family.
- **Foreground / text** `#FFFFFF` for the clock, period, down-and-distance, and the network-logo glyph inside the center circle. NOTE: team-box code + score text is **hard-bound** to `#ffffff` regardless of the `foreground` prop (line 314 of `score-bug.tsx`); only the central clock + period + down + center-circle text obey `foreground`.
- **Center circle hosting the NBC mark** `centerCircle: true` + `networkLogo: 'NBC'`. Per the primitive's render path (lines 384–404 of `score-bug.tsx`), this paints a `48 × 48 px` round black `#000000` circle (`borderRadius: '50%'`) ABOVE the clock + period + down spans in the center column, with foreground-colored 14 px / weight 800 text reading `'NBC'` inside. `marginBottom: 4` separates it from the clock text. **First production consumer of `centerCircle` AND `networkLogo`**.
- **Per-team kit colors** KC red `#E31837` (Kansas City Chiefs official primary — Pantone 186 C) + BUF navy `#00338D` (Buffalo Bills official primary — Pantone 281 C). The KC vs BUF fixture pairing is a canonical Sunday Night Football AFC matchup. KC red reuse across T-334 (Super Bowl LIX rematch) and T-335 (Sunday Night canonical) is intentional — KC is a Sunday-Night-frequent register exemplar and the brand reuse documents intra-cluster register variation across NBC vs Fox NFL. Each team box renders the kit color as the **whole team-box background fill** rather than the stub's "4 px edge strip on the outer side" (D-T335-12 — primitive-level cosmetic divergence inherited from T-333 D-T333-11-a / T-334 D-T334-12; the brand signal is preserved at the area level).
- **Position** anchored at `(280, 600)` — bottom-center on a 1280×720 canvas. The primitive's default bug-width is `720 px`, so `x = (1280 − 720) / 2 = 280` centers horizontally; `y = 600` puts the bug `~120 px` above the bottom edge. The primitive renders at `position: { x, y }` via `rootStyle()` absolute-positioning. Default size `720 × 80` (primitive lines 339, 285) since `position.width` / `position.height` are not provided. Same anchor as T-334.
- **Layout shape** horizontal flex row with three children — `score-bug-football-home` (KC-red team box; left), `score-bug-football-clock` (centerCircle + clock + period + down stack; center), `score-bug-football-away` (BUF-navy team box; right). Home box reads `code` then `score` left-to-right (`'KC' '21'`); away box reads `score` then `code` (`'14' 'BUF'`).
- **Possession highlight** `possession: 'home'` — KC has the ball; the home team box receives `filter: 'brightness(1.12)'` (primitive line 309). The away box stays at `'none'`. **Second production consumer of `possession`** in production goldens (after T-334). The fixed 1.12 (12%) sits at the upper bound of the stub's "subtle 8–12% brightness boost" range (D-T335-11-b — within stub spec; documented for clarity).
- **Directional chevrons baked into `down` string** `down: '<< 1st & 10'` — leading `<<` chevrons signal left-to-right play direction. The `'football'` branch's `direction` prop is **schema-accepted but NOT consumed by the primitive's render path** (D-T335-11-e; verified during spec drafting — there is no `props.direction` reference in `renderFootball`). v1 bakes the chevrons into the `down` string for visible render AND supplies `direction: 'left-to-right'` for schema compliance + downstream-consumer awareness. A future `T-332b`-family carve-out can read `direction` to flip chevron rendering automatically.
- **Sweet Sans Pro + NBC Tinker → Public Sans 600 OFL fallback** preserves the stub's "Bold, 18–22 pt" register on team abbreviations (line 32). The proprietary Sweet Sans Pro + NBC Tinker pairing (commercial-byo + proprietary-byo) cannot ship in OSS render; v1 uses Public Sans 600 (D-T335-11-d). Same posture as T-333 D-T333-11-b / T-334 D-T334-11-c.

The kit-color tile fill IS the message — applied uniformly to the team-box background. Code text and score text stay white across both kit-color states; the eye locks onto the kit-colored tile body as the salient signal. The home-box brightness boost (`brightness(1.12)`) layers possession-state on top of the kit-color signal without disturbing it. The center black circle hosting the NBC mark is the brand signature treatment that distinguishes the SNF register from sister Cluster B football consumers.

## Typography

- **`preferredFont: Sweet Sans Pro + NBC Tinker`** (`commercial-byo + proprietary-byo` per ADR-004 §D3). NBC's brand-licensed pairing for the SNF identity — Sweet Sans Pro is a commercially-licensed display family (commercial-byo); NBC Tinker is the proprietary network mark wordmark used inside the centroid circle. Tenants with both licensing arrangements slot them in via the FontManager (T-072). Cluster B IS in `TYPE_DESIGN_REQUIRED_CLUSTERS` (verified during T-333 / T-334 spec drafting), so `signOff.typeDesign` MUST be `'pending-cluster-batch'` or `'signed:YYYY-MM-DD'`, NOT `'na'`. T-335 holds at `pending-cluster-batch`; the cluster-B type-design batch review (cluster-composer task) flips this field across all nine Cluster B presets in one downstream PR.
- **`fallbackFont: Public Sans`** weight `600` (OFL, SIL Open Font License 1.1 via Google Fonts; originally USWDS / GSA). The SemiBold weight matches the stub's "Bold, 18–22 pt" register on team abbreviations (line 32). Lighter than T-334's Inter Display 900 (Black); heavier than T-333's Space Grotesk 600 only by family choice. Substituted automatically by the FontManager on every rendering medium where the BYO Sweet Sans Pro + NBC Tinker faces are not cleared.
- **Team abbreviations** (`'KC'` 2-letter / `'BUF'` 3-letter — both canonical NFL conference team codes; the primitive's `code: z.string().min(1)` accepts any length-1+ string) at the primitive's default 28 px / weight 800 (line 320 of `score-bug.tsx`); rendered in the active font family. Stub line 32 calls for "Bold, 18–22 pt" — the primitive's 28 px default is larger than the stub's print-canon size; the relative hierarchy (heavy-weight bold tabular team codes) is preserved.
- **Scores** (`'21'` / `'14'`) at the primitive's default 28 px / weight 800 alongside the team codes (same `teamSectionStyle`). Stub line 33 calls for "Bold, 26–32 pt, tabular" — the primitive's 28 px sits inside the stub's range. The supplied `font.weight: 600` exercises the SemiBold weight on the typeface, but the score `fontSize: 28` cannot lift independently. Cosmetic divergence at the score-size axis is the same primitive-level limitation as T-333 / T-334; documented as a `T-332b`-family follow-up (new `scoreFontSize` axis OR `scale: 'compact' | 'massive'` enum on the football branch).
- **Match clock + period + down** (`'08:14'` / `'Q2'` / `'<< 1st & 10'`) — clock at 20 px / weight 700 (line 332 of `score-bug.tsx`); period at 12 px / opacity 0.85 (line 406); down at 12 px (no opacity, line 410). The down text sits BELOW the period text in the center clock column.
- **Center-circle text** `'NBC'` at 14 px / weight 800 / foreground color (line 397 of `score-bug.tsx`). The circle is a static black `48 × 48 px` round element (no brightness boost — D-T335-11-c; the stub's 8–12% brightness boost applies ONLY to the possessing team section).
- **`font.tabularNums` omitted** (D-T335-13). T-333 included it explicitly; T-334 + T-335 omit per the stub-implied register. Public Sans ships tabular numerals by default in its 600 weight via Google Fonts; the primitive applies `fontVariantNumeric: 'tabular-nums'` only when `font.tabularNums === true`. The 2-digit scores `'21'` / `'14'` and fixed-position clock `'08:14'` align by gravity even without explicit tabularNums; the down text `'<< 1st & 10'` is left-aligned and tabular-alignment is irrelevant. Cosmetic divergence; either choice (with or without tabularNums) is acceptable.
- **Casing** `'as-is'` — snapshot strings (`'KC'`, `'BUF'`, `'21'`, `'14'`, `'08:14'`, `'Q2'`, `'<< 1st & 10'`, `'NBC'`) are already in target casing. The primitive's `applyCasing` helper (lines 231–249) applies `'as-is'` as a no-op transform. NOTE: `applyCasing` short-circuits leading-numeric strings (`/^\d/`) regardless of the casing prop (lines 233–235), so `'08:14'`, `'21'`, `'14'` would render verbatim under any casing. The down string `'<< 1st & 10'` starts with `<` (non-digit), so the leading-digit short-circuit does NOT fire; with `casing: 'as-is'`, no transform runs anyway.
- **Distinct numeral design** Public Sans 600 numerals are the OFL fallback render; Sweet Sans Pro numerals (commercial-byo) and NBC Tinker glyphs (proprietary-byo) cannot render in the parity golden. Cosmetic divergence (D-T335-11-d / D-T335-12); same posture as T-333 D-T333-11-b / T-334 D-T334-11-c.
- **No italic, no underline, no strikethrough.** NFL broadcast graphics never use them.

The frontmatter schema accepts a single `preferredFont` and a single `fallbackFont` entry. The combined `commercial-byo + proprietary-byo` license string on `preferredFont` is accepted shape (verified — the schema does not parse the license string into separate axes); the OFL `Public Sans` 600 fallback satisfies the bespoke-font invariant 6 fallback half.

## Animation

- **Steady-state register only in v1 per D-T335-3.** The `'football'` style branch of T-332a renders a **static layout** — there is no entrance animation, no possession-change transition, no penalty-flag slide-in, no score-pulse on score change. The reference frame for the parity golden is mid-hold steady-state at frame 60.
- **500 ms ease-out entrance slide-in from bottom** (per stub line 37) is **out of v1 scope per D-T335-3**. Adding a primitive-level entrance enum (slide-in / fade-in / zoom-in) with cubic-bezier params is a primitive-level concern. Candidate `T-332b`-family carve-out IF Reviewer scrutiny demands. v1 captures the steady-state mid-hold frame.
- **400 ms possession-change animation** (per stub line 38 — "illuminated side transitions smoothly over 400 ms — both a brightness shift and a position adjustment for directional chevrons") is **out of v1 scope per D-T335-3 / D-T335-11**. The `'football'` branch's `possession` prop renders as **static** brightness boost (lines 309–310 of `score-bug.tsx`); there is no frame-driven transition between possession states. v1 ships `possession: 'home'` (static brightness boost on KC home box). The chevron position shift on possession change requires the primitive to consume `direction` AND drive a frame-keyed transition — both primitive-level additions. Candidate `T-332b`-family carve-out IF Reviewer demands.
- **300 ms penalty-flag slide-in** (per stub line 39 — "animated yellow-flag indicator slides in from the center, 300 ms") is **out of v1 scope per D-T335-3 / D-T335-11**. The `'football'` branch has no `penaltyFlag` slot, no yellow-flag asset, no frame-driven slide-in. Adding a `penaltyFlag: boolean` + asset bundle + frame-driven choreography is a primitive-level concern. Candidate **`T-335a`** carve-out IF Reviewer scrutiny demands.
- **200 ms score-change quick flash** (per stub line 40) is **out of v1 scope per D-T335-3**. No `scoreChange: { animation, frame }` slot in T-332a's `'football'` branch. Candidate `T-332b`-family carve-out IF Reviewer scrutiny demands; primitive-level addition.
- **Directional-chevron auto-render driven by `direction`** (per stub line 34 — "directional chevrons … `<< 1st and 10 <<` indicating direction of play (compass: 'a genuine innovation')") is **out of v1 scope per D-T335-11-e**. The primitive does not consume `direction`. v1 bakes the chevrons into the `down` string itself (`'<< 1st & 10'`) and supplies `direction: 'left-to-right'` for schema compliance + downstream awareness. Candidate `T-332b`-family carve-out — extend `renderFootball` to consume `direction` and auto-place chevrons on either side of the `down` text.
- **Mid-hold steady-state at frame 60** (per ADR-004 §D5 and D-T335-5). Parity fixture snapshots at this frame. The football branch is a static layout so any post-mount frame produces an identical render; frame 60 is the cluster-norm reference (T-323 / T-325 / T-326 / T-327 / T-328 / T-329 / T-330 / T-333 / T-334 all use 60).
- **No state-transition animation in v1.** State transitions (entrance ramp, possession-change, penalty-flag, score-pulse) belong to the live-mount surface where the data source streams updates AND to the runtime composition where the host orchestrates the broadcast pacing.
